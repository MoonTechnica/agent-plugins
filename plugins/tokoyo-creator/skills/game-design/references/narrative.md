# 物語と世界（小さい作品で効く語り方）

物語は**遊びを強くするために使う**。長い文章・設定資料は作らない。インディーの規模で効くのは、
世界の規則が遊びの規則と一致していること、環境で語ること、短い言葉の口調。
会話を AI で生成する遊びは `$game-ai`、RPG の会話・クエストの保存は [rpg.md](rpg.md)。

## 1. 先に決める 3 つ（`design/brief.md` の「世界」に 3〜6 行で）

| 決めること | 例 | 規則 |
|---|---|---|
| 世界の規則 1 つ | 「光が無いと影が実体になる」「街は毎晩 1 区画ずつ沈む」 | **遊びの規則と同じもの**にする（[fun.md](fun.md) §1「テーマの規則」）。設定だけの規則は語られない |
| 主人公の望み | 「沈む前に妹の店を見つける」 | 1 文。プレイヤーの目的（クリア条件）と一致させる |
| 口調 | 皮肉・寡黙・明るい童話・報告書 | UI の言葉（成功・失敗・記録更新）・敵の名前・アイテムの説明まで同じ口調（[fun.md](fun.md) §3「反応にも個性を」） |

設定・年表・人物の長い紹介は書かない。決めた 3 つから外れる物語の要素は足さない。

## 2. 環境で語る（文字を減らす）

- **場所が出来事を語る**: 倒れた家具・止まった時計・途中で終わった手紙・敵の巣の骨。「何がここで起きたか」をプレイヤーが組み立てる。
- 1 つの区切り（面・部屋・地域）に**語る物を 1〜3 個**。多すぎると背景に溶ける。光・置き方・音で「見るべき物」と分かるようにする
  （`$game-level-design`・`$game-art-direction`）。
- 変化で語る: 同じ場所に戻ると何かが変わっている（花が咲いた・壁が崩れた）。プレイヤーの行動の結果を世界に残す。
- 敵の見た目・動きも世界の説明になる（沈む街の敵は水から出てくる・光を嫌う）。

## 3. 言葉を書く

| 場所 | 長さの目安 | 規則 |
|---|---|---|
| 1 回の会話の吹き出し | 1〜2 行（全角 30〜40 字まで） | スマホの画面で読める量。長い説明は分ける |
| 1 回の会話 | 3〜6 吹き出し | 終わったら次の行動が分かる（行き先・欲しい物） |
| 開始前の導入 | 0〜3 文 | 遊び始めを待たせない。冒頭の 1 分は操作で語る（[fun.md](fun.md) §2） |
| アイテム・敵の説明 | 1 文 + 一言の味付け | 何に効くか（遊びの情報）を先に、物語を後に |
| 終わり（クリア・敗北） | 1〜3 文 | 望みが叶ったか・何が残ったか。敗北の言葉にも口調を |

- 会話は**キャラの望みと口調**から書く。説明のための会話（「知っての通り〜」）をさせない。
- 1 人のキャラに 1 つの言い方の癖（語尾・言わないこと・繰り返す言葉）。
- 会話中は遊びを止める。読む速さは人による: 送りはボタン・タップ、文字の表示は即時か 1 秒以内で全文、既読は飛ばせる。
- 文言は全部データ（`godot/dialogue/*.json` か `tuning.gd` の Dictionary）に分ける。安定 ID を付け、コードに直書きしない
  （言い換え・翻訳・既読の記録が楽になる。RPG の保存は [rpg.md](rpg.md)）。

## 4. 選択と結果

- 選択肢は 2〜3 個。どれを選んでも**遊びに見える差**（手に入る物・敵の態度・開く道）を付ける。言葉が違うだけの選択肢は作らない。
- 結果は選んだ直後に 1 つ、後で 1 つ見せる（遅れて返ってくる結果が「選んだ」実感を作る）。
- 分岐を広げすぎない: 結末 2〜3 種、途中の分岐は小さい差で合流させる。全部の組み合わせを作らない。
- 選んだ内容は保存の対象（安定 ID と保存版。[rpg.md](rpg.md)）。

## 5. 物語の山と遊びの山を合わせる

- 物語の転（意外な事実・裏切り・世界の規則の反転）を、遊びの「ひねり」の区切りに置く（[fun.md](fun.md) §1「起承転結」）。
- ボスの前後は短い言葉（1〜3 行）で、戦う理由と勝った意味を見せる（`$game-combat` references/bosses.md §4）。
- 物語の最大の場面では、操作を奪わずに語る（歩ける・触れる中で起きる）。長い演出は 3 秒を超えたら飛ばせるようにする。

## 6. 検査（新規制作と物語を変えたとき）

- [ ] 世界の規則・主人公の望み・口調を brief に書いた。世界の規則が遊びの規則と同じ
- [ ] 1 回の吹き出しが 2 行以内、会話は 6 吹き出し以内。会話の後に次の行動が分かる
- [ ] 区切りごとに環境で語る物が 1〜3 個ある
- [ ] UI の言葉（成功・失敗・リザルト）が作品の口調になっている
- [ ] 文言がデータに分かれ、既読を飛ばせる
