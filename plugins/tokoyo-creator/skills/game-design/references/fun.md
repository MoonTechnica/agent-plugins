# 面白さの設計と「AI が作った感じ」を消す

新しく作るとき・遊びの核を変えるときの段階 1（企画）で読み、段階 6〜8（遊んで直す〜磨く）で §4 の表を
自分の作品に当てる。数値・不具合・細部だけのターンでは読まなくてよい。
出典は MDA 論文・Celeste の公開ソース・Tuning Canabalt・Mario の起承転結・Apple HIG など（サービス側の調査記録
`docs/_research/2026-10-22-game-design-fun-and-feel.md`。作業環境には無いので読みに行かない）。ここにはそこから引いた**確かめられる規則**だけを置く。

**目指す規模はインディーの名作。** 大作（AAA / AA）の量や演出は作れないし、目指さない。少ない仕掛けを深く磨く。

**「遊べる」と「面白い」は別物。** 起動して最後まで遊べても、核が無い・変化が無い・反応が無いゲームは
「AI が作った」と一目で分かる。原因は能力ではなく、**作者が決めるべきことを決めずに平均値で埋めたこと**にある。

## 1. 企画で決めること（`design/brief.md` に書く）

| 決めること | 規則 | 自分に聞く |
|---|---|---|
| **狙う感じ**（MDA の美学） | 感覚 / 見立て / 物語 / 挑戦 / 仲間 / 発見 / 表現 / 暇つぶし から 2〜3 個。機能の一覧から作り始めない | 各仕掛けがどの感じに効くか 1 行で言えるか。言えない仕掛けは削る |
| **核の動詞** | 何度も繰り返す操作を 1 つ。全部の面・波・敵をその動詞の使い方で組む（Downwell: 跳ぶボタンが空中で撃つ・撃つと落下が遅くなる・踏むと弾が戻る） | 「〇〇して〇〇するゲーム」と 1 文で言えるか |
| **看板の仕掛け**（hook） | このゲームでしかできないことを 1 つ。ジャンルの下限だけでは看板にならない | 似たゲームと並べたとき、何が違うと言うか |
| **テーマを規則にする** | テーマの名詞を動詞と規則に変える（「猫」→ 気まぐれに向きを変える・高い所が安全・狭い所に入れる）。絵を貼り替えても成り立つ規則だけなら、テーマは飾り | テーマ固有の規則を 2 つ以上書けるか |
| **選択** | 1 分のうちに数回「A か B か」を迷わせる（位置取り・どの強化・今撃つか溜めるか）。どの選択肢にも有利になる場面がある | 常に正解が 1 つの選択肢を出していないか。「全部 +10%」の強化になっていないか |
| **危険と見返り** | 安全で小さい得と、危険で大きい得を両方置く（Downwell: 着地しないほど連鎖の報酬が増える）。危険側の得は演出・音でも分かる | 上手い人が選ぶ「より速い・より危ない」道があるか |
| **山と休み** | 難しさは直線で上げず、鋸の歯にする。山（大群・ボス・難所）の後に、得た力を味わう楽な区間を置く。新しい敵や仕掛けを足すことで難しくする（数値だけを上げない） | 難しさを時間で描くと、山と谷が見えるか |
| **起承転結** | 1 つの面・波・区切りは 1 つの仕掛けで貫き、導入（安全に教える）→ 発展（少し難しく）→ ひねり（予想外の使い方）→ 決着（習熟を見せる）。**ひねりを最初に考える**（宮本茂） | 各区切りの仕掛けを 1 語で書けるか。ひねりがあるか |
| **もう 1 回** | 失敗から次の挑戦まで 1 操作・数秒。失敗しても何かが残る（記録・解放・次に試したい選択）。終盤に「あと少し」を見せる（残り距離・次の解放まで） | 負けた直後にもう一度押したくなる理由があるか |
| **表現** | 2 人の結果が違って見える余地（構成・経路・作った物）。表現を狙う作品だけ | 結果画面が人によって違うか |

小さな作品でも同じ。30 秒のゲームなら「区切り」は 10 秒の波、「山と休み」は 3 回の波で作る。

## 2. 最初の 1 分（文字に頼らず教える）

| 時点 | すること |
|---|---|
| 0〜5 秒 | タイトルは世界と主役が見える 1 画面。主操作は「はじめる」1 つ。説明文を並べない（`$game-controls` §4） |
| 5〜15 秒 | 主役が動き、核の動詞を 1 回**必ず成功**させる。操作は必要になる瞬間に画面の中の物（光るボタン・矢印・看板）で示す |
| 15〜30 秒 | 最初の危険は失敗しても安全な場所で出る（World 1-1 のクリボー）。最初の報酬は通り道に置く |
| 30〜60 秒 | 仕掛けの「発展」と最初の選択 |
| 1〜3 分 | 最初の「ひねり」か山場、その後の休み |

## 3. 作者として手で決める（平均値で埋めない）

- **出現は作者が設計し、乱数はその中で使う。** 敵や障害物を一様乱数・等間隔で出さない。波・群れ・休みの並び
  （例: Canabalt は特殊な建物を 3〜8 個ごと、平均 10 秒の休み）を表にして `tuning` に置き、その中で揺らす。
- **生成は「違いが見えて、遊びが変わる」ときだけ。** 見分けられない違いは何百通りあっても同じに見える
  （「オートミール問題」）。手で作った部品（部屋・パターン・波）を組み合わせる（Spelunky 方式）。
- **対比を 3 段以上つける。** 速い敵 / 遅い敵、軽い攻撃 / 重い攻撃、静かな区間 / 激しい区間、小さな音 / 大きな音。
  全部が同じ速さ・同じ大きさだと、重さも山場も伝わらない。
- **反応にも個性を。** 「GAME OVER」「Score: 10」だけで終えない。成功・失敗・記録更新の言葉と演出を世界観の口調で
  書き、結果に「次に試すこと」か「あと何 m」を添える。終わりの 0.5〜2 秒に減速・停止・まとめの演出を置く。
- **UI も世界の素材で。** ボタン・ゲージ・数字の見た目をゲームの絵柄で作り、押した状態を必ず付ける。
  UI だけを見て何のゲームか分かるのが目安。
- **手触りは最初から。** 主役の移動と核の動詞は、灰色の箱の段階で気持ちよくする（`$game-ux` §2、references/feedback.md）。
  磨きの段階で付け足すものではない。

## 4. 「AI が作った感じ」の点検表（段階 6〜8 で自分の作品に当てる）

| # | 症状 | 直し方 | 確かめ方 |
|---|---|---|---|
| 1 | 仮の図形・汎用の絵のまま | 主役・敵・報酬・危険に役割が分かる輪郭と色の差。図形で作るなら図形で一貫した方針と動き（伸縮・目） | 白黒にしても 4 つを区別できるか |
| 2 | 出現が等間隔・一様乱数 | §3 の出現表 | 出現の並びに山と谷を書いたか |
| 3 | 難しさが時間の一次式だけ | 鋸の歯・休み・新しい敵種で上げる | 山の後に楽な区間があるか |
| 4 | テーマが見た目だけ | テーマを規則に（§1） | テーマ固有の規則が 2 つ以上あるか |
| 5 | 看板の仕掛けが無い | 核の動詞と hook を決め直す | 1 文で何のゲームか言えるか |
| 6 | 全部が同じ速さ・強さ | 3 段以上の対比 | 速度・大きさ・音量に 3 段の差があるか |
| 7 | 出来事が無言 | 主要な動詞ごとに音 + 見た目 + 重さに応じた停止/揺れ（`$game-ux` references/feedback.md） | 押したフレームで何かが反応するか |
| 8 | UI が標準部品のまま | 世界の素材で作る・押下状態 | UI だけで何のゲームか分かるか |
| 9 | 説明が長文 | 遊びながら教える。説明は「操作方法」画面へ | 開始までに読む文字が数十文字以内か |
| 10 | 結果が定型文だけ | 世界観の言葉・ニアミス・次に試すこと | 結果画面に世界の言葉が 1 つ以上あるか |
| 11 | 同じ音・同じ死に方の繰り返し | 音程のばらつき・複数素材・撃破の変化 | 連打する音にばらつきがあるか |
| 12 | 定型のタイトル（題名 + Start + Settings） | 実際の場面と主役、主操作 1 つ | タイトルだけで遊びの種類が分かるか |
| 13 | 唐突な終わり | 減速・停止・まとめ、即リトライ | 終わりの 0.5〜2 秒に演出があるか |
| 14 | 選択肢がどれも同じ価値 | 状況で価値が変わる・掛け算で効く組み合わせ | 強化が「全部 +10%」でないか |
| 15 | カメラが中央固定だけ | 進行方向を見せる・ジャンプで上下に揺らさない・重要物へ寄せる | 速いゲームで前方が 0.5 秒以上見えるか |
| 16 | 生成した面が見分けられない | 手作りの部品 + 生成、目立つ目印 | 3 回遊んで各回の特徴を 1 語で言えるか |

当てはまったものを全部直す必要はない。**依頼と狙う感じに効くものから**直し、`design/playtest.md` に
「点検で見つけたこと / 直したこと / 残したこと」を 1 行ずつ残す。数値・不具合だけのターンでは点検しない。

ジャンルごとの手本（名作が実際にやっていること）は [exemplars.md](exemplars.md)。
