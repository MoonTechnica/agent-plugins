# 地域移動・部屋の読み込み・プレイヤー用の地図

RPGの町/フィールド/屋内移動、メトロイドバニアの部屋移動、マップメニュー/ミニマップを作る・変える時に読む。
全作品に地図メニューを追加する指示ではない。指定した作品に必要な方式を選ぶ。
この文書のID/状態名はゲーム内データの例で、SDKの新APIや共通Schemaではない。

## 1. 世界の構造と読み込み方式を分ける

| 方式 | 設計すること |
|---|---|
| 独立した場所へ切替（町→家、フィールド→洞窟等） | 出口ID→移動先の地域/入口ID、到着位置/向き、切替演出、地域固有の進行 |
| 部屋単位の切替（メトロイドバニア等） | 部屋の形/位置/階層、出口同士の接続、到着時の速度/向き/カメラ、再訪時の状態 |
| 連続した世界を近傍ロード | 地域境界の座標/衝突の一致、先読み、活動範囲、保持/解放の上限 |
| 混合 | 地上は連続、屋内/地下は別空間等。接続に応じて切替方法を変える |

RPG/メトロイドバニアという名前だけで読み込み方式を固定しない。
**遊び上の地域/部屋、素材bundle、計算/読み込み用chunkは別の単位**。
一部屋が複数chunkでも、複数部屋が同じbundleでもよい。
地図上で見える部屋をすべて実体化しない。小さい世界の索引と現在の詳細データを分ける。
局所読み込み/資源解放は `$game-open-world`。小さい場所切替へ半径式chunk管理を強制しない。

## 2. 接続と安全な切替

地域/部屋と入口/出口は安定IDで参照する。隣に描かれたことだけで移動可能と扱わない。
必要なら前提能力/鍵/進行、片道/往復、移動先の入口、到着位置を接続データへ持つ。
双方向の接続は対応する出口を照合する。片道/teleport/階段は意図した例外として表す。

- 移動要求→移動先の準備→位置/状態の確定→旧地域の解放という責務を分ける。
  移動先の表示/衝突/必要な定義が揃うまで、到着済み・訪問済み・地図の現在地にしない。
- 境界の連続入力/二重接触で複数の遷移を開始しない。要求ID/世代を照合し、古いロード結果を採用しない。
  不採用の要求が準備した専用資源も既存loaderの所有規則で解放し、現地域の共有資源は破棄しない。
- ロード失敗/取消/離脱では現在の有効な場所と進行を保ち、再試行できるようにする。
  切替前後の重複保持も予算化し、無制限に旧地域を残さない。
- 到着は壁/落下穴/即時再遷移の範囲を避ける。位置/向き/速度を維持するかresetするかは作品で決める。
- セーブ/復帰位置と地域IDは同じ確定状態から保存する。切替途中の新地域IDと旧位置を組み合わせない。
- 再訪時は扉/宝箱/ボス/収集物/能力/クエストの進行を復元する。
  通常敵の復活等、意図したresetと永続状態を区別し、読み込みのたびに進行を初期化しない。

## 3. メトロイドバニアの能力と再探索

通路/障害の条件を実際の移動能力と進行へ結び付ける。
「二段ジャンプが必要」と文書へ書くだけでなく、その能力無し/有りの入力で実地形を検査する。
能力獲得→以前の地域へ戻る→新しい経路→次の目的という往復を検査対象にする。

- 能力を、その能力が必要な場所の奥へ置かない。複数能力の循環依存、片道での閉じ込めを確認する。
- 獲得前の行き止まりには、後で戻る理由が理解できる手掛かりを置く。
  全障害の答えを最初から地図へ表示する必要はない。
- shortcut/復帰地点と探索の報酬で戻る負担を調整する。再訪の量を面白さの数値に置き換えない。
- 能力取得/扉解除/保存再開後も、変更した地域間の往復と必要な目的の成立を確認する。

## 4. 実ステージとマップ表示の正本

**同じ世界定義の安定した地域/部屋/接続IDから、実ステージとマップ表示を導出する。**
地図用の部屋/扉一覧を別に手書きしない。表示用の簡略形/ラベルを持つ場合も同じIDへ結び付ける。

| 表示の種類 | 対応方法 |
|---|---|
| 部屋の輪郭/格子 | 実地形から簡略化/占有セルを作るか、同じ部屋IDに対応する輪郭を保持して整合を検査 |
| 地理的な地図/ミニマップ | 部屋のローカル座標→世界配置→地図座標の変換を一か所で定義する。縮尺・原点・軸/回転・階層も明示 |
| RPGの概略図 | 縮尺/距離を正確に描かなくてもよい。実際の地域/入口/接続を参照し、teleportや別階層を隣接通路と混同しない |

現在地は**確定した地域/部屋IDと実際のプレイヤー位置**から変換する。
上下階/屋内が同じ平面座標でも、階層/別空間IDを区別して別の場所へ現在地を描かない。
出口/階段/転送点、扉/障害、目的/復帰地点の印は、同じ実体IDと作品が許す公開情報から描く。
表示上の線があるなら実際の接続があるかを確認する。近接する部屋を勝手につながない。

見た目を地図画像にする場合は、確定した世界定義から描画/書き出すか、同じID/座標のoverlayで対応を保つ。
AI生成のそれらしい地図画像を独立した正本にしない。地形更新後は古い画像/輪郭/cacheを再生成/失効させる。
地図のために未読込地域のtexture/mesh/physicsまで読み込まない。

## 5. 探索状態とメニュー操作

未発見、存在を知っている、訪問した、地図を入手した等は作品に必要な状態だけ定義する。
地域全体の一括公開か、通ったセルだけの公開かを決め、部屋ID/安定したセルIDで保存する。
**ロード済み/先読み済みを探索済みと扱わない。**

- 地図の入手で地形が分かっても、未取得の宝箱や未見のボスまで知ってよいとは限らない。
  秘密の部屋、未遭遇の障害/報酬、目的の表示は明示した探索/知識ルールで制御する。
- 扉状態は最新の実状態を出すか、最後に見た記憶を出すか決める。
  変化を知らないはずの扉や能力不足を、勝手に地図で教えない。
- 進行・探索状態・地図の表示用cacheを区別する。再訪/保存再開/能力取得で対応が崩れないようにする。
- 地形/生成版の更新では、探索セル/部屋IDの意味が維持されるかを照合する。位置だけのセル番号を
  新しい地形へそのまま引き継がない。必要な対応付け/移行を定義し、移行できない旧探索履歴を
  勝手に消去・別の地域へ付け替えない。旧セーブの扱いは `$game-open-world` と既存の保存互換性方針に従う。
- マップメニュー中の移動/攻撃/時間は作品に合わせて止める。対戦で他人まで停止したと扱わない。
  ズーム/移動/階層切替/戻るはPCとタッチに対応し、閉じる入力をゲーム操作へ漏らさない。
- fast travelがある場合だけ、行先/解除条件/移動先準備を通常の接続/遷移と共有する。

## 6. 必要な検査

データ/ルールで確認し、表示/操作は利用できる実画面でも確かめる。未実施はunknown。

- 全出口の参照先が実在し、目的の入口へ安全に到着する。往復/片道/階段/転送を区別して検査。
- 二重接触、失敗、取消、古いロードの後着、移動途中の保存で位置/進行/現在地が壊れない。
- 初訪問→別地域→再訪→保存/再開で、開扉/取得/探索状態が作品のreset規則どおり。
- 能力獲得前後で障害の通過可否と、戻り道/shortcut/目的地への経路が実ルールどおり。
- 複数の部屋/端/階層で、プレイヤー位置と出口を地図へ写し、向き/縮尺/原点/IDが一致する。
- 地図の表示対象と実世界の対応IDに欠落/余分/誤接続がない。秘密を隠す等の意図した省略は明示。
- 未探索/地図入手/訪問/解除後の表示が知識ルールどおりで、先読みだけで地図が開かない。
- 読み込んだ詳細地域を解放しても、地図の索引と探索履歴が消えず、地図表示が全世界を実体化しない。
- 地形版の変更/旧セーブ/古い地図cacheでも、探索履歴の対応付けと表示が一致し、移行不能を隠さない。
