# 動きを作る（キャラ・UI・演出）

動きは**情報**である。「何をしているか」「いつ当たるか」「押したか」「何が起きたか」を、文字より先に伝える。
飾りの動きを全部に盛らない。伝えるべきことの量まで動かし、ほかは静かにする（盛りすぎは読みにくく、酔う）。

数字は**出発点**。この Skill の値で作り、試遊で 1 つずつ変え、変えた理由を `design/` に残す。

| 読むもの | いつ |
|---|---|
| この SKILL.md | 動きを作る・直すとき（原則・時間の置き場所・道具の選び方） |
| [references/sprite-2d.md](references/sprite-2d.md) | 2D のキャラを動かすとき（AI で描いたコマ・ドット絵・カットアウト・トゥイーン） |
| [references/3d-animation.md](references/3d-animation.md) | 3D のキャラを動かすとき（AI モーションの選び方と整形・AnimationTree・足滑り・ルートモーション・IK） |
| [references/motion-library.md](references/motion-library.md) | 人型の標準モーションをフリー素材（CC0）から探して取り込むとき（クリップ名の一覧つき） |
| [references/ui-motion.md](references/ui-motion.md) | メニュー・HUD・リザルト・通知の動き、演出の場面、動きを減らす設定 |

## 1. 原則（ゲームの手触りに直したもの）

| 原則 | ゲームでの意味 | 数字の出発点（60fps） |
|---|---|---|
| **予備動作 → 有効 → 戻り** | 攻撃・ジャンプ・技は 3 段。**プレイヤーは予備動作を短く**（押した瞬間に動き出す）、**敵は長く**（読んで避けられる） | プレイヤー 2〜6F / 敵 12〜45F。敵の「合図 + 攻撃」は 340ms（20F）以上。詳細は `$game-combat` §1 |
| **出だしは即座、重さは戻りで** | 入力への反応を遅らせて重さを出さない。重さはフォロースルー（振り終わり・反動・着地）で見せる | 入り `EASE_OUT` で短く、戻り `EASE_IN_OUT` で長く |
| **操作が戻るフレームを決める** | 入力が無ければ戻りを最後まで見せ、入力があればそこで次の行動へ切れる | 戻りの 40〜60% あたりから受け付ける。先行入力は 6〜10F 覚える |
| **速さ = 距離 ÷ 時間** | 同じ動きでもフレームが少ないほど速く軽い。振り切った姿勢を一瞬保つと読める | 決めの姿勢を 2〜4F 保つ |
| **伸び縮み（体積を保つ）** | 着地で潰れ、跳ぶと伸びる。縦を縮めたら横を広げる | 着地 縦 0.8 / 横 1.12 を 0.06 秒 → 0.16 秒で戻す |
| **弧と崩し** | 手足・投げた物は弧を描く。打撃の瞬間だけ弧を崩すと強く見える | — |
| **二次動作** | 髪・尻尾・布・武器は本体より遅れて揺れる。主動作を濁らせない量で | 手続きならバネ（§3）、3D は `SpringBoneSimulator3D` |
| **止める** | 当たった瞬間に当てた側と当てられた側を止める（ヒットストップ） | 軽 3〜6F・中 6〜10F・大 10〜20F・上限 30F（`$game-ux` references/feedback.md） |

**入力から見た目までを遅らせない**。押したフレームのうちに何かが変わる（姿勢・音・光のどれか）。
50〜100ms の反応はきびきび、200ms 前後は鈍く感じる。重いキャラでも最初の 1 フレームは変える。

## 2. 時間は 1 か所に置く（`motion.gd`）

AI が書いたゲームで動きが散らかる原因は、時間と緩急の数字がシーンごとにばらばらに書かれること。

1. `assets/motion.gd` を `godot/motion.gd` にコピーし、`const Motion := preload("res://motion.gd")` で使う。
   UI の時間（`UI_ENTER` 0.225 秒・`UI_EXIT` 0.195 秒・`UI_SCREEN` 0.3 秒など）はここにある。
2. ゲーム固有の時間（攻撃のフレーム数・クロスフェード・ヒットストップ）は `tuning.gd` に**名前付きの定数**で置く。
   `create_tween().tween_property(..., 0.37)` のような裸の数字をシーンに書かない。
3. トゥイーンは `motion.gd` の部品を通す。部品が Godot の注意（**使い回さない・同じプロパティに重ねない＝前のを kill・
   ノードから作る・UI はヒットストップ中も動かす `set_ignore_time_scale`**）を 1 回だけ守っている。
4. `Motion.effects`（0〜1）を設定の「画面の揺れ・動き」（`$game-ux` §5 の `effects`）につなぐ。
   0 では移動・拡大・バネが即時の変化になり、**色と不透明度の変化は残る**（情報なので消さない）。
5. 状態とアニメの対応表を先に書く（`design/motion.md`。下の表の形）。AnimationTree・SpriteFrames はこの表から組む。

| 状態 | クリップ / 動き | ループ | 長さ | 入り / 抜け | 操作が戻る | 移動 |
|---|---|---|---|---|---|---|
| 例: 攻撃 1 | `attack_1` | しない | 予備 4F・有効 3F・戻り 14F | 0.06 / 0.2 秒 | 戻りの 8F 目から | その場（コードで少し前進） |

## 3. 道具の選び方

| 動かしたいもの | 第一候補 | 理由 |
|---|---|---|
| 2D の主役・敵の歩き・攻撃（絵柄が凝っている） | AI でキー姿勢を 4〜8 コマ → `sprites.gd frames` で整列（references/sprite-2d.md） | 連番は絵柄を保てる。コマは少なく、キー姿勢から |
| 2D の小さなドット絵（32〜64px） | 同上 + `sprites.gd pixel` | 縮小とパレットをそろえて本物のドットにする |
| 2D の大きな一枚絵のキャラ・ボス | カットアウト（部品に分けて Node2D の階層で回す）または Polygon2D + Skeleton2D | 描き直さずに動かせる。部品の切り出しは references/sprite-2d.md §5 |
| 2D の待機・被弾・着地・拾う | トゥイーン（`Motion.squash` / `pop`、白フラッシュ） | コマを描かずに手応えが出る |
| 3D 人型の待機・歩き・走り・跳び・被弾・死亡 | フリー素材のアニメ付きキャラ・Meshy / Tripo のプリセット | ループとその場の動きが最初から整っている |
| 3D 人型の固有の一発もの | `generate_motion`（HY-Motion）→ `$game-3d-studio` §4.3.1 | ループ・その場の動きは作れないので一発ものだけ |
| 3D 人型以外（四足・多足・蛇・水棲）の移動 | `rig_model_3d` → `animate_model_3d` のプリセット | 人型用は使えない |
| 3D 人型以外の攻撃・待機 | Blender で 3〜4 姿勢をキーにし、間を補間 + バネ | どの AI も対応していない |
| 揺れ・呼吸・視線・傾き・追従・砲塔 | 手続き（`Motion.Spring`・`LookAtModifier3D`・`SpringBoneSimulator3D`） | キーが要らず軽い |

`Motion.Spring(f, z, r, start)` は「追いかける値」に性格を付ける。f は速さ（Hz）、z は減衰（1 未満で行き過ぎて揺れる）、
r は初動（0 でためてから、1 で即座、1 超で行き過ぎ、**負で一度逆へ動く＝予備動作**）。
出発点: きびきび f=4 z=0.6 r=1.5 / 重い f=1.5 z=1 r=0 / ぷるぷる f=5 z=0.3 r=2。
`update(delta, target, Motion.effects)` を毎フレーム呼ぶ。カメラ追従・武器の遅れ・加速での体の傾き・カーソルに使う。

## 4. 確かめる

- **コード上の確認（毎回）**: 状態の対応表どおりにクリップ・遷移・時間がつながっているか。クロスフェードが 0 秒のまま
  残っていないか（Godot の既定は 0。references/3d-animation.md §2）。ループするクリップの先頭と末尾が合っているか。
- **連番のコマ（作ったとき）**: `sprites.gd frames` の `*.check.png`（足元の赤線・胴の青線・重ね描き）と警告を見る。
- **実画面（新規制作・見た目の方向の変更・利用者の依頼のときだけ。リポジトリ方針）**: 代表の動作（待機・歩き・攻撃・被弾・UI の遷移）を
  固定のカメラで連番に撮り、足滑り（接地中の足の移動）・遷移の跳び・予備動作の長さを見る（`$game-playtest`）。

## 5. 検査（`design/playtest.md` に書く）

- [ ] 時間の数字が `motion.gd` か `tuning.gd` の名前付き定数にあり、シーンに裸の秒数が無い
- [ ] 押したフレームで何かが変わる（重いキャラでも）。プレイヤーの予備動作は短く、敵の予備動作は読める長さ
- [ ] 攻撃・技に「操作が戻るフレーム」が決まっている
- [ ] 3D の遷移にクロスフェードが設定されている（0 秒のままの遷移が無い。被弾など意図的なものを除く）
- [ ] 歩き・走りの再生速度が移動の速さに合い、足が滑って見えない
- [ ] 連番のコマの足元と大きさがそろい、ループの継ぎ目でつっかえない（最後のコマが最初の繰り返しでない）
- [ ] 設定の「画面の揺れ・動き」を 0 にすると、揺れ・拡大・バネが止まり、色・不透明度・音で情報は残る
- [ ] 演出（入手・勝利・ボス登場）は飛ばせ、2 回目以降は短い
