# 2D のキャラを動かす（AI で描いたコマ・ドット絵・カットアウト・トゥイーン）

目次: 1 どの作り方か / 2 AI でコマを描く / 3 整列と検査（`sprites.gd`）/ 4 Godot に載せる / 5 カットアウト / 6 トゥイーンだけで動かす / 7 検査

画像生成 AI は「同じキャラを、少しずつ違う姿勢で、同じ大きさ・同じ位置に」描くのが苦手。
1 回の指示で全部そろうことは期待しない。**キー姿勢を少なく描き、道具でそろえ、目で確かめ、悪いコマは作り直す**。

## 1. どの作り方か

| キャラ | 作り方 |
|---|---|
| 小さなドット絵（32〜64px） | コマ描き（§2）→ 整列 → `pixel` でドット化 |
| 絵柄が凝った中くらいのキャラ（〜256px） | コマ描き（§2）→ 整列。コマは最小限 |
| 大きな一枚絵・ボス・会話の立ち絵 | カットアウト（§5）。描き直さずに部品を回す |
| 動きが小さい（待機・被弾・拾う・着地）、または敵が多い | トゥイーンだけ（§6）。コマを描かない |

コマの目安（8〜12fps で再生）:

| 動作 | コマ数 | メモ |
|---|---|---|
| 待機 | 2〜4（またはトゥイーンの上下ゆれ） | 呼吸の小さな上下 |
| 歩き・走り | 4〜6 | 接地・通過・接地（反対の足）・通過。ループする |
| 攻撃 | 3〜5 | 予備動作は長め、当たる瞬間は 1 コマを短く、戻り。`$game-combat` §1 |
| 被弾 | 1〜2 | + 白フラッシュとノックバック（§6） |
| 跳び | 2〜3 | 踏み切り・上昇・落下（落下は速さで切り替え） |

コマを半分に減らしたら、1 コマの長さをおよそ 2 倍にする（動きの速さを保つ）。
左右対称のキャラだけ `flip_h` で反転して使う。武器を片手に持つキャラは反転すると持ち手が変わるので別に描く。

## 2. AI でコマを描く

1. **基準の 1 枚を決めて固定する**: 無地の背景・全身・足元に余白・横向きか正面。承認済みの設定画（`hero.png`）を使う。
   以後の全部の生成にこの 1 枚を入力として渡す（`edit_image`。`generate_image` は参照画像を受け取らない）。
   指示文だけでは同じキャラにならない。
2. **1 枚の中に 4〜8 のキー姿勢を並べて描く**（1 列、または 2 列）。指示に必ず入れる:
   - 「同じ大きさの枠が横に N 個、各枠に同じキャラクター、同じ大きさ、足元は同じ高さ、カメラは固定、枠の間は無地」
   - 「単色の背景（キャラに無い色。緑 `#00FF00` かマゼンタ `#FF00FF`）、影なし」— 透過で作れるなら透過（`generate_image(transparent=true)`）
   - 姿勢は**手前の足 / 奥の足**で書く（「右足・左足」は向きによって取り違える）
   - 「左右を反転しない、向きは全部右向き」
3. ポーズの見本が要るなら、マネキンの姿勢の画像を 1 枚目、キャラを 2 枚目として渡し「1 枚目の姿勢で 2 枚目のキャラを」と頼む。
4. **キー姿勢を先に**。中割り（間のコマ）を AI に描かせると崩れやすい。キー姿勢だけで動きが読めるか先に確かめ、
   足りなければ中割りを 1 コマずつ足す。
5. 下書きは低い品質で候補を複数出して選ぶ。気に入らない 1 コマを指示で直し続けるより、そのコマを作り直すほうが早い。
6. **足の入れ替わりは目で見る**。歩きの接地コマで前後の足が逆になる誤りは、画像を読む AI でも見落とす。
   `*.check.png` を拡大して、接地コマごとに「前の足はどちらか」を確かめる。
7. 背景を抜いたら（`remove_background` か色抜き）、縁に背景色が残っていないか確かめる（下の警告）。

## 3. 整列と検査（`sprites.gd`）

```bash
TOOL=<kit>/skills/game-motion/assets/sprites.gd
# 1 列 6 コマを、背の高さ 96px にそろえて 1 枚のシートに
godot --headless -s $TOOL -- frames design/sprites/hero_run_raw.png --grid 6x1 --height 96 --out godot/sprites/hero_run.png
# ドット絵にする（整列した後、シート全体に 1 回だけ）
godot --headless -s $TOOL -- pixel godot/sprites/hero_run.png --cell 64x112 --to 32x56 --colors 16 --out godot/sprites/hero_run.png
```

`frames` がすること:

- 枠ごとに切り、透明でない範囲を見つける
- **全部のコマを同じ 1 つの倍率で**縮める（コマごとに合わせると大きさが脈打つ）
- **一番下の不透明なピクセル（足元）を 1 本の線に**、胴（上 60% の中心）を 1 本の縦線にそろえる（枠の中心でそろえない）
- 出力: `<out>.png`（同じ大きさのコマが並んだシート）、`<out>.json`（コマの大きさ・倍率・警告）、
  `<out>.check.png`（拡大したコマ + 足元の赤線 + 胴の青線 + 全コマの重ね描き）

警告と対処:

| 警告 | 対処 |
|---|---|
| frame N is empty | 枠の数（`--grid`）が絵と合っていない。数え直す |
| height differs … by more than 12% | そのコマを作り直す（しゃがみ・跳びなど意図した姿勢なら無視してよい） |
| last frame repeats the first | ループでつっかえるので最後のコマを消す（`--frames N-1`） |
| green/magenta edge pixels | 背景色の縁が残っている。背景の抜き直し、または縁の色抜き |
| half transparent pixels | 塗りの絵なら問題ない。ドット絵なら `pixel` を通す |

`pixel` は、1 ピクセルずつ拾うのではなく**ブロックの多数決**で色を決め、透明度を 0 か 255 にし、色数を N にそろえる。
動かす前ではなく**整列の後、全部のコマに一度に**かける（コマごとにかけるとパレットがずれてちらつく）。

## 4. Godot に載せる

- シートは 1 行 = 1 動作にそろえる。`SpriteFrames` に `AtlasTexture`（`region` でコマを切る）を並べる:
  ```gdscript
  var frames := SpriteFrames.new()
  frames.add_animation(&"run")
  frames.set_animation_speed(&"run", 10.0)
  frames.set_animation_loop(&"run", true)
  for i in 6:
      var atlas := AtlasTexture.new()
      atlas.atlas = preload("res://sprites/hero_run.png")
      atlas.region = Rect2(i * 64, 0, 64, 112)
      frames.add_frame(&"run", atlas, 1.0)   # 3 つ目の値はそのコマの長さの倍率
  ```
  攻撃の「当たる瞬間を短く・振り切りを長く」は、`add_frame` の長さの倍率（例 0.5 / 2.0）で表す。
- 攻撃の判定を出すタイミングはアニメに合わせて `AnimatedSprite2D.frame_changed` で知る。または `Sprite2D` の
  `hframes` / `vframes` + `AnimationPlayer` でコマとメソッド呼び出し（判定の出し入れ）を同じトラックに置く。
  `AnimationPlayer` で `play()` した直後に姿勢を確定させたいときは `advance(0)` を呼ぶ。
- **ドット絵の設定**: プロジェクト設定 `rendering/textures/canvas_textures/default_texture_filter = Nearest`、
  `rendering/2d/snap/snap_2d_transforms_to_pixel = true`、画像の取り込みは Lossless、
  ウィンドウは `stretch/mode = viewport` + `stretch/scale_mode = integer`（にじみ・揺れが出ない）。
  なめらかに動かしたい絵柄のゲームは `canvas_items` のまま。
- 足元を原点にする: `offset` か `centered = false` で、足元の線（`<out>.json` の `baseline_y`）がノードの原点に来るように置く。

## 5. カットアウト（大きな絵を部品で動かす）

1. 基準の絵から部品の分解図を `edit_image` で作る: 「頭・胴・上腕・前腕・手・腿・すね・足を離して並べる。
   重なって隠れていた関節の部分（肩・肘・膝の丸み）も描く」。重なりの裏が無いと回したときに穴が開く。
2. 部品を `Sprite2D` にし、関節の位置に原点（`offset`）を合わせて `Node2D` の親子にする（胴 → 上腕 → 前腕 → 手）。
3. `AnimationPlayer` で回転のキーを打つ。最初に「rest」（基本姿勢）のアニメを作り、全部の部品の回転を 0 に戻せるようにする。
4. 柔らかく曲げたいもの（大きなボスの体・布）は `Polygon2D` + `Skeleton2D` で頂点に重みを付ける。
5. 手続きで足す: 呼吸（胴の上下）・待機の揺れ（頭の小さな回転）・尻尾（`Motion.Spring`）。

## 6. トゥイーンだけで動かす

| 動き | 作り方（`motion.gd`） |
|---|---|
| 着地 | `Motion.squash(sprite, 0.2)`（落下が速いほど大きく、最大 0.4） |
| 跳ぶ | `Motion.squash(sprite, -0.15)` |
| 拾う・強化 | `Motion.pop(sprite, 0.25)` |
| 被弾 | `modulate` を白（加算のマテリアルか `self_modulate`）にして 0.05〜0.1 秒で戻す + ノックバック + ヒットストップ（`$game-ux` references/feedback.md） |
| 待機 | 位置 y を歩幅の周期の sin で 2〜4% 上下（ループのトゥイーンか `_process`） |
| 歩き（簡素） | 体を左右に数度傾ける + 上下ゆれ。コマが無い敵・小物に |

敵が多い 2D（サバイバー系）は、1 体ずつトゥイーンを作らず、シェーダーか `_process` で時間から計算する（`$game-design` references/performance-risk.md）。

## 7. 検査

- [ ] 基準の 1 枚を全部の生成に渡した。コマはキー姿勢から作った
- [ ] `frames` の警告を全部処理した。`*.check.png` で足元・胴・大きさがそろっている
- [ ] 歩きの接地コマで、手前の足と奥の足が正しく入れ替わっている（目で確かめた）
- [ ] ループの最後のコマが最初の繰り返しでない
- [ ] ドット絵は `pixel` をシート全体に 1 回かけ、Nearest・ピクセルスナップ・整数倍率で表示している
- [ ] 反転して使うのは左右対称のキャラだけ
