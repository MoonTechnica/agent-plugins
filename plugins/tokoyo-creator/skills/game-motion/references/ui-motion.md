# UI の動き・演出の場面・動きを減らす設定

目次: 1 時間と緩急 / 2 部品ごとの動き / 3 画面の切り替え / 4 演出の場面 / 5 動きを減らす / 6 検査

UI の動きは「どこから来て、どこへ行ったか」「押せたか」「何が増えたか」を伝えるためにある。
**遊びの操作を待たせない**。メニューの動きのせいで次の操作が遅れたら短くする。
見た目（色・文字・部品の形）は `$game-art-direction` references/ui-visual.md、配置は `$game-screen-layout`。

## 1. 時間と緩急

数字は `motion.gd` の定数（`$game-motion` SKILL.md §2）。

| 動き | 時間 | 緩急（Godot） |
|---|---|---|
| 部品が入る | 0.225 秒（`UI_ENTER`） | `TRANS_CUBIC` + `EASE_OUT`（速く入って静かに止まる） |
| 部品が出る | 0.195 秒（`UI_EXIT`。入るより短く） | `TRANS_CUBIC` + `EASE_IN`（静かに動き出して速く消える） |
| 画面全体の切り替え（スマホ） | 0.3 秒（`UI_SCREEN`。0.4 秒を越えると遅い） | `TRANS_CUBIC` + `EASE_IN_OUT` |
| 画面全体（PC） | 0.15〜0.2 秒 | 同上 |
| 押した反応 | 0.05〜0.1 秒で 0.95 倍、離して戻る（`press_feedback`） | 戻りは `TRANS_BACK` で少し弾む |
| 一覧の段差 | 1 つあたり 0.03〜0.05 秒、全体で 0.3〜0.4 秒以内（`stagger`） | 各要素は「入る」と同じ |
| 数字のカウントアップ | 0.4〜1.0 秒。ボタンで最後まで飛ばせる（`count_up` / `finish`） | `EASE_OUT` |
| 通知（トースト） | 入り 0.2〜0.25 秒・表示 2〜4 秒・出 0.15〜0.2 秒 | 入り EASE_OUT / 出 EASE_IN |

`TRANS_CUBIC` + `EASE_IN_OUT` が、Material の標準曲線（cubic-bezier(0.4, 0, 0.2, 1)）にいちばん近い。
弾む `TRANS_BACK` / `TRANS_ELASTIC` は「手に入った」「押せた」など喜ばせたい所だけに使う。全部を弾ませると安っぽい。

## 2. 部品ごとの動き

| 部品 | 動き |
|---|---|
| ボタン | 押した瞬間に縮む + 色が変わる。フォーカス（コントローラー・キーボード）は枠か明るさで、動かさなくても分かるように |
| HP・ゲージ | 減った分を白（または明るい色）で残し、0.3〜0.5 秒遅れて減らす（何が減ったか読める）。回復は即座に伸ばす |
| 増えた数字（スコア・コイン） | `count_up` + 増えた瞬間に `pop`（0.1〜0.15）。毎フレーム増える数字には pop しない |
| 浮かぶ数字（ダメージ） | 上へ 0.4〜0.6 秒 + 最後の 0.15 秒で消える。重要な数字（会心）は大きく、色と形でも分ける（`$game-ux` §4） |
| 獲得した物のアイコン | 拾った場所から HUD の所持数へ飛ばす（0.3〜0.5 秒、弧を描く）。届いた瞬間に HUD 側を pop |
| ダイアログ | 下から 16px + フェードで入る。背景を 50〜70% 暗くする。閉じるときは逆に、速く |
| タブ・ページ | 進む方向へ横に滑らせる（戻るなら逆向き）。距離は画面幅の 10〜20% で十分（全幅は酔う） |
| 読み込み | 1 秒未満は何も出さない。それより長ければ進み具合か、ゆっくりした動き（`$game-ux` §8） |

**HUD は遊びの最中に動かしすぎない**。値が変わった所だけを短く動かし、常に揺れ・脈打つ部品を置かない（目が引かれて遊びが見えない）。
UI のトゥイーンは `set_ignore_time_scale(true)`（`motion.gd` の `ui = true`）で、ヒットストップやスローの最中も動かす。

## 3. 画面の切り替え

| 切り替え | 作り方 |
|---|---|
| タイトル → 遊び | 0.3〜0.5 秒の暗転（`ColorRect` の不透明度）。読み込みが要るなら暗転の間に。暗転したまま 1 秒以上待たせない |
| 遊び → ポーズ | 即座に（0.1 秒以内）。ゲームの絵は止めて少し暗くする |
| 遊び → リザルト | 決着の瞬間を 0.3〜0.5 秒見せてから（§4）、リザルトの部品を `stagger` で |
| 部屋・場面の移動 | `$game-level-design` references/transitions-and-map.md |

暗転・白転・ワイプは 1 つのゲームで 1〜2 種類にそろえる。

## 4. 演出の場面

| 場面 | 長さ | 作り方 |
|---|---|---|
| 普通のアイテムを拾う | 0.3〜0.6 秒 | pop + 音 + HUD へ飛ぶ。操作は止めない |
| 重要なアイテム・能力 | 1.5〜3 秒 | 操作を止め、キャラが掲げる / 物が光って回る + 名前と効果を 1 行。2 回目以降の同じ物は短く |
| 勝利・撃破の決め | 0.3〜0.5 秒のスロー（`Engine.time_scale` 0.3〜0.5）または停止 → 戻す | 最後の一撃のヒットストップを長め（`$game-ux` references/feedback.md） + カメラを少し寄せる |
| ボス登場 | 初回 2〜5 秒、2 回目以降は飛ばすか 1 秒 | 名前の帯・咆哮・カメラの寄り。**いつでも飛ばせる** |
| レベルアップ・ランクアップ | 1〜2 秒 | 光・数字の pop・音。選択肢が出るならその画面でゲームを止める |
| 失敗 | 0.5〜1 秒 | 何が起きたかが分かる一瞬を見せ、すぐ再挑戦（`$game-ux` §6） |

演出は**飛ばせる**（決定・タップで進む）。同じ演出を何度も見せる場面は、2 回目から短くする。
演出中に `Engine.time_scale` を変えたら、終わりで必ず 1 に戻す（途中でシーンが変わっても戻るように `tree_exiting` でも戻す）。

## 5. 動きを減らす

- 設定の「画面の揺れ」（`$game-ux` §5 の `effects`）を `Motion.effects` にもつなぐ。0 のとき:
  - 移動・拡大・バネ・揺れ・スローは止める（即座に最後の状態へ）
  - **不透明度・色の変化、音、ヒットストップは残す**（情報だから）
  - 画面の切り替えは、滑りを止めて短いフェード（0.15 秒）にする
- `DisplayServer.accessibility_should_reduce_animation()` は macOS と Windows だけで端末の設定を返す。
  Web とスマホでは読めないので、**ゲーム内の設定を必ず置く**。読める環境では最初の既定値に使ってよい。
- 大きく回る・ズームし続ける・画面全体が揺れ続ける演出は、`effects` が 1 でも短く（1 秒以内）。

## 6. 検査

- [ ] UI の時間が `motion.gd` の定数を使い、出るのが入るより短い
- [ ] 押した瞬間に反応し、メニューの動きのせいで次の操作が待たされない（画面の切り替えはスマホで 0.4 秒以内）
- [ ] 一覧の段差が全体で 0.4 秒以内、カウントアップは飛ばせる
- [ ] HUD は値が変わった所だけが動き、常に動き続ける部品が無い
- [ ] 演出は飛ばせ、2 回目以降は短い。`Engine.time_scale` は必ず 1 に戻る
- [ ] `effects` 0 で移動・拡大・揺れが止まり、色・不透明度・音・ヒットストップは残る
