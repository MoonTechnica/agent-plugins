# 3Dモデルの診断・修復・仕上げ

3Dモデルを調達/生成/加工するときに読む。生成器の精細度、静止画の綺麗さ、減面の成功だけで完成にしない。
現行素材と承認済みの基準を使い、問題のある工程だけ直す。調達順は `$game-art-direction` §3、
形/装備/骨格/動作の再利用とレシピ保存は `$game-asset-tools` references/efficient-production.md。

## 1. 入力と用途を固定する

`design/asset-manifest.md`の対象に、静止/硬い可動部/スキン変形、必要な動作、基準画像、
原型のパス/素材IDと修復方針を短く残す。実カメラの距離・同時表示数・輪郭や関節に必要な形から予算を選ぶ。
主役の顔・衣装・特徴を、処理を簡単にするため別のデザインへ替えない。

- 生成前に入力を開く。単一対象、背景の分離、歪みの少ない全身、均等な照明を確認する。
  人型はA/Tポーズと手足の隙間、非人型は脚の本数・付け根・尾/翼を確認する。
- 複数視点を使うなら、正面/側面/背面の体型・装備・模様・照明を揃える。
  別々に生成した画像が同一個体とは限らない。画像内の影を立体やベースカラーへ混入させない。
- **入力形式・生成モードは提供されたツールのスキーマだけを使う。** 現行`generate_model_3d`へ
  複数画像、Smart Topology、原型保存、再テクスチャ等の未公開引数を追加しない。
  複数視点APIや高密度原型が使えない時は、その制約を記録して既存入力とBlenderで仕上げる。
- 武器/交換装備/車輪/扉等は、独立して動かす必要があるか決める。必要な部品を身体と融合させない。

## 2. 原因に合う修復を選ぶ

原本を残し、作業用コピーで変更する。テクスチャを外した形状、ワイヤーフレーム、方向別の描画で、
実形状の問題と陰影の問題を区別する。生成したGLBにも既存素材にも同じ判断を使う。

| 症状 | 修復候補 | 保護するもの |
|---|---|---|
| 凸凹・陰影の筋 | 法線/接線/材質を先に確認し、形状ノイズなら局所平滑化や造形修正 | 顔、硬い角、輪郭。全面smoothで丸めない |
| 不要な破片・内部の塊・穴 | 意図を確認して不要部分削除/穴修復。原型の再構成が必要なら局所リメッシュ | 意図した開口、独立部品、薄い翼/膜、指の隙間 |
| 正常な静止形状が重い | 輪郭とUV境界を保つ減面、必要なLOD | 実カメラで見える特徴。閉じた一体形状に作り直さない |
| 肩・肘・股・膝が潰れる | 面配置/骨位置/ウェイトを分けて診断し、必要箇所のリトポロジーとウェイト修正 | 関節の面の流れと曲げた体積。面数だけ減らして終えない |
| 貼り付いた影・継ぎ目・ぼけ | 入力照明、ベースカラー、UVの画素配分、ベイク投射を修正 | 基準の模様と配色。全作品でnormal map除去やroughness固定をしない |

Decimateは減面、Voxel Remeshは表面の再構成、Retopologyは用途に合う面構造への作り直し。
ボクセルの均等な面や自動の四角面化は関節変形を保証しない。ボクセル処理は必要な原型修復に使い、
動くキャラの最終トポロジーとして無条件に採用しない。意図した隙間/薄い部品が消えたら加工を戻す。
単純な機械/小物の壊れた部分は、既存部品やプリミティブで必要な品質まで再構築する案も比較する。

## 3. 原型から軽量モデルへ細部をベイクする

高密度原型が取得済みで、単純減面では必要な細部を失うときに使う。低密度しか取得していない素材に
高密度原型があると推測しない。全素材への有料再生成やベイクを必須にしない。

1. 原型の造形を整え、静止小物は減面、スキン変形するキャラは関節に合う面構造でゲーム用メッシュを作る。
2. ゲーム用UVを確定し、原型から法線/色等の必要な情報をCyclesのSelected to Activeで焼き付ける。
   出力画像とUV、投射用cage/距離、UV島の余白を設定する。近接した指/衣服/装備への誤投射を確認する。
3. シルエットや関節に必要な立体はメッシュに残す。法線マップで輪郭の欠落を修復できるとは扱わない。
4. ゲーム側の照明でベースカラーとPBRを確認する。AO/光を強く色に混ぜて二重の陰影にしない。
5. 最終メッシュでリグ/ウェイトを仕上げる。形状/UVを変えたら影響するベイクを更新し、
   頂点構造を変えたらウェイトやshape keyも再確認する。正常な既存リグを圧縮だけのため作り直さない。

同梱Blenderの版とbpy APIを確認してスクリプトにする。原型、最終形状、UV/ベイク、リグ、動作、
撮影を分け、入力/設定/エンジン版を保存する。変更の影響を受ける工程だけ再実行する。

## 4. リグと動作を仕上げる

- 自動リグ後も未割当頂点、他の脚/反対側の骨への誤ウェイト、骨位置、関節の体積を確認する。
  必要ならウェイトを整理/正規化し、影響骨数を出力先に合わせる。骨や頂点グループの数だけで合格にしない。
- 硬い装備/機械部品は意図した骨へ剛体として追従させる。骨格が不要な可動部はノードアニメーションも使える。
- 必要な既存クリップがあれば再利用する。リターゲットは骨対応だけでなく休止姿勢・骨のローカル軸・
  大きさを合わせ、必要な補正を行う。ワールド回転をそのままコピーして全リグに合うと扱わない。
- in-place/root motionは本編の移動方式と合わせる。移動の二重適用、足滑り/貫通、
  手と武器のずれ、腕のひねり、ループの継ぎ目を直す。局所修正で済む動作を丸ごと再生成しない。
- 非人型はreferences/non-humanoid.mdの体型別経路を使う。自動リグ対応とpreset動作対応を区別する。
- Blenderのconstraint/IK/補正処理がそのままGLBで動くとは扱わない。
  必要なボーン/ノード/shape keyの動作として焼き込み、書き出したGLBを再読み込みする。

## 5. 完成GLBで確認する

制作中と最適化後に同じカメラ/照明/表示サイズ/動作で比較する。原型画像やBlender画面だけで
ゲームの完成素材を確認済みにしない。

1. 実三角形数/頂点数、材質とprimitive数、骨/ウェイト、必要クリップ、寸法/原点/向き、
   テクスチャ寸法、容量を確認する。APIの目標ポリゴン数とGLBの三角形数を混同しない。
2. 利用できるGLB検査で形式と参照を確認する。Sandboxでリグ/動作を要求する出力には
   `require_rig: true`と`required_animations`を指定する。形式合格は変形品質の保証ではない。
3. 完成GLBを本編のBabylonローダーとAnimationGroupで再生する。前/横/後ろと必要な曲げ/ひねり、
   代表動作の接地・ループ・切替を確認する。4方向の静止プレビューだけで動作を確認済みにしない。
4. 重い部分を区別して既存の減面/LOD/材質共有/KTX2/meshopt/量子化を選ぶ。
   統合で可動部を壊さず、圧縮や量子化後にも輪郭・模様・変形を比較する。
   負荷測定は `$game-design` references/performance-risk.md、実画像の観察は
   `$game-playtest` references/visual-observation.mdの既存経路を使う。
5. 修正箇所/使用版/場面/入力/比較結果と未確認を`design/playtest.md`へ記録する。
   再生環境や必要な連続観察が無ければ未確認と書く。スマホ幅を実機性能と扱わない。

新しい生成サービス/GPU環境や未提供モードを勝手に追加しない。公式の紹介や他人の成功例を、
この素材の品質/費用削減実績へ転用しない。提供された生成モードを比較する場合は、既存予算の範囲で
同じ基準素材と最終用途の品質・修正時間・実費を比較する。
