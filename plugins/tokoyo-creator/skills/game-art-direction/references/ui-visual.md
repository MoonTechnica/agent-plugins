# ゲーム UI の見た目（世界観に合わせる・AI で部品を作る・Godot の Theme）

UI は**作品の美術の一部**。Godot の既定の灰色のまま、または汎用のカードと光彩で済ませない。
置き場所・大きさ・セーフエリアは `$game-screen-layout`、文字の大きさの下限・色だけに頼らない・設定は `$game-ux`、
動き（出入り・押した反応）は `$game-motion` references/ui-motion.md。調査と出典: 制作環境の外の `docs/_research/2026-11-26-ai-game-ui-visual.md` に相当する内容をここに要約した。

作る順番（この順を崩さない）:

1. `design/style-guide.md` に **UI の型と部品の決まり**（§1・§2）を書く
2. **Theme** を作る（§4。色・文字の段・余白・角丸・全部の状態）。この時点で `StyleBoxFlat` だけで全画面が組める状態にする
3. 個性が要る所だけ画像の部品を作る（§3）。差し替えは Theme の中だけで済む
4. コンテナで組み、最初のフォーカスと隣を決める（§4.4）
5. 縦・横・幅の狭いスマホで撮影して §6 で確かめる（撮影するのは新規制作・見た目の方向を変えたとき・利用者が頼んだとき）

## 1. 作品の UI の型を 1 行で決める

| 型 | 中身 | 例 | 向く |
|---|---|---|---|
| 画面に重ねる（non-diegetic） | 普通の HUD・メニュー | 体力バー・スコア | ほぼ全部。スマホ・短い遊びは読みやすさでこれ |
| 世界の中に置く（spatial） | 物の上の印・敵の頭上 | 掘れる場所の印、会話できる人の「!」 | 3D・見下ろし。必要な物だけ |
| 世界の一部（diegetic） | 登場人物も見ている物 | 背中のゲージ、手に持つ地図 | 没入が核の作品。読みにくくなるので大事な数値は重ねる側にも出す |
| 画面の効果（meta） | 画面の縁が赤くなる | 被弾の縁 | 補助。点滅の上限は `$game-ux` §5 |

- 型より大事なのは**枠・色・形を世界の美術に合わせる**こと（「作品の素材でできた普通の HUD」）。木の世界なら木の枠、
  SF なら細い線と半透明、手描きなら少し揺れた線。どの型でも読みやすさが美術より先。
- 型は研究上「世界の中の方が良い」とは言えない（Fagerholt & Lorentzon 2009 の分類は分類であって優劣ではない）。

## 2. 部品の決まり（`design/style-guide.md` の「UI」）

| 項目 | 決めること | 例 |
|---|---|---|
| 形 | 角丸の量・線の太さ・影の方向・光源・材質 | 角丸 12、枠 3px、影は右下 4px、木と真鍮 |
| 色の役割 | 背景・面・文字・**主な操作の色（1 色だけ）**・危険・無効 | 主な操作は `design/palette.json` のアクセント |
| 文字の段 | 4〜5 段だけ（`$game-screen-layout` §4 の 720 基準） | 見出し 56 / 本文 30 / 補足 24 / 数字 48 |
| 余白 | 4 の倍数の段 | 8 / 16 / 24 / 32 |
| 状態 | 通常・押した・無効・**選択中（フォーカス）**・（PC の）hover | 押した = 2px 下がって暗く、選択中 = 太い明るい縁 |

- 1 画面に主な操作は 1 つ。大きさ・コントラスト・彩度・位置で「主 → 補助 → 飾り」の 3 段にし、アクセント色は主だけに使う。
- HUD は**今の判断に要る物だけ**。変わったときだけ出す（体力が減ったときだけバーを出す）、隅に寄せ、中央はプレイに空ける。
- 装飾の多い枠の上に細い文字を置かない。背景が変わる所の文字は縁取り（§4.3）。

### 2.1 アイコン

- **黒で塗りつぶしても見分けられる**形（シルエットの検査）。形が色より先。種類を色だけで分けない。
- 1 セットは同じ線の太さ・同じ視点・同じ塗り方。別の画風のアイコンを混ぜない。
- **実際の表示の大きさで確かめる**（48px 以下で細い線と細かい模様は消える）。当たりの大きさは絵より大きくてよい（44pt 以上）。

### 2.2 よく使う画面の型

| 画面 | 落としやすい物 |
|---|---|
| 所持品 | 格子 + 選んだ物の詳細。空きのマスも描く。個数・装備中・新着の印 |
| お店 | 所持金を常に見せる。買えない理由（足りない・持てない）を無効の見た目と文で。買った後に数が変わる |
| 技の木 | 取得済み・取れる・まだ・の 3 状態を形と色で。前提の線と必要な点数 |
| 地図 | 現在地・目的地・凡例・探索済み/未探索（`$game-level-design` references/transitions-and-map.md） |
| 会話 | 話者名・顔・本文・送りの印（▼）・早送り・履歴。1 行 40 字まで、3 行まで |
| ポーズ / 設定 | 「つづける」に最初のフォーカス。音・画質・操作方法（`$game-ux` §7） |

同じジャンルの名作の画面を手本にする（`$game-design` references/exemplars.md）。参照集は Game UI Database（gameuidatabase.com）。

## 3. 画像の部品を AI で作る

全部を画像にしない。`StyleBoxFlat`（角丸・枠・影・単色）で十分な作品は多く、軽く、解像度に依らず、状態の違いも作りやすい。
画像は**作品の個性が出る所**（タイトルのロゴ・主なパネルの枠・アイコン・ゲージ）に絞る。

手順:

1. 承認済みのコンセプト（`design/concept/key-art.png`）を参照に、**UI キットのシートを 1 枚**作る。指示に書くこと:
   「真正面・平面（遠近なし）・文字なし・単色の背景・部品の間は広く空ける・ボタンは通常 / 押した / 無効を横に並べる・
   パネル・枠・ゲージの空の溝と中身・タブ・所持品のマス」。シートは方向を決めるためのもので、ここから切り抜かない。
2. 部品は**シートを参照に 1 つずつ**作り直す（`edit_image` に登録済みのシートを渡す。透過は `generate_image(transparent=true)` か
   単色背景 → `remove_background`。`$game-asset-tools` §3）。各部品は**中央を平らに、飾りは角と辺に寄せる**（9 分割で伸ばすため）。
3. ラベルの位置は「空の平らな面」と指示する。**文字は絵に入れない**（誤字・翻訳できない・伸びて潰れる）。文字が出たら作り直すか、
   その部分を `edit_image` で消す。「文字を入れない」という否定の指示だけでは効かないことがある。
4. コンセプトに無い状態（押した・空のゲージ・選ばれていないタブ）は**明示して**頼む。足りない物だけ作り直す（全部やり直さない）。
5. アイコンは同じ参照で**格子（4×4 など）に並べて 1 枚**で作り、等間隔で切る（`$game-level-design` の `tiles.gd sheet` で格子を確かめる）。
   足りない物は同じシートを参照に足す。
6. 透過の縁に色が残っていないか、**暗い背景と明るい背景の両方**の上で見る。
7. 角の飾りの幅を画像で測り、9 分割の値（§4.2）に入れる。

よくある失敗: 文字の焼き込み／部品ごとに光の向き・色・枠の太さがずれる（別々の指示で作った）／斜めのパネルと正面のボタンが混ざる／
小さくすると潰れる細かい描き込み／中央に模様があって伸ばすと歪む／通常の状態しか無い／隣の部品がくっついて 1 本の帯になる／
パネルの絵が強すぎて文字が読めない（パネルの中は静かに）。

## 4. Godot 4.5 での作り方

### 4.1 Theme を最初に作る

- プロジェクトの Theme を 1 つ作り、`gui/theme/custom` に設定する。既定のフォントと文字の大きさ（`default_font` / `default_font_size`）もここ。
- 役割ごとに**型の変種**を作る: `theme.set_type_variation(&"PrimaryButton", &"Button")`、ノード側は `theme_type_variation = &"PrimaryButton"`。
  `TitleLabel`・`HudLabel`・`DangerButton`・`Panel` の変種など。変種は元の型の一部だけ上書きでき、両方あれば変種が勝つ。
- ノードごとの `add_theme_*_override` は例外だけ。同じ上書きを 2 か所に書いたら変種にする。
- ボタンは全部の状態を Theme に入れる: StyleBox の `normal` / `hover` / `pressed` / `hover_pressed` / `disabled` / `focus`、
  文字色の `font_color` / `font_hover_color` / `font_pressed_color` / `font_hover_pressed_color` / `font_disabled_color` / `font_focus_color`。
  `focus` は他の状態の上に重ねて描かれるので、縁取りや光の輪だけを描く StyleBox にする。スマホには hover が無いので、hover だけに情報を置かない。

### 4.2 画像の部品をつなぐ

| 使う物 | 場面 | 主な設定 |
|---|---|---|
| `StyleBoxFlat` | 角丸・枠・影で足りる面 | `bg_color` / `border_width_*` / `border_color` / `corner_radius_*` / `shadow_size` / `shadow_offset` / `content_margin_*` |
| `StyleBoxTexture`（Theme の中） | ボタン・パネルなど状態を持つ物の画像 | `texture` / `texture_margin_*`（9 分割の境界）/ `axis_stretch_horizontal/vertical`（STRETCH / TILE / TILE_FIT）/ `expand_margin_*`（外へはみ出す影）/ `modulate_color`（1 枚から状態の色違い） |
| `NinePatchRect`（ノード） | 状態を持たない飾りの枠を 1 枚置く | `patch_margin_*` / `axis_stretch_*` |

- 1 枚の画像を `modulate_color` で明るく（hover）・暗く（押した）・灰色（無効）にすると、生成する枚数が減り、色のずれも出ない。
- ピクセルアートの UI は `texture_filter` を `NEAREST` にし、9 分割の値も元の画素の倍数にする。

### 4.3 文字

- 日本語のフォントは同梱の物を Theme の既定にする（`$game-ux` §3。Web は端末のフォントで補われず、無い字は □ になる）。
  インポート設定で Allow System Fallback を切ると、手元でも足りない字が □ で見えて気づける。
- 太さは 2 つまで（本文と見出し）。サイズの段を Theme で決める（動的フォントは大きさごとに字を作って持つので、段が少ないほど軽い）。
- 背景が変わる所の文字は縁取り: Theme の `font_outline_color` と `outline_size`（720 基準で 4〜8）。影は Label / RichTextLabel だけ
  （`font_shadow_color` / `shadow_offset_x` / `shadow_offset_y`）。
- MSDF（インポートの Multichannel Signed Distance Field）は**大きく拡大縮小する文字だけ**（タイトル・ダメージの数字）。小さい文字は
  ぼやけ、低性能のスマホでは重いと公式に書かれている。MSDF で縁取りするなら Pixel Range を縁取りの 2 倍以上にする。
- 長い日本語は `autowrap_mode = TextServer.AUTOWRAP_WORD_SMART` と `language = "ja"`（禁則の改行のため）。1 行 40 字まで・行間を広めに・左揃え。
- 文字と背景の明るさの比は 4.5:1 以上（大きい文字は 3:1）。

### 4.4 並べ方と選択

- 絶対座標で置かない。`MarginContainer`（セーフエリアと余白）・`VBoxContainer` / `HBoxContainer`・`GridContainer`（所持品）・
  `ScrollContainer`・`PanelContainer`（StyleBox の背景と内側の余白）で組む。伸び方は `size_flags_*`、押せる大きさは `custom_minimum_size`。
- 余白・間隔は Theme の定数（`separation` / `margin_*`）にまとめる。
- 画面を開いたら最初の選択をコードで与える（`_ready()` で `button.grab_focus.call_deferred()`）。無いとパッドとキーで何も起きない。
  並びが複雑なら `focus_neighbor_left/top/right/bottom` を指定する。`ui_*` の action はメニューの選択専用で、遊びの操作に使わない（`$game-controls`）。

## 5. エージェントがやりがちな失敗

- Godot の既定の灰色の Theme のまま出す／ノードごとに上書きを散らす／絶対座標で置いて縦横で崩れる
- 選択中の見た目が無い（パッドで今どこか分からない）／押した・無効の状態が無い
- 生成した UI に文字が入ったまま使う／アイコンの画風がばらばら
- 画像を作る前に Theme を作らず、画像の部品が届くまで画面が組めない

## 6. 検査

- [ ] UI の型と部品の決まり（形・色の役割・文字の段・余白・状態）を style-guide に書いた
- [ ] Theme を `gui/theme/custom` に設定し、役割は型の変種で分けた。上書きは例外だけ
- [ ] ボタンに通常・押した・無効・選択中があり、選択中がはっきり見える。最初の選択がある
- [ ] 生成した部品に文字が入っていない。角と辺の飾りを 9 分割で伸ばしても歪まない。暗い背景と明るい背景で縁が汚れない
- [ ] アイコンは黒で塗っても見分けられ、実際の大きさで読める
- [ ] 日本語のフォントを同梱し、□ が出ない。背景が変わる文字に縁取りがある
- [ ] 縦・横・幅の狭いスマホで崩れない（`$game-screen-layout` §7）
