# ジャンル別の操作の割り当て

遊びの説明に合うジャンルの節だけ読めばよい。どれにも当てはまらないときは、いちばん近いものを土台にし、
SKILL.md §2 の決まりごとで埋める。

どのジャンルにも共通:

- **ポーズ**: PC は `Escape` / `P`、スマホは**右上のポーズボタン**（44px 以上。メニュー類は画面の上に置く）、ゲームパッドは **OPTIONS / メニュー**（`pad: [9]`）
- **決定・開始・もう一度**: Space / Enter / クリック / タップ / ゲームパッドの下のボタン（× / A。`onAction`）。再挑戦がある作品は**R**でリトライ。RPGの進行を無確認で消さない
- **ゲームパッド**は各節の「ゲームパッド」行のとおり。書いてある割り当ては `buttons` の宣言順で自動的に付くので、
  節に `pad:` が書いてあるところだけ明示する。タイトル・ポーズ・リザルトのメニューは `onNavigate` で上下に動かし
  端でループ、下のボタンで決定、右のボタンで戻る。対応度は SKILL.md §7 で決めて `manifest.json` の `gamepad` に書く
- **操作説明**はタイトル・ポーズの「操作方法」画面に入力方法ごとに置き、プレイ中は初めての瞬間に一言だけ示す（SKILL.md §4。ゲームパッドは `padLabel`）
- **Godot** ではこの表のキーとスマホの配置を InputMap・`tokoyo_touch_stick.gd`・`TouchScreenButton` に写す（references/godot-input.md）。`createInput` のコードは旧 JS 作品のもの

## 1. 横スクロール・プラットフォーマー（ジャンプして進む）

| PC | スマホ |
|---|---|
| 移動 ← → / A D、ジャンプ Space / ↑ / W / Z、攻撃・ダッシュ X / J / Shift | 左下に ◀ ▶（`dpad-x`）、右下にジャンプ（大）+ 攻撃 |

```ts
createInput({
  root: document.body,
  move: { style: 'dpad-x' },
  buttons: {
    jump: { keys: ['Space', 'ArrowUp', 'KeyW', 'KeyZ'], label: 'ジャンプ' },
    attack: { keys: ['KeyX', 'KeyJ'], label: '攻撃' },
  },
})
```

- 上キーがジャンプなので、`move` の上下は使わない（`dpad-x` は y を常に 0 にする）。
- **押している長さでジャンプの高さを変える**（`released('jump')` で上昇を打ち切る）。
- 足場から落ちた直後の 0.1 秒はまだジャンプできる、着地の 0.1 秒前の入力を覚えておく
  （厳しいタイミングを緩める。タッチの遅れを吸収する）。
- **ゲームパッド**: 左スティック / 十字キーで移動、下（× / A）でジャンプ、左（□ / X）で攻撃（宣言順の既定どおり）。ポーズは `pause: { keys: ['Escape', 'KeyP'], pad: [9] }` を足す。**`full`**
- **手応えの定番**（`$game-ux` §2）: 着地の小さな煙と着地の潰れ（squash）、ジャンプの伸び、敵を踏んだらヒットストップ 50ms。

## 2. 見下ろしアクション・探索（上下左右に歩く）

| PC | スマホ |
|---|---|
| 移動 WASD / 矢印、主アクション Space / J、副 Shift / K | 左下にスティック、右下にアクション 1〜2 個 |

```ts
createInput({
  root: document.body,
  move: { style: 'stick' },
  buttons: {
    action: { keys: ['Space', 'KeyJ', 'Enter'], label: '攻撃' },
    dash: { keys: ['ShiftLeft', 'ShiftRight', 'KeyK'], label: 'ダッシュ' },
  },
})
```

- `input.move` はアナログ（0〜1）。速度にそのまま掛けると、スマホで「少しだけ動かす」ができる。
- キャラクターの向きは最後に 0 でなかった `move` の向きにする（止まっても向きが戻らない）。
- **ゲームパッド**: 左スティック / 十字キーで歩く（`move` はアナログ）、下で主アクション、左でダッシュ。**`full`**
- **手応えの定番**（`$game-ux` §2）: 攻撃が当たった敵の白い点滅とノックバック、倒したら破片、拾った物は浮かぶ数字。

## 15. RPG（会話・所持品・クエスト・地域探索）

- 探索はWASD/矢印・左下stick・ゲームパッド左stick。主アクションは調べる/話す/決定へ統一する。
- 会話/所持品/設定を開くときは探索の入力をresetし、移動へ同じ入力を流さない。メニューは`onNavigate`/`onAction`で選択し、タップでも同じ状態遷移を使う。
- Escape/画面の戻る/ゲームパッドの戻るで1段閉じる。会話決定を長押しで連続消費せず、目的と次の操作を表示する。
- 主操作部は最大4ボタン。全コマンドを常時並べず、会話/戦闘/探索の状態に応じた割当を示す。
- ロード/保存失敗のメニューでも未保存状態と再試行を操作できるようにする。新規開始は保存済み進行を上書きする前に確認する。
- データと保存の詳細は`$game-design`の`references/rpg.md`。性能設定を入力方式だけで決めない。

## 3. シューティング

### 3a. 縦・横スクロールの弾幕（自機を動かして避ける）

| PC | スマホ |
|---|---|
| 移動 WASD / 矢印、ショット Z / Space（押しっぱなし）、ボム X | **指をずらした分だけ自機が動く**（指の下に自機を置かない）、ショットは自動、ボムはボタン |

```ts
const input = createInput({
  root: document.body,
  move: { style: 'none' },   // スマホは相対ドラッグ。キーボードの移動は自分で読む
  buttons: { shot: { keys: ['KeyZ', 'Space'] }, bomb: { keys: ['KeyX'], label: 'ボム' } },
})
// 相対ドラッグ: 前フレームとの差分で動かす（自機が指に隠れない）
let last: { x: number; y: number } | null = null
function dragDelta() {
  const p = input.pointer
  if (!p.down) {
    last = null
    return { x: 0, y: 0 }
  }
  const delta = last ? { x: p.x - last.x, y: p.y - last.y } : { x: 0, y: 0 }
  last = { x: p.x, y: p.y }
  return delta
}
```

- キーボードの移動は `move: { style: 'none' }` では出ないので、矢印キーも使うなら `move: { style: 'stick' }` にして
  スマホではスティックとドラッグのどちらでも動かせるようにするか、キーの Set を自分で読む。
- **スマホではショットを自動にする**（押し続けとドラッグの同時操作をさせない）。PC も自動でよい。

### 3b. ツインスティック（移動と照準が別）

| PC | スマホ |
|---|---|
| 移動 WASD、照準 **マウスの位置**、射撃 左クリック（押している間）か自動 | 左下にスティック（移動）、**照準は一番近い敵に自動で合わせ、射撃も自動** |

- スマホで 2 本のスティックを同時に操作させない。「動いている間は撃たない・止まると近くの敵を撃つ」も定番。
- マウスの照準は `input.pointer`（`root` 基準の CSS px）から自機への向きで決める。
- **ゲームパッド**: 3a は左スティック / 十字キーで自機、ショットは自動（PC と同じ）、ボムは下のボタン。`move: { style: 'stick' }` にしておけばスマホのスティックとパッドの両方が効く（相対ドラッグはその上乗せ）。3b は左スティックで移動、**右スティック（`input.look`）で照準**、`look` が 0 なら近い敵に自動。**`full`**
- **手応えの定番**（`$game-ux` §2）: 発射のたびに自機が 2px 反動、当たった敵の白い点滅、撃破の破片と小さな揺れ。自機の被弾はヒットストップ + 揺れ。

## 4. エンドレスランナー

| PC | スマホ |
|---|---|
| ジャンプ Space / ↑ / W、スライド ↓ / S、レーン移動 ← → / A D | **スワイプ**（上 = ジャンプ、下 = スライド、左右 = レーン）。タップでもジャンプ |

```ts
const input = createInput({
  root: document.body,
  buttons: {
    jump: { keys: ['Space', 'ArrowUp', 'KeyW'] },
    slide: { keys: ['ArrowDown', 'KeyS'] },
    left: { keys: ['ArrowLeft', 'KeyA'] },
    right: { keys: ['ArrowRight', 'KeyD'] },
  },
})
input.onSwipe((swipe) => queue.push(swipe.direction))   // up / down / left / right
input.onTap(() => queue.push('up'))
```

- 画面の操作部は出さない（`label` を付けない）。スワイプは画面の中央寄りで始めるよう説明する。
- 入力は**キューに積んで次の判定で使う**（先行入力。着地の直前のスワイプを捨てない）。
- **ゲームパッド**: 十字キー / 左スティックの上下左右を `onNavigate` で受けてスワイプと同じキューに積む（上 = ジャンプ、下 = スライド、左右 = レーン）。下のボタンでもジャンプ。**`full`**
- **手応えの定番**（`$game-ux` §2）: 障害物に当たった瞬間のヒットストップと揺れ、コインは浮かぶ「+1」、スライドの土煙。

## 5. ワンボタン（フラッピー系・タイミング 1 つ）

| PC | スマホ |
|---|---|
| Space / ↑ / クリック | 画面のどこでもタップ |

```ts
const input = createInput({ root: document.body, buttons: { flap: { keys: ['Space', 'ArrowUp'] } } })
input.onTap(() => flap())                                 // タップとクリック
// キーは毎フレーム: if (input.pressed('flap')) flap()
```

- 反応を速くしたいときは `onTap`（指を離したとき）ではなく、`root` の `pointerdown` を自分で聞いて即座に反応させてよい
  （開始画面を抜ける最初の 1 回だけは `firstInteraction` を待つ）。
- **ゲームパッド**: 下のボタン（`pressed('flap')`。`flap` は 1 つ目なので自動で下に付く）。**`full`**
- **手応えの定番**（`$game-ux` §2）: 押した瞬間の伸びと短い音、通過ごとに数字が跳ねる、ぶつかったらヒットストップ。

## 6. パズル・盤面（オセロ、三目並べ、2048、マッチ 3、ナンプレ、落ち物）

| 種類 | PC | スマホ |
|---|---|---|
| マスを選ぶ（オセロ・三目並べ・ナンプレ） | クリック。矢印でカーソル + Enter / Space でも | マスを直接タップ |
| 入れ替え（マッチ 3） | クリック → 隣をクリック、またはドラッグ | タップ → 隣をタップ、またはスワイプ（**両方受け付ける**） |
| 全体を動かす（2048） | 矢印 / WASD | スワイプ |
| 落ち物（テトリス系） | ← → 移動、↑ / X 回転、↓ ソフトドロップ、Space ハードドロップ | 下に ◀ ▶ と回転・落下のボタン（`dpad-x` + ボタン）、盤面のタップで回転も可 |

- **操作部は出さない**（落ち物を除く）。マスは 44px 以上になるよう盤面の大きさを決める（`$game-screen-layout`）。
- **ドラッグでしかできない操作を作らない**。ドラッグの代わりに「タップ → タップ」でも同じことができるようにする。
- 選んでいるマスは枠や色で示す（キーボードのカーソルとタッチの選択を同じ見た目にする）。
- マスの判定は `input.onTap` の座標、またはキャンバスの `pointerup` から盤面座標に変換して行う。
- **ゲームパッド**: **十字キー / 左スティック（`onNavigate`）でマスのカーソルを動かし、下（× / A）で決定、右（○ / B）で選択を取り消す**。マッチ 3 は「決定 → 隣を選んで決定」の 2 段階。2048 は `onNavigate` をスワイプと同じ 1 手に。落ち物は `move`（`dpad-x`）+ ボタン（宣言順に 下 = 回転、左 = ハードドロップ、下押し込みは十字キーの下）。カーソルの枠はマウスの hover・タッチの選択と同じ見た目。**格子は端でループしない**。`buttons: { confirm: { keys: ['Enter', 'Space'] }, cancel: { keys: ['Escape', 'KeyX'] } }` のように決定 / 取り消しをアクションに持つ（1 つ目が下、2 つ目は `pad: [1]` で右に）。**`full`**
- **手応えの定番**（`$game-ux` §2）: 消えるマスの pop（拡大して消える）とパーティクル、連鎖ごとに音程を上げる、置けない所は小さく震える。

## 7. カードゲーム

| PC | スマホ |
|---|---|
| クリックで選ぶ → 「出す」ボタンかもう一度クリック。ドラッグで場へ出すのも可。数字キー 1〜9 で手札を選べると便利 | タップで選ぶ（持ち上げて拡大表示）→ 「出す」ボタン。ドラッグは補助 |

- カードの詳細を hover で出さない（スマホに無い）。選んだカードを大きく見せる。
- 「出す」「パス」などの決定はカードとは別の大きなボタン（44px 以上）にし、画面の下部に置く。
- 手札が多いときはカードを重ねて並べ、触れる幅（見えている部分）を 44px 以上に保つ。
- **ゲームパッド**: 左右（`onNavigate`）で手札のカーソル、下で選ぶ / 出す、右で戻す、上下で場と手札を移る。選んでいるカードは持ち上げて拡大（タッチの選択と同じ見た目）。「出す」「パス」のボタンにもカーソルが乗る（メニューと同じ線形。端でループ）。**`full`**
- **手応えの定番**（`$game-ux` §2）: 出したカードの着地の跳ね、得点の数字が増えていく演出、出せないカードは灰色 + 鍵か「出せません」。

## 8. リズム・音ゲー

| PC | スマホ |
|---|---|
| レーンごとのキー（4 レーンなら D F J K、または ← ↓ ↑ →）、Space | **画面下部のレーン全体がタップの範囲**（レーンの幅いっぱい） |

- レーンのタップはキャンバスの `pointerdown` を `pointerId` ごとに扱う（複数の指）。レーンの判定は x 座標で。
- 時間は `AudioContext.currentTime` を基準にする（`Date.now()` や `requestAnimationFrame` の時間ではずれる）。
- 判定の幅を広めにする（タッチは入力の遅れが大きい）。開始は音のアンロック（`onFirstInteraction`）の後。
- **ゲームパッド**: レーンにボタンを割り当てる（4 レーンなら 左・上・右・下 = 十字キー、または □ △ ○ ×）。`buttons` の `pad` に十字キー（14 / 12 / 15 / 13）を明示する。**`full`**（レーンが 6 を超えるなら `partial`）
- **手応えの定番**（`$game-ux` §2）: 判定文字（PERFECT / GOOD / MISS）の跳ね、押したレーンの光、コンボ数の拡大。判定は色だけでなく文字で。

## 9. レース・乗り物

| PC | スマホ |
|---|---|
| ステア ← → / A D、アクセル ↑ / W（または自動）、ブレーキ ↓ / S、ドリフト・ブースト Space | 左下に ◀ ▶、右下にブレーキ・ブースト。**アクセルは自動** |

```ts
createInput({
  root: document.body,
  move: { style: 'dpad-x' },
  buttons: {
    brake: { keys: ['ArrowDown', 'KeyS'], label: 'ブレーキ' },
    boost: { keys: ['Space'], label: 'ブースト' },
  },
})
```

- ステアとアクセルの同時押しをさせない（自動アクセル）。傾きでのステアは使えない。
- **ゲームパッド**: 左スティック / 十字キーの左右でステア、アクセルは自動、宣言順に 下 = ブレーキ、左 = ブースト。ブレーキを L2 / R2 に置きたいときだけ `pad: [6]` / `[7]` を明示。**`full`**
- **手応えの定番**（`$game-ux` §2）: 壁やほかの車に当たったときの火花と小さな揺れ、ブーストの速度線（`effects` に掛ける）。

## 10. 3D 三人称・一人称（歩き回る）

| PC | スマホ |
|---|---|
| 移動 WASD、カメラ **マウスをドラッグ**か、マウスで視点を回す遊び（FPS など）なら**マウス固定**（`device.pointerLock` を宣言。SKILL.md「マウス固定」）、ジャンプ Space、アクション E / F / クリック | 左にスティック（移動）、**右半分をドラッグしてカメラ**、右下にジャンプ・アクション |

- キットの `stick` は画面の左 55%・下 70% に触れると出る。カメラのドラッグはそれ以外の場所で、
  `input.pointer` の差分（`down` の間の前フレームとの差）で回す。
- 移動の向きはカメラの向き基準にする（スティックの上 = カメラの前）。
- 感度は控えめに（1px で 0.3〜0.5 度）。上下の角度は制限する。
- **ゲームパッド**: 左スティックで移動、**右スティック（`input.look`）でカメラ**（感度は 1 フレーム 2〜3 度を上限に。上下は制限）、下でジャンプ、左でアクション。**`full`**
- **手応えの定番**（`$game-ux` §2）: 攻撃が当たったらヒットストップ 50〜80ms と当たった物の点滅。カメラは揺らしすぎない（一人称は揺らさない）。

## 11. ひっぱり・投げる・打つ（アングリーバード、ゴルフ、ビリヤード）

| PC | スマホ |
|---|---|
| ドラッグして離す（マウス）。矢印で角度・Space を押す長さで強さ、でも操作できると親切 | ドラッグして離す |

- マウスとタッチは同じ Pointer Events で 1 本に書ける（`pointerdown` で開始 → `pointermove` で狙い → `pointerup` で発射）。
  `setPointerCapture` を使い、`pointercancel` では撃たずに取り消す。
- 指の下に予測線が隠れるので、狙いの線は指と反対側に伸ばす。
- **ゲームパッド**: **左スティックで狙う向き、下のボタンを押している長さで強さ**（離して発射。ゲージを出す）。これがドラッグの代替になる。付けられないなら **`partial`**（プレイはマウス / タッチ）
- **手応えの定番**（`$game-ux` §2）: 引っぱる長さに合わせて予測線とゲージが伸びる、離した瞬間の伸び、当たった物の揺れと破片。

## 12. ターン制・ストラテジー・シミュレーション・経営

| PC | スマホ |
|---|---|
| クリックで選ぶ → クリックで指示、右クリック / Escape で取り消し（右クリックだけに頼らない）、ホイールで拡大、ドラッグで移動 | タップで選ぶ → タップで指示、「取り消し」ボタン、1 本指ドラッグで移動、**拡大縮小はボタン（＋ −）**（ピンチは付けてもよいが必須にしない） |

- 取り消し・ターン終了などのボタンは画面の端に固定し、44px 以上にする。
- 選んでいるものと、選べる場所（移動できるマス等）をはっきり示す。
- **ゲームパッド**: 十字キー / 左スティック（`onNavigate`）でマスや駒のカーソル、下で選ぶ / 指示、右で取り消し、OPTIONS でメニュー（ターン終了はメニューか上のボタン）。拡大縮小は L1 / R1（`pad: [4]` / `[5]`）。マップの移動はカーソルが端に来たら追従。**`full`**（自由な位置の指定が中心なら `partial`）
- **手応えの定番**（`$game-ux` §2）: 選んだ駒の浮き上がり、移動できるマスの表示（色 + 印）、攻撃の結果は数字を浮かべる。

## 13. クリッカー・放置

| PC | スマホ |
|---|---|
| クリック（Space でも可） | タップ |

- 連打を強いない。押し続けで連続実行、または自動化の強化を用意する。
- 数字は大きく、増えたことが分かる演出（ポップ）を付ける。
- **ゲームパッド**: 下のボタンで押す（`down` で連続実行）。強化の一覧は `onNavigate` + 下で買う。**`full`**
- **手応えの定番**（`$game-ux` §2）: 押すたびに押した物が縮んで戻る、数字のポップ、大きな節目（桁が上がる）で派手な演出。

## 14. 格闘・対戦アクション

| PC | スマホ |
|---|---|
| 移動 WASD / 矢印、弱 J、強 K、必殺 L（または Z X C） | 左にスティック、右に 2〜3 ボタン（弱・強・必殺） |

- コマンド入力（↓↘→ + 攻撃）を必須にしない。必殺技は専用ボタン 1 つで出せるようにする。
- オンライン対戦は `$game-multiplayer` を先に読む（入力は `session.input` / `session.send` でサーバーへ送る）。
- **ゲームパッド**: 左スティック / 十字キーで移動、下 = 弱、左 = 強、右 = 必殺（宣言順の既定。上に置きたければ `pad: [3]`）。対戦の入力 schema は変わらない（`session.input.data` にキットの値を書く）。**`full`**
- **手応えの定番**（`$game-ux` §2）: 当たりはヒットストップ 4〜6 フレーム（66〜100ms）とノックバック、ガードは火花の色と音を変える。
