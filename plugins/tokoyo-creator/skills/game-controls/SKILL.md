# ゲームの操作（PC とスマホの両対応 + ゲームパッド）

作るゲームは **PC でもスマホでも最後まで遊べる**こと。同じゲームが、PC ではキーボードとマウスで、
スマホでは画面の操作部とタップ・スワイプで動く。片方でしか遊べないゲームは未完成とみなす。
**市販のコントローラー（ゲームパッド）はその上乗せ**で、どこまで対応したかを `manifest.json` の `gamepad` に書く（§7）。
Godot での書き方の正本は [references/godot-input.md](references/godot-input.md)。

## 1. 手順

1. **ジャンルを決め、[references/genres.md](references/genres.md) の該当する節を読む**。キー・スマホの操作部・
   ゲームパッドの割り当てがジャンルごとに書いてある。遊びの説明に操作の指定があればそれに従い、無い部分だけ表で埋める。
2. **操作を「アクション」で決め、`project.godot` の InputMap に登録する**（`jump` / `fire` / `move_left` …）。
   1 つのアクションにキー・ゲームパッドを両方登録し、ゲームのコードはアクションだけを読む（キーやボタン番号を直接見ない）。
   **1 つ目に決めた主アクション**が、画面では一番大きいボタン、ゲームパッドでは下のボタン（× / A）になる。
3. **スマホの操作部を置く**: 動かし続けるゲームの移動はスターターの `tokoyo_touch_stick.gd`、アクションは `TouchScreenButton`。
   盤面・カードのように直接触るゲームは操作部を出さない（§2）。
4. **開始画面**（最初の操作と音。§3）と、**タイトル / ポーズの「操作方法」画面**（§4）を作る。
5. **`manifest.json` の `gamepad` を §7 の基準で決める**。
6. **§6 のチェック**を全部満たしてから出力する。

## 2. 入力の決まりごと

### PC（キーボード・マウス）

| 決まり | 理由 |
|---|---|
| キーは**物理キー**（InputMap の `physical_keycode`）で登録する | 配列の違うキーボード（AZERTY 等）でも WASD の位置が変わらない |
| 移動は **WASD と矢印キーの両方**に割り当てる | どちらを使う人もいる |
| 決定・ジャンプ・主アクションは **Space**（加えて `Z` か `Enter`）。副アクションは `X` / `Shift`。ポーズは **`Escape` と `P`** | 定番の配置。説明なしで試される |
| 押しっぱなしは `Input.is_action_pressed`、1 回だけの操作は `is_action_just_pressed`。キーリピート（`InputEventKey.echo`）で連打扱いにしない | 押しっぱなしで同じ操作が何度も起きる |
| マウスで遊ぶゲームは**クリックとドラッグ**で完結させる。右クリック・ホイールだけに割り当てた操作を作らない | トラックパッドにホイールが無いことがある |
| hover（マウスを乗せる）だけに意味を持たせない | スマホに hover は無い。光る程度の補助に留める |
| **マウス固定（視点をマウスの移動で回す FPS 型）は使わない** | Godot 作品では `device.pointerLock` を宣言すると検証で落ちる（使用の検出がバンドルのコードしか見ない）。視点は**ドラッグ**で回し、ゲームパッドの右スティックでも回せるようにする |

### スマホ（タッチ）

| 決まり | 理由 |
|---|---|
| **盤面・カード・マスを直接触るゲームは、操作部を出さない**（触った場所がそのまま操作になる） | 仮想ボタンは「動かし続ける」ゲームのためのもの |
| 移動し続けるゲームは**左下に移動スティック**、**右下にアクションボタン**。ボタンは多くて 3 つ | 両手の親指が届く位置。定番の配置 |
| 移動スティックは `tokoyo_touch_stick.gd`。**自作しない**（触れた所が中心・遊び・追従・指の所有をそろえるのは難しい） | 自作のスティックは「触れた瞬間に走る」「半分倒さないと動かない」「ジャンプで乱れる」になる |
| アクションボタンは `TouchScreenButton`。**`Button` などの Control をアクションボタンにしない** | タッチのまねのマウスは 1 本目の指だけ。スティックを押さえたまま 2 本目の指で `Button` は押せない |
| 主要な操作部は **48px 以上**（物理）、触れる対象（マス・カード）も **44px 以上** | 指の幅。Apple HIG 44pt / Android 48dp |
| ボタンの絵は**動作を表すアイコンか言葉**（「ジャンプ」）。`A` / `B` / キーの名前は描かない | 見ただけで何が起きるか分かる |
| 押している間は**見た目が変わる**（`texture_pressed`）。効果音も付ける | 触った手応えの代わり。振動は無い端末が多い |
| 操作部はセーフエリアの内側（`$game-godot` の Host safe area）。スティックの始動範囲に別のボタンを置かない | ホームバー・ノッチと重ならない。範囲内のボタンはスティックに取られて押せない |
| **同時押しを 2 つまで**（移動 + アクション 1 つ）。2 本指ジェスチャー（ピンチ）でしかできない操作を作らない | 片手持ち・親指 2 本で遊ぶ。拡大縮小はボタンでもできるようにする |
| ダブルタップ・長押しに主要な操作を割り当てない | 誤操作と発見しづらさ。やるなら押している間のゲージを出す |
| **画面の端から始まるスワイプ**を操作にしない | OS のホーム・戻るの操作と取り合いになる |
| 厳しいタイミングだけで決まる操作にしない（判定に余裕、少し早い入力も受け付ける） | タッチは入力の遅れとずれが大きい |
| 振動（`Input.vibrate_handheld`）に頼らない | Web の Safari と Android の Firefox に無い。付けるなら付加情報だけ |

### ゲームパッド（市販のコントローラー）

InputMap のアクションに `InputEventJoypadButton` / `InputEventJoypadMotion` を登録すれば、キーとタッチと同じアクションで動く。

| 決まり | 理由 |
|---|---|
| **機能はボタンの位置で決める**: 下（`JOY_BUTTON_A`）= 決定・主アクション、右（`JOY_BUTTON_B`）= 取り消し・戻る、上（`Y`）/ 左（`X`）= 副アクション、Start = ポーズ、十字キー / 左スティック = 移動と選択、右スティック = 照準・カメラ | PS5 の × も Xbox の A も Switch の B も「下」。位置で固定する |
| Guide（Home）と Back（Select / ビュー）に機能を割り当てない | OS やブラウザの操作と取り合いになる |
| **ボタン名を文字で固定しない**（「×で決定」「A でジャンプ」）。`Input.get_joy_name(device)` から機種を推定し（"PS" / "DualSense" / "Xbox" / "Nintendo" / "Switch"）、分からなければ「下のボタン」のように位置で書く | 機種でボタン名が全部違う |
| **「選んで決める」ゲーム**（盤面・カード・メニュー・ターン制）は、十字キー / 左スティックで**カーソルを 1 段ずつ動かし**、下で決定・右で取り消し。メニューは Control のフォーカス（`focus_neighbor_*`・`grab_focus()`）で作る。スティックでポインタを動かす仮想カーソルは作らない | 主要なゲーム機・エンジンの既定はフォーカス移動 |
| カーソル（選んでいるもの）は**常に見える**（枠か色 + 位置）。**線形のメニューは端でループ、格子（盤面）はループしない**。マウスの hover・タッチの選択・パッドのカーソルは同じ見た目 | 見失わない |
| **ドラッグ（ひっぱる・投げる・照準）には、左スティックで向き・押す長さで強さ、の代替を付ける**。付けられないなら `gamepad` は `partial` | ゲームパッドにドラッグは無い |
| Web ではボタンを 1 回押すまでパッドが見えない。**最初の操作（§3）はタップ / クリック / キー**にする | ブラウザがパッドを利用者の操作と認めない（音を鳴らせず、iframe にキーも届かない） |
| スティックの遊びは InputMap の `deadzone` 0.2。移動は `stick.get_move()` で読む（キー/パッドは遊び 0.2 で読み直す） | 遊びを二重に掛けると、ゆっくり倒しても動かない |

### 入力方法の切り替え

- **最後に使った入力に合わせる**。画面に触ったらスマホの操作部と説明を出し、キーやパッドを使ったら消す
  （タッチ付きノート PC、Bluetooth コントローラーをつないだスマホの全部で正しく出る）。`_input` で
  `InputEventScreenTouch` / `InputEventKey` / `InputEventJoypadButton` を見て 1 つの `input_mode` に入れ、
  変わったときだけ説明を描き直す。移動スティックは自分で切り替える。キーボードとパッドは 1 秒以内に交互に来ても点滅させない。
- タッチとマウスを両方数える処理は、`InputEventMouseButton.device == InputEvent.DEVICE_ID_EMULATION` を除外する
  （タッチから作られたまねのマウスを二重に数えない）。

### 傾き・カメラ・マイク（それを使う遊びだけ）

端末の機能は **`TokoyoDevice`**（スターターの autoload）だけで使う。Godot の端末 API やブラウザの API を直接呼ばない。
宣言（`device.motion` / `device.camera` / `device.microphone` と `manifest.device` の `purpose` / `required`）、
開始・停止、届く値は `$game-godot`「Permission-controlled devices」。操作の決まりとしては:

- **`required: false` にし、使えないときの代わりの操作を必ず用意する**（PC には傾きが無い。iOS は許可を断られることがある）。
  `failed` / `stopped` のシグナルで、スティックやボタンの操作と操作説明に切り替える。
- 傾きは持ち始めの角度を基準にし、取り直す操作（「水平にする」）を置く。画面の向きの変化（`screenAngle`）を考える。
- カメラ・マイクは**使う場面でだけ**始め、終わったら止める。始める前に、画面の中で何に使うかを一言出す。
- カメラ / マイクと `ai.chat` は一緒に宣言できない（顔や声が外に出る経路になる。検証で落ちる）。

## 3. 開始画面（最初の操作と音）

画面の構図は `$game-screen-layout` §5、開始/再開/任意設定は `$game-ux` references/start-screen.md。
**最初の操作による音の解禁と、選んだ項目の決定を分ける**。設定/ミュート/操作方法の操作でゲームを開始しない。
準備済みの短時間ゲームは開始の決定 1 回で遊べるようにする。

これは飾りではなく必要な処理:

- ゲームは iframe の中で動く。**PC では、ゲームの中を 1 回クリックするまでキー入力が届かない**。
  「クリック / タップではじめる」がそのクリックになる。
- ブラウザは**利用者の操作の後でしか音を出させない**。BGM は最初の操作の後に鳴らし始める（それまでに鳴らした音は聞こえない）。
  Godot の Web 出力は最初の操作で音を再開するが、無音の間に鳴らした BGM は頭が欠ける。
- **ゲームパッドのボタンは最初の操作にならない**。パッドがつながっていて（`Input.get_connected_joypads()`）最初の操作がまだなら、
  開始画面に「コントローラーは最初に 1 回クリック / タップしてから」と添える。その後の開始・ポーズ・もう一度は下のボタンで進めてよい。
- 開始の決定（主ボタンのクリック/タップ、Enter/Space、パッドの下）は**同じ開始処理**に集める。開始に使った押下を本編の攻撃・移動へ
  流さない（開始の次のフレームまで入力を読まないか、`Input.action_release` で離す）。
- 画面の上端に**ミュートのボタン**を置く（44px 以上。スマホは音を出せない場所で遊ばれる）。

リザルト画面も同じ: 操作部を隠し（`stick.set_shown(false)`）、「タップ / クリック / Space でもう一度」。

## 4. 操作方法の画面と出し分け

**操作の説明はタイトル画面に並べない。** タイトルメニューとポーズメニューに「操作方法」項目を置き、専用の画面で
入力方法ごと（タッチ / キーボード・マウス / コントローラー）に丁寧に説明する。プレイ中は、その操作が初めて要る
瞬間に一言だけ示す（`$game-ux` §1）。画面の中身は [references/godot-input.md](references/godot-input.md) §4。

- 説明は**その端末で使う入力で書く**。操作方法の画面は今の入力のタブを開いて出し、ほかの入力のタブも見られるようにする。
- プレイ中はスマホの操作部のボタンの絵と、初めての瞬間の一言が説明の代わりになる。
- コントローラーのボタン名は機種に合わせ（§2「ゲームパッド」）、分からなければ位置で書く。

## 5. やってはいけないこと

| 禁止 | 代わりに |
|---|---|
| 移動スティックを自作する / 画面の `Button` をアクションボタンにする | `tokoyo_touch_stick.gd` と `TouchScreenButton` |
| 移動を `ui_left` などの `ui_*` で読む / スティックの値を `action_press` して `Input.get_vector` で読む | 自作のアクション（遊び 0.2）と `stick.get_move()` |
| マウス固定（`Input.mouse_mode = MOUSE_MODE_CAPTURED`）・`device.pointerLock` の宣言 | ドラッグで視点を回す（§2「PC」） |
| 全画面（`DisplayServer.window_set_mode`）・画面の向きの固定を自分でする | 全画面は Platform の枠が出す。向きは `manifest.json` と画面への追従（`$game-screen-layout`） |
| Godot の端末 API・`JavaScriptBridge` で傾き・カメラ・マイクを直接取る | `TokoyoDevice` |
| キーボードだけ・タッチだけで遊べるゲーム | §1 の手順で両方に割り当てる |
| ゲームパッドのボタン番号や機種名をゲームのコードで直接見る | InputMap のアクション。名前の表示だけ `get_joy_name` |
| Guide / Back に機能を割り当てる。「×で決定」と文字で固定する | 位置で決め、名前は機種に合わせる |
| 全画面に広がった Control・ColorRect・Panel を `MOUSE_FILTER_STOP` のまま置く | HUD のルート・背景・装飾は `MOUSE_FILTER_IGNORE`（タッチを食べて遊びに届かなくなる） |
| 押しっぱなしをポーズ・会話・画面切替・フォーカス喪失で残す | `stick.reset()` と `Input.action_release` |
| 画面の操作部の上に HUD（スコア等）や重要な敵・足場を置く | HUD は上端。スマホの下の約 25% は操作部が使う（`$game-screen-layout`） |

## 6. 出力前のチェック

- [ ] すべてのアクションが **キーボードでも、タッチでも**実行できる（InputMap と画面の操作部、または直接タッチ）
- [ ] 移動は `tokoyo_touch_stick.gd` の `get_move()`、画面のアクションボタンは `TouchScreenButton`。[references/godot-input.md](references/godot-input.md) §5 を確かめた
- [ ] 開始・ポーズ・再挑戦が、タップ / クリック / キー（Space か Enter）のどれでもできる。開始の押下が本編へ流れない
- [ ] タイトルとポーズから「操作方法」画面を開け、入力方法ごとに説明し、今の入力のタブで開く。タイトル画面に説明文を並べていない
- [ ] スマホの操作部とゲームの重要な表示が重ならない。スティックの始動範囲にボタンが無い
- [ ] ポーズ・画面切替・フォーカス喪失で押しっぱなしが残らない
- [ ] BGM は最初の操作の後に始まり、ミュートのボタンがある
- [ ] **傾き・カメラ・マイクを使うなら**: `TokoyoDevice` で使い、`required: false`、断られた/止められたときもタッチ・キーで遊べる
- [ ] **ゲームパッド**: 全アクションにパッドの割り当てがあり、開始・ポーズ・もう一度が下のボタンで進み、盤面 / カード / メニューは
      十字キーのカーソル + 決定（下）/ 取り消し（右）で選べる。ボタン名を文字で固定していない。開始画面に「最初に 1 回クリック」の一言がある
- [ ] `manifest.json` の `gamepad` を §7 の基準で書いた（`full` / `partial` / `none`）

## 7. `manifest.json` の `gamepad`（対応度）の決め方

ゲームのページに「コントローラー対応」「コントローラー一部対応」のバッジとして出る。**利用者への約束**なので、
下の基準で正直に書く（偽ると通報の対象）。

| 値 | 基準（全部満たすときだけ） |
|---|---|
| **`full`** | **最初のタップ / クリック / キーの後は、開始・プレイ・ポーズ・リザルト・もう一度まで全部をゲームパッドだけで操作できる**。盤面 / カード / メニューはカーソル + 決定 / 取り消しで選べる。ドラッグの操作には全部スティックの代替がある。文字入力が無い |
| **`partial`** | 主なプレイはゲームパッドでできるが、**一部**にマウス / タッチが要る（自由な位置の指定、文字入力、ピンチなど）。何が要るかを操作方法の画面に書く |
| **`none`** | 遊びの中心が位置の指定（お絵描き・どこでもタップ）でゲームパッドに載せられない |

迷ったら **`partial`**（過大に約束しない）。`none` にするのは本当に載せられないときだけ。
