# 戦いを作る（攻撃・敵・ボス）

戦いの面白さは**読める → 反応できる → 自分の判断で勝った**の 3 つで決まる。強い敵・多い敵では面白くならない。
負けたプレイヤーが「今のは見えていた、自分のミスだ」と思えるかどうかを全部の判断の基準にする。

規模はインディーの名作（`$game-design` references/fun.md）。敵は**少ない種類を組み合わせて**深くする。
数値の決め方（体力・攻撃力・倒すまでの回数・難しさの曲線）は `$game-balance`、手応えの量（ヒットストップ・揺れ・点滅）は
`$game-ux` references/feedback.md、移動とカメラは `$game-character-camera`。

| 読むもの | いつ |
|---|---|
| この SKILL.md | 戦いを作る・変えるとき |
| [references/enemies.md](references/enemies.md) | 敵を作る・増やす・動きを変えるとき（役割・頭脳・Godot の追跡と視認） |
| [references/bosses.md](references/bosses.md) | ボス・中ボス・強敵を作るとき |
| `assets/combat_kit.gd` | 攻撃の段階（startup / active / recovery）と攻撃の順番待ち（AttackTokens）の検証済み部品。`godot/combat_kit.gd` にコピーして使う |

## 1. 攻撃は 3 段階でできている

どの攻撃（剣・パンチ・弾・噛みつき・ボスの技）も **予備動作（startup）→ 判定が出る（active）→ 硬直（recovery）**。
フレーム数（60fps）で `godot/tuning.gd` に置き、`combat_kit.gd` の `attack()` / `phase()` で段階を決める。
アニメの側（コマの長さ・クロスフェード・連段の受付・判定をクリップの出来事で出す）は `$game-motion`。

| 段階 | 役割 | プレイヤーの攻撃 | 敵の攻撃 |
|---|---|---|---|
| startup | 何が来るか見せる | **短く**（2〜6F）。押した瞬間に動き出す | **長く**（弱い攻撃 12〜20F、強い攻撃 24〜45F）。構え・光・音で予告する |
| active | 当たる | 2〜6F | 2〜8F。見た目の動きと一致させる |
| recovery | 隙 | 重い攻撃ほど長く（6〜25F）。振りっぱなしの代償 | **反撃の機会**。強い攻撃ほど長く（20〜60F） |

- **予告は敵の startup の中で 3 つ重ねる**: 形（構え・溜め）+ 光（白・攻撃色の点滅や輪郭）+ 音（溜めの音）。
  色だけ・音だけに頼らない（`$game-ux` §4）。速い攻撃ほど予告を大げさにする。
- **当たり判定は active の間だけ有効**にする。見た目の剣の軌跡より少し小さく。プレイヤーの被弾判定は見た目より小さく、
  プレイヤーの攻撃判定は見た目より少し大きく（`$game-design` §3 の「ごまかし」）。
- **1 回の振りで同じ相手に 1 回だけ当てる**（`combat_kit.gd` の `try_hit`。多段攻撃はわざと分ける）。
- 攻撃中の入力は捨てずに**先行入力**として 6〜10F 覚え、recovery が終わった瞬間に出す（連続技・回避の気持ちよさ）。
- **キャンセル**（回避で recovery を打ち消す）は「プレイヤーだけ」「当てたときだけ」など条件を決めて入れる。
  全部キャンセルできると攻撃の重さが消える。
- 格闘・対人では `advantage_on_hit()` で「当てたら次に動けるのはどちらか」を確かめる。ガードされたら攻撃側が
  少し不利（-2〜-8F）が標準。

## 2. 当たり判定（Godot）

| 部品 | 2D | 3D |
|---|---|---|
| 攻撃の判定（hitbox） | `Area2D` + `CollisionShape2D` | `Area3D` + `CollisionShape3D` |
| 受ける判定（hurtbox） | `Area2D`（体の当たりは `CharacterBody2D` と別にする） | `Area3D` |
| 速い弾・レーザー | `RayCast2D` / `ShapeCast2D`、または前の位置から今の位置への `intersect_ray` | `RayCast3D` / `ShapeCast3D` |

- **層（collision layer / mask）を最初に決めて `design/brief.md` の「道具」に書く**: 例 1 地形 / 2 プレイヤーの体 / 3 敵の体 /
  4 プレイヤーの攻撃 / 5 敵の攻撃 / 6 プレイヤーの被弾 / 7 敵の被弾 / 8 拾う物。攻撃は相手の被弾の層だけを mask に入れる。
- 判定の出し入れを物理のコールバックの中で行うときは `set_deferred("monitoring", true)` を使う（直接変えるとエラー）。
  有効にした直後の `get_overlapping_areas()` は次の物理フレームまで更新されない。重なりは `area_entered` で受ける。
- 速い弾は 1 フレームで壁や敵を通り抜ける（弾の速さ × 1/60 秒 > 相手の厚さ）。速い弾はレイで判定する。
- **ルール（体力・無敵・得点）は `rules.gd` か敵のスクリプトの 1 か所で決める**。Area の信号は「重なった」を知らせるだけにし、
  ダメージの計算をあちこちの信号に散らさない。
- 対戦の当たりは `server/main.ts` の `defineSpace` が権威（`$game-multiplayer`）。画面側の Area は演出だけ。

## 3. 当たったとき（被弾・無敵・ノックバック）

| 項目 | 目安 |
|---|---|
| ヒットストップ | `$game-ux` references/feedback.md の表（1 回ずつの攻撃 50〜80ms、連射 10〜20ms、格闘 4〜6F） |
| ノックバック | 攻撃の向きへ。軽い 1〜3 タイル分、重い 4〜8 タイル分。0.1〜0.25 秒で止まる（摩擦で減速） |
| のけぞり（hitstun） | 雑魚: 当てるたびに短くのけぞる。強敵・ボス: のけぞらない（スーパーアーマー）か、一定量で崩れる |
| プレイヤーの無敵時間 | 被弾後 0.5〜1.2 秒、点滅（透明度。`$game-ux` §5）。連続被弾で一瞬で倒れない |
| 体力の見せ方 | プレイヤー: 数が少ないならハート、多いならゲージ。敵: 雑魚は出さないか小さく、強敵とボスはゲージ |
| 倒したとき | 0.1〜0.3 秒の演出（白点滅 → 崩れる / 弾ける）、報酬は通り道へ散らす、`trauma` は倒したときだけ大きく |

- **被弾の理由が分かる**: どの攻撃に当たったかを 1 フレーム目で見せる（当たった方向へ押される・攻撃側が光る）。
- **体力 1 の即死**はアーケード・ワンボタン以外では使わない。使うならリトライを 1 秒以内に。
- 回避（ローリング・ダッシュ）の無敵は 0.15〜0.3 秒。動作全体より短くし、回避の終わりに小さな隙を残す。

## 4. 敵とボス

敵の役割・組み合わせ・頭脳は [references/enemies.md](references/enemies.md)、ボスは [references/bosses.md](references/bosses.md)。
ここでは全体の規則だけ:

- **敵は役割で作る**（近づく / 遠くから撃つ / 守る / 突進 / 呼ぶ / 邪魔する）。見た目違いの同じ敵を増やさない。
- **同時に攻撃してよい敵の数を絞る**（`combat_kit.gd` の `AttackTokens`。近接は 1〜2 体、飛び道具は 2〜3 体）。
  待っている敵は間合いの外を回る・構えるなど、待っていることが見える動きにする。
- **出現は作者が設計する**（`$game-design` references/fun.md §3）。波ごとの敵の組み合わせを表にして `tuning.gd` に置く。
- 画面外からの攻撃は予告を画面の端に出す（矢印・音）。予告できないなら撃たせない。

## 5. 2D と 3D の違い

| | 2D | 3D |
|---|---|---|
| 予告 | 輪郭・色・姿勢が大きく変わる | **距離で見えにくい**。光る範囲・地面の予告（足元の円・線）、構えの音を足す。ロックオン中は予告の位置を画面内に保つ |
| 当たりの形 | 矩形・円 | カプセル・箱。剣の振りは扇形の判定を active の間だけ、または ShapeCast で軌跡を追う |
| 敵の数 | 多くてよい（サバイバー系は数百。`$game-design` references/performance-risk.md） | 同時に戦う敵は 3〜6 体が読める上限の目安。後ろからの攻撃は予告の音と画面の端の印 |
| 向き | 左右（または 8 方向） | カメラの外にいる敵を知らせる（`$game-character-camera` references/camera-3d.md §1・§2 のロックオンと画面端の印） |
| 足元 | — | 地面の影（丸い影）で高さと位置を読ませる。Compatibility では Decal が使えないので板のメッシュで描く（`$game-art-direction` references/vfx.md） |

## 6. 検査（`design/playtest.md` に書く）

- [ ] 敵の攻撃は全部、startup の中に形・光・音の予告がある（`tuning.gd` のフレーム数と予告の演出を照らし合わせた）
- [ ] 当たり判定は active の間だけ出る。1 回の振りで同じ相手に 1 回だけ当たる
- [ ] 被弾後の無敵時間があり、囲まれても一瞬で倒れない（`AttackTokens` か同等の制限がある）
- [ ] 倒すまでの回数が役割どおり（雑魚 1〜3 回・強い敵 5〜10 回。`$game-balance` §2）
- [ ] 最初の敵は安全な場所で、核の動詞だけで倒せる
- [ ] ボスがいるなら [references/bosses.md](references/bosses.md) §5 のチェック
- [ ] ルールを `rules.gd` で持つ遊びは `$game-playtest` §2 と `$game-balance` §4 のシミュレーションを回した
