# 敵の設計と頭脳

## 1. 役割で作る

敵 1 種は「プレイヤーに何をさせるか」1 つで作る。見た目と名前は世界観から、動きは役割から決める。

| 役割 | プレイヤーにさせること | 動きの例 | 組み合わせの効果 |
|---|---|---|---|
| 近づく（雑魚） | 位置取り・核の動詞の練習 | まっすぐ歩いてくる、遅い | 数で押す。他の役割の「壁」になる |
| 撃つ（射手） | 距離を詰める・遮蔽を使う | 距離を保って予告付きの弾 | 近づく敵と組むと「前後を同時に気にする」 |
| 突進 | 横へ避ける・タイミング | 溜めて直線に走る、壁で止まって隙 | 突進を壁や他の敵に当てられると面白い |
| 守る（盾） | 回り込む・崩す手段を使う | 正面だけ防ぐ / 強攻撃で崩れる | 後ろの射手を守ると優先順位の判断が生まれる |
| 呼ぶ・回復 | 優先して倒す判断 | 離れた所で仲間を出す・治す | 放置すると状況が悪化する時計になる |
| 邪魔する | 場の把握 | 足場を消す・視界を遮る・遅くする | 他の敵の脅威を一段上げる |
| 飛ぶ・跳ねる | 上下の位置取り | 地形を無視して来る | 地上の敵と組むと空間全体を使わせる |
| 強い敵（エリート） | 習熟の確認 | 2〜3 種の攻撃を予告付きで使い分ける | 区切りの山場（`$game-design` references/fun.md §1「山と休み」） |

- **最初の 1 体は「近づく」だけ**で、核の動詞 1 回で倒せる。新しい役割は 1 つずつ、安全な場面で初めて見せる（導入）。
  次の区切りで既知の役割と組み合わせる（発展）、その後に意外な組み合わせ（ひねり）。
- 1 つの波・部屋に出す役割は 2〜3 種まで。全部を同時に出さない。
- **敵の変種**（色違い）は「同じ役割で 1 つだけ性質を変えたもの」に限る（速い・弾が 3 方向・倒すと分裂）。
  変えた性質は見た目でも分かるようにする（色 + 形の一部 + 動きの速さ）。

## 2. 頭脳は小さな状態機械

敵の行動は状態（state）と、状態を移る条件で書く。木構造（behavior tree）や汎用の AI の仕組みは作らない。
インディーの規模なら状態 4〜7 個で足りる。

```text
待機/巡回 ──見つけた──▶ 気づいた（0.3〜0.6 秒。! を出す）──▶ 追う/間合い取り
   ▲                                                         │ 間合いに入った & 攻撃の札を取れた
   │ 見失って一定時間                                         ▼
   └──────────────── 探す ◀── 見失った ──── 攻撃（startup → active → recovery）
                                                            │ 被弾
                                                            ▼
                                                         のけぞり → 追う
```

- **状態は enum + `match`** で書く（`enum State { IDLE, ALERT, CHASE, ATTACK, RECOVER, SEARCH, STAGGER }`）。
  各状態に「入ったとき」「毎フレーム」「出るとき」を分け、状態の経過時間を持つ。
- 移る条件は**数値で**（見える距離・視野角・間合い・経過時間）。`tuning.gd` に置く。
- **気づいた瞬間に攻撃しない**。気づき（! と短い音）→ 0.3〜0.6 秒 → 動き出す。プレイヤーが状況を読む時間。
- 攻撃の前に `AttackTokens.request(id)` を取り、取れなければ間合いの外を回る（`assets/combat_kit.gd`）。
  攻撃の recovery の終わりか、倒されたときに `release` / `forget` する。
- 判断は毎フレームでなくてよい（0.1〜0.25 秒ごと。敵ごとに開始をずらす）。多い敵（数十〜数百）で効く。
- **ずるをしない**: 見えていないはずのプレイヤーの位置を使わない（壁越しに追い続けない）。最後に見た位置へ行き、探す。
  例外は、遊びの規則として明示したもの（音で気づく・ホラーの追跡者）だけ。

## 3. 見る・追う（Godot 4.5）

| やること | 2D | 3D |
|---|---|---|
| 見えるか | 距離 → 視野角（`facing.dot(dir) > cos(角度/2)`）→ `RayCast2D` か `intersect_ray` で遮るものが無いか、の順で安い判定から | 同じ順。`PhysicsRayQueryParameters3D.create(from, to, mask)` |
| 歩ける道を追う | `NavigationAgent2D`（`NavigationRegion2D`、`TileMapLayer` の navigation） | `NavigationAgent3D` + `NavigationRegion3D`（焼いたナビメッシュ） |
| 格子の上を追う（パズル・ローグライク・タクティクス） | `AStarGrid2D`（`region` / `cell_size` / `update()` / `set_point_solid()` / `get_id_path()`） | 格子なら同じく `AStarGrid2D`、自由な点の網は `AStar3D` |
| 押し合いを避ける | `NavigationAgent2D.avoidance_enabled` + `velocity_computed` | 同じ（3D） |

- `NavigationAgent` は `target_position` を入れ、`_physics_process` で `get_next_path_position()` へ向かう。
  `is_navigation_finished()` で止まる。**ナビの地図は最初の物理フレームまで準備できていない**ので、`_ready()` で
  すぐ経路を聞かず `await get_tree().physics_frame` の後に始める。
- 経路の再計算は毎フレームしない（目標が一定距離動いたとき、または 0.25〜0.5 秒ごと）。
- 群れ（サバイバー系の数百体）は 1 体ずつナビを使わない。プレイヤーへの方向 + 近い仲間から離れる力（分離）で十分。
  重なりの計算は格子に分けて近くだけ見る（`$game-design` references/performance-risk.md）。
- 対戦の敵（PvE 協力）はサーバーが動かす（`$game-multiplayer`）。画面側で敵の判断をしない。

## 4. 出現と遭遇の組み立て

- 遭遇（1 部屋・1 波）は「役割の組み合わせ × 地形」で設計する。地形の遮蔽・高低差・狭い通路が敵の役割を活かす
  （`$game-level-design`）。
- **出現の表**を `tuning.gd` に置く: 波ごとに（時刻・役割・数・出る場所）。乱数は表の中の揺らぎだけ。
- 出る場所はプレイヤーの視界の外か、予告（地面の光・扉の音）付き。プレイヤーの真横・真後ろに無言で出さない。
- 1 つの遭遇の長さの目安: アクションの部屋 20〜60 秒、サバイバーの波 30〜60 秒、その後に 5〜15 秒の休み。

## 5. 敵の検査

- [ ] 役割の表（§1）で各敵の役割を 1 語で言える。役割が同じで見た目だけ違う敵がいない
- [ ] 新しい役割は安全な場面で単独で初登場する
- [ ] 気づき → 動き出しの間がある。壁越しにプレイヤーを追い続けない
- [ ] 同時に攻撃する敵の数に上限がある
- [ ] ナビは最初の物理フレームの後に始め、経路の再計算を間引いている
