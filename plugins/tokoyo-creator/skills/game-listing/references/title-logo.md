# 独立したタイトルロゴと掲載画像

アイコン・カバー・スタート画面を作る時に読む。タイトルロゴは一度作る独立した透過素材とし、
同じ画像を各用途で再利用する。キャラクターは必須ではない。車・建物・道具・盤面・場所など、
遊びを象徴する対象を主役に選ぶ。参照画像からは構成を学び、他作品のロゴやキャラクターを写さない。

## 作る順番

1. 現在の掲載タイトルを確定し、既存の `assets/title-logo.png` と素材一覧を確認する。
   正確な文字列・画風が合うロゴは再利用する。企画の仮タイトル画像を完成ロゴとみなさない。
2. タイトルだけを独立して生成する。プロンプトに確定タイトルを引用し、日本語の英訳・ローマ字化をしない。
   世界観に合う字体・縁取り・配色を指定し、人物・風景・操作ボタン・説明文を描かせない。
   外周に余白を確保し、ロゴの装飾や文字の内部の抜きも含めて透過を確認する。
3. **`generate_image(name="タイトルロゴ", prompt=…, transparent=true)`** の既存経路を使う。
   内蔵画像生成で作る場合は単色背景で生成し、`$game-asset-tools` §3 の
   `upload_image` → アップロード完了 → `remove_background` → 取得の順に従う。
   内蔵生成への「透過にして」という指示だけで背景透過済みとは扱わない。
   有料処理は既存の素材ツール・予算・使用量記録を使い、独自API呼び出しを増やさない。
4. 結果をアルファ付きPNGの `assets/title-logo.png` へ保存する。画面ごとの再生成や、
   合成済みアイコンからのロゴ切り抜きはしない。文字の誤字・抜け・白い縁・背景の残りを実画像で確認する。
   明暗両方の背景で透過を確かめる。市松模様が画像に描かれているだけなら不合格。
5. アイコン用とカバー用の**文字なし**の絵を別構図で作り、独立ロゴを合成する。
   キャラクターを見せる作品では、**ゲームで実際に採用しているキャラクター画像・設定画と独立ロゴを
   i2iの参照入力に使う**。キャラクターとロゴから完成画像を直接生成してもよく、文字なしの中間画像の
   生成を必須にしない。顔・髪・衣装・体形・特徴的な装備・画風を維持するよう指定し、文章だけで
   別のキャラクターを描き直さない。キャラクターが不要な作品は、実際に使う車・建物・道具・盤面などを参照する。
   **i2iによる合成も使ってよい**。利用可能な画像編集ツールのスキーマを確認し、ロゴとビジュアルを
   参照入力にして、文字列・字形・配色・装飾を維持するよう指定する。複数参照がない経路では、
   ローカルで仮配置した1枚を登録して `edit_image` へ渡せる。未対応の参照配列を引数に足さない。
   ローカル合成も選べる。i2iの結果は原本と照合し、文字の変形・誤字・装飾の不一致があれば修正する。
   合成済み画像で独立ロゴの原本を上書きしない。
   キャラクターの顔・衣装・特徴も採用済み参照と照合し、別人化や装備の欠落があれば修正する。
   象徴を大きく、背景で世界観を示し、ロゴの置き場（アイコンは原則下部）を空ける。
   ロゴの比率を維持し、主役の見せ場を隠さない。完成アイコン・カバーは不透明とする。
6. スタート画面では `app.assets.url('assets/title-logo.png')` で同じ素材を読み、背景と別に配置する。
   縦横で位置・大きさを変えられるようにし、開始/再開の操作をロゴに焼き込まない。

## 素材として残す

`design/game-assets.json` の既存itemsへ次の項目を追加する（一覧全体を置き換えない）。
生成結果の素材UUIDがある時は `asset_id` も記録する。内蔵で作った完成PNGは
`$game-asset-tools` の `upload_image` で登録できる。未加工の入力画像のUUIDを完成ロゴへ流用しない。

```json
{
  "id": "title-logo",
  "name": "タイトルロゴ",
  "description": "アイコン・カバー・スタート画面で共用する透過タイトルロゴ",
  "kind": "image",
  "purposes": ["game"],
  "sources": [{"path": "assets/title-logo.png"}],
  "thumbnail_path": "assets/title-logo.png"
}
```

`design/asset-manifest.md` に確定タイトル・元画像/素材ID・合成先・実際のスタート画面の実装パスと
合成手順（i2iでは入力素材ID・プロンプト・結果ID）を記録する。`assets/` のロゴは配信するゲーム素材、`listing/` の完成画像は掲載用。
ロゴを `listing/` や `design/concept/` だけへ置いてゲームから参照しない。
再利用する絵と合成スクリプト/設定はソースへ保存し、既存の `asset-recipe` を使える場合は
入力画像・ロゴ・配置・加工エンジンの版をレシピへ記録する。

タイトル変更時はロゴを更新し、記録した参照先を調べてアイコン・カバーを再合成し、スタート画面を確認する。
ロゴだけの変更で無関係な背景を再生成しない。安定IDは維持し、利用者が手直しした掲載項目は既存ルールを守る。

## 完成確認

- ロゴ単体の文字列が現在のタイトルと一致し、アルファ透過がある。
- 完成アイコンは48px/96px・丸角表示でも象徴が分かり、ロゴがつぶれず主要部分が欠けない。
  読めない時は配置・背景の情報量・ロゴの字組みを修正する。
- カバーの切り抜きとスタート画面の縦横表示で、同じロゴと主役・操作が読める。
- ソースと素材一覧に完成ロゴが残り、次の編集で選択・再利用できる。

生成失敗・透過不良・未確認は `notes` に残す。完成していない素材を成功扱いしない。
