# FDPocket Developer Kit

Build mini-apps for the FDPocket super app with the coding agent you already use on your own machine
(Claude Code, Codex, and others).

A mini-app is a small web project: a user-facing `web` app and, optionally, an `admin` app that share one database,
one set of users and permissions, and one file store. The Kit gives your agent the same Skills, instructions, SDK and
project template that the Platform's generation agent uses, plus a connection to the Platform (an MCP server called `fdpocket`).

> This plugin directory is generated by CI from the main repository. **Do not edit it directly** —
> your changes will be overwritten by the next generation.

## How it works

```text
 You (describe the app)
   │
   ▼
 Coding agent  ──  Kit Skills + SDK + template  ──▶  edits ./source/ on your machine
   │                                                  └── kit dev runs every app locally
   ├── Platform MCP (`fdpocket`) ◀──▶ Platform   create / pull / push / images / proposals
   │
   ▼
 Push  ──▶  Platform validates it  ──▶  a draft appears in the editor (a URL is shown)
                                         └── you try it, publish, and post from the browser
```

Things to know up front:

- **`kit dev` runs your apps locally** with the same Gateway the Platform uses, a local database and file store,
  and a development host page (`http://localhost:4320`) where you switch between apps and test users.
- **Publishing and posting are done by you, in the browser.** The agent can create, edit, and push drafts,
  but it cannot make an app public.
- **Pushing runs the Platform's validation every time.** The Kit runs the same static checks locally before each push.

## Requirements

- Node.js 22.12 or later and [Bun](https://bun.com) 1.3 or later
- `git` 2.38 or later and [Git LFS](https://git-lfs.com) (`source/` is a git repository; images and other media are stored with LFS)
- `tar` (built in on macOS and Linux; Windows 10 and later ships `tar.exe`)
- A registered account (an anonymous guest account is not enough). You sign in through the browser the first time.
- Network access to the npm registry (the project's dependencies are installed with `bun install`).

`node <kit>/scripts/kit.mjs doctor` checks all of these at once, shows how to fix anything missing, and tells you
when a newer Kit is available.

## Quick start (Claude Code)

### 1. Install

```text
/plugin install fdpocket-creator --marketplace https://github.com/MoonTechnica/agent-plugins
```

This adds the marketplace and installs the plugin in one step (Claude Code v2.1.275 or later).
On older versions, run `/plugin marketplace add https://github.com/MoonTechnica/agent-plugins` first, then `/plugin install fdpocket-creator@moon-technica`.

### 2. Sign in

Nothing to do yet: the first time the agent uses FDPocket, your browser opens and you approve the login once.
The same login is used by the agent's tools and by the Kit (pull, push, Git LFS, the real AI in `kit dev`).

### 3. Make an app

Create a working folder and start Claude Code in it, then:

```text
/fdpocket-creator:new A shared to-do list for my family, with an admin page to manage members
```

The agent creates the app on the Platform, sets up your working directory from the template, designs the data model,
builds the screens in `source/`, and checks them with `kit dev`. Then push it:

```text
/fdpocket-creator:push Added due dates
```

When the push succeeds, the editor opens in your browser (the agent also prints the URL). Try your draft there.

### Commands

| Command | What it does |
|---|---|
| `/fdpocket-creator:new <idea>` | Start a new mini-app: creates it on the Platform, sets up a working directory, and places the template project. |
| `/fdpocket-creator:pull <project_id or editor URL>` | Bring the latest version of an existing app to your machine. |
| `/fdpocket-creator:dev [member\|admin\|anonymous]` | Run every app locally and open the development host page. |
| `/fdpocket-creator:check` | Run the pre-push checks locally. |
| `/fdpocket-creator:push <message>` | Check, then send your app to the Platform as a new draft. |
| `/fdpocket-creator:remix <app page URL>` | Start a branch of someone else's published app to contribute to it. |
| `/fdpocket-creator:propose <title>` | Propose your branch's changes to the app's main, like a GitHub pull request. |
| `/fdpocket-creator:proposals` | Review proposals other people sent to your app, then comment, merge, or decline. |

You can also just describe what you want in plain language ("push this", "add a search box") — the agent picks the right Skill.

Opening, withdrawing, commenting on, and merging a proposal all reach another person, so Claude Code
asks you to confirm each one every time (allow rules cannot skip this).

### Update

```text
/plugin marketplace update moon-technica
/plugin update fdpocket-creator@moon-technica
/reload-plugins
```

Then ask the agent to run `kit.mjs link` in each working directory. `kit push` and `kit doctor` tell you when a newer Kit is out.

To update automatically, run `/plugin`, open the **Marketplaces** tab, select `moon-technica`, and choose **Enable auto-update**
(auto-update is off by default for this marketplace).

## Quick start (Claude app)

You can install the Kit from the Claude desktop app without typing any commands.

1. Open **Customize → Plugins**, choose **Add → Add marketplace**, and enter `https://github.com/MoonTechnica/agent-plugins`.
2. Add **FDPocket Developer Kit** from the list.
3. Open the **Code** tab, pick a working folder, and use the same commands as in Claude Code (for example `/fdpocket-creator:new`).

The plugin is saved to your Claude account, so it also appears in Claude Code on your computer.
Building and pushing run on your computer, so use the **Code** tab (chat cannot run the Kit's tools).

## Quick start (Codex)

### 1. Install

```text
codex plugin marketplace add https://github.com/MoonTechnica/agent-plugins
codex plugin add fdpocket-creator@moon-technica
```

Then start a new Codex session. The first time the agent uses FDPocket, your browser opens and you approve the login once. (You can also install from `/plugins` inside Codex.)

### 2. Use it

In Codex, call the Skills with `$`:

| Skill | What it does |
|---|---|
| `$fdpocket-new` | Start a new mini-app. |
| `$fdpocket-pull` | Bring an existing app's latest version to your machine. |
| `$fdpocket-push` | Check and send your app to the Platform. |
| `$fdpocket-remix` | Contribute to a published app. |
| `$fdpocket-propose` | Propose your branch's changes to main. |
| `$fdpocket-proposals` | Review proposals sent to your app. |

### 3. Require approval for proposal actions

Opening, withdrawing, commenting on, and merging a proposal reach other people, so make them approval-only.
Codex plugins cannot ship this setting, so add the following to `~/.codex/config.toml`
(`node <kit>/scripts/kit.mjs codex-config` prints the same text, and `codex-config --write` writes it there for you,
replacing an earlier copy and keeping the rest of the file):

```toml
[plugins."fdpocket-creator@moon-technica".mcp_servers.fdpocket]
default_tools_approval_mode = "writes"

[plugins."fdpocket-creator@moon-technica".mcp_servers.fdpocket.tools.open_proposal]
approval_mode = "approve"

[plugins."fdpocket-creator@moon-technica".mcp_servers.fdpocket.tools.close_proposal]
approval_mode = "approve"

[plugins."fdpocket-creator@moon-technica".mcp_servers.fdpocket.tools.comment_proposal]
approval_mode = "approve"

[plugins."fdpocket-creator@moon-technica".mcp_servers.fdpocket.tools.merge_proposal]
approval_mode = "approve"
```

### Update

```text
codex plugin marketplace upgrade moon-technica
```

### About the pre-push hook

The Kit ships a hook that runs the checks before every push. In Codex it stays off until you trust it in `/hooks`.
If you do not trust it, `$fdpocket-push` still runs the checks as one of its steps.

## Other agents

Any agent that supports Skills and remote MCP servers can use the Kit.

1. **Get the Kit.**
   ```bash
   git clone https://github.com/MoonTechnica/agent-plugins ~/fdpocket-creator-kit
   ```
   The Kit root is `~/fdpocket-creator-kit/plugins/fdpocket-creator`.
2. **Install the Skills.** Link `plugins/fdpocket-creator/skills/*` into your agent's Skills folder (for example `.agents/skills/`).
3. **Register the MCP server.** Either run the Kit's local server (stdio): `node ~/fdpocket-creator-kit/plugins/fdpocket-creator/scripts/kit.mjs mcp`
   — it signs in once in your browser and shares the login with the Kit's commands — or connect directly to
   `https://fdpocket.dev/mcp/creator` (Streamable HTTP with OAuth; pin the callback port to `43125` if your client allows,
   and sign in from your agent's MCP screen; the Kit's commands then ask for their own login once).

## What happens in your working directory

| Path | What it is |
|---|---|
| `.fdpocket.json` | Links the folder to an app on the Platform (app id, session id, the branch you push, the commit you last pulled, the Kit location). Do not edit by hand. |
| `source/` | **Your project — a git repository.** `apps/web`, `apps/admin`, `packages/db-schema` (the data model), `infra/project.yaml`, `listing/`. |
| `assets-cache/` | Images downloaded from the image tools; copy what you need into `source/`. |
| `outputs/` | The three files that get sent: `source.bundle` (your new commits), `dist.tar.gz`, and `build-report.json`. Generated by `pack`. |
| `AGENTS.md` | Short guidance for the agent working in this folder. |

## Typical workflows

**Make a new app** — `new` → describe and iterate (`dev` to try it) → `push` → open the editor URL, try it, publish.

**Keep working on an app** — `pull <project_id>` → ask for changes → `push`. If the Platform moved on while you were working,
the agent rebases your commits onto it (like `git pull --rebase`) and resolves any conflicts.

**Change the data model** — Ask in plain language. The agent edits `packages/db-schema/schema.zmodel`, runs `kit generate`
and `kit db diff`, and commits the pending migration. Changes that can destroy data (dropping or renaming a column) are
written down with their intent, and the Platform asks for confirmation when merging into main.

**Contribute to someone else's app** — `remix <app page URL>` → make one focused change → `push`
→ wait until it is validated → `propose`. The owner reviews it and can merge it into their main.

## Command-line tool (advanced)

The Skills drive these for you, but you can run them yourself from the working directory:

```bash
node <kit>/scripts/kit.mjs <command> [--flag value]
```

| Command | What it does |
|---|---|
| `doctor` | Check Node, git, Git LFS, Bun, your login and the Kit version, and show how to fix what is missing. |
| `clone` | Create a working directory for an app (`--project-id` / `--session-id`): `source/` becomes a git repository of its history. |
| `pull` | Fetch the Platform's new commits and rebase your branch onto them. |
| `push` | Build, check, send, and wait for the Platform's validation in one step (`--message`; `--open` opens the editor when it is ready). |
| `new` | Place the template project into an empty `source/`. |
| `generate` | Check `infra/project.yaml`, place the base data model, and generate the typed client from the ZModel. |
| `db diff` | Regenerate the branch's pending migration (`pending/generated.sql`) and report destructive changes. |
| `dev` | Run every app locally with the Platform's Gateway, a local database and file store, and the development host page. |
| `check` | Run the pre-push checks locally (exit code 2 when something fails). |
| `build` | Install with the lockfile and build every app into `source/dist/`. The only way to build. |
| `pack` | Bundle your new commits as `outputs/source.bundle`, pack `outputs/dist.tar.gz`, and print the push arguments (used by `push`). |
| `upload` | Upload the LFS files, then the packed files to the signed URLs from `begin_build` (used by `push`). |
| `mcp` | The plugin's local MCP server (started by Claude Code / Codex). Uses the Kit's login, so you sign in once. |
| `login` | Sign the Kit in (for `clone`, `pull`, `push`, Git LFS and the real AI in `kit dev`). `clone` / `pull` / `push` start it for you when needed; the token stays in `~/.config/fdpocket/`. |
| `assets add` | Put an image from the asset library under `source/`. |
| `open` | Open the editor URL in your browser. |
| `link` | Re-point the working directory at a newer Kit (after updating). |
| `codex-config` | Print the recommended Codex approval settings (`--write` adds them to `$CODEX_HOME/config.toml`, by default `~/.codex/config.toml`). |

## Troubleshooting

| Symptom | What to do |
|---|---|
| "Kit is outdated" / `SDK_VERSION_DEPRECATED` when pushing | Update the Kit (see the Update sections above), then ask the agent to run `kit.mjs link` and `kit.mjs generate`. |
| The push fails validation | Ask the agent to read the validation report and fix the problem. Running `check` locally reproduces most failures. |
| A Kit command stops with an environment error (`bun` not found, `mise ERROR …`) | Run `node <kit>/scripts/kit.mjs doctor` and follow each `fix`. |
| `kit dev` does not start | It needs Node 22.12 or later. If `seed.ts` failed, the error is printed; ask the agent to fix it. |
| "Someone changed the app first" / `STALE_BASE` | The app moved on. The agent pulls, rebases your commits, and pushes again. |
| LFS asks for credentials / `LFS_OBJECT_MISSING` | Run `node <kit>/scripts/kit.mjs login` once, then push again. |
| `author_mismatch` | A commit is not in your name. Do not change `user.name` / `user.email` in `source/`; the agent resets the author and pushes again. |
| Rate or quota limit | Wait a bit and try again. Do not resend repeatedly. |
| Permission error on an app | You can only edit apps owned by your account or a team you belong to. |
| A tool says you need to log in to FDPocket | Approve the login in the browser window that opened, then ask again. If no window opened, run `node <kit>/scripts/kit.mjs login`. |

## Connecting to a different Platform environment

In Claude Code, set the `CREATOR_MCP_URL` environment variable to point the MCP server somewhere else
(for example, local development: `http://localhost:4042/mcp/creator`).
