# 掲載情報

アプリのページ・一覧・共有のカードに出る情報を、**ソースの `listing/`** に置く（`dist/` には入れない）。
**そろっていない版は公開できない**。利用者はここを見てアプリを選ぶので、中身と食い違わないこと。

```text
listing/
├── listing.json   # 文字の項目
├── icon.png       # アイコン（正方形。.webp も可）
└── cover.png      # カバー画像（横長。.webp も可）
```

## 1. まず今の掲載情報を読む

`./input/listing.json`（手元では `get_project` の `listing`）が**今の掲載情報**。
ソースの `listing/listing.json` より**こちらを優先する**（利用者が画面で直した値はこちらにしか無い）。

| キー | 意味 |
|---|---|
| `title` `tagline` `description` `category` `tags` | 今の値（空なら未作成） |
| `hasIcon` / `hasCover` | 今の版にアイコン / カバーがあるか |
| `userEdited` | **利用者が手で直した項目** |
| `missing` | **公開に足りない項目**（`icon` `cover` を含む）。このターンで必ず埋める |

最初に `listing/listing.json` を `input/listing.json` の値で書き直してから作業する（古い値で利用者の手直しを上書きしない）。

## 2. このターンで何をするか

| 状況 | すること |
|---|---|
| 企画のターン | **何もしない** |
| 初回・`missing` がある | 足りない項目を作る（§3・§4） |
| 目的・主な画面・対象の利用者が変わった | `description` を直す。分類が変わるほどなら `category` も |
| 見た目が大きく変わった | `icon` と `cover` を作り直す |
| 名前を変えた | `cover` のタイトルも新しい名前で作り直す |
| 利用者が名前・説明などの変更を頼んだ | 頼まれた項目を直す（`userEdited` にあっても。§5） |
| 細かい修正（色・文言・不具合） | **何も変えない** |

- **`userEdited` の項目は、頼まれたとき以外は変えない**。合わなくなったら `build-report.json` の `notes` に 1 行書く。
- 直したら、何を直したかを `notes` に 1 行書く。
- **`releaseNotes` だけは版を作るターンで毎回書く**。先頭に `## タスクに期限を設定できるように` のような**変更内容の短い見出し**
  （15〜40 文字、最大 100 文字。作業履歴と提案の題名に自動で使われる）。空行のあと、使う人に向けて何が変わったかと理由を 1〜3 行。
  依頼文をそのまま写さない。前の版の文を残さない。実行していない確認を「確かめた」と書かない。

## 3. 文字の項目（`listing/listing.json`）

```json
{
  "title": "チームのタスク帳",
  "repositoryName": "team-taskboard",
  "tagline": "やることを、チームでさっと共有",
  "description": "家族や小さなチームで…（本文）",
  "category": "productivity",
  "tags": ["タスク管理", "チーム", "共有"],
  "releaseNotes": "## タスクに期限を設定できるように\n\n期限の近い順に並べられるようになった"
}
```

| キー | 文字数 | 書き方 |
|---|---|---|
| `title` | 1〜30 | 何のアプリか伝わる短い名前。「〇〇アプリ」「無題」にしない |
| `repositoryName` | 3〜48 | 初回に付けるURL名。用途・表示名に対応する短い英語の単語を小文字とハイフンでつなぐ（例: 顧客管理 → `customer-hub`、チームのタスク帳 → `team-taskboard`）。UUID・乱数・日時・依頼文の切り出しを名前にしない。所有者内の同名はPlatformが連番で調整する。手動変更後や初回確定後のURL名は上書きされない |
| `tagline` | 1〜40 | 一覧に出る一言。誰の何に役立つかを 1 文で |
| `description` | 1〜1000 | 目的・主な機能・使い方の流れ・管理画面があればその役割。改行してよい |
| `category` | 下の id | 最も近いもの 1 つ |
| `tags` | 0〜5 個・1 個 1〜20 文字 | 用途・対象・特徴。`#` は付けない。カテゴリ名の繰り返しは入れない |
| `releaseNotes` | 1〜2000 | この版で変わったこと（§2） |

`category` の id: `business`（ビジネス）/ `productivity`（仕事効率化）/ `education`（教育）/ `kids`（キッズ）/ `community`（ソーシャル・コミュニティ）/
`tools`（ユーティリティ）/ `lifestyle`（ライフスタイル）/ `finance`（ファイナンス）/ `health`（ヘルスケア・フィットネス）/ `medical`（医療）/
`entertainment`（エンターテインメント）/ `games`（ゲーム）/ `news`（ニュース）/ `books`（ブック）/ `reference`（辞書・リファレンス）/
`music`（ミュージック）/ `photo_video`（写真・ビデオ）/ `graphics_design`（グラフィック・デザイン）/ `food_drink`（フード・ドリンク）/
`shopping`（ショッピング）/ `travel`（旅行）/ `navigation`（ナビゲーション）/ `sports`（スポーツ）/ `weather`（天気）/
`developer_tools`（開発ツール）/ `other`（その他）。

- `kids` は子ども向けのアプリだけに使う。選ぶと審査が子ども向けの義務（外部リンク・購入・広告・解析の制限、保護者の確認）を確かめる。
- 文言は利用者の言語。誇張しない（中身と違うこと・「公式」「世界一」を書かない）。実在の企業・ブランド・人物の名前を使わない。

## 4. 画像

| 画像 | 形 | 何を描くか |
|---|---|---|
| `icon.png` | **正方形**・512〜2048px・PNG か WebP・4 MiB まで | アプリを象徴するモチーフを 1 つ大きく。小さくても形と色で識別できる。文字は入れない。背景を四隅まで塗る（角は Platform が丸める） |
| `cover.png` | **横長**（幅 / 高さ 1.4〜1.9。16:10 を推奨）・幅 1200〜2560px・PNG か WebP・4 MiB まで | 用途が伝わるキービジュアルに、**確定した `title` をロゴ風の文字として組み込む**。タイトルと主役は中央の安全な範囲に |

- 色はアプリの配色（`packages/ui` のトークン）とそろえる。画面のスクリーンショットをそのまま使わない（検証の記録は Platform が撮る）。
- タイトルは `listing.json` の最終的な `title` を引用し、「この文字列を正確に描く」と指定する。勝手に英訳しない。

**`generate_image` で作る**。アイコンは `size="square"`、カバーは `size="landscape"` で作り、`download_url` から取って
`source/listing/` に置く（届いた形式に合わせて拡張子を `.webp` にする）。

**生成後は最終画像を開いて確かめる**: カバーのタイトルの誤字・欠け・不要な文字・読みにくさ、アイコンを 48px / 96px と丸角で見ても判別できるか。
整わなければ作り直し、それでも駄目なら完成扱いにせず `notes` に理由を書く。

## 5. `listingRequested`

`userEdited` の項目を、**利用者が依頼文で頼んだので**変えたときだけ `build-report.json` の `listingRequested` に挙げる
（`title` / `tagline` / `description` / `category` / `tags`）。挙げない限り、Platform は前の値のまま残す。

## 6. チェック

- [ ] `input/listing.json` の値から始め、`missing` をすべて埋めた
- [ ] 文字数の上限を守り、`category` は一覧の id、`tags` は 5 個まで
- [ ] `icon` は正方形、`cover` は横長（比 1.4〜1.9）。最終画像を開いて確かめた
- [ ] `userEdited` は頼まれたときだけ変え、変えたなら `listingRequested` に挙げた
- [ ] `releaseNotes` の先頭に短い見出しを付け、このターンの変更だけを書いた
