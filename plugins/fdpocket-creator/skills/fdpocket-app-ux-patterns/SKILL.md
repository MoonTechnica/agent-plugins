# 使いやすい流れを作る

*`$fdpocket-app-ui`（技術的な約束）と `$fdpocket-app-visual`（見た目）を使ったうえで、**操作の流れ**を決める Skill。文言は `$fdpocket-app-ux-writing`、表・数字・グラフは `$fdpocket-app-data-display`。*

目的は、**初めての人が説明を読まずに、いちばん多い仕事を最短で終えられること**。
画面を作る前に「この App でいちばん多い操作は何か」を 1 つ決め、それが **トップから 1〜2 タップ**で始められるようにする。

## 1. 画面の行き来

スマホの人が慣れている行き来（下のタブ・左上の戻る・下から出るシート・1 画面 1 つの主な操作）に合わせる。根拠と細かい規則は `$fdpocket-ios-design-guidelines` §2・§7 と `$fdpocket-android-design-guidelines` §2・§5。

| 項目 | 決め方 |
|---|---|
| 主な行き先が 2〜5 個 | `AppNav` を `AppShell` の `nav` に渡す（スマホ幅は**下のタブ**、タブレットは左のレール、PC は左のサイドバーに自動で変わる。ホームバーの余白も取る。`$fdpocket-app-responsive` §2） |
| 主な行き先が 1 個 | タブを作らない。トップをその一覧にする |
| 6 個以上 | 5 個に絞り、残りは「その他」の画面に入れる。ハンバーガーメニューに主な行き先を隠さない |
| 管理画面（admin） | PC 幅が主。同じ `AppNav`（PC はサイドバー）+ `width="wide"`。見比べる一覧は表、一覧と詳細は横に並べる（`$fdpocket-app-responsive` §6・§7） |
| 深さ | 一覧 → 詳細 → 編集 の **3 段まで**。詳細の中で別の一覧を深く掘らせない |
| 戻る | 詳細・編集の画面は `PageHeader` の `back`（左上。`<Link>`。ホーム画面から開くとブラウザの戻るが無い。`$fdpocket-app-pwa` §3）。本文の途中に戻るの行を置かない。ブラウザ・Host の戻るでも同じ場所へ戻る（状態は URL の search params に置く）。画面の端から始まる横スワイプを作らない（iOS の左端からの戻る・Android の予測型「戻る」とぶつかる。カルーセル・行のスワイプ操作は画面の端から 24px 以上内側で始まるようにし、同じ操作をボタンや「…」メニューにも置く） |

- 今いる場所を常に分かるようにする（タブの選択中の表示・見出し）。
- **タブを切り替えて戻ったら、元の状態のまま**にする（スクロールの位置・入力の途中・開いていた絞り込み。iOS のタブバー・Material のナビゲーションバーはどちらも「各タブの状態を保つ」が前提）。絞り込みは search params、入力の途中は下書きとして保存（`sessionStorage` か、長いものはデータとして保存）、スクロールは TanStack Router の `scrollRestoration` に任せる。今いるタブをもう一度押したら、その一覧の先頭へ戻す。
- 一覧の絞り込み・並び順・ページは **URL の search params**（TanStack Router の `validateSearch`）に置く。詳細から戻ったとき、共有したとき、読み直したときに同じ状態に戻る。

## 2. フォーム

- **聞く項目を減らす**。分かる値は聞かない（本人の名前は SDK のプロフィール、今日の日付、前回の値）。任意の項目は「詳しく」の下に畳む。
- **既定値を入れておく**（いちばん多い選択・今日・前回と同じ）。空欄から選ばせない。
- 選択肢が 2〜5 個ならボタン群かラジオ（1 タップで済む）。6 個以上は `<select>`（スマホでは OS の選択画面が出て使いやすい）。日付・時刻は `type="date"` / `type="time"`。
- **検証の時機**: 入力中は叱らない。欄を離れたとき（`onBlur`）と送信時に検証し、**直したらすぐ消す**。エラーは欄の下に、何をどう直すかを書く（`aria-invalid` と `aria-describedby`）。
- 送信に失敗したら入力を消さない。最初のエラーの欄へフォーカスを移す。
- 長い入力（日報・申請）は**下書きを残す**（`localStorage` に `try/catch` で。送信したら消す）。画面を離れるとき未保存なら確認する。
- 主ボタンは 1 つ。「キャンセル」は文字のボタン（`variant="ghost"`）で主ボタンより弱く。
- 検証の規則（必須・長さ・形式）は ZModel の `@length` などと**同じ値**にする（`zod` で共通の定義を `packages/` に置いてもよい）。画面だけの検証を守りにしない。

## 3. 操作の結果を伝える

| 操作 | 伝え方 |
|---|---|
| 作成・保存 | 結果がその場で見えるならそれで十分（一覧に行が増える・ボタンが「保存しました」に変わる）。見えない場所に保存したときだけ、画面上部の短い通知（`role="status"`、3〜5 秒で消える。消える前に読めること） |
| 時間がかかる（2 秒以上） | ボタンを無効にして文言を「保存しています…」に。10 秒以上かかるものは進み具合（件数・段階）を出し、画面を離れても続くなら「終わったら知らせます」 |
| 失敗 | その場に原因と次の操作（再試行）。通知だけで済ませない（消えると分からなくなる） |
| 反応が速くてよい小さな操作（完了のチェック・お気に入り） | 押した瞬間に見た目を変え（楽観的更新）、失敗したら戻して理由を出す |

- 何かを押して 100ms 以内に**何かが変わる**こと（押した反応・スピナー・無効化）。何も変わらないと二度押しされる。
- 成功を `alert()` で出さない。ブラウザの `confirm()` / `alert()` は使わない（埋め込みでは見た目が崩れる・止まる）。

## 4. 削除と取り消し

| 種類 | 扱い |
|---|---|
| 戻せる（アーカイブ・完了・非表示） | 確認を出さずに実行し、「取り消す」を数秒出す |
| 戻せない（削除・送信・公開・支払い） | `Dialog` で確認。**何が消えるかを具体的に**（「タスク『棚卸し』と 3 件のコメントを削除します」）。ボタンは動詞（「削除する」）で `variant="destructive"`、既定のフォーカスは「やめる」 |
| 影響が大きい（全件・他人のデータ） | 確認に対象の名前の入力を求めるか、件数を示す |

- 削除ボタンを主な操作の隣に置かない（押し間違い）。詳細画面の下か「…」メニューの中へ。
- 行のスワイプ削除は作らない（気づかれない・誤操作が多い）。

## 5. 検索・絞り込み・並べ替え

- 項目が 20 件を超えうる一覧には検索を付ける。入力は 300ms ほど待ってから検索し（毎キー打鍵で送らない）、検索中も前の結果を消さない。
- 絞り込みは**よく使う 2〜3 個をチップで常に出す**（「未完了」「自分の」）。それ以外は「絞り込み」の `Sheet` に。
- 絞り込み中であることと、解除の方法を常に見せる（「3 件の条件で絞り込み中・解除」）。結果が 0 件のときは、条件を外す操作を出す。
- 並び順の既定は**その仕事で一番使う順**（期限が近い順・新しい順）。

## 6. 初めての人

- 空の一覧が最初の画面になるので、`EmptyState` を**始め方の案内**にする（何ができるか 1 行 + 最初の操作のボタン）。チュートリアルの連続画面は作らない。
- 試せるように例を 1 つ作るボタン（「例を作ってみる」）は、業務で役立つときだけ。
- 説明は、必要になったその場所に短く（入力欄の補足・`?` のアイコン）。画面の上に長い説明を置かない。

## 7. 段階的に見せる

- 1 画面で決めさせることは 1 つ。項目が多い設定・詳細は、よく使うものを上に、残りを「詳しい設定」に畳む。
- 複数ステップの手続き（申請・予約）は 3〜5 段。今何段目か（「2 / 4」）を出し、戻っても入力が残り、最後に**確認の画面**（入力をまとめて見せ、各項目から直せる）を挟む。

## 8. 権限と状態

- 権限の無い操作は、ボタンを隠すか、無効にして理由を出す（「管理者だけが変更できます」）。押してから `FORBIDDEN` で断らない。守りは ZModel（`$fdpocket-app-ui` §5）。
- 他の人が編集中・すでに変更された（`CONFLICT`）ときは、上書きせず最新を読み直して、何が変わったかを示す。

## 9. 確かめる

`kit shot` で撮る前に、**いちばん多い操作を最初から最後まで実際に操作する**（`kit dev` の画面で。手順は `$fdpocket-app-testing`）。
数えるもの: トップから始めるまでのタップ数 / 入力欄の数 / 迷う分かれ道。多ければ減らせないか考えてから終える。
