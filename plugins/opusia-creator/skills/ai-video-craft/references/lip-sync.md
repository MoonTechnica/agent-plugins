# リップシンク（口を音に合わせる）

**やり方は 3 つあり、選び方を間違えると品質も費用も大きく損する。**
まず §1 の表でルートを決めてから、該当する節へ進む。

## 1. どのルートで行くか

| | ルート A: 生成時に喋らせる | ルート B: 音を渡して生成する | ルート C: あとから口を差し替える |
|---|---|---|---|
| **何をする** | モデルが**声も口も**作る | **手持ちの音**に口と動きを合わせて生成 | 完成した映像に別の音を合わせる |
| **使うもの** | `generate_audio` を有効化 | `reference_to_video` の `reference_audio` | `sync-lipsync-v2`（`lipsync`） |
| **使えるモデル** | Seedance 2.5 / MiniMax H3 系・HeyGen Video（常に音付き）/ LTX 2.5 / Kling v3 pro・4K・o3 pro / FLUX 3・FLUX 3 Max / Wan 3.0・Prime | **Seedance 2.5**（音声 最大 10）/ **Wan 3.0・Prime**（最大 5、合計 15 秒）/ **MiniMax H3・H3 Max・HeyGen Video**（最大 3）/ **Vidu Q4**（声 3 本） | sync-lipsync-v2 のみ |
| **音を自分で選べるか** | ❌ モデルが作る | △ 渡した音は**参照**。出力の音はモデルが作り直す（§3） | ✅ 渡した音がそのまま |
| **向いている用途** | 台詞・会話・掛け合い | **MV・歌唱**・既存のナレーション | 既存映像の作り直しを避けたい・別言語版 |
| **課金** | 動画の秒単価（**音声ありで単価が上がるモデルがある**） | 動画の秒単価 | **分単位**（例外。§4） |

**判断はこれだけで足りる。**

- **曲や録音済みの声が既にある** → **ルート B**（無ければ C）
- **台詞をモデルに喋らせてよい** → **ルート A**
- **映像がもう確定していて作り直したくない** → **ルート C**

**MV は原則ルート B。** 曲は先に確定しているので、それを渡して生成するのが
いちばん素直。ただし**音を渡しただけでは歌わない**。プロンプト本文で
「誰が・どの参照音声を・歌う」と書いて初めて口が動く（§3）。

⚠️ **`generate_audio` の既定は false。** 明示しないと**音は出ない**
（プロンプトに台詞を書いても無音の映像が返る）。**例外は MiniMax H3 / H3 Max** ——
項目そのものが無く、**常に音声付き**で生成する（fal のモデル説明: "video with
synchronized audio"）。`generate_scene` は受けるモデルに対して既定で true を送る。

## 2. ルート A — 生成時に喋らせる

モデルが声と口を同時に作る。**声を選べない**代わりに、口の同期は最も安定する。

### 書き方

| 決まり | 中身 |
|---|---|
| **台詞は引用符で囲む** | `A woman says: "We have to leave now."` のように**コロンと引用符**を使う。**これが無いと、喋らないか、台詞が画面に文字として出る** |
| **音の指示はプロンプトの前半** | 後半に置くと落とされる（`ai-video-craft` §3） |
| **音の記述と画の記述を混ぜない** | 混ぜると口が合わない確率が上がる。段落を分けて書く |
| **話者は 1 人にする** | **複数話者にすると成功率が大きく落ちる**（単独ならおおむね実用、複数だと半分以下という報告がある） |
| **台詞中は音楽を鳴らさない** | 環境音も「声の下で小さく」と明示する |
| 台詞は短く | 一度に長い台詞を喋らせない |

### 切り分けの手順

いきなり本番を投げない。**次の最小構成で 1 本通してから**要素を足す。

```
話者 1 人 / 5 語程度の短い台詞 / ミディアムアップの固定カメラ /
効果音は 1 つ / 環境音は薄く / 台詞中に音楽なし
```

これが通ってから、音楽・カメラの動き・2 人目を**1 つずつ**足す。
まとめて足すと、何が原因で崩れたか分からなくなる。

### 音は 4 つの層に分けて指示する

**台詞 / 物音 / 環境音 / 音楽**。それぞれ「何が・いつ・どのくらい」を書き、
**画面で起きていることに結び付ける**（`audio-engineer` の references/sound-design.md と同じ考え方）。

## 3. ルート B — 音を渡して生成する（MV の本命）

**Seedance 2.5 / MiniMax H3 / H3 Max の `reference_to_video`** は、参照として
**画像・動画・音声**を受け取る。

| モデル | 音声の枠 | プロンプトでの呼び方 |
|---|---|---|
| **Seedance 2.5** | `reference_audio` 最大 10（1 本 1.8〜30 秒） | **`@Audio1`**（音声参照の中での順番） |
| **MiniMax H3** | `reference_audio` 最大 3（合計 15 秒） | **`Audio 1`** |
| **MiniMax H3 Max**（シーンの既定） | 同上（480P / 768P / 1080P） | **`Audio 1`** |

### ⚠️ 音を渡しただけでは歌わない（実際に起きた）

**参照音声は「口をこの音に合わせろ」という入力ではない。** fal / 各社の説明でも、
参照音声の役割は**リズム・タイミング・声色の参照**であり、モデルは**プロンプト本文が
命じた演技**を作る。本文に歌う指示が無ければ、曲はただの BGM として扱われる。

2026-10-01 の MV（Seedance 2.5）で、歌い手が映るカットの口が全く動かなかった。
原因はどれも**こちらの書き方**だった:

| やってしまったこと | どうなるか |
|---|---|
| 歌唱カットのト書きに **`（台詞なし）`** を書いた | 「このカットは誰も声を出さない」とモデルに命じている |
| 参照音声の役割を**素材の注記（`note`）にだけ**書いた | **`note` はモデルに送られない**（記録に残るだけ）。本文に曲への言及がゼロになる |
| 役割を「演奏とライトのタイミング参照」と書いた | 歌ではなく演奏に合わせる指示になる |
| 「口元アップなし」と書いた | 歌っている口を見せない指示になる |

### 書き方（本文に書く。`note` には頼らない）

**参照の役割はプロンプト本文に書く。** `generate_scene` の本文はカットのト書き
（`note`）から組み上がるので、**歌唱カットのト書き自体に**書くか、
`fields: { "prompt": … }` で本文を差し替える（前置きは残る）。

| 決まり | 例 |
|---|---|
| **誰が・どの音声を歌うかを名指しする** | `レン sings the lead vocal of @Audio1.`（H3 なら `Audio 1`） |
| **口の動きを音声に縛る** | `Their mouth follows the vocal in @Audio1: opens on each phrase onset, holds one shape on sustained vowels, closes when the vocal stops.` |
| **歌っていない間は口を閉じる** | `Sing only while the lead vocal is audible; mouth closed during instrumental parts.` |
| **歌唱カットに `（台詞なし）` / `no dialogue` を書かない** | 代わりに `（歌唱: @Audio1）` と書く。台詞が無いことと、歌わないことは別 |
| **歌い手は 1 カットに 1 人** | ハモり・掛け合いは別カットに割る |
| **歌う行を書く**（曲の地図の `lyric_lines[]` に時刻があるとき） | そのカットの時間に歌われる行だけを引用符で短く: `レン sings "…" (@Audio1).`。長い歌詞をまとめて書くと画面に文字として出やすい |

**画角とカメラワークは決め打ちしない。** 演出の判断で選ぶ。ただし口を見せたいカットで
マイク・手・髪が口を覆い続ける構図にすると、合っているかどうか自体が分からなくなる。

### 渡す音

- **歌なら、伴奏込みより*ボーカルのみ*のほうが口は合いやすい**（§6）。
- ただしルート B は**動きのテンポも音から取る**ので、
  **ビートを画に乗せたいなら伴奏込みを渡す**という選択もある。
  **どちらを狙うかで渡す音を変える**（両方渡せるモデルもある）。
- **歌っていない区間のカットに歌を渡さない**（合わせるものが無い）。
- **音声の尺は生成の尺と揃える。** Seedance は歌唱を含む生成が **13 秒を超えると
  口が合わなくなる**という実践報告がある。歌唱カットを含むシーンは短めに組む。
- **切り出しは小節頭から小節頭まで、ms 単位で**（`slice_media`。128 BPM の 2 小節 =
  3750 ms）。小節の途中から切ると拍の位相が揃わず、動きが拍に乗らない。切った音の頭が
  クリップの頭になるので、タイムラインの `data-start` はその小節頭に置く
  （`film-grammar` の `references/beat-sync.md` §8）。

### 出力の音は使わない

**モデルは参照音声を元に音を作り直す**（`generate_audio` が有効なため）。口は
その作り直した音に合っている。タイムラインでは**生成クリップの音を使わず、原曲を
同じ時刻に**重ね、**原曲に対して**口が合っているかを確かめる（§9）。

## 4. ルート C — あとから口を差し替える

| | |
|---|---|
| モデル | `sync-lipsync-v2`（sync.so lipsync 2） |
| タスク | `lipsync` |
| 必須の素材 | **`source_video` と `source_audio` の両方**（欠けると通らない） |
| 調整できる項目 | **無い**（パラメータを持たない） |
| 課金 | **分（minute）単位**。入力動画の尺が数量 |

**パラメータが無い＝出来映えは入力で決まる。** 失敗したらプロンプトを直すのではなく、
**入力の映像か音を変える**しかない。

⚠️ **課金単位が「分」なのはこのモデルだけ。** 他の動画モデルは秒単位なので、
**秒のつもりで数えると 60 倍ずれる**。手で数えず `estimate_asset_generation` で引く。

### 入力動画の条件（ここでほぼ決まる）

| 条件 | 目安 | 外すと |
|---|---|---|
| **顔の大きさ** | **画面の 20〜40%** | 小さいと検出できない。大きすぎると解像感が合わない |
| 解像度 | **480p 以上** | 顔が粗いと検出も生成も不安定 |
| **顔の向き** | 正面〜やや斜め | **真横は破綻する** |
| 口と下あご | **遮るものが無い** | 手・マイク・髪・サングラスで精度が落ちる |
| 光 | 均一 | 強い影・逆光のシルエット・明滅は不可 |
| 動き | **自然に動いている** | **完全な静止・止まった区間は結果が悪い** |
| 尺 | **2 分未満に割る** | 長いほど崩れる |

**出力の顔は 512 x 512 で作られる。** 顔が画面いっぱいの大アップだと、
**口の周りだけ解像感が落ちて浮く**。

## 5. 歌は喋りとどう違うか

| | 喋り | 歌 |
|---|---|---|
| 音素と口形の対応 | 素直 | **ロングトーンで口が開きっぱなし**になり対応が崩れる |
| ズレの見え方 | すぐ気づかれる | **気づかれにくい**（数フレームのズレは人が知覚しにくい） |

**歌は「合わせにくいが、多少ズレても見逃される」。**
完璧を狙って何度も投げ直すより、**条件を整えて 1 回で決める**ほうが安い。

**ラップは例外。** 口が速く動くぶんズレが目立つので、条件を厳しめに揃える。

## 6. 音の準備

**伴奏が混ざっているとリップシンクの精度は落ちる**（ルート B・C とも）。

⚠️ **このプロダクトに音源分離のタスクは無い。** `text_to_music` が返すのは
**伴奏込みの完成ミックス**なので、そのままでは条件を満たせない。

| 状況 | どうするか |
|---|---|
| ユーザーがボーカルのみのステムを持っている | **渡してもらう**（最良） |
| 完成ミックスしか無い | **そのまま渡し、§3 の書き方で歌わせる**。口が合わなかったカットだけ §7 に倒す |
| 台詞（歌ではない） | `text_to_speech` の出力は素の声なので**好条件** |

**加工の強いボーカルは精度が落ちる**（オートチューン・ボコーダー）。
そういう曲は最初から §7 に倒す。

ステムがあるかは着手時にユーザーへ確認する。**無いことを理由に歌唱カットを諦めない。**

## 7. 合わせない設計

**リップシンクを使わないという選択が普通にある。** 実際、MV の多くは
歌唱カットの比率が低い。

**これは歌わせないカットの作り方であって、歌唱カットの既定ではない。**
歌い手が歌う画を求められているカットでは、まず §3 で歌わせる。

| 手 | 中身 |
|---|---|
| **歌唱カットと風景カットを交互に** | **最も効く**。多少の粗が気にならなくなる |
| 口元を大きく映さない | 引き・ミディアムで撮る |
| 横顔・逆光・後ろ姿にする | 口が見えなければズレも無い |
| マイク・手・髪で口を隠す | 演出として自然 |
| 口が動く尺を短くする | 長く映すほど粗が見える |

**「合わせられないから諦める」ではなく、「合わせなくてよい画にする」。**

## 8. アニメの口パク

**日本のアニメは、そもそも音素に厳密に合わせない。**
実写基準の同期を追うより、**アニメの流儀に合わせたほうが「らしく」なる**。

| 口形の数 | 使われ方 |
|---|---|
| **2 形**（「あ」と「閉」） | 通称「パクパク」。**TV アニメの省力形として普通に使われる** |
| 3 形 / 5 形（母音） | 標準的 |
| 6 形 | 丁寧に作るとき |

**タイミングの目安（24fps）**: 1 文字あたり **2〜4 フレーム**
（早口 2 / 普通 3 / ゆっくり 4）。

**アニメでは「音素が合っていること」より「口が開閉していること」のほうが大事。**
様式化された顔でもモデルは動くが、**実写ほどの精度は出ない**前提で見る。

## 9. 見るときの観点

静止画のプレビューでは**何も分からない**。必ず再生して確かめる。

| # | 見るところ |
|---|---|
| 1 | 口の開閉が**音の切れ目**と合っているか（ルート B は**原曲**に対して見る。生成クリップの音ではない） |
| 2 | 口の周りだけ**質感が変わっていない**か（貼り付いたように見える） |
| 3 | 顔の輪郭が**揺れていない**か |
| 4 | 歯・舌・口の中が破綻していないか |
| 5 | **無音の区間で口が動いていない**か |
| 6 | 顔が動く所で**口だけ取り残されていない**か |
| 7 | （ルート A）**台詞が画面に文字として出ていない**か |

## 10. 破綻したときの原因

| 症状 | まず疑うところ |
|---|---|
| **音が鳴らない** | `generate_audio` が既定の false のまま（ルート A） |
| **台詞が字幕のように画面に出る** | 引用符とコロンで囲っていない（ルート A） |
| 複数人の口が合わない | **話者を 1 人に減らす**（ルート A は複数話者に弱い） |
| **歌唱カットで口が全く動かない** | 本文に歌う指示が無い／`（台詞なし）` を書いている／役割を `note` にだけ書いた（**モデルに届かない**）。§3 の書き方で本文に書く（ルート B） |
| 口がほとんど動かない | 音に伴奏が混ざっている（§6）／顔が小さすぎる |
| 口の周りがぼやける・浮く | 顔が大きすぎる／入力が低解像度（ルート C） |
| 顔が歪む・別人になる | 真横を向いている／顔が途中で隠れる |
| 途中から合わなくなる | 尺が長すぎる。**2 分未満に割る** |
| そもそも通らない | `source_video` か `source_audio` が欠けている（**両方必須**、ルート C） |

**ルート C は同じ入力で投げ直しても直らない**（パラメータが無いので結果はほぼ決まる）。
**入力を変える**か、**§7 に倒す**。
