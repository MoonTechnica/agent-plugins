# グリッド絵コンテ

## 1. 1 シーン = 1 枚

**カットごとに 1 枚ずつ投げない。** 1 シーンぶんのカットを 1 枚のシートに並べて、
**1 回の生成**で作る。理由は 3 つある。

| | 1 コマずつ 6 枚 | グリッド 1 枚 |
|---|---|---|
| 費用（額は `estimate_asset_generation`） | **6 回分** | **1 回分**（1 枚が大きいぶん単価は少し上がる） |
| 絵柄の一貫性 | 回ごとに振れる | 同じ 1 回の生成なので揃う |
| 動画化 | 先頭フレームにしか使えない | **シートを丸ごと R2V の参照に渡す**（既定。前置きが「カット順と構図」だとモデルに伝える） |

**シートはコマへ切らない。** 1 枚で動画化の参照になるので、切ると使わない素材が
6 件増えるだけになる（設定資料でも同じ判断をした）。1 コマずつが要ると**人に
言われたときだけ** `split_board_sheet` を呼ぶ
（design: `docs/designs/2026-09-09-board-sheets-are-split-on-request.md`）。

**モデルは `gpt-image-2.5-sunburst`。** グリッド絵コンテは**1 枚に 6 コマを詰める画**で、
コマ割りの線・各コマの構図・コマ間で同じ顔を保つことのすべてが細部の精度に効く。
sunburst は fal が「extra fidelity on intricate detail」と言っている側で、
**単価は flare とまったく同じ**（払うのは生成時間だけ）。
6〜8 コマまでは同一性を保てるが、それを超えると顔が破綻し始める。
**1 枚に載せるのは最大 6 コマ**で、超えるならシーンを割る
（`get_scene_budget` で確かめ、`move_cut` で移す。切り目の判断は `screenwriter`）。

> 立ち絵・背景・小物のように**1 枚に情報を詰めない**画は `gpt-image-2.5`（flare）
> のほうが速くて同じ値段。使い分けの軸は「1 枚あたりの情報密度」で、値段ではない。

**`quality` は渡さない（既定の `high` で作る）。** モデルと違い、**quality は金額が動く**。
gpt-image-2.5 は `high` の上に
`xhigh` / `max` があるが、**絵コンテは構図の参照であって最終画ではない**。
シートは 2560x1440 の段に乗るので `high` 177 クレジットに対し `max` は 708 ——
シーンの数だけ効く。上げるのは設定資料（`generate_material_sheet`。既定で `max`）と、
本編にそのまま出る 1 枚だけ。

逆に、構図の方向性だけ見たい試し撮りなら `quality: "medium"` で回してよい
（46 クレジット）。**モデルは変えない** —— 別モデルに逃げると絵柄が変わり、
本番に上げたとき構図から取り直しになる。

## 1.2 静止画を動かすシーン（`motion`）は**1 カット 1 枚のラフ**

字コンテの「作り方」の列が `motion` のシーンでは、絵コンテは動画生成の入力にならない
（最終の絵は art-director が描き、compositor が動かす）。**人が V コンで承認する設計図**なので、
グリッドのシートもマスター（§1.5）も作らない。

```
1. list_cuts(scene_id)                       # 絵のあるカットだけ描く（文字・図だけのカットは描かない）
2. create_scene_board({ scene_id })          # 盤面はシーンに 1 枚のまま
3. create_canvas_nodes(...)                  # カットごとに image の空ノード
4. generate_asset({ model: "gpt-image-2.5", task: "image_edit",
     fields: { prompt: <そのカットの構図だけ>, quality: "low" },  # 迷ったら "medium"
     media: [キャラの設定表・スタイルフレーム], canvas_node_id })  # board_sheet は付けない
5. get_asset_preview → set_cut_board(cut_id, asset_id)        # プレビューがこのコマを流す
```

- **動き（寄り・パン・揺れ）は描かない。** 字コンテの「動き」の列が持つ。
- **`bind_board_sheet` は呼ばない**（シートが無い）。
- このラフは**本番の絵ではない**。本番は art-director が承認されたラフを構図の参照にして
  描き直す（`art-director` の references/motion-stills.md §2）。
- ⚠️ 後で作り方を `generate` に変えたシーンは、**ラフを外して §2 のシートを描き直す**。
  `set_cut_board` のコマはそのまま image-to-video の先頭フレームになるので、低画質のラフが
  動画に入る。
- 3D（`previz3d`）のシーンはプリビズが動く絵コンテなので描かない（§6.5 と同じ）。

## 1.5 描く前にマスター（空間と光の 1 枚）

**マスターは、そのシーンの絵コンテを描くための引きの静止画 1 枚**。場所・誰がどこに
立つか・光（時間帯・色・向き）をこの 1 枚で決め、シートの全コマをその中で描かせる。
コマごとに場所や光が振れるのを止めるのが仕事で、**動画には渡さない**
（`cinematographer` §0。以前は引きの通しの動画を本番に添えていたが、2026-10-24 に廃止）。

| 要るか | `get_scene_budget` の `master_recommended`（話者 2 人以上 / 3 カット以上 / 8 秒以上） |
|---|---|
| 置き場 | `scenes.master_image_asset_id`（`set_scene_master(scene_id, asset_id)`。**画像のみ**） |
| 効き方 | シートの生成（`board_sheet` 付き）が**参照画像の先頭に自動で添え**、「空間と光はこれ、コマではない」という前置きをサーバが付ける。`media` に自分で入れない |
| 省くとき | 物語もの（anime / 縦型アニメ / ショートドラマ / ドラマ・映画）は**マスターが無いとシートの生成が断られる**。1 人の短いシーンなど要らないと判断したら `board_sheet.use_master=false` |

```
1. create_scene_board({ scene_id })        # 絵コンテの盤面（材料の列が並ぶ）
2. create_canvas_nodes(...)                # 盤面に image の空ノードを 1 つ
3. generate_asset({                        # 引きの 1 枚。人物と背景の確定シートを参照に
     model: "gpt-image-2.5", task: "image_edit",
     fields: { prompt: <場所・立ち位置・光を言葉で> },
     media: [ 人物シート…, 背景シート ],
     canvas_node_id: <2 のノード> })
4. get_asset_preview(asset_id)             # ★ 見る。立ち位置と光が字コンテどおりか
5. set_scene_master(scene_id, asset_id)
```

- **光は字コンテの言葉と同じにする。** マスターの光と字コンテの光が食い違うと、
  絵コンテと動画で光が割れる（動画は字コンテの言葉だけで光を決める）。
- **同じ場所・同じ光が続くシーンは同じ 1 枚を使い回してよい**（`set_scene_master` を
  シーンごとに同じ asset で）。照明プランが変わるシーンは別の 1 枚を作る。
- **プリビズがあっても描いてよい。** プリビズは見た目（顔・光・色）を持たないので、
  シートを作るならその光はマスターが決める。
- **マスターを `style.*` に入れない。** スタイルボードは作品全体の絵柄の見本で、
  構図を持つ 1 枚絵を入れると全シーンの参照に混ざる（2026-10-24 の事故）。

## 2. 手順

**参照はその回の目的に合わせて選ぶ。** `get_work_order.scene.references` と
文字コンテの `note` を見て、無言の人物も含め誰 / 何を描くかを判断し、必要なら
`resolve_slot` / `search_assets` で追加取得する。`references` は候補で、全件添付の指定ではない。
人物のいない画、顔を伏せる演出、背景や小物だけの画もある。キャラシの必須化・全人物や
全衣装の一括添付はしない。各参照が何を固定するかを指示し、選んだ画像だけを `media` に渡す。
**盤面に並べただけでは生成入力にならない。** 手元生成では返った `references[].url` を
全件画像入力に渡す。渡せない画像を黙って省いて描かず、選択や生成方式を見直す。
生成後は `get_asset` の `generation.reference_inputs` で選んだ素材 ID とスロットを照合し、
`get_asset_preview` で参照そのものと各コマを見比べ、維持するはずの顔・髪・衣装・
体格・小物・場所など、その回に選んだ不変項を確認してから確定する。

**人物の参照は、キャラシから作った顔（`.face`）と全身（`.body`）の 2 枚。キャラシ本体は渡さない。**
キャラシ（`character.<key>.<衣装>`）は顔・全身や 2 着目以降の衣装を作る**元**で、絵コンテ・動画の
入力には使わない（ユーザーの方針、2026-11-11。`cinematographer` と同じ）。`resolve_slot` で
`character.<key>.<衣装>.body` と、顔は `character.<key>.<衣装>.face`（**無ければ `character.<key>.base.face`。顔は基本の衣装のものを共有する**）を引いて `media` に入れる。どの衣装かはシーンで決める
（盤面に自動で並ぶのは基本の衣装の顔・全身だけ。別の衣装は自分で引く）。**顔か全身が無い・古い
（キャラシを作り直したのに作り直していない）なら、先に `art-director` 手順 10 で作る**
（盤面に顔・全身の代わりにキャラシが置かれているのはその合図）。使う画は人がキャラの画面で
決めているので、スロットの現在の画を使う（作業台のキャンバスの候補を渡さない）。

```
1. list_cuts(scene_id)                     # 何コマ要るか
2. resolve_slot(project_id, key)           # 今回必要なキャラ / 背景などの確定シート
                                           #   背景のシート 1 枚に引きも俯瞰も
                                           #   載っているので、それを渡す
3. create_scene_board({ scene_id,        # ★ このシーンの絵コンテ盤面（シーンごとに 1 枚）
     name: "S4 の絵コンテ" })                #   字コンテ → マスター → キャラ → スタイル → 美術の列と、
                                           #   その右の空ノードをサーバが並べる。
                                           #   返る sheet_node_id へ投げる（冪等）
4. generate_asset({                        # ★ 1 回だけ。ノード宛てに投げる
     project_id, model: "gpt-image-2.5-sunburst", task: "image_edit",
     fields: { prompt: <描き方の指示だけ> },   # カットの記述は書き写さない
     media: [ ...2 の素材を source_image として... ],   # マスター（§1.5）は自動で 1 枚目に添わる
     board_sheet: { scene_id, orientation: "landscape" | "portrait" | "square" },
     canvas_node_id: <3 の sheet_node_id>
   })
5. get_generation_status(derivation_id)    # 待つ
6. get_asset_preview(asset_id)             # ★ 必ず見る
7. bind_board_sheet(sheet_asset_id)        # このシーンの板として確定（1 枚のまま）
```

**task は `image_edit`。** `text_to_image` は入力画像を 1 枚も取らないので、設定資料も
マスターもシートに届かない（本番で半数のシートがこれで描かれていた。2026-10-24 に確認）。
マスターが結んであるシーンを `text_to_image` で描こうとするとサーバが断る。

> **Codex で動いているときは、手順 4〜5 を自分の `image_gen` に置き換える**（デスクトップでも、
> 手元の Codex から繋いだときでも。サーバの生成はクレジットを使うので、サーバも断る）。
> `generate_asset` の代わりに `start_local_generation({ asset: <4 と同じ指定> })` を呼び、
> 返った `prompt`（字コンテ・版面を前置き済み）と `references[].url` で `image_gen` に
> 描かせ、PNG を `upload.curl` で置いて `complete_local_generation` で戻す。6 以降は同じ。
> **ローカルの ComfyUI（`comfy-mcp`）が繋がっているときも同じ形**で、
> `start_local_generation({ renderer: "comfyui", asset: … })` → ComfyUI で描く →
> `fetch_outputs` → PUT → `complete_local_generation`（エンジンを問わず。Codex なら ComfyUI を優先）。
> 手順は `director` の references/local-vs-server.md。

**カットの記述（字コンテ）はサーバが添える。** `board_sheet` を付けた生成は
シーンに紐づくので、受付がそのシーンの字コンテ（カット順・寄り・場所・時間帯・
ト書き・台詞）を**素材として**入力に入れ、プロンプトの前に置いてモデルへ届ける。
同じ素材が盤面の材料の列にも並ぶので、人が盤面を開けば**何から描いたか**が見え、
カットを直して作り直せば新しい記述で描き直される。だから `prompt` には
**カットの記述を書き写さない**（書き写すと同じ本文が 2 重に入り、カットを直しても
古い文が残る）。`prompt` に書くのは字コンテに無いこと —— 絵柄、毎コマ言い直す
キャラの不変項（§3）、枠線とコマ番号を描かないこと、コマごとの描き分けの注意だけ。

**生成は盤面の上で行う**（常時の規律）。盤面を通さないとシートは「素材一覧に
増えた 1 件」でしかなく、作り直したときに前の版と並べて見比べられない。
シートは 1 回で決まらないことが多いので、ここが効く。

**盤面は `create_scene_board` で用意する。`create_canvas` から自分で組み立てない。**
盤面の線は**盤面に乗っている素材同士**にしか引かれない。手で組み立てていた頃は、
参照 5 枚で作ったのに**シートが 1 枚だけ浮いた盤面**になり（S1〜S5 の絵コンテ盤面が
すべてノード 1 個だった）、字コンテも並ばなかった。その盤面で人がプロンプトを直して
作り直すと、盤面に無い参照は入力に戻らず、**キャラも背景も外れた絵**になる。
`create_scene_board` はシーンの関係（字コンテ・登場キャラの確定シート・スタイル・
シーンの美術）から材料を並べ、`media` に渡した残り（小物など）はサーバが投げた時点で
盤面左の材料レーンに並べる。盤面は 1 シーンにつき 1 枚で、`scenes.board_canvas_id` に結ばれる。

**盤面は 1 シーンにつき 1 枚**（`1 キャンバス = 1 最終成果物`）。「絵コンテ」と
いう箱に全シーンのシートを並べない —— 確定枠は 1 つしか無いので、混ぜると
どれがそのシーンの決定稿なのか決められなくなる。

**`image_size` は渡さない。** 版面はコマ数と向きから決まり、渡すと弾かれる。
向きは**そのシーンを動画にするときの比**に合わせる（横長の本編なら `landscape`、
縦型ショートなら `portrait`）。

`bind_board_sheet` はシートを `scenes.board_sheet_asset_id` に差すだけで、
**コマは作らない**。これで「このシーンに板がある」が満たされ、`generate_scene` の
前置きが「参照画像の 1 枚はカット順と全カットの構図だ」とモデルに言う。

**コマが要るのは、人がそう言ったときだけ。**
（1 コマを i2v の先頭フレームに使う / コマ単位で描き直す / コマを個別に見せる）

**切るときは、絵を見て境界を自分で決める。** §2.6 の手順に従うこと。

## 2.5 カットの記述が薄いまま描かない

シートは**カットの記述（サーバが添える字コンテ）から描かれる**ので、カットが
「A と B が言い争う」のような要約のままだと、**コマごとに何を描けばよいか決まらない**
（結果、6 コマとも似た構図になるか、話が読めない絵になる）。

**描く前に `python3 <SKILL_DIR>/scripts/board_ready.py <list_cuts の JSON>` を通す**（6 コマ超・空欄・
動詞 1 個の note・均等な尺）。所作は `screenwriter` の `scripts/gesture_lint.py`。

**各カットに「誰が / どこで / 何をしている / 何が見えている / 光と時間帯 /
寄りとカメラ（`shot`）」の 6 つが入っているかを先に確かめる。**
入っていなければ `screenwriter` に戻してビートへ割り直してもらう
（`screenwriter` §3.4）。**ここで戻すほうが安い** —
絵コンテを作り直すより、文字を直すほうが桁違いに安い。

**7 つ目は「芝居」。** 「何をしている」が**動詞 1 個で止まっていたら戻す**
（「食べる」「話す」「怒る」）。コマに描くのは**小道具をどちらの手でどう持ち、
どの姿勢から、何を経由して動くか**であって、出来事の名前ではない。
**日本の所作（箸・靴・襖・お辞儀）が書かれていないカットも戻す** ——
書かないと西洋の既定値で描かれ、そのまま動画の参照になる
（`screenwriter` の references/acting-and-gestures.md）。

**`shot` が空のカットは、コマの構図が決まらない。** シートのプロンプトの
「1: <ロング> …」の寄りはここから起こすので、空だと 6 コマとも似た画になる
（`screenwriter` §3 / `film-grammar` §1）。

**尺が均等に並んでいたら、そこも戻す。** 全カットが同じ長さのシートは、
そのまま「編集していない」映像になる（`screenwriter` §3.4 / `film-grammar` §4）。

## 2.6 切るときは、絵を見て境界を決める（機械には決められない）

`split_board_sheet` は**境界を渡さないと呼べない**。渡すのは、`get_asset_preview` で
シートを見て**自分で読み取った線**である。

```
split_board_sheet(
  sheet_asset_id = <シート>,
  columns = [0.01, 0.34, 0.67, 0.99],   # 縦の境界。左から、両端を含めて
  rows    = [0.02, 0.50, 0.98],         # 横の境界。上から、両端を含めて
)
```

| 決まり | なぜ |
|---|---|
| **値はシートの幅・高さに対する割合（0〜1）** | 実寸はシートごとに違う。割合なら見たまま書ける |
| **両端を含める**（3 列なら 4 個、2 行なら 3 個） | 外周に余白があるシートが普通にある。`columns[0]` を 0 に決め打ちすると余白ごと切る |
| **線は「コマとコマの隙間」に置く** | 絵の上に置いた線は、そのままその絵を切る |
| **見ずに等分を書かない** | それは機械がやっていたことで、**絵の途中で切れる原因そのもの** |

サーバは**渡した線の近くに区切り（枠線・余白の帯）があればそこへ寄せる**ので、
目分量で構わない。寄せられなければ渡した線をそのまま使う（戻り値の
`source` が `detected` / `given` で分かる）。**等分へ戻すことはしない。**

読み取った並びが版面と違えば（3×2 のはずが 2×3 に描かれている等）**切らずに断る**。
そのときは切るのではなく、シートを作り直す。

### 切ったら必ず全コマを見る

`get_asset_preview` で 1 枚ずつ確かめる。**絵の途中で切れていないかは、見るまで
分からない**（比も blank も機械の検査は通ってしまう）。おかしければ §5 へ。

## 3. プロンプトの書き方

1 つのプロンプトで N コマぶんを指示する。**コマごとに何を描くかを番号で書き分け、
変えないものを毎回言い直す。**

```
6 コマのストーリーボード。3 列 x 2 行、左上から右下へ時系列。

全コマ共通（変えない）: <キャラの髪型・服・体型・色>／<画風>／<光の向きと時間帯>
コマごとに変えるのは字コンテが指定した背景・ポーズ・寄り・視点・カメラ位置と傾き。

1: <ロング> 夜の市場の入口。A が左手前、奥に屋台の列
2: <ミディアム> A が屋台の主人と向かい合う。A は画面右
...
```

**必ず守ること**（守らないと切り出しか動画化のどちらかが壊れる）:

| 決まり | 破ると |
|---|---|
| **動画生成に渡す絵コンテは、生成の持ち分だけで描く** | 字コンテの `note` / `shot` にある人物・背景・光・構図だけを描く。字コンテの `上の層:` に書かれた文字・光・粒子・図形・効果は描かない（生成の入力に入ると動画へ焼き込まれ、上の層と二重になる）。文字の置き場は空きの構図として残す。持ち分は字コンテが決める。絵コンテ側で足し引きせず、食い違いは screenwriter へ戻す（`ai-video-craft` の references/layer-ownership.md §2〜3） |
| **枠線・コマ番号・キャプションを焼き込まない** | そのまま映像に出る。切り出しの境界も狂う |
| **コマは隙間なく等分に並べる** | 切り出しがずれ、隣のコマが写り込む |
| **コマの比は全コマ揃える** | 歪んだ絵がカットの構図になる |
| **人物を描く場合、その人物の不変項を該当コマで言い直す** | 途中から顔と服が変わる |
| 参照が必要なときは `resolve_slot` 等で引いた確定素材を選んで渡す | 設定資料と絵柄が食い違う |
| **参照が複数なら、番号と役割を書く**（`Image 1 = <人物名>の顔、顔・髪の正本`、`Image 2 = <人物名>の全身、体型・衣装の正本`、`Image 3 = 背景` のように）。人物は**変えない部分を名指し**し、コマごとに繰り返す | どの画像が何の正本か決まらず、顔や衣装が混ざる（OpenAI / BFL の公式ガイド） |
| **空間の一貫性が必要なら、その場の背景シートを渡す** | コマごとに部屋の形が変わる（§4.5） |

5 コマのときは 6 枠のシートになる。**余る枠は「使わない」と明示**すること
（サーバは空の枠を見つけて自動で落とす）。

## 4. 何を描き込むか

カットの構図の正本（R2V の参照）として機能させるために、コマごとに次を決める。

| 決めること | 理由 |
|---|---|
| カメラの寄り（ロング / ミディアム / アップ） | 動画生成はここを起点に動かす |
| **そのシーンの視点人物（1 人）と、誰に寄るか** | カメラの位置が同情の方向を決める。決めないと切り返しが均等になり誰の話か分からない（`film-grammar` の references/direction-design.md §5） |
| キャラの画面内の位置と向き | 位置が変わると次のカットと繋がらない |
| 背景のどの部分が映るか | 場所の連続性 |
| 光の向きと時間帯 | シーン内で光が飛ぶと別の場所に見える |

**文字コンテのカメラ演出を構図に反映する。** 用語と設計の正本は `film-grammar` の
references/shot-vocabulary.md §3 と references/camera-design.md。描く前と描いた後に
[references/camera-continuity.md](references/camera-continuity.md) を読み、`shot` / `note` と照合する。
通常は動き出す前の1枚を描く。軌道や揺れは文字とプリビズで引き継ぎ、静止画だけで表現済みにしない。

**音楽に合わせる作品（MV・ダンス・BGM 主体）だけは例外。** 字コンテの `note` にある切る根拠で
コマの中身が変わる: `action` のコマは**拍で着地する瞬間（ピーク）**の絵（振り向き切った顔・着地・
決めポーズ・光った瞬間。生成はこの絵へ向かって動く）、`lyric` のコマは**その語を言う顔か、その語の
画**（見たままにせず意味を広げる）、`story` のコマは物語ものと同じ。**サビ頭のコマは前のコマから
場所・サイズ・色のどれかを変えるのが既定**（区間の頭で画が変わらないと曲の山が潰れる。長回しで
通す意図があるなら `note` に書く）。`beat_cut` の区間は 4 小節ごとにシーンが割られている前提
（`screenwriter` の references/other-formats.md §2）。作法の正本は `film-grammar` の
`references/beat-sync.md`。

## 4.5 このシートが、そのシーンの空間を決めている

**同じ場所のカット間で部屋の形が合うかどうかは、ここで決まる。**
6 コマは同じ 1 枚の中に描かれるので、**このシートの中では互いに整合する** ——
逆に言えば、シートを作り直せば空間ごと作り直される。

だから背景の確定素材を参照に渡すことが要る。

| 渡すもの | 何を決めるか |
|---|---|
| `background.<場所>.<時間帯>`（シート 1 枚） | 引き（立ち目線）が色と光の基準、俯瞰が壁・開口・大きな物の位置関係。**1 枚に両方載っている** |

**切り返しのコマは、この 1 枚の引きと俯瞰から反対側を描き起こす。** 背景資料に
`alt_angle` のような面は用意されていない（`art-director` の
references/background-art.md §1）。用意されていないのではなく、
**ここで描き起こすほうが 1 枚の中で整合するから**そうしている。

シートを見るときは構図だけでなく、**コマ間で部屋が同じか**も確かめること。
ここで見逃すと、動画にしてから全カット作り直しになる。

**構図そのものの決め方**（ショットサイズが何を伝えるか、イマジナリーライン、
30 度ルール、視線の一致、隣り合う 2 カットの検査）は `film-grammar` が正本。
**シートを確定する前にその検査を通す** — 繋がらないカットを構図の正本にすると、
動画を生成してから作り直すことになる。

## 5. 切り出した（`split_board_sheet` を呼んだ）ときは、結果を必ず確かめる

生成された絵は**数学的な格子にピタリは乗らない**（勝手な枠線・不均等な間隔・
全体のずれ）。サーバは区切り線を探して境界を寄せ、見つからなければ等分に戻し、
比が歪んだコマと空の枠は**配らずに報告**する。

`split_board_sheet` の戻り値 `skipped` に何か入っていたら、そのカットは**空のまま**。
（切らずにシート 1 枚で使うなら、この節は関係ない）

| 症状 | すること |
|---|---|
| 1〜2 コマだけ落ちた / 絵が気に入らない | そのカットぶんだけ `generate_asset`（`board_sheet` 無しの 1 枚）→ `set_cut_board` |
| 何コマも落ちた / 全体の絵柄が違う | **シートごと作り直す**（1 回分）。グリッドは部分編集できない |
| コマの中身は良いが構図だけ直したい | `gpt-image-2.5`（flare）の `image_edit` でそのコマを編集 → `set_cut_board`（1 コマだけなので精度側は要らない） |

**歪んだコマや隣が写り込んだコマをそのまま構図の正本にしない。**
1 コマ壊れているだけで、そのカットの動画が丸ごと使えなくなる。

## 6. cinematographer への渡し方

シートとコマは**別の使い方ができる**。どちらで行くかを決めて伝える。

| 渡し方 | 使うもの | 向いている場面 |
|---|---|---|
| **シートを参照に渡す**（既定） | **`bind_board_sheet` まで済ませれば自動** —— `generate_scene` が `reference_image` の先頭に添える | 1 パスでシーンを通す。ショットの流れをモデルに読ませる |
| **コマを先頭フレームにする**（要 `split_board_sheet`） | カットごとの `board_image_asset_id`（`frames_to_video`） | 構図を 1 カットずつ厳密に固定したい |

`generate_scene` の `task` は既定が `reference_to_video` なので、前者は
**`bind_board_sheet` で結んでおけば渡す作業そのものが要らない**。

## 6.5 プリビズと併用するとき（**シートは省けることがある**）

撮影ゲート（`board_missing`）は**板かプリビズのどちらか一方**で通る。`previz` が同じシーンの
レイアウトを 3D で組んで書き出しているなら、**シートは無くても撮れる** —— カット順・構図・
カメラはプリビズが運ぶ。**板のためだけにシートを作らない**（`cinematographer` §3.2）。

それでもシートを作るのは、**プリビズが持たないもの**が要るとき（判断表は `previz` §0.2）:

| | 決めるもの | 決めないもの |
|---|---|---|
| グリッド絵コンテ（ここ） | 絵柄・光・人物の同一性・各コマの構図 | カメラの動き・立ち位置の連続・尺 |
| プリビズ（`previz`） | 位置・向き・大きさ・タイミング | 見た目（灰色の代役） |

- **アップが入る**（`get_scene_budget` の `layout.close_ups ≥ 1`）—— 顔の同一性は参照画像でしか
  支えられない
- **人物が 3 人以上出る**（目安）—— 設定資料だけでは誰がどこに立つかの見分けが振れる

両方あるなら `generate_scene` へ**両方が届く** —— シートは結んであれば
`reference_image` の先頭に自動で添わり、プリビズは `previz_asset_id` で渡す。
マスター（§1.5）はシートを描くための 1 枚なので、シートを作るならプリビズがあっても要る。

## 7. 終わったら

**シートがシーンに結ばれている**（`bind_board_sheet` 済み。`get_work_order` の
`board_sheet_asset_id` が入っている）か、書き出し済みのプリビズがあることを
確かめてから `cinematographer` に渡す。どちらも無いと `generate_scene` は
`board_missing` で断る。

**結んだシートは、動画ができるまでの間そのまま画面に出る。** タイムラインのシーンの
クリップにはカットごとのコマが敷かれ、プレビューもそのコマで流れ、絵コンテ画面の
カット行にも同じコマが出る（どれもシートの版面から割り付ける）。動画が確定すれば
自動で動画に替わる。したがって:

- **絵コンテを見せるためのクリップをタイムラインに作らない。** シート画像を素材として
  `bind_composition_variable` で直接束ねる・`<img>` のクリップを HTML に書き足す・
  コマの切り抜き位置を手で書く —— どれもシーンとつながらない**複製**になり、シートを
  描き直しても古い絵が残る（画面ごとに絵コンテが食い違う）。
- 見せたいのが「カットの順と尺」なら直すのはシーンのカット（`set_cut` の `order` と尺）で、
  クリップは追従する。

コマへ切った（`split_board_sheet`）ときだけ、`list_cuts(scene_id)` で**全カットに
`board_image_asset_id` が付いている**ことも確かめる。1 つでも空だと、そのカットだけ
text-to-video になって画面が飛ぶ。
