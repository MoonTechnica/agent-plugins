# 説明もの（`explainer`）— サービス・製品・機能の紹介、使い方、会社紹介、概念の説明

**物語ではなく約束で組む形式。** 「誰に・何を約束するか」が 1 行で言えて、残りの全部が
その根拠になっている動画。サービス紹介・製品のローンチ・機能の使い方・会社紹介
（採用 / IR）・概念や仕組みの説明がここに入る。**人物の動画生成を前提にしない**。
主役は文字と図と**実物の画面**で、それをナレーションに合わせて見せる。

作法の出どころは HyperFrames 公式の `product-launch-video` / `faceless-explainer` /
`slideshow`（それぞれの `references/story-design.md` / `visual-design.md` /
`motion-language.md` / `cut-catalog.md`）と `hyperframes-creative`
（`story-spine.md` / `narration.md` / `typography.md` / `data-in-motion.md`）、
`hyperframes-studio`（トラックとセーフゾーン）。上流はローカルの CLI プロジェクト
（`BRIEF.md` / `STORYBOARD.md`）で回す前提なので、**ここではうちの道具（`put_document` /
`plan_scenes` / `put_composition_bundle`）で同じことをする形に書き直してある**。
段取り（誰が・どの順で・どの tool）は `director` §1.4。

## 0. 先に決める 6 つ

| # | 決めること | 決めないと |
|---|---|---|
| 1 | **対象**（誰に向けた動画か。既に困っている人 / まだ知らない人 / 比較している人） | フックが刺さらない |
| 2 | **約束**（見終わった人が得るもの 1 行。機能の列挙ではない） | 機能ツアーになる |
| 3 | **根拠**（実物の画面・数字・事例・ロゴ・デモ） | 言いっぱなしで信用されない |
| 4 | **CTA**（見た人に何をしてほしいか。URL / コマンド / 申し込み） | 終わり方が決まらない |
| 5 | **尺と縦横**（30〜90 秒が最も強い。約 3 分が上限。横 16:9 が既定、SNS は縦） | 詰め込みすぎる |
| 6 | **実物の有無**（画面収録・スクショ・ロゴ・ブランド色・書体を人が出せるか） | 近似で描いて信用を失う |

**6 は最初に人に頼む。** 製品の UI・ロゴ・実際の数字は**近似で描かない**（上流
`hyperframes-studio` §5「Never approximate the launched product's UI」）。無いまま進める
ときは、その枠に「ここに画面収録」のプレースホルダを置いて、届いたら差し替える。
第三者のツール（チャットアプリ・エディタ）を文脈として見せるときも、実物の
キャプチャから忠実に組む。

## 1. 構成の型（1 つ選ぶ。物語の型は当てない）

### 1.1 売る・紹介する（サービス / 製品 / 機能 / 会社）

| 型 | 使うとき | ビートの並び |
|---|---|---|
| **PAS**（問題 → 深掘り → 解決） | 痛みが既に知られていて切実（壊れた業務フロー） | フック → 痛み → 深掘り → 解決の予告 → 製品 → 根拠 / デモ → CTA |
| **未来の先取り** | 新しいカテゴリ・新しいやり方を売る | 想像してみて → 名前 → 痛みが消える → 仕組み → 結果 → CTA |
| **デモの輪** | UI が自明で、動いているところが一番の説明 | 問い → 製品 → デモ 1 周目 → デモ 2 周目 → 信頼 → CTA |
| **BAB**（前 → 後 → 橋） | 古いやり方から新しいやり方へ渡す | 前 → 後の予告 → 橋（製品） → 手順 1 → 手順 2 → 驚き → CTA |
| **機能 → 便益の連鎖** | 機能が多い / 欲しさや地位で動く | カテゴリの宣言 → 機能 → 便益 → 機能 → 便益 → 山 → CTA |

機能が多いときはどの型でも**機能 → 便益の 2 拍**で進める。機能を積み上げない。
**1 つの機能は 1 つの便益に翻訳してから出す**。

### 1.2 教える（概念 / 手順 / 列挙 / 事例）

| 型 | 「これは…」 | 中身 | 本体の形 |
|---|---|---|---|
| **概念** | 何で、なぜ大事か | 半分知られている 1 つの考え・用語・現象 | 名前 → 仕組みを 1 層ずつ → 含意 |
| **手順** | どうやるか / どう動くか | 始まりと終わりがある手続き | 同じ舞台で 3〜6 手。1 手に 1 つの動き |
| **列挙** | X について N 個 | 対等な項目の集合（コツ・失敗・理由） | フック → N 個 → まとめ。3 つが最も強い |
| **事例** | 物語で教える | ケーススタディ・歴史・失敗談 | 設定 → 緊張 → 転 → 解決 → 教訓 |

**元の文書の段落順をなぞらない。** 記事は情報の山で、動画は理解の道筋。並べ替え・統合・
省略・圧縮して教える順にする。**段落順の言い換えが一番多い失敗**。

### 1.3 ビートの役（`storyboard.v1` の各行に 1 つ）

```
hook | pain_point | product_intro | feature_showcase | benefit_highlight | social_proof | branding | cta
```

教えるときはこう読み替える: 名前を出す = `product_intro`（主役は考え）、仕組み・手順・項目
= `feature_showcase`、含意・「だから何」= `benefit_highlight`、数字・例・比較 = `social_proof`、
主題・持ち帰る 1 行 = `branding`、試して / 気にして / 問い直して = `cta`。

**1 ビート = 1 つの仕事。** 「もう 1 つ便益」「もう 1 つ機能」というビートは作らない。
UI のデモはたいてい同じ画面上の 3 つ以上の連続ビート（入力 → 応答 → 結果 → 便益）で、
孤立した 1 枚ではない。

## 2. フックと約束（最初の 2 ビートで勝負が決まる）

**冒頭 3〜5 秒で、見る側の言葉で「なぜ見るべきか」に答える。** 機能名・ファイル名・
社内用語・元記事の見出しは**フックに出さない**。数字は賭け金を運ぶときだけ
（「コールドスタートが 40% 速く」は可、「23 ファイル変更」は不可）。

| フックの型 | 使うとき |
|---|---|
| 衝撃的な数字 | 信頼できる数字が賭け金を量れる |
| 問い | 認知の隙間を即座に開ける |
| 常識に反する主張 | 真実が通念と逆 |
| 痛みの代弁 | 相手が既にその混乱を感じている |
| 体に効く比喩 | 抽象を具体にする必要がある |
| 概念の宣言 | その言葉自体が主題で、覚えてほしい |
| 直接呼びかけ | 対象がはっきりしている |
| 想像してみて | 思考実験が全体の枠になる |
| 賭け金・結果 | 「今やらないと」が実費やリスク |

**同じ型を毎回使わない**（数字で始めるのが癖になりやすい）。会社の概要から始めるのは禁止。

**約束（`message`）は 2 ビート目までに着地させる。** それ以降は全部が約束の根拠
（デモ・仕組み・画面・数字）。実装や作り方は脚注であって背骨ではない。

自己点検: 根拠のビートを全部消しても、残ったビートだけで約束が言えているか。
約束のビートを消しても動画が成立するように見えたら、それは機能ツアーで、物語ではない。

## 3. ナレーション

量（秒に入るか）・TTS が字面どおりに読む数字や略語・約束の位置は `screenwriter` の
`scripts/narration_check.py` が見る。

- **1 秒 2.5 語（英語）/ 日本語はおよそ 1 分 300 字**。15 秒 ≈ 37 語、30 秒 ≈ 75 語、
  60 秒 ≈ 150 語。原稿は動画より**短く**感じるぐらいでよい（画に息をさせる）
- **人の話し方で書く。** パンフレットの文体にしない。短い句と長い句を混ぜる。声に出して
  読んでロボットに聞こえたら書き直す
- **数字は読み方で書く**（TTS は字面どおりに読む）: `135+` → 「百三十五以上」、
  `$1.9T` → 「およそ二兆ドル」、`99.999%` → 「九十九点九パーセント」、`API` → 「エーピーアイ」、
  `stripe.com` → 「ストライプ ドット コム」。画面は正確な数字を出し、声は丸める。
  読みは `glossary.v1` に置くと `text_to_speech` へ渡る（`audio-engineer`）
- **1 行を句切りの見える「きっかけ」の並びで書く。** 「コンテンツ、感情、エンゲージメント
  ——ひとつの画面に」のように**句の切れ目が、画面の出る順になる**。長い 1 文は画面が
  合わせる場所を失う（§6 の「ナレーションに合わせて出す」の前提）
- 構成は フック → 中身 → 根拠 → CTA。15 秒の SNS 広告はフック + 根拠 + CTA だけでよい

## 4. 1 ビートの文字（スライドの書き方。上流 `slideshow` の「hard constraints」）

| 決まり | 中身 |
|---|---|
| **見出しは文章の主張。ラベルにしない** | 「中小企業は手作業の予定調整に週 14 時間使っている」であって「予定調整の課題」ではない。画を見なくても見出しだけで立つ |
| **1 ビートに 1 つの考え + 1 つの画** | 2 つ目の箇条書きの塊、2 つ目のグラフを足したくなったらビートを割る |
| **結論を先に** | 一番強い点をビートの中でも動画の中でも先に置く。見る人は左上から読んで、途中でやめる |
| **市場の数字は積み上げで** | 「TAM 500 億ドル」と書かない。口座数 × 単価、取引数 × 手数料率のように**式を見せる** |
| **文字の最小サイズ** | 1920×1080 で見出し 72〜96px、本文 48px。**読ませる文字は 40px 未満にしない** |

## 5. 画面の設計（上流 `visual-design.md`）

### 5.1 1 ビート = 時間つきのショット列。前倒ししない

「PowerPoint に見える」原因は**前倒し**（最初の 25% で全部出して、残りは置きっぱなし）。
ビートはナレーションに合わせた**時間窓の列**で書く:

```
窓 1 (0.0–X s):  t=0 で声が言っているものだけ入る。全部は入れない
窓 2 (X–Y s):    声が次を言ったら、その 1 つ（1 行 / 1 枚 / 1 つの数字 / 1 つのアイコン）が出る
…               声のきっかけ 1 つに 1 窓。数は決めない
窓 N (…–end):    出し終わったら止めて読ませる（静止。あっても微かな揺れだけ）
```

- **窓の数 = 声のきっかけの数。** 2 拍の行は 2 窓、5 機能の列挙は 5〜6 窓。
  中間の「第 2 幕」は義務ではない。禁じ手は前倒しだけ
- **終わりは止める。** 出し終えたら動かさない。無理なカメラの流れ・怠惰な呼吸・後半の
  パンや押し込みは入れない（**悪い動きより静止**）。短いショットでは最後の出現と
  静止は同じ窓
- **わざと止めるビート**（出し終えて読ませる）は正しい。山場の前の息継ぎになる。
  失敗は「静かすぎる」ではなく「前倒しして凍る」
- 他の形式と違い、ビートの出口は次のビートの入りが決める（§7 の継ぎ目）

### 5.2 形は型から起こす（`hyperframes-animation` の blueprints）

ゼロから発明しない。ビートの役から**実績のある形**を引く:

1. `hyperframes-animation/blueprints-index.md` の「役 → blueprint」で候補を選ぶ
   （`titlecard-reveal` / `kinetic-type-beats` / `dataviz-countup` / `comparison-split` /
   `device-surface-showcase` / `logo-assemble-lockup` / `grid-card-assemble` /
   `cursor-ui-demo` / `zoom-out-workspace-reveal` …）
2. その `blueprints/<id>.md` の `[slot]` を**この製品の言葉・画像・数字**で埋める。
   そのまま（Reproduce）/ 構造だけ借りる（Adapt。何を残し何を変えるか 1 行）/
   合わない（Compose。§6 の語彙で組む）
3. **署名の動き（signature move）は落とさない。** 落とすなら型の選び間違い。
   `kinetic-type-beats` は 6 つの役で使える主力だが、毎回これだと同じ顔になる。
   **型を動画の中で散らす**

### 5.3 配置の語彙（ビートごとに言葉で指定し、px は書かない）

- **フレーミング**: 中央（主役 / 山場）・三分割・分割画面（比較）・奥行き重ね（没入）・
  非対称 60/40 か 70/30（編集的）・三連（3 枚）・全幅の帯。**同じ型を繰り返さない**
- **密度**: 主役の画は画面の **40% 以上**。奥行きは **3 層以上**（背景 + 中景 + 前景）。
  空白に小さな塊が 1 つ浮いている画は禁止。**目を細めても一番の要素が分かる**か
- **階層**: 大きさ（3:1）・太さ（800 と 400）・コントラスト・位置（上 1/3 が特等席）・
  動きのうち **2 つ以上**を重ねて、1 つがはっきり勝つ
- **奥行き**: 大きさ・ぼかし・透明度の勾配・重なり・影の積み重ねから 2〜3 つ
- **出さないもの**: ナビバー・フッター・スクロールバー・本物のカーソルやブラウザの枠・
  実物の代わりの装飾図形・浮いたボケ・**紫青の「AI っぽい」グラデーション**
  （UI デモの忠実な再現としてだけ許す）
- **実物のスクショは証拠として扱う。** 文字が読める画像（UI・グラフ・ツイート・コード・
  表）は元の比率のまま（`object-fit: contain`）。`cover` で切ってよいのは装飾の背景だけ。
  はめ込んだら四辺を見て、文字・ロゴ・ボタンが切れていないか確かめる
- **1 つの世界。** 同じウィンドウやキャンバスがビートをまたいで続く。カットごとに
  残るものが飛ばないか、全部の切れ目を擦って確かめる。カーソルやスクロールで消える
  内容は**窓や画面の端から**出ていき、画面の途中でフェードしない

### 5.4 動画全体で 1 回だけ決めること（`## Video direction`）

パレット（ブランド色 → 役割）・動きの文法（§6）・止めるビートの配分・禁止リストは
**企画書（`series_bible.v1`）に 1 回書き**、各ビートは差分だけ書く。これが多数のショットを
1 本の映像に束ねる。

### 5.5 セーフゾーンとトラック（上流 `hyperframes-studio`）

| 箱 | 画面に占める割合 | 各辺の内側 |
|---|---|---|
| アクションセーフ | 90% | 5% |
| タイトルセーフ | 80% | 10% |

- **見えるものは全部アクションセーフの中。字幕と主要な内容はタイトルセーフの中**
  （横も縦も同じ 2 つの箱）。2 分割の画は左右それぞれの中身をタイトルセーフに収める
- ガイド線は composition の HTML に入れない（プレビュー側が描く）
- **字幕は 1 トラック**、**種類ごとに 1 トラック**（下地 `video` / 図と文字 `graphics` /
  字幕 `captions` / 音 `audio`）。構造のあるビートは**サブ composition**にする
  （`compositor` §10）

## 6. データの見せ方（`hyperframes-creative` の `data-in-motion.md`）

- **数字には重さを持たせる。** 数字だけ浮かせない。量に比例する棒・背景色の変化・
  値を表す形・進捗のリングのどれかを添える。グラフでなくてよい、画面を埋めて手触りを出す
- **同じ概念の数字は同じ場所・同じ見た目で、値だけ変える**（Q1 → Q2 → Q3）。見た目が
  変わるのは概念が変わったとき
- **Web の型を持ち込まない**: 円グラフ（比べられない）・二軸グラフ（3 秒で読めない）・
  6 枚のダッシュボード（2〜3 枚まで）・グリッド線・目盛り・凡例（動く画では雑音）・
  グラフライブラリの出力（GSAP + SVG / CSS で組む）

## 7. 動き（上流 `motion-language.md` Part 2 と `cut-catalog.md`）

| 決まり | 中身 |
|---|---|
| **滑らかさ > 弾み** | 既定のイージングは `power3`。弾む・跳ねる動きは意図があるときだけ |
| **後半 50% にも出現を配る** | ナレーションの語に合わせて出す。前倒しして凍らない（§5.1） |
| **怠惰な呼吸・悪いパンや押し込みをしない** | 止めているあいだに意味の無い動きを足さない。「悪い動きより無い動き」 |
| **ビートの中の継ぎ目は速度を合わせたカット** | 出ていく側と入ってくる側が**同じ軸・同じ向き・同じ速さ**で、両側とも動いている最中に切る。Z 軸なら拡大 = 前へ、縮小 = 後ろへで、縮んで消えたものに小さく生えて入る画を続けない（鏡像。最も多い違反） |
| **動画に 1 つの「流れ」を決める** | ふつうの継ぎ目は全部その向き（上流の既定は左）。他の向きは意味を持つときだけ使う: 上 = 結論が浮かぶ、Z 前 = 同じ考えを掘る、Z 後 = 大きなものが到着する |
| **山場の前は止める** | 静止が次の動きを大きく見せる |

継ぎ目の 4 つ（全部「最高速で切り、両側の向きと速さを合わせる」の変種）:

| 継ぎ目 | 軸 | 使うとき |
|---|---|---|
| **zoom-through** | Z・手前へ | 同じ場面の中で文字を差し替える。「進んでいく」 |
| **inverse zoom-through** | Z・奥へ | 到着・ご褒美のビート |
| **cut-the-curve** | x / y | 場面から場面へ。未完の句を複数の画でつなぐ（複数行の文字・連続するカード） |
| **waterfall** | x / y・語単位 | 文字から文字へ、語ごとに時差をつけて |

Z 軸のぼかしは**被写体の大きさで決める**: 文字スケールは最大 10px（20px だと字が溶けて
グリッチに見える）、全画面の面（ウィンドウ・カード・スクショ）は 18〜20px。両側で同じ値、
ラッパーに掛ける（子要素に掛けない）。

**2 つの失敗の形**: スライドショー（前倒しして凍る）とスクリーンセーバー（全部が
勝手に漂う）。この 2 つに名前を付けて、企画書の禁止リストに書く。

## 8. 字幕（上流 `embedded-captions` のモデル）

- 話された句は **drop（つなぎ言葉・言い直し。出さない）/ rail（ふつうの台詞。下段の
  読みやすい字幕）/ embed（見出しになる 1 語。画面中央に大きく）** のどれか。
  **rail が既定で embed は希少**（1 ビートに 1 つまで、続けて 2 つ出さない、
  間を 1 拍以上あける）。全部 embed にするのが最も多い失敗
- **字幕は重ねる層で、帯ではない。** 下に帯を取って本編を上にずらさない。本編は画面の
  真ん中（y = H/2）に組む。字幕が座る下端 5〜8% の中央に、URL や注記のような
  **小さな読ませる文字**だけ置かない
- 書き方と置き場の実装は `compositor` §10

## 9. 終わり方

- **コマンドか URL で閉じる。** ロゴは**まだ動いている画面の上に**着地させる（止まった黒に
  ロゴだけ、は弱い）
- **版を出すたびに尺を言う。** 目標の尺を超えるかどうかは人の判断で、こちらで決めない
- 免責（AI が作った内容・推計の数字）が要るものは画面に出す（`.claude/rules/store-review.md`
  の考え方と同じ）

## 10. うちの段取りでの対応（詳細は `director` §1.4）

| 上流の段 | うちでの置き場 |
|---|---|
| BRIEF（対象・約束・尺・縦横・CTA） | `declare_deliverable` + `series_bible.v1`（企画書） |
| frame.md（パレット・書体・トーン） | `style_guide.v1`（`art-director`） |
| STORYBOARD.md / SCRIPT.md | `storyboard.v1`（画 / ナレーション / 尺 / 音の 4 列。1 行 = 1 ビート）→ `plan_scenes`（1 ビート = 1 シーン） |
| capture/（実物の画面・ロゴ・数字） | 人がアップロードした素材（`search_assets`）。無いものは画像生成（文字が読める図は `sunburst`） |
| 各フレームの HTML | 下地（プレート）の動画は**シーンのクリップ**（サーバが置く）。文字・図・端末・ロゴは **`graphics` トラックのサブ composition**（`compositor` §10） |
| audio_meta（ナレーション・BGM） | `generate_asset(text_to_speech)` / `text_to_music`（`audio-engineer`） |
| `hyperframes check` → render | `record_check` → `render_composition` |

**文字と図だけのビートは今のまま**（下地 + `graphics` トラック）。**イラスト（人物・製品・場面）を
描いて動かすビート**（層に分けて視差・揺れ・差分で見せる）は、作り方の選び方と動きの語彙を
[motion-stills.md](motion-stills.md) から引く。

| 1 | 約束が 1 行で言え、2 ビート目までに着地しているか |
