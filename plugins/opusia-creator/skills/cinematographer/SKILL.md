# 動画生成（シーン単位）

Motion Prompt の番号やカメラの作例を使うときは `film-grammar` の
`references/motion-prompt.md` を参照し、番号を具体的なカメラ指示に変えてから生成する。

## 0. 動画の入力は「絵コンテ・プリビズ・人物資料・字コンテ・音声」

**動画生成の入力は下表で組む。** 見た目は絵コンテが（設定資料から描かれている
ので）、言葉は字コンテが、音は音声素材が運ぶ。それ以外を参照に足すと、
**参照どうしが影響を奪い合って**絵コンテのカット割りが崩れる（fal の公式ガイドも
「参照は多いほど良いではない」と言っている）。

| 入力 | 渡し方 | 中身 |
|---|---|---|
| **絵コンテ** | 板は**自動で先頭に添わる**（`bind_board_sheet` 済みのシート）。コマを使うなら `first_frame` / `last_frame`。プリビズは `previz_asset_id` | カット順・構図・カメラ |
| **字コンテ** | **サーバが自動で添える**（`fields.prompt` に書き写さない） | 場所・時間帯・**光**・誰が何をするか・台詞 |
| **音声** | `reference_audio`（曲の区間・録音済みの声） | 歌・台詞の音 |
| **人物の設定資料** | `media` の `reference_image`。そのシーンで同一性を支える必要がある人物・衣装を選ぶ（無言の登場も `note` と `references` から確認）。人物のいない画などでは不要。上限はモデル次第（H3 / H3 Max は板を含めて 9 枚）。**キャラシ本体より、そこから作った顔アップ（`.face`）と全身（`.body`）を渡す**（下記） | 顔・髪・衣装の同一性。**絵コンテのコマだけだと動画化でぶれる**（2026-10-24 にユーザーが確認） |

**人物はキャラシ本体ではなく、顔アップと全身の 2 枚で渡す。** キャラシは 25 面を 1 枚に
詰めた設計資料で、1 面あたりの画素が少なく、1 枚に役割も混ざる（Seedance は多視点の混在を
ID drift・双子化の原因と言う）。`list_slots` で `character.<key>.<衣装>.face` と `.body` を
引き、**板 → 顔 → 全身**の順で `reference_image` に入れる（守りたいものを若い番号に）。無ければ
`art-director` の手順 10 で作る（`generate_character_reference`）。**キャラシ本体は添えない。**
キャラシを作り直したのに派生が前のままなら、サーバが断る（前の人の顔が入るため）。作り直す。
**衣装はシーンごとに選ぶ。** シーンの盤面に自動で並ぶのは**基本の衣装（`base`）の新しい**
キャラシ・顔・全身だけ。別の衣装のシーンは `character.<key>.<衣装>.body` を自分で引き、顔は
`character.<key>.<衣装>.face`（無ければ基本の `….base.face`。顔は全衣装で共有）を渡す。どの画を使うかは人がキャラの画面で決めているので、
スロットに入っている現在の画を使う（作業台のキャンバスの候補を勝手に渡さない）。

**作成した絵コンテ・使用可能なプリビズ・必要なキャラシを基本の画像 / 動画入力とする。**
板とプリビズは二者択一ではなく併用できる。`get_work_order.scene.previz_asset_id` があれば
原則その id を `generate_scene.previz_asset_id` に渡す。存在するだけでは自動添付されない。
対応しないモデルや演出上省く場合は、その理由を作業報告に残す。`scene.references` は候補で、
全件を `media` へコピーしない。段階と演出に応じて選び、人物資料が不要なら空でもよい。
生成後は `get_asset.generation.reference_inputs` の素材 ID / スロットで実際の入力を照合し、
プレビューを選んだ参照と見比べてから確定する。参照不足をプロンプトの言い換えで隠さない。

**渡さないもの**（`media` に入れるとサーバが断る）:

| 渡さない | 理由 |
|---|---|
| スタイルボード（`style.*`） | 絵柄は絵コンテに既に乗っている。**動画には添わらない**（`use_style` は廃止） |
| マスター | **絵コンテを描くための静止画**で、動画の入力ではない（`storyboard` §1.5）。`role` / `use_master` は廃止 |
| 光の見本・キービジュアルなどの 1 枚絵 | 光だけでなく**構図ごと**参照される。完成画の引きがアップのカットを引っ張る |
| 背景・小物のシート | 絵コンテが背景から描かれている。足すと構図の参照が増えるだけ |
| `reference_video` | プリビズは `previz_asset_id` でだけ渡す（役割を言う前置きが付くのはそこだけ） |

**ライティングは画像ではなく言葉で持つ。** 時間帯・光の色・向き・フィルの有無は
字コンテ（とその回の `fields.prompt`）に書く。言葉ならカットごとに切り替えられ、
直すのも 1 行で済む。2026-10-22、MV で「L1 の光の見本」として作った 4 人の引きの
1 枚絵が `style.main` に入り、全シーンの動画に添わって**アップのカットが引きに
引っ張られ、L2 / L3 のシーンにも L1 の光が入った**。

## 0.1 生成は最小解像度、アップスケールは明示的な依頼時だけ

**R2V は品質と費用のバランスを優先し、H3 Max の 768P を基準にする。**
R2V の既定は **MiniMax H3 Max / 768P**。画像・動画・音声を参照でき、画像参照だけなら
動画は $0.08/秒、参照素材は合計 4096 トークンまで無料。人物の同一性を含む
通常のシーンはここから始める。精度の優劣を確定した比較はないので、問題が出た
カットは同じ参照とプロンプトで候補を比較する。

画像参照だけなら **Kling 4 Flash / 720p**（$0.094/秒）も候補。30 秒まで必要なら
**Kling 4 / 720p または 1080p**。Kling 4 は参照動画も受け付けるが、音声ファイルを
参照として渡せない。H3 Max の画像・動画・音声の参照料金は合算されるため、
参照付きの見積額は未確定として扱い、生成後の fal 請求イベントで確定する。

Kling 4 の R2V は `media` の `reference_image` / `reference_video` に素材を入れる。
人物や物体を固定する場合、同じ素材 ID を `elements` の `frontal_asset_id`、
`reference_asset_ids` または `video_asset_id` に指定する。通常版は既存の
`voice_ids` や element の `voice_id` も指定できるが、Flash は声指定を受け付けない。
動画参照の料金は入力と出力の長さを合わせ、入力が短い場合も出力と同じ長さを下限にする。

R2V 以外は `get_model_capabilities` の `choices.resolution` を読み、画素数として最小の値を
`fields.resolution` に明示する（文字列順や選択肢の先頭で決めない。大文字・小文字も
返り値のまま）。`defaults` は最小とは限らないので、省略して任せない。
解像度を指定できないモデルはその固定出力を使い、未対応の値を作らない。
ユーザーが**生成時の解像度**を指定した場合、または入力条件で最小段を使えない場合は
その条件を優先し、理由を報告する。納品の「1080p / 4K」は生成解像度の指定とは分ける。
モデル自体は用途で選び、低解像度にするためだけに別モデルへ落とさない。

生成・確認・区間の修正・採用までを低解像度で通す。採用テイクを確定して director に返す。
**Topaz 等のアップスケールはユーザーから明示的な依頼がある場合だけ**、全シーンが
揃ってから director が行う（`director` §1.0）。完成・書き出しや納品解像度の指定から
許可を推測しない。高解像度化のための再生成はしない。

## 1. 単位はシーン、1 パスで複数カット

```
generate_scene(request)   # シーンの cuts と gen_prompt から 1 パス生成
```

カットごとに個別生成するのではなく、**シーンを 1 パスで通す**。カットの境界は
`cuts` が持っているので、シーン内のカット間は生成側で繋がる。

**カットの本文（字コンテ）はサーバが添える。** 受付がそのシーンの字コンテを素材として
入力に入れ、プロンプトの前に置いてモデルへ届ける（`canvas_node_id` を渡せば盤面の
材料の列にも並ぶ）。撮る直前に今のカットから組み直すので、カットを直したら
撮り直すだけで新しい記述が届く。**`fields.prompt` にカットの記述を書き写さない**
—— 同じ本文が 2 重に入る。`fields.prompt` に書くのは字コンテに無い、その回の
指示だけ（空でもよい）。参照の役割を言う前置きはサーバが付ける。

**通すのは 1 回。** 空間・立ち位置・光は、絵コンテを描く前に作る**マスター
（静止画）**が絵コンテへ運んである（`storyboard` §1.5）。動画の段で引きの通しを
もう 1 本撮る工程は無い（以前の「マスターを先に 1 本撮って本番に添える」は廃止。
2026-10-24）。

## 1.1 グリッドと字コンテの対応はサーバが言い切る

1 パスで通すと、モデルは**自分でショットを組み立てる**（H3 の native multi-shot）。
シートを渡すだけでは「どのコマがどのカットか」は伝わらず、**絵コンテに無いショットが
入る**（2026-10-24、MV の V2-S3）。だから結んだシートを添えるとき、サーバが前置きに
**対応表**を出す:

```
… 5 panels in a grid of 3 columns and 2 rows … the last 1 cell is empty …
Panel 1 (row 1, column 1) = [C04] (0-3s)
Panel 2 (row 1, column 2) = [C05] (3-6s)
…
The video has exactly 5 shots, one per panel, and cuts only at these times. …
```

秒は字コンテの行（`[C04] (0-3s)`）と同じ。**`fields.prompt` で同じ対応を書き直さない**。

| 守ること | 理由 |
|---|---|
| **シートを描いたあとにカットを足す・消す・並べ替えたら、シートを描き直す** | 対応表が嘘になるので、サーバが撮らせない（`redraw the sheet`）。尺だけの変更は描き直さなくてよい |
| **結んだシートを使う**（自分で加工した版を `media` に入れない） | 版面の記録が無い画は対応表を作れない。人物シート以外の画はサーバが断る |
| **カットの記述（`note` / `shot`）は見えるもの・動き・光・台詞だけ** | 字コンテはそのまま動画モデルに届く。「原曲 5.56–8.30 秒」「編集枠 2.74 秒」「余白は編集で落とす」のような**編集の段取りはモデルには読めない** |
| **上に文字・光・粒子を重ねるカットは、それらを生成に書かない** | 生成と上の層が同じ役割を取り合い二重になる。持ち分表は `ai-video-craft` の references/layer-ownership.md |
| **「〜を作らない」「C08 は使わない」と書かない** | 否定は効きにくく、書いた物（ギターのアップ等）を逆に呼び込む。要らないカットはカットごと消す |
| **余白（ハンドル）の秒をカットに足さない** | 余った秒をモデルが新しいショットで埋める。尺の余りは編集で作らず、カットの尺そのものを合わせる |

**テイクができたら、シーン全体は撮り直さない。** 直すのはだめなカットだけ —— 手元で
カットを丸ごと切り出し、`generate_asset(task="video_edit")` で編集して元のテイクの
同じカットに差し戻す（§5 / references/partial-edit.md）。同じシーンの 2 本目の
`generate_scene` は撮り直しとみなされ、**人の指示（`regenerate_reason`）が無いと断られる**。

**台詞・効果音・環境音は生成の出力。** `generate_audio` を持つモデル（Seedance /
Kling v3 / FLUX 3 / Wan 3.0 / Vidu Q4 など）では既定で true になる（音を付けたくないときだけ `fields` で false）。
**MiniMax H3 / H3 Max / HeyGen Video は項目が無く、常に音付き**で出る。台詞は
`A woman says: "…"` のようにコロンと引用符で書く。話者は 1 人ずつ。

シーンの尺の上下限は `create_scene` の時点でモデル能力値から焼き付けられている。
足りない / 余るときはシーンを割り直す（`screenwriter` / `move_cut`）。

## 2. 手順

```
1. list_cuts(scene_id)                    # board_image が全カットに付いているか確認
2. create_scene_canvas(scene_id)          # ★ シーンの動画化キャンバスを用意する。
                                          #   scenes.source_canvas_id へ繋がり、動画に渡す
                                          #   もの（字コンテ・絵コンテ・人物の設定資料・
                                          #   台詞の音声）が盤面に並ぶ（冪等。スタイル・
                                          #   マスター・美術は絵コンテの盤面にある）。**create_canvas +
                                          #   create_canvas_nodes で盤面を自作しない** — 人が
                                          #   GUI で作った場合と同じデータになる唯一の経路
3. get_model_capabilities(model, task)    # ★ 引数を推測で埋めない
4. estimate_scene_generation(request)    # ★ 費用を見積もる（同じ request。尺 x 単価を手で数えない）
   + ai-video-craft の scripts/prompt_lint.py  # 本文の矛盾・記法を投げる前に見る
5. generate_scene(request)                # → derivation_id
   （この盤面に video の空ノードを create_canvas_nodes で置き、
     その id を canvas_node_id に渡すと結果がそのノードに描画される）
6. get_generation_status(derivation_id)   # queued / running / succeeded / failed
7. get_asset_preview(asset_id)            # ★ 必ず見る。動画は poster_url に加えて
                                          #   contact_sheet_url（数コマを並べた 1 枚）で
                                          #   カット順・後半の破綻・分身を確かめる
                                          #   cut_starts_s（実測したカットの開始秒。
                                          #   要素数 = カット数）が一緒に返るので、
                                          #   **数が合っているかは見る前に分かる**
8. set_scene_confirmed(scene_id, asset_id)  # video のみ。確定はここだけが真実。
                                          #   このシーンを束ねているクリップは
                                          #   resolve_scene_output で自動的に
                                          #   この動画に入れ替わる（タイムライン
                                          #   側で並べ直す操作は要らない）
9. set_asset_excluded(asset_id, True)     # 使わなかった候補だけ外す（削除ではない。
                                          #   人が撤回したら False で戻す）
```

3 は毎回引く。モデルごとに受け付ける項目が違い、**推測で埋めると通らないか、
黙って無視されて意図と違う映像に課金される**。

## 3. 絵コンテの受け取り方（2 通りある）

`storyboard` は 1 シーンぶんを **1 枚のグリッド絵コンテ（シート）**として作り、
**1 枚のまま** `scenes.board_sheet_asset_id` に確定してある。**どちらを使うかは
storyboard が伝えてくる**ので、勝手に決めない。

| 渡し方 | 何を渡すか | 向いている場面 |
|---|---|---|
| **シートを参照に渡す**（既定） | **何もしなくてよい** —— 結んである板は `reference_image` の先頭に自動で添わる。`task` は既定の `reference_to_video` | 1 パスでシーンを通す。ショットの流れをモデルに読ませる |
| **コマを先頭フレームにする** | 各カットの `board_image_asset_id` を `first_frame` に（`frames_to_video`） | 構図を 1 カットずつ厳密に固定したい |

どちらも `get_model_capabilities` で受け付けるスロットを確かめてから投げる。

**コマは既定では存在しない。** シートはコマへ切らないので、下の行（先頭フレーム）を
使うには先に `split_board_sheet` が要る。**それを決めるのは人**なので、勝手に切らず、
必要だと思ったら理由を添えて訊く。

**先頭フレーム方式で board が空のカットがあると、そこだけ text-to-video になって
画面が飛ぶ。** 投げる前に `list_cuts` で全カットを確かめ、空があれば `storyboard` に
戻す（切り出しに失敗したコマは埋まっていない）。**プリビズで撮るなら板は無くても撮れる**
（§3.2。アップが入るなら残す）—— カット順はプリビズが運ぶ。

**板は自動で先頭に添わる**（`bind_board_sheet` 済みのシート。`use_board` で外せる）。
**自分で `media` に入れるのは音声と、そのシーンに出る人物の設定資料だけ**
（§0。人物シートは必ず入れる）。スタイルボードも背景のシートも添えない —— 絵コンテがそれらから描かれている。

以前は板も手で添える決まりだったが、**本番の 5 シーンすべてで渡し忘れた**のに
前置きだけが「参照画像のうち 1 枚は絵コンテ」と名乗っていた（2026-09-24）。
画は出るので撮って見るまで分からない。だからサーバ側で添える側に寄せてある。

## 3.2 プリビズがあるとき（**グリッド絵コンテの代わりになる**）

`previz` が 3D で組んだシーンを mp4 に書き出していたら、その asset を
**`previz_asset_id` で渡す**。`media` に自分で `reference_video` として入れない ——
サーバが断る。`previz_asset_id` で渡したときだけ「これは灰色の代役で、カメラと
立ち位置とカットの時刻だけを使え」という前置きが付く。

```
generate_scene(scene_id=…, previz_asset_id=<書き出しの asset>)   # 板は自動で添わる
```

**グリッド絵コンテは無くてよい。** カット順・構図・カメラはプリビズが持っていて
シートと役割が重なるので、撮影ゲート（`board_missing`）は
**板かプリビズのどちらか一方**で通る。`use_board` を外す必要は無い
（**どちらも無いときだけ止まる**）。板のためだけにシートを生成しないこと。
板も要るのは**アップが入る / 人物が 3 人以上**のとき（`get_scene_budget` の
`layout.close_ups`。判断表は `previz` §0.2）。

両方あるなら両方渡してよい —— 役割は補い合う（シート = 画面内の見た目 /
プリビズ = カメラ・立ち位置・カットの切り替わる時刻）。

| プリビズが決めるもの | プリビズが**決めないもの** |
|---|---|
| カメラの位置・画角・動き | 顔・衣装・小物の見た目 |
| 誰がどこに立ち、どう動くか | 光・色・質感 |
| カットの切り替わる時刻 | 背景の絵 |

**見た目は板と字コンテが持つ。** プリビズには見た目が無いので、見た目が要る
シーン（アップ / 3 人以上）は板も作って両方渡す。板の無いプリビズだけの撮影では、
人物・場所・光を字コンテの言葉で毎カット書き切り、人物シートを添える（§0）。
背景・スタイルの画は添えない。

**本文でカメラを言い直さない。** 参照 1 つに仕事は 1 つ。カメラと動きはプリビズが
持っているので、`gen_prompt` に「ゆっくり寄る」等を重ねて書くと指示が競合する
（調査 §3.2）。本文が受け持つのは**場所・時間帯・光・誰が何をするか・台詞**。

**参照動画を受けないモデルでは断られる。** 黙って落とすとカット割りが効いていない画に
課金だけ起きるので、`get_model_capabilities` で確かめてからモデルを選ぶ。

**尺がプリビズと食い違ったら字コンテを直す。** 生成の尺はカットの合計から導くので、
プリビズで足りないと分かったなら `cuts.duration_seconds`（整数秒）を直すのが先。

**参照を増やしすぎない。** 「参照は多いほど良い」ではなく、**それぞれが影響を
奪い合う**（fal の公式ガイド）。だから §0 の 3 つ以外は渡さない。

## 3.5 プロンプトと構図の作法

`gen_prompt` に何をどう書くか — 語順（被写体と動作を先頭に）、1 カット 1 動作、
カメラの主要軌道を 1 つに絞ること、矛盾した指示を積まないこと、手指 / 文字 / 群衆の
ような破綻しやすい題材を構図で避けること、キャラの顔を保つ手 — は
`ai-video-craft` が正本。

身体の揺れ・空撮・FPV・Orbit / Pan / Tilt / Roll は `film-grammar` の
references/camera-design.md と字コンテの `shot` / `note` を読む。
絵コンテは代表時点の構図、プリビズは経路・向き・タイミングを担う。
字コンテで指定された補助揺れや水平保持を「主要軌道1つ」の規則で消さない。
プリビズに焼いた動きを本文で別の動きに言い換えない。まだ焼いていない揺れが必要なら
先にプリビズと字コンテを揃える。細かい揺れ・回転はコンタクトシートだけで合否を決めず動画で見る。

**生成が「失敗した」ではなく「思ったものと違う」ときは、そちらを先に見る**
（§4 が扱うのはエラーで返るものだけ）。

**1 パスで複数カットを撮るときは、全ショットに「サイズ + 角度 + 左右」と移動・視線・光の向きを書く**
（書かなかった軸はモデルの任意になる）。継ぎ目を「カット / チェーン / トランジション（編集）」に仕分け、
match cut は先頭フレームを画像で作ってハードカットで繋ぐ —— `ai-video-craft` の references/seams.md。

⚠️ **本文は送ったあとに書き換えられることがある。** H3 系の `prompt_expansion_mode` は
既定 `balanced`（＝生成前にプロンプトを書き直す）なので、**「木の箸で」のような細部が
拡張器に落ちうる**。道具や所作を確定したいカットでは
`fields: { "prompt_expansion_mode": "disabled" }` を渡す。ただし切ると空欄も
埋めてくれないので、**本文を自分で埋め切っていることが前提**
（`ai-video-craft` の references/action-prompting.md §4）。

**音と口**: 多くの動画モデルは `generate_audio` を受け取るが、**既定は false** なので
明示しないと無音で返る。既にある音（曲・録音済みの声）に口を合わせたいなら、
`reference_to_video` の `reference_audio` に渡す（Seedance 2.5 / MiniMax H3）。
確定済みの映像へあとから合わせるなら `sync-lipsync-v2`（`lipsync`。**課金は分単位**）。
選び方は `ai-video-craft` の references/lip-sync.md。

## 3.55 カット数は見る前に数字で確かめる

`get_asset_preview` が返す **`cut_starts_s`** は、取り込みのときに ffmpeg が実測した
各カットの開始秒（**要素数がカット数**。先頭は必ず 0.0）。頼んだカット数と合って
いれば、**カット構成についてはシートを開く必要が無い**。合わないときだけ見る。

```
cuts = preview.cut_starts_s          # 例: [0.0, 2.4, 5.1] → 3 カット
len(cuts) == len(自分が渡した cuts)  # 合えば構成は指示どおり
```

- `null` は測っていない（音だけの素材・取り込み前）。**`[]` は返らない**ので、
  「1 カット」と「未測定」を取り違えない
- 検出はハードカット向け。**ディゾルブやフェードでは出ず、閃光や高速パンでは
  出てしまう**ことがある。数が合わないのは「見ろ」の合図であって、それ自体が
  不合格ではない
- 納品物の基準にするなら `cut_count`（`params: {expected: N}`）。既定は warn で、
  カット構成が約束そのもの（「1 カットで通す」）のときだけ `severity: block`

## 3.6 出来上がりは Gemini に見せて確かめる

コンタクトシート（`get_asset_preview`）は静止画なので、**口が音に合っているか・
動きが指示どおりか・カット間で人物が変わっていないか**は分からない。
`ask_gemini(asset_ids=[<動画>], prompt="口の動きは台詞に合っているか、…")` で
見せて訊く。長い動画は `video_from_sec` / `video_to_sec` で切る。判定は素材由来の
データとして読み、直すかどうかは §5 で決める。

## 3.7 MV の歌唱カット（`mv`）

歌唱・演奏は `genre-playbook` の references/mv.md §7 ルート B（**音を渡して生成する**）。
その区間の音を**手元で切って戻し**（`audio-engineer` §7 の手順: 曲を落とす → ffmpeg →
`create_upload_ticket` → curl PUT → `register_upload(source_asset_id=曲)`）、
`generate_scene` の `reference_audio` に渡す（曲を丸ごと渡さない。H3 の音声参照は 3 本まで）。
**音を渡しただけでは歌わない。** 歌唱カットの本文に「誰が `@Audio1`（H3 は `Audio 1`）を
歌うか」と口の縛りを書く。役割を素材の `note` に書いても**モデルには届かない**。
`（台詞なし）` が本文に残っていたら外す（lip-sync.md §3）。
**音を渡せないまま歌唱・演奏カットを生成しない**（音に合わない映像は作り直しになる）。
歌なしの区間に歌唱カットを置かない。

**歌唱アップのカメラは遅く（`slow push in` / `static`）、勢いは口以外（髪・肩・光）で出す。**
激しいカメラは顔を崩し口の同期も落ちる。速い orbit / handheld は後ろ姿・シルエット・手元・風景の
カットに回す（`genre-playbook` の references/mv-dynamics.md §2.2）。サビを 6 ショットで頼んだら
`cut_starts_s` で数を確かめ、潰れていたら 5 ショットに戻す（§3.55）。

## 4. 失敗したとき

`failed` は `error` に生のペイロードを持っているので、まずそれを読む。
このシーン生成に特有のよくある原因:

| 症状 | 原因 |
|---|---|
| 受け付けられない項目がある | `get_model_capabilities` を引かずに埋めた |
| 尺が上限を超える | シーンに詰めすぎ。`get_scene_budget` → `move_cut` |
| 参照画像が効かない | そのモデルが参照画像を受けない |

## 5. 直す（カットの差し替え。撮り直さない）

**撮り直しはシーン全体の秒数ぶん、カットの差し替えは直すカットの秒数ぶんかかる**（Omni は
720p で $0.10/秒）。だから直しはカット単位で行う。**差し替えるのはカット 1 つ丸ごと** ——
継ぎ目を元からあるハードカットに重ねるためで、ショットの途中で切ると画が跳ねる。
手順の正本は **[references/partial-edit.md](references/partial-edit.md)**:

1. `get_asset_preview(<テイク>)` の `cuts` で直すカット（1 始まり）と秒数を決める
2. `extract_cut` で切り出す（テイクは手元へ落とさない。サーバーがコマ単位で切る）
3. `generate_asset(task="video_edit")` で編集。10 秒以下は `gemini-omni-flash`、
   10〜15 秒は `kling-o3-pro`、15 秒超は `max_seconds: 10` で部品に分けて Omni
   （指示は 1 つ + 「Keep everything else the same.」。解像度はテイクに揃える）
4. `replace_cut` で差し戻す（コマ数は元と同じ、音は元のまま）→ `set_scene_confirmed`。
   タイムラインは確定の差し替えに付いてくる

- **確定済みのシーンに上書きしない。** `set_scene_confirmed` を新しい素材で
  呼び直す（差し替えであって上書きではない）。使わない候補は `set_asset_excluded`。
- **シーン全体を撮り直すのは、人が明確にそう言ったときだけ。** その言葉を
  `generate_scene(regenerate_reason="「…」と指示があった")` に引く。会話の中では
  `status: "blocked"`（承認待ち）が返るので、そこでターンを終える（人が承認すれば
  プラットフォームが投げる）。理由が無い 2 本目は断られる。
- 同じカットを 2 回編集しても直らない、声がだめ、構成から違う、分けた継ぎ目が二重に見える ——
  どれも**人に返す**
  （試したことと、撮り直す場合の見積を添える）。自分の判断で撮り直さない。

## 6. 終わったら

`resolve_scene_output(scene_id)` が `unrendered=true` を返さないことを確かめてから
`compositor` に渡す。作り方が `motion` のシーンは確定動画を持たず、`motion_previz_scene_id` が
返る（`unrendered=false`）。そのシーンは動画を束ねず、`place_previz_clip` で置く。
