# 物語もの以外の形式（撮影済み素材 / MV / 説明もの）と字コンテ

**この 2 つは、シーンの切り方が物語ものと根本的に違う。**
物語ものの手順（ビートへ割る・速度を整える）は当てない
（[scene-writing.md](scene-writing.md) §20）。

## 1. 撮影済み素材（`footage_edit`）— 素材が先

**生成しない形式。** 素材が先にあり、構成は「どの区間を使うか」を決める仕事になる。

```
1. create_canvas + create_canvas_nodes（document の空ノード 1 つ）
   generate_asset(task=speech_to_text, media=[{slot: source_audio, asset_id: <動画>}],
                  canvas_node_id: <その空ノード>)
   → transcript.v1（語ごとの時刻）。**素材から作るので盤面の外では投げられない**
2. read_transcript(asset_id, from_sec, to_sec)   # 窓で読む。truncated なら狭める
   + get_asset_preview（コンタクトシート）/ ask_gemini（「どこで誰が何を、時刻つきで」）
3. plan_footage_scenes(asset_id, segments=[{start_ms, end_ms, title, note}, …])
   → 区間ごとにシーン（クリップは区間だけ再生する）
4. apply_scene_proposal（いつもどおりレーンへ置く）
```

区間の選び方（行間の空き・余白の足し算・重なりの検査は `python3 <SKILL_DIR>/scripts/footage_segments.py
<文字起こしの行> --pick <使う行番号>` が `segments` まで出す）:

- **話の単位で切る**（1 つの主張・1 つのエピソード = 1 区間）。文の途中で切らない
- **言い直し・咳・沈黙は区間の外に出す**。`read_transcript` の行頭の時刻と
  次の行の頭の間が空いているところが切れ目
- **カット尻に 0.3〜0.5 秒の余白**（言い終わりで切ると詰まって聞こえる）
- 区間は**時系列順で重ならない**（`plan_footage_scenes` が断る）
- 字幕の原稿は文字起こしそのもの。`compositor` §10 が時刻をクリップへ写す

ここでは②b（設定素材）④'（洗い出し）⑤（絵コンテ）⑥（生成）は無い。素材の一部を単体の素材に
したいときだけ `slice_media`（タイムラインに置くだけなら要らない）。

## 2. MV（`mv`）— 曲が先

`audio-engineer` §7 の段取り（測る → 聴く → 分割を決めて `write_music_map`）で `audio_map.v2`（区間・
**編成の帯**・**出来事**・フレーズと歌詞・**`scene_plan`**。時刻はすべて計測の小節頭）ができる。構成はそれを写す:

1. `scene_plan` を読む（MCP なら `get_document(audio_map の asset_id)`）。**歌のある曲で地図に
   `lyric_lines` が無ければ、ここで止まって先に歌詞の時刻を取る**（`audio-engineer` §7。歌詞を画面に
   出さない MV でも要る。無いまま割ると、どのカットがどの行を受け持つかを決められない）
2. 企画（トリートメント・差し替えテスト・6 つの型）を `series_bible.v1` に
   （`genre-playbook` の references/mv.md §2）
2.5 **カットを書く前に小節の表を出す**: `python3 <SKILL_DIR>/scripts/mv_check.py --map <地図の doc> --sheet`。
   シーンごとに、小節番号・小節頭の秒・区間 / フレーズの頭・出来事（キメ・全員が入る…）・**その小節で
   始まる歌詞の行**が並ぶ。**カットはこの表の上で割る** —— 「どの小節から何小節、どの行を受け持つか」を
   決めてから文にする。秒から逆算しない（整数秒の尺を積むと拍から外れる）。割るときの決まり:
   - **区間の頭・フレーズの頭・出来事の小節は、カットの頭にする**（サビ頭・全員が入る・ドロップ）
   - **`phrase_flow`（A メロ・静かな区間）は歌詞の行で切る。** 行の途中に頭を置かない —— 行の頭の
     前の小節頭か、行の終わりの後の小節頭で切る。1 行 = 1 カット、または 2 行 = 1 カットが基本
   - **`beat_cut`（サビ・ドロップ）は拍で切る。** 行の途中で切ってよいが、**決めの語（サビ頭の語・
     タイトルの語）は語の頭に最も近い小節頭 / 拍で切る**（`cut: lyric "語"`）
   - **歌唱カットは歌詞の行がある小節にだけ置く。** 歌の無い小節（イントロ・間奏・ブレス）は
     演奏・情景・物語のカットにする
   - キメ（表の `kime`）の小節では、その近くで必ず割る
3. `plan_scenes`: **`scene_plan` の 1 項目 = 1 シーン**（長すぎる項目は**フレーズの頭**で割る。下表）。
   **短いシーンを隣と束ねない** —— `reason` が `full_band_in` / `breakdown` / `instrument_in` などの
   シーンは、7 秒でも曲が展開した瞬間なので 1 シーンのまま（`genre-playbook` の mv.md §1.5）。
   シーンの見出しに `reason`（何が起きて画が変わるか）を写し、`visual` は編成の帯
   （`arrangement[].parts`）に従って誰を映すかを書く（mv-dynamics.md §7）。
   `hits_sec`（キメの打点）があるシーンは、その近くで必ずカットを割り `note` に `cut: kime` と書く。
   **各シーンの 1 カット目に `starts_scene: true` を立てる**（立てないとサーバが尺の上限で勝手に割り、
   フレーズの途中でシーンが替わる）。1 回の生成に収まらないシーンは割らずに断られるので、
   曲の地図の `phrases[].start_sec` の位置で割り直す。シーンの境目の 2 カットには同じ繋ぎを書く
   （`genre-playbook` の references/mv-dynamics.md §2.4）。
   尺は `bars` 小節、カットは `cut_hint` と `visual` に従い、**カット数は
   `genre-playbook` の references/mv.md §5 の区間ごとの表**で決める（少なく作らない）。
   **全カットの `note` の先頭に `♪ n bars`（1 小節未満は `♪ n beats`）を書き、シーンの中の合計を
   `scene_plan[].bars` に一致させる。** 受け持つ歌詞があるカットは `歌「<行>」` も書く
   （人が字コンテを読んで、どのカットで何が歌われるかを確かめられるように）:

   ```
   ♪ 2 bars · cut: lyric "名前" · 歌「君の名前を」 · レンが振り返る…
   ♪ 4 bars · cut: phrase · （歌なし）ギターの手元に寄る…
   ```

   **`plan_scenes` の前に、下書きのカット列で `mv_check.py`（下）を回し、所見を 0 にする。**
   書いた後（`list_cuts`）にもう一度回し、0 のまま `complete_scene_request` / 絵コンテへ進む。
   所見を残したまま先へ進まない（生成してから気づくと撮り直しになる）
4. **下書きを区間・フレーズの頭に置く**: `apply_scene_proposal(scene_ids=[…], boundaries_sec=[…],
   audio_map_asset_id=<曲の地図>)`。地図を渡すと、境界がフレーズの途中なら断られる。
   `boundaries_sec` は各シーンの `start_sec` を順に並べ、最後に末尾のシーンの `end_sec` を足した
   **シーン数 + 1 個**の時刻（ミリ秒まで効く）。**`at_seconds` で置かない** —— シーンの尺は
   整数秒の切り上げなので、尺で順に並べると 1 シーンごとに最大 1 秒近く拍から外れていく
   （シーンの切り替わりがズレて見える一番の原因）。シーンをフレーズの頭で割ったときは、その
   `phrases[].start_sec` を境界に足す（計測の小節頭なので、そのまま使える）

   ```
   scene_plan: [{start 12.42, end 27.42, bars 8}, {start 27.42, end 34.92, bars 4}]
   → boundaries_sec = [12.42, 27.42, 34.92]
   ```

   **境界・尺・歌詞・サビの密度は手で数えない**: `python3 <SKILL_DIR>/scripts/mv_check.py --map <地図の doc> <シーンごとのカット列>`
   がカットの頭を**小節の格子の上で**（`♪ n bars` を積んで）数え、次を出す:

   - `boundaries_sec`（`apply_scene_proposal` へ）と、シーンごとの **`cut_starts_sec`**
     （`align_scene_cuts` へそのまま渡す。累積小節を手で掛け算しない）
   - カットごとの**受け持つ歌詞**（`歌「…」` と食い違っていたら直す）
   - 所見: 小節数の無いカット・**カットの小節数の合計がシーンの小節数と合わない**・`♪ n bars` と
     合わない尺・枠より短いシーン・区間の頭を跨ぐカット・**`phrase_flow` で歌詞の行の途中に置いた
     カットの頭**・**歌詞の行が 1 つも重ならない歌唱カット**・**`cut: lyric "語"` の語が頭の前後で
     歌われていない**・**歌詞の時刻（`lyric_lines`）が地図に無い**・切る根拠の無い `note`・
     サビの密度 / static / サイズの跳躍 / 同じ動きの連続・TL でやる技法・キメの近くに無いカットの頭・
     全員が入る頭でサイズが跳ばない

   **シーンの生成尺（カットの切り上げ整数秒の合計）は枠以上にする。** 枠より短いと
   サーバが断る（クリップの尻が黒になるため）。余りは枠の外へ捨てられる

`screenwriter` §3.4 のビート分割は当てない（曲の区間が展開を決める）。

### カットの尺は小節数で決める（整数秒には拍が乗らない）

作法の正本は `film-grammar` の `references/beat-sync.md`。字コンテで守ること:

| 決まり | 中身 |
|---|---|
| **カットごとに「切る根拠」を決めて `note` に書く** | `♪ 2 bars · cut: beat` / `cut: lyric "word"` / `cut: action peak` / `cut: story`。拍は 5 つの根拠（拍・歌詞・旋律 / 和声・芝居・物語）の 1 つで既定値ではない。**サビ / ドロップは拍、A メロは歌詞と芝居、ブリッジは拍から浮かせる**（beat-sync.md §2）。書かないと下流で全部拍に吸着される |
| **カットの尺は小節数で決める** | サビ 1〜2 小節、A メロ 2〜4 小節、間奏 4〜8 小節。1 / 2 / 4 小節を混ぜる。**シーンの中の合計はシーンの小節数と一致させる**（1 小節でもずれると後ろの頭が全部拍から外れる） |
| **歌詞の行とカットを対応させる** | `--sheet` の表で、各カットが受け持つ行を決めて `歌「…」` と書く。A メロは行の頭 / 終わりで切り、サビは拍で切りつつ決めの語の頭を拍に合わせる。**歌唱カットは行のある小節だけ**（mv.md §4・§7） |
| **`duration_seconds` は切り上げの整数秒** | `ceil(小節数 × 240 ÷ BPM)`。128 BPM × 2 小節 = 3.75 s → **4 s**。余りはタイムラインで捨てる（短く作ると穴が開く） |
| **整数秒に小節が乗るテンポは 80 / 120 / 160 BPM 系だけ** | 128 BPM は 8 小節（15 s）のみ、140 BPM はどれも乗らない。合わせようとして小節数を曲げない |
| **サビ頭・ドロップ・編成の変わり目はカットの頭に置くのが既定** | 区間の頭と出来事で画が変わる。`sections[].start_sec` / `events[].at_sec`（キメ以外）を跨ぐカットは作らない。長回しで通す意図があるなら `note` に書く |
| **シーンの切れ目は区間かフレーズの頭だけ**（`phrases[].start_sec`。小節頭でもフレーズの途中は不可。弱起・ブレスの位置で割らない） | 下書きはその時刻で置く（上の手順 4）。割った時刻がそのまま `boundaries_sec` に入る |
| **1 回の生成に入らないシーンはフレーズの頭で割る** | 1 シーン 6 コマ（`storyboard` §1）と参照動画 30 秒（`previz` §6.2）の上限。サビ 8 小節を 1 小節刻みで切ると 8 カットになる。**割るのは生成の都合なので、地図の `scene_plan` の境目は動かさない**（境目の理由に生成の上限を書かない） |
| **`phrase_flow` の区間はフレーズ（4 / 8 小節）で切る** | 拍で切らない |
| **カット数とカメラは区間で既定を切り替える** | サビ・ドロップ・大サビは 15 秒に 5〜6 カット・カットごとに別の動き、A メロ・ブリッジは抑制。**書き終えたら `genre-playbook` の references/mv-dynamics.md §6 の「のっぺりチェック」を全部通す**（MV の字コンテの完了条件） |
| **同じ長さを並べない** | 1 / 2 / 4 小節を混ぜる。等間隔は「編集していない」ように見える（`film-grammar` §4） |


## 3. 説明もの（`explainer`）— 約束が先

**生成した物語ではなく、約束と根拠で組む形式。** サービス・製品・機能の紹介、使い方、
会社紹介、概念の説明。構成の型・フック・ナレーション・1 ビートの文字の決まりの正本は
`genre-playbook` の references/explainer.md。ここでは**書く順と、`plan_scenes` への写し方**だけ。

```
1. put_document(series_bible.v1)   # 企画書: 対象 / 約束 1 行 / 根拠の一覧 / CTA / 尺と縦横 /
                                   # 構成の型 / 動画全体で 1 回だけ決めること（explainer.md §5.4）
2. put_document(storyboard.v1)     # ビート表。画 / ナレーション / 尺 / 音 の 4 列、1 行 = 1 ビート
3. plan_scenes                     # 1 ビート = 1 シーン。カットは「画面に出る順」の窓
4. apply_scene_proposal            # いつもどおりレーンへ置く
```

ビート表の各行に書くこと:

| 列 | 中身 |
|---|---|
| **画** | 役（`hook` / `pain_point` / `product_intro` / `feature_showcase` / `benefit_highlight` / `social_proof` / `branding` / `cta`）、**見出しの主張 1 文**（ラベルにしない）、画面に出るもの（実物のスクショ・数字・図・端末・ロゴ）と出る順、候補の型（`hyperframes-animation` の blueprint id。無ければ `compose`） |
| **ナレーション** | 話す本文。**句の切れ目が画面の出る順**になるように書く（長い 1 文にしない）。数字は読み方で（`135+` → 「百三十五以上」） |
| **尺** | ナレーションの長さから（英語 1 秒 2.5 語、日本語はおよそ 1 分 300 字）+ 読ませる静止。15 秒に 1 ビートではなく、**1 つの考えに 1 ビート** |
| **音** | BGM の雰囲気、効果音のきっかけ（スラムの衝撃音・押し込みの風切り・出現前のライザー）。`music: none` なら無音と書く |

守ること:

- **約束は 2 ビート目までに着地**（explainer.md §2）。1 ビート目は見る側の言葉のフックで、
  機能名・社内用語・会社の概要から始めない
- **1 ビート = 1 つの仕事。** 「もう 1 つ機能」「もう 1 つ便益」のビートは割るか消す。
  UI のデモは同じ画面上の連続した 3 ビート以上（入力 → 応答 → 結果 → 便益）
- **元の文書（LP・資料・記事）の段落順をなぞらない。** 並べ替え・統合・省略して約束 → 根拠の順にする
- **実物の数字・画面・ロゴだけを根拠に書く。** 無いものは「ここに実物」と書いて人に頼む
  （近似で描かせない）。市場規模は積み上げの式で書く
- **ナレーションの本文はビート表の「ナレーション」列が正本。** `audio-engineer` がそのまま
  `text_to_speech` に渡す。読みは `glossary.v1`

§3.4（ビート分割と速度の規律）・第 1 部 / 第 2 部・ログラインは当てない。
主人公も欲求も山場も要らない —— 見終わった人が約束を信じて CTA に進めば成立する。

## 4. 静止画とモーショングラフィックのシーンがあるとき — 字コンテ（形式を問わない）

どの形式でも、静止画を描いて動かすシーン（`motion`）や 3D のシーン（`previz3d`）が入るなら、
シーンとカットに割る前に**字コンテ**を `put_document(storyboard.v1)` に書く（1 行 1 区切りの表）。
V コン（ラフと文字を音に乗せて流す確認）と、何枚描くかの見積りがこの表から決まる。
作法（作り方の選び方・打点の配分）の正本は `genre-playbook` の references/motion-stills.md。

| 列 | 中身 |
|---|---|
| `time` | 時刻の基準から取る。**手で書かない**（MV は地図の `lyric_lines[]` / 小節の頭、それ以外は `read_transcript` の文の頭） |
| `section` | MV: イントロ / A メロ / サビ … / 説明もの: つかみ / 課題 / 解決 … / 物語: 幕・シーン |
| `words` | 語り。下の 3 通り |
| `picture` | 何が見えているか（どの静止画・どの差分・どの層・どのコマ）。**同じ絵の別の画角は同じ絵の名前で書く**（描く枚数を数えるため） |
| `motion` | カメラ・揺れ・帯や図形・光と粒・打点（拍頭 / ピーク / 子音 / 語の頭のどれに合わせるか）を**言葉で**。語は motion-stills.md §5.1 の語彙（compositor がその語から作り方を引く）。そのカットの**主役の動きを 1 つ**決める。絵コンテには描かない |
| `text` | 文字の出し方（出さない / 字幕的 / 演出として動かす）と中身。MV は**見せる行か読ませる行か**、見せる行は**核の語（1〜2 字）**と人物との前後関係（後ろ / 避ける / 重ねる）まで書く（`genre-playbook` の references/mv-lyrics.md） |
| `supply` | `motion` / `previz3d` / `generate`。**形式の既定と違うなら理由を 1 行** |

`words` の 3 通り:

| 形式 | 1 行 | `words` |
|---|---|---|
| MV | 歌詞の 1 フレーズ | 歌詞（地図の行をそのまま。聴き取りの本文を使わない） |
| 説明もの | ナレーションの 1 文（§3 のビート表の 1 行を、文に割ったもの） | ナレーション。**句の切れ目が画面の出る順** |
| アニメ / 縦アニメ / ドラマ | 台詞 1 つ。モーションコミックは**漫画の 1 コマ** | 台詞（話者つき）。モーションコミックは吹き出しの文と擬音を分けて書く（どちらも絵に焼かない） |

- 説明ものは §3 のビート表（画 / ナレーション / 尺 / 音）に `motion` / `text` / `supply` の列を足す
  （別の文書を作らない）。
- シーンとカットへの写し方は各形式の節のまま（MV §2、説明もの §3、物語ものは scene-writing.md）。
  **字コンテの `supply` が同じ行はなるべく同じシーンに入れる**（シーンごとに作り方を 1 つ選ぶため）。
- 書いたら `director` に戻す。V コンを人に見せて承認を取るまで、本番の絵を描かせない。
