# 脚本と文字コンテ

## 1. 文書は版を積む（消さない）

```
put_document(spec)  # spec.doc_schema_id で形を宣言する
  script.v1          脚本（**タイムラインの中身**。単独では作れない）
  arc.v1             複数本にまたがる筋の設計（全体の筋 / 各本の役割 /
                     本の間の因果 / 伏線の回収先）
  storyboard.v1      文字コンテ
  character_sheet.v1 設定資料の文書
  series_bible.v1    シリーズ設定
```

**種類は 5 つで固定。増やさない。** `doc_schema_id` は「**読み方**」を表すもので
（脚本＝シーンと台詞の構造がある / 資料＝散文）、年表も用語集も美術設定も読み方は
同じ「シリーズ資料」である。ここに無い `doc_schema_id` を書くと、**その文書は
資料の目次に一度も載らない**（黙って無視される）。

**同じ種類の文書は何本でも作れる。** 具体性は `name` が持つ ——「企画書」「年表」
「文化・風俗」は `series_bible.v1` として並べる。**後工程が値を読むものは種類を持つ**:
用語と読み → `glossary.v1`（`{terms: [{term, reading, notes}]}`）、相関と呼称 →
`relationships.v1`（`{edges: [{from, to, label, address}]}`）、色と光・画風・禁則・音の基調 →
`style_guide.v1`（`{palette: {morning, dusk, night}, light, key, art_style, negative, sound}`）、
劇伴の発注表 → `music_menu.v1`（`{cues: [{code, mood, use}]}`）。どれも `text` に読める本文を添える。

### 標準の `name`（**揺らすと目次から引けなくなる**）

目次は名前でしか引けないので、`series_bible.v1` の `name` は下から選ぶ。

| `name` | 中身 | いつ |
|---|---|---|
| **企画書** | ログラインの 4 要素・ターゲット・売り（`genre-playbook` §2.5） | ① |
| **話数表** | 各話のねらい・あらすじ・引き（連作のとき） | ① |
| **世界のルール** | 技術水準・魔法・法・通貨・時代。**画面に出てよい物 / 出ない物** | ②a |
| **年表** / **文化・風俗** | 時系列 / 服装規範・食・建築様式 | ②a |
| **禁則** | 作品として描かない物・表現。全生成のネガティブ | ②a |
| **箱書き** | シーンの箱の列（§1.5）。**`composition_id` を渡す** | ③ |
| **香盤表** | 設定の洗い出しの結果（`art-director` §1.5） | ④' |

## 1.1 どの段に置くか（**別の段のものは読まれない**）

| 置き場所 | 指定 | 誰が読むか |
|---|---|---|
| プロジェクト共通 | `composition_id` を渡さない | **常に読まれる** |
| このタイムライン | `composition_id` | そのタイムラインの依頼だけ |

**第 5 話だけの設定をプロジェクト共通に置くと、第 1 話の依頼でも目次に並ぶ。**
逆にタイムラインへ置いたものは、別のタイムラインからは読めない。

## 1.2 脚本はタイムラインの中身（単独では作れない）

**先に `start_timeline` を呼ぶ。** タイムラインと空の脚本が**対で**でき、
名指し（`compositions.script_asset_id`）まで済んでいる。返ってきた
`script_asset_id` が「このタイムラインの脚本」なので、**新しく作らずそこに版を積む**
（`put_document(asset_id=…)`）。

`asset_id` を渡さずに `script.v1` を作ろうとすると**断られる**。そのまま作れて
しまうと、どこからも指されない稿がライブラリに残り、`read_script` は名指しされた側
（空の稿）を返して**成功する** —— `counts: 0` を見て「書式に乗っていない」と
誤読することになる。エラーが返ったら、先にタイムラインを作る。

**名前は 1 つ。** `start_timeline(name=…)` がタイムラインと脚本の両方の名前になり、
以後タイムラインを改名すると脚本も追従する（DB のトリガ）。脚本だけを改名しようと
すると断られる。

**タイムラインを消すと、その脚本も一緒に消える**（対なので）。
生成素材（動画・画像・BGM）は消えない。

## 1.3 資料が多いとき

目次に載るのは上限まで。載り切らないときはプロンプトにその旨が出るので、
**検索で辿る**（検索は目次より広く見る）。「目次に無い＝存在しない」ではない。

**tool 名は、どちらのエージェントとして動いているかで違う。** MCP（スタジオ・Slack・
ACP から）は **`get_document(asset_id)` / `search_assets`**、レーンの依頼
（`<scene_request>` の中）は `read_document(document_id)` / `search_documents(query)`。
**MCP には `search_documents` も `read_document` も無い**（呼ぶと弾かれる）。

- `asset_id` を**渡すと**その文書に新しい稿を積む。**渡さないと**新しい文書になる。
- 前の稿は消えない。`get_document(asset_id, version)` で任意の稿を読める
  （`version` 未指定は最新）。
- 直しの依頼が来たら、**新しい文書を作らずに版を積む**。作り直すと、
  シーンから張られた `storyboard_asset_id` が古い稿を指したままになる。

## 1.4 脚本の書式

アニメのシナリオは **柱（場所・時間）/ ト書き（動き・状況）/ セリフ（誰が何を）**
の 3 要素でできていて、**字コンテの受け皿とそのまま 1 対 1 で対応する**。

| シナリオ | `plan_scenes` の受け皿 |
|---|---|
| 柱 | `location` / `time_of_day` |
| ト書き | `note` |
| セリフ | `lines[{text, speaker_label, delivery}]` |

だから**この書式で書く**。散文で書くと字コンテを書くたびに抽出し直すことになり、
**抽出のたびに話者名や場所の呼び名が揺れる**。

```
.夜市・屋台前（夜）
ネオンの下、ユキが立ち止まる。足元に財布。
@ユキ
（小さく）……これ、僕のじゃない。
```

**そのまま書く。コードブロックで囲まない。** **秒数・カット割りは書かない**
（尺は字コンテの判断。二重管理になる）。記法の全文・伝統的な書き方・
`read_script` の読み直しは **[references/script-format.md](references/script-format.md)**。

## 1.5 ハコ書き（**本文より先に箱を並べる**）

**脚本を一発書きしない。** 工程は **企画 → プロット → ハコ書き → 初稿 → 決定稿**で、
**箱書きが構成の土台**（全工程の 2/3 を箱書きに使う脚本家もいる）。飛ばすと、
書いたあとに型（`genre-playbook` §1）を当てて「中間点が無い」と分かり、**全文の書き直し**になる。

**1 つの箱に書くのは 5 つ** —— 場所 / 時間帯 / 出る人 / **何が転じるか（1 行）** / 概算尺。

```
S3 夜市・路地（夜） / ユキ・屋台の主人 / 約 25 秒
    ユキは財布を返せない → 主人に押し返される（拒絶 −）
```

**転じることを書けない箱は、まだシーンになっていない**（references/scene-writing.md §4）。
本文はまだ書かない —— 箱を並べ終えてから本文に入る。

箱＝シーンの切れ目（1.場所 2.時間帯）なので **④ の字コンテがほぼ機械的に起こせ**、
**尺の見積もりが本文の前に出る**（§3.1）。直すのも全文ではなく箱の入れ替えで済む。

置き場所は `series_bible.v1`（`name`「箱書き」）に **`composition_id` を渡して**
そのタイムライン専用にする（§1.1）。3 段（大バコ / 中バコ / 小バコ）の割り方と
尺別の使い分けは **[references/script-format.md](references/script-format.md) §1**。

## 2. 文字コンテを書いて、シーンへ梱包する

```
1. read_script(composition_id)              # 脚本を柱・ト書き・セリフに分けて読む
2. put_document(storyboard.v1)              # ★ 文字コンテを書く（人が読む形）
3. plan_scenes(request)                     # カット列 → scenes + cuts を作る
4. set_scene_storyboard(scene_id, asset_id) # 2 の稿を、そのシーンの出自として繋ぐ
5. apply_scene_proposal(spec)               # ★ レーンへ置く（人は undo で戻せる）。
                                            #   「提案だけして」なら propose_scenes
```

### 2 を飛ばさない（`plan_scenes` の JSON を直接組まない）

脚本から `plan_scenes` の引数へ直行できてしまうが、**そうすると
人が読める形の文字コンテがどこにも生まれない**。効く所が 3 つある。

| 飛ばすと失うもの | 中身 |
|---|---|
| **人がレビューできる最後の地点** | 次に人が見るのは**課金済みの絵コンテ画像**になる。ここで直せば文字を直すだけで済む |
| **シーンの出自** | `set_scene_storyboard` に渡す稿が無い。あとから「このシーンは何から起こしたか」が辿れない |
| **書き落としの発見** | 4 列（下記）に並べると、`shot` と音の空欄がその場で見える |

**直しの依頼が来たら、この稿に版を積む**（新しい文書を作らない。§1.3）。

### 文字コンテの書式（**4 列**）

業界の字コンテと同じ 4 列で書く。**列は `plan_scenes` の受け皿とそのまま対応する。**

| 列 | 中身 | 受け皿 |
|---|---|---|
| **画・カメラ** | 何が映っているか（ト書き）＋ **寄りとカメラワーク** | `note` ＋ **`shot`** |
| **セリフ・ナレーション** | 誰が何を、どう言うか | `lines[{text, character_id / speaker_label, delivery}]` |
| **尺** | 秒（整数） | `duration_seconds` |
| **音** | BGM の出入り・効果音 | `note` の中に書く（§3.1） |

柱（場所・時間帯）はシーンの見出しに置き、各カットへ `location` / `time_of_day` として写す。

```
S3 夜市・路地（夜）

C09  4s  [medium shot, handheld follow]
     ユキが人混みを縫って走る。屋台の湯気が横切る。  ♪M3 in
     ユキ「待って……!」

C10  2s  [close-up, static]
     足が止まる。地面の財布に目が落ちる。
     （台詞なし）

C11  6s  [medium close-up, slow push in]
     ユキ、拾い上げて裏返す。名前が書いてある。  SE:遠くの太鼓
     ユキ（小さく）「……これ、僕のじゃない」
```

**字コンテの時点で、カットごとに要素（見た目も音も）の持ち主を 1 つ決める。** `note` / `shot` は生成の持ち分だけ、上の層は `上の層:`、音は `音:` の行へ（`ai-video-craft` の references/layer-ownership.md §2）。
**`（台詞なし）` を書き落とさない。** 台詞の無いカットは意図して置くもので
（references/scene-writing.md §11）、空欄にすると「書き忘れ」と区別が付かない。
**ただし歌唱カットには書かない。** 歌は台詞（`lines`）に入らないが、`（台詞なし）` は
そのまま生成の本文に入り「誰も声を出さない」と命じてしまう。歌唱カットのト書きには
`（歌唱: @Audio1）` と、誰が歌うかを書く（`ai-video-craft` の references/lip-sync.md §3）。

**`plan_scenes` はタイムラインに何も置かない。** シーンはタイムラインの持ち物で、
タイムラインへは「配置」される（`director` §0）。作ったまま黙っていると人からは
**何も起きていない**ように見えるので、`apply_scene_proposal` で置くまでを 1 続きにする
（`project_id` / `composition_id` / `scene_ids` / `at_seconds` / `track_index`。空きに
収まらなければ `mode` を `ripple` か `truncate` に）。「提案だけして」と頼まれたときだけ
`propose_scenes`（差し出すだけ。並べるか捨てるかは人がダイアログで決める）。

**自分で束ねない**（`bind_composition_variable`）。並べるか捨てるかは人が決める
（適用は画面側）。先に束ねると、断られた提案がタイムラインに残る。

> **レーンからの依頼（`<scene_request>`）ではこれを使わない。** あちらは
> `plan_scenes(..., scene_request_id=…)` で書いて `complete_scene_request` を呼ぶと、
> **画面がレーンへ置く**（`director` §0.2）。`propose_scenes` も `apply_scene_proposal` も
> 呼んでも断られる。

**シーンの切り目は次の順で決まる。**

1. **場所が変わる** — 背景が変わるので、1 パスで通しては生成できない
2. **時間帯が変わる** — 光が変わるので同上
3. **生成予算** — 1 シーンに詰められる尺には上限がある

1 と 2 が同じでも 3 で切れることはある。逆に、3 に余裕があるからといって
場所や時間帯をまたいで 1 シーンにまとめてはいけない。

`get_scene_budget(scene_id)` が「このシーンにもう 1 カット入るか」の判断材料を返す。
超過は DB が弾くので、詰めすぎたら `move_cut(cut_id, to_scene_id, order)` で
別シーンへ移す（これがシーン分割・統合の実体）。

## 2.5 物語もの以外の形式

| 形式 | 何が先か | 手順 |
|---|---|---|
| `footage_edit`（撮影済み） | **素材** | 文字起こし → 区間を選ぶ → `plan_footage_scenes` |
| `mv` | **曲** | 曲の地図（`write_music_map` + 歌詞の時刻）の `scene_plan` を、**`mv_check.py --sheet` の小節の表の上で**カットに割って `plan_scenes` に写す（拍・小節・区間・歌詞の行に合わせる。`mv_check.py` の所見 0 が完了条件） |
| `explainer`（説明もの） | **約束** | 企画書（誰に・何を約束するか）→ ビート表（役・主張・ナレーション・画・根拠）→ `plan_scenes`（1 ビート = 1 シーン） |

いずれも**シーンの切り方が物語ものと違う**（生成しない / 曲の区間が展開を決める /
約束と根拠の並びが決める）。§3.4（ビート分割と速度の規律）は**当てない**。

手順の全文は **[references/other-formats.md](references/other-formats.md)**。静止画を動かすシーン・3D のシーンが
入るとき（形式を問わない）は、割る前に**字コンテ**（時刻 / 区間 / 語り / 画 / 動き / 文字 / 作り方）を書く（同 §4）。

## 3. カットの粒度

### カットが持つもの

| 項目 | 何を書くか | 空にすると |
|---|---|---|
| `duration_seconds` | 尺（**整数秒**） | — （必須） |
| **`shot`** | **寄りとカメラ**。`medium close-up, slow push in` のように**英語で** | **動画生成の本文にカメラの指示が 1 つも載らない**（下記） |
| `note` | ト書き（誰が / **何をどうしている（芝居）** / 何が見えている / 光）＋ **音**（§3.1）。**そのまま動画モデルに届く**ので、編集の段取り（原曲の秒・編集枠・余白）と「〜を作らない」は書かない（`cinematographer` §1.1） | 絵コンテのコマに描くものが決まらない |
| `location` / `time_of_day` | 場と時間帯 | 生成に `@教室 / 夕` が載らず、参照画像のどれがこの場か決まらない |
| `lines` | 発話（§3.5。`set_cut_lines` で置く） | — |
| `material_asset_ids` | このカットに要る設定資料（§5-2） | 動画化キャンバスが骨組みだけになる |

**発話と登場を分ける。** 無言・後ろ姿・手元だけでも、制作側が人物を識別する必要が
あるなら `note` に登録済みの名前 / key・衣装・見えている特徴を書く。例えば
「ユキ (yuki)、制服、窓際の後ろ姿、無言。顔は見せない」。観客に正体を伏せる演出と、
内部で誰かを識別することは両立する。識別不要の群衆や人物のいない画にキャラを作らない。
人物シートが必要と判断したら、台詞の有無によらず該当衣装の確定素材を
`material_asset_ids` に含める。登場情報は参照選択の材料で、キャラシの使用義務ではない。

### **`shot` を空にしない**

`shot` は `note` や `location` と並んで **`scenes.gen_prompt`（動画生成の本文そのもの）**
に載る。

```
[C09] (4s) @夜市・路地 / 夜 medium shot, handheld follow ユキが人混みを縫って走る ユキ: "待って……!"
```

空だと**モデルが毎カット勝手に画角を決める**。症状は「全カットが似た寄りになる」
「隣のカットと繋がらない」で、**絵コンテを見るまで気づけない**。

- **何を選ぶか** … `film-grammar` §1（ショットサイズが何を伝えるか）と §7（隣り合う 2 カットの検査）
- **どう書くか** … `film-grammar` の references/shot-vocabulary.md。
  **日本語の用語（T.U / PAN / アオリ）をそのまま書かない** —— `shot` は
  加工されずにモデルへ渡るので、モデルが学習している英語のカメラ用語で書く

### カメラの演出は文字コンテの段階で決める

身体の揺れ・主観・空撮・FPV・複合軌道を扱うときは `film-grammar` の
**references/camera-design.md** §3 の記述例で `shot` と `note` に落とす。
`shot` はサイズ・視点・主要軌道・注視条件・必要な揺れを英語で、`note` は動機と
開始→経路→終了・きっかけ・音を記す。技法の定義は同 references/shot-vocabulary.md §3。
人が読む `storyboard.v1` とカットの両方を更新し、既存の4列を維持する。
絵コンテには描く瞬間を伝え、経路の検証はプリビズへ渡す。文字で指定した動きを
撮影時に省いたり、動きの途中を別カットに数えて絵コンテのコマを増やしたりしない。

### そのほか

- `create_cut(spec)` で足す。**in 点は渡さない**（in / out は導出値で保存されない）。
- **尺は整数秒**（`duration_seconds`）。動画生成モデルは全機種が整数秒刻みでしか
  尺を受け取らない（ほとんどは 1 秒、LTX 2.5 は 2 秒刻み）
  ため、0.5 秒のカットは作れない。短い刻みが欲しければ、そのぶんカットを減らす。
- 部分更新は `set_cut(cut_id, patch)`。`null` のフィールドは触らない。
- **台詞は `set_cut_lines(cut_id, lines)`**（カットの列ではない）。丸ごと置き換えるので、
  行の追加・削除・並べ替えを 1 回で表せる。空リストで全部消える。
- 1 カットは「カメラが切り替わらない一続き」。会話の切り返しは別カット。
- **`note` の動詞を 1 個で止めない。** 「食べる」「話す」「怒る」は出来事の要約で、
  そのまま投げると**箸を使わず手で食べる**映像が返る。小道具（何を、どちらの手で、
  どう持つか）／予備動作／主動作の 3 つは必ず書き、**日本の所作は明示する**
  （書かないと西洋の既定値が出る）→ **[references/acting-and-gestures.md](references/acting-and-gestures.md)**。
  **ト書きは観客に届かないので、厚く書いても害が無い**（台詞とは逆向きの規律）。
- カットには後で `storyboard` が絵コンテ画像を付け、`cinematographer` が
  `gen_prompt` を使って動かす。**このとき参照されるのはカットの記述なので、
  「誰が」「どこで」「何をしている」を各カットで自足させる**
  （前のカットを読まないと分からない書き方をしない）。

## 3.1 尺と音の決め方（**勘で置かない**）

```
台詞のあるカット = ceil( 台詞の総文字数 ÷ 5 + 0.5〜1 ) 秒   ← 日本語は 1 秒 ≒ 5 文字
台詞の無いカット = 画の情報量で決める（`film-grammar` §4）
音               = note に `♪M3 in` / `SE:…` と書く（字コンテの 4 列目）
```

**外すと 2 方向に壊れる。** 文字数に対して尺が足りなければ**早口で潰れ**、
余れば**間延びする**（生成モデルは尺を守るので、余った時間ぶん何かを動かす）。

**④ の終わりに合計を目標尺と突き合わせる。** `get_scene_budget` が返すのは
**1 シーンの生成予算**であって、作品の上映尺ではない。

話速の表・音に書くもの / 書かないもの・形式ごとの目標尺は
**[references/cut-timing.md](references/cut-timing.md)**。

**平均カット長も測る。** 生成尺（8〜10 秒）のまま置くと現代映画（3〜5 秒）の倍以上遅い。
`python3 <SKILL_DIR>/scripts/cut_pacing.py <list_cuts の JSON> --format <形式>`（帯と出典は同 §4）。
カットの**並び**（場所が変わって始まるシーンの頭がアップ・場所が変わったのに引きが無い・引きからアップへ直接・パンの反転・`shot` が空や日本語表記）は `python3 <SKILL_DIR>/scripts/shot_lint.py <list_cuts の JSON>`（根拠は `film-grammar` §1・§7）。

## 3.4 ビートに割り、速度を整える

> **適用範囲: 物語もの**（アニメ / ドラマ / 映画 / 縦型ショートドラマ）。
> **MV と撮影済み素材には当てない**（§2.5）。

**カットに「あらすじの要約」を書かない。** これが最も多い失敗で、そのまま絵コンテと
生成へ流れると、**見た人が話を追えない映像**になる。

```
❌ 1: A と B が言い争う   2: A が気づく   3: 二人は和解する
```

「言い争う」「気づく」「和解する」は**出来事ではなく出来事の要約**で、内側には
**行動と反応の往復（＝ビート）**が何回もある。飛ばしたぶんだけ伝わらなくなる。

### 手順（この順で書く。②と④を飛ばさない）

```
① このシーンで何が転じるかを 1 行で書く   例:「B は A を拒んでいた → 受け入れる」
② ビートを箇条書きで列挙する              「行動 → 反応」の往復。まだカットにしない
③ 圧縮語が残っていないか検査する          残っていたらそのビートを割る
④ 速度を整える                            下の 5 つ
⑤ 各ビートを 1 カットに割り当て、尺を配る  1 カット 1 ビート。**転換点はつなぎの 2 倍以上**
⑥ 各カットに情景を足す                    誰が / どこで / 何をしている / 何が見えている /
                                          光と時間帯 / **寄りとカメラ**（`shot`）
```

**②を飛ばして⑤へ行くと必ず要約になる。④を飛ばすと、ビートは足りているのに速い。**

### 圧縮語（見つけたら割り直す）

**和解する / 打ち解ける / 気づく / 理解する / 決意する / 対立する / 距離が縮まる /
絆が深まる / 惹かれ合う / 成長する / 葛藤する / 受け入れる**

**結果**であって**過程**ではない。過程を書くのが仕事。**1 シーンのビートは 3〜7**
（1〜2 なら転換が足りない。10 超ならシーンを割る）。内面（不安だ・怒っている）は
撮れないので行動に翻訳する（爪を噛む・静かに箸を置く）。

### 速度の 5 つ（**ビートを数えても検出できない**）

**ビートが 7 つあっても 1 つ 2 秒なら早い。** 上は数を、ここは**時間と因果**を縛る。
「展開が早い」「唐突」「急に仲直りした」と言われたら、まずこの 5 つを通す。

| # | 規律 | 一言でいうと |
|---|---|---|
| 1 | **一度で成功させない** | 1 回目の試みで手に入ると話は終わる。**試みは 3 回**（短尺 2 回）。各回を **「はい、しかし」**（手に入ったが代償が出た）か **「いいえ、そのうえ」**（手に入らず悪化した）で閉じ、**回ごとに前提が変わっていること** |
| 2 | **変わる前に揺り戻す** | 気づいただけでは変わらない。**変化の直前に「まだ変わっていない」ビートを 1 つ**置き、**代償を伴わせる** |
| 3 | **尺は山へ寄せる** | 情報量ではなく体験の長さで配る。**転換点はつなぎの 2 倍以上**。説明が長く山場が一瞬になるのが既定の失敗 |
| 4 | **間（ま）を置く** | **1 シーンに台詞の無いカットを最低 1 つ**。山の直前（タメ）／直後（**リアクション**）／出際 |
| 5 | **先に教えて、待たせる** | 隠して最後に明かすと**驚きは一瞬**。先に知らせると**同じ長さの会話が緊張として保つ**（カット数が増えない＝生成費が増えない） |

**この 5 つは尺で当て方が変わる**（短尺は作品全体で転換 1 回・間は音と動きを止めて作る・
待たせない / 長尺は副筋を編み込む）。尺ごとの表は **references/scene-writing.md §13**。
**短尺は `vertical-shortform` が優先**（尺が短いほど、視聴維持の制約が物語の作法より強い）。

機序・型と実例・提出前の **21 項目の検査**は
**[references/scene-writing.md](references/scene-writing.md)** が正本。

## 3.5 台詞は「誰が」とセットで書く

```
create_character(spec)            # 登場人物の実体。key / name / note / height_cm / 声の既定
list_characters(project_id)       # 既にいる登場人物（毎回作り直さない）
set_cut_lines(cut_id, lines)      # そのカットの発話を丸ごと置き換える
```

**量には下限がある。** `150 字/分` を割った稿は「静かな演出」ではなく**情報不足**で、
実際にこのスキルで 28 字/分 の無言劇を作って「どういう場面か分からない」と言われた。
**短い作品ほど言葉が要る**（縦型の現場は「ト書きで説明せず、セリフで説明しろ」と言う）。
量の式・冒頭 20 秒で立てる 4 点・呼称・説明の渡し方 14 技法は
**[references/dialogue-and-exposition.md](references/dialogue-and-exposition.md)**。
提出前に `python3 <SKILL_DIR>/scripts/dialogue_report.py <list_cuts の JSON>` で測る。

**話者の無い台詞は DB が弾く。** `character_id`（登録済み）か `speaker_label`
（ナレーション・モブ）のどちらかが要る。**読み上げでどの声を当てるか**（キャラは
`character_voices` にいま使う声を持つ）と、**生成モデルに誰の台詞か
伝えるため**（切り返しで喋る側が入れ替わっても、話者が無いと `gen_prompt` には
台詞しか載らない）。

**1 カットに複数の発話を置いてよい**（ナレーションに台詞が重なる構成は定型）。
会話の切り返しは別カットのままでよい — こちらは「同時に鳴る音」のための構造。

```jsonc
// set_cut_lines の lines
[
  { "character_id": "…", "text": "これ、いくら？", "delivery": "遠慮がちに" },
  { "speaker_label": "ナレーション", "text": "夜市は今日も賑わっていた" }
]
```

- `delivery` は**声への指示**。画への指示（ト書き）は `cuts.note` のまま。
- `text` に鉤括弧を入れない（付けるかどうかは表示側が決める）。
- **キャラクターの `key` はスロットの接頭辞と揃える**
  （`character.<key>.*` が立ち絵、`voice.<key>.*` が声）。揃えておくと、
  同じ人物の見た目と声を id で突き合わせられる。

## 3.5.1 登場人物には口調と身長を持たせる

**`characters.note` が空のまま台詞を書くと、書き手が同じである以上、全員が同じ
言い回しになる。** 作る時点で **一人称 / 語尾 / 敬語の距離 / 口癖 / 禁句**の 5 つを
`note` に書き、**`height_cm` も一緒に入れる**（身長比較表は全員分が揃わないと作れず、
欠けると複数人のカットで身長が入れ替わる）。役割語（「〜じゃ」「〜ですわ」）に逃げない。
→ **[references/characters.md](references/characters.md)**

## 3.6 構成の型（どこで何が起きるべきか）

脚本の起伏そのもの（15 ビート・ストーリーサークル・三幕構成・起承転結・短尺への
畳み方・連作の筋の割り振り）は `genre-playbook` の references/beat-sheets.md が正本。
**型は先に埋めるのではなく、書いたあとに当てて点検する** —— その「あと」が
ハコ書きの段（§1.5）で、本文を書く前に点検できる。「盛り上がらない」と言われたときは、
たいてい中間点の反転か最低点（すべてを失う）が抜けている。

## 4. 連作のとき

- タイムラインは `start_timeline(name, key?)`。番号は**名前に書く**（話数という
  概念は無い）。シーン名の前置きが要るなら `key='E01'` → `E01-S1`。
- 複数本にまたがって効く設定（世界観・キャラの口調・禁則）は `series_bible.v1` に置き、
  各話の脚本からはそれを前提にする。**各話の脚本に設定を書き写さない**
  （書き写すと必ずずれる）。

## 5. タイムラインのレーンからの依頼について

**レーンからの依頼は `<scene_request id="…" />` として発話に届く。** 位置（どの本編の
どのレーンの何秒か）と前後のシーンは `get_scene_request` でしか分からないので、必ず
最初に読む。書くときは `plan_scenes` に `scene_request_id` を渡し、書けたら
`complete_scene_request` を呼ぶ —— **そこで画面がレーンへ置く**ので、`propose_scenes` も
`apply_scene_proposal` も使わない。段取りの全体は `director` §0.2、設計は
`docs/designs/2026-09-03-lane-scene-request-agent.md`。

**どちらの経路でも守ること**（会話の中から `apply_scene_proposal` で置くときも同じ）:

1. **既にある素材を先に見る** — `search_assets` / `list_scenes` / `get_document`。
   世界観・キャラ・場所の呼び名は既存に合わせる（勝手に作り直さない）。
2. **文字コンテのまま**シーンとカットを作る。**動画は作らない**
   （`generate_scene` を呼ばない。ここは構成の相談であって生成ではない）。
3. **カットに `material_asset_ids` を付ける。** 1 で見た結果から、人物（無言の登場も含む）・背景・小物・様式・
   決まりごとの資料を id で指す。サーバが梱包先のシーンへ寄せて `scene_materials`
   に残し、**動画化キャンバスはそれを読んで盤面へ並べる**。

   付けないと盤面は骨組み（コンテ画・喋る人物・台詞）だけになる。**後から
   キャンバス側で推測し直す仕組みは無い**（開くたびに違うものが並ぶため、
   意図的に持たせていない）。

   選び方は**合うものだけ**。場所が違う / 時間帯が違う背景は、無いより悪い
   （盤面で正しいものの隣に並び、間違って生成へ渡る）。**隣のシーンと同じ場・
   同じ時間帯が続くなら、隣が使っている素材と同じものを指す**。

## 6. 終わったら

- 文字コンテが確定したら `art-director` に設定資料を、`storyboard` に絵コンテを渡す。
- シーンとカットが揃っていることを `list_scenes` / `list_cuts` で確かめる。
- **切り返し・人の移動・カメラの動き・位置関係が要になるシーン**は `previz` にレイアウトを
  頼む（`get_scene_budget` の `previz_recommended` が目安。要否の判断表は `previz` §0.2。
  プリビズを撮るシーンでは絵コンテを省けることがある）。**プリビズは文字コンテの後工程**で、
  ここが確定していないと作っても動画にできない。
