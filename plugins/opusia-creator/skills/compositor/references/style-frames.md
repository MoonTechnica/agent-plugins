# スタイルフレーム（HyperFrames で組んで 1 コマ撮る）

モーショングラフィックが画の主役の作品（イラストが主役の MV・説明もの・広告・短尺）で、
**本番を作る前に「どういう絵になるか」を人に見せて決める**ための手順。
生成 AI に「それっぽい絵」を描かせるのではなく、**本番と同じモーションのシーン（`create_previz_scene`。別の composition を作らない）を組み、`place_previz_clip` で置いて決めどころの
コマを静止画で撮る**。撮ったコマはそのまま完成の見た目になるので、承認した絵と仕上がりがずれない。
画像生成を使わないので費用はほぼかからない（撮るのは数秒）。

いつやるか: director の references/other-formats.md の **G1（企画のスタイルフレーム）** と
**G3（V コン）**。G1 は作品全体の見た目を 2〜3 枚で、G3 はモーショングラフィックで組むカットの絵コンテとして。

---

## 1. 何を撮るか

| どこで | 枚数 | 選ぶ瞬間 |
|---|---|---|
| G1（作品の見た目） | 2〜3 枚 | 一番派手な瞬間（サビ頭・タイトル）/ 一番静かな瞬間（A メロ・説明の地）/ 文字が主役の瞬間 |
| G3（カットの絵コンテ） | 図形・光・文字で組むカットに 1 枚ずつ | そのカットの**主役の動きが一番効いている瞬間**（伸びきった帯・光のピーク・文字の着地の直後） |

**決めるもの**: 色（ベースとアクセント）・帯や図形の角度と太さ・光の量と色・書体と文字の大きさ・
層の重なり（人物の前か後ろか）・画面の密度。**尺とタイミングは決めない**（それは V コンで音に乗せて見る）。

## 2. 組み方

- **本番と同じ書き方で組む**（[shape-motion.md](shape-motion.md) / [light-particles.md](light-particles.md) /
  [text-motion.md](text-motion.md) / [parallax-camera.md](parallax-camera.md)）。色・角度・強さは本番の値。
  ここで決めた値を本番でもそのまま使う。
- **絵はラフのままでよい**（G3 のラフ・G2 のキービジュアル）。本番の絵は G4 で描く。差し替えは変数（`data-var-src`）なので
  composition はそのまま使える。
- 動きは最後まで書かなくてよい。**撮る瞬間に正しい形になっていれば足りる**（その時刻に向かう tween だけ書く）。
- G1 の 2〜3 枚は 1 つのモーションのシーンに時刻をずらして並べてよい（0 秒・2 秒・4 秒に別の場面を置く）。**試作の尺が長くなっても、独立した composition に逃がさない**（本番へ持ち越せず、人が直せない）。

## 3. 撮り方

```bash
# 1. get_composition_bundle で本文と素材の署名 URL を手元へ（素材は 1 時間で切れる）
# 2. 撮りたい時刻を指定して撮る（--no-end で末尾のコマを足さない）
npx hyperframes snapshot <dir> --at 12.5,48.0 --no-end -o frames
#   → frames/frame-00-at-12.5s.png …（書き出しと同じ寸法）と contact-sheet.jpg（一覧）
```

- 撮る前に `npx hyperframes lint` を通す（lint の error があると本番で断られる。`gsap_css_transform_conflict` など）。
- 時刻は**シーンの頭からの相対ではなく、その composition の時刻**。
- 撮れたコマは自分で見る（`contact-sheet.jpg`）。文字が読めるか・主役が潰れていないか・光が白く飛んでいないか。
- 実測（HyperFrames 0.9.30、1920×1080）: 3 コマで約 4 秒。Google Fonts は `&display=block` で読み込めば撮る前に効いた。
  同じ絵を複数の場面に置くと lint が `duplicate_media_discovery_risk` の警告を出すが、スタイルフレームでは無害。

## 4. 渡し方

| どこへ | 道具 |
|---|---|
| カットの絵コンテ（G3） | `register_upload`（PNG を素材にする）→ `set_cut_board(cut_id, asset_id)`。Studio の絵コンテとプレビューにこのコマが出る |
| 企画のスタイルフレーム（G1） | `register_upload` → 企画の文書に asset を載せ、`report_work` で見てほしい点（色・角度・光・書体）を添えて承認を取る |

- **`set_cut_board` に貼ってよいのは `motion` のカットだけ。** `generate` のカットの絵コンテは
  **動画生成の先頭フレーム**になる（storyboard §1）ので、図形や文字の載ったコマを貼ると生成の入力が壊れる。
  `generate` のシーンの上に重ねる文字・光は、絵コンテではなく G1 のスタイルフレームで見せる。
- 直しが来たら値を直して撮り直し、同じカットに貼り直す（組んだ composition は捨てずに本番へ持ち越す）。

## 5. 落とし穴

| 症状 | 原因 | 対処 |
|---|---|---|
| 絵が空のまま撮れた | 素材の署名 URL が切れた / 変数が束ねていない | `get_composition_bundle` を取り直す / `list_composition_variables` で空枠を見る |
| 動いている途中の半端な形で撮れた | 撮る時刻が tween の途中 | 撮る時刻を tween の終わりの後に置く（`--at` は指定した瞬間を撮る。コマに丸めない） |
| 本番と色が違う | スタイルフレームだけ別の値で組んだ | 値は 1 か所（CSS 変数）に置き、本番もそれを使う |
| 文字が別の書体で撮れた | Web フォントの読み込み前に撮った | 文字は `document.fonts.ready` の後に組む（lyric-motion.md） |
