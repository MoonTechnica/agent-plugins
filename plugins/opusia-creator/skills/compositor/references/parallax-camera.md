# 背景のパララックスと仮想カメラ（2D / 2.5D）

層に分けた絵（前景 / 人物 / 中景 / 遠景 / 空）を、**仮想のカメラが動いたように**見せる書き方。
寄り・引き・横移動・Ken Burns・ドリーズーム・回り込み風・whip pan・揺れ・ピント送り・終わらない移動。
モーションのシーンの 2D レイヤー・カードの中身（[motion-scene.md](motion-scene.md)）でも本編の 1 カットでも同じ。
**検算は `scripts/parallax_plan.py`**（余白・拡大率・1 コマの速さ）。根拠と出典は
`docs/_research/2026-11-12-parallax-camera.md`。数値の多くは設計値で、書き出しでは実測していない（§9）。

---

## 0. どれで作るか

| 動き | 作り方 |
|---|---|
| 平行な層の寄り・引き・横移動・揺れ・ピント（ほとんどの MV のカット） | **§2 の 2D 展開**（層ごとの 2D の transform を 1 つの関数が毎コマ書く） |
| 層（カード）そのものを回す（回り込み・俯瞰・傾いた床） | CSS 3D（`3d-camera-flight` の型）。±10〜15° を超えて回すならプリビズ |
| 大きく回り込む・カメラが空間を飛ぶ・立体と 2D を混ぜる | **プリビズのカメラ + カード**（[illustration-mv.md](illustration-mv.md)、previz の camera-moves §8.9） |
| 本物の被写界深度（玉ボケ・前ボケの形） | Blender（[blender-by-hand.md](blender-by-hand.md)）で層を描き出して重ねる |
| 層に分けていない 1 枚の絵 | pan と寄りだけ（視差は出ない）。§5 の Ken Burns |

**2D 展開を既定にする理由**: CSS 3D は world と中間のラッパーに `filter` / `opacity < 1` / `overflow` /
`clip-path` / `mask` があると奥行きが潰れる。2D 展開なら層ごとにぼかし・霞・暗さを掛けられ、
縁の検査も層ごとの矩形で閉じる。画は CSS 3D と同じになる（§2.1 の式）。

## 1. 層の配り方（先に決める）

| 項目 | 目安 |
|---|---|
| 層の数 | **3〜5**（前景 / 人物 / 中景 / 遠景 / 空）。3 で奥行きは読める |
| 視差比 r（被写体 = 1.0 のときの動きの倍率） | **比で等間隔**: 2.0 / 1.0 / 0.5 / 0.25 / 0.1。z で等間隔にすると奥どうしの差が消える |
| 隣り合う層の r の比 | **1.5〜2.5 倍**。1.2 未満は 1 枚に見え、4 倍を超えると層の隙間（描いていない裏）が見える |
| 空・遠山 | r ≤ 0.1 か固定 |
| 被写体 | r = 1.0。カメラの移動量は被写体の平面の px で考える |

**書き割り（紙の切り抜きが並んだ見え）を避ける**: 層の中でも動かす（髪・服 = layer-rig、まばたき）・
大きな物は層を 2 枚に割る（手前の腕・机の縁）・遠い層ほどコントラストを下げて明るく青く（大気遠近）・
ピントで奥行きを足す（§4.4）・**カメラを完全に止めない**（§4.2 の呼吸）。

**描く側への注文**（art-director に渡す）: 層ごとに**手前ほど広く描かせる**（余白は r に比例して要る。§3）。
人物の切り抜きの背後は背景側に描き足しておく（前景を動かしたときの欠け）。

## 2. 式と骨格

### 2.1 式（P = `perspective` px、被写体の平面 z = 0）

```
層の距離           d = P / r                       (r を先に決めて d を出す)
寄り (dolly)       被写体を S 倍に寄せる: cam.z = P (1 − 1/S)
層の倍率           k = d / (d − cam.z)              (手前ほど大きく変わる)
層の移動倍率       s = P / (d − cam.z)              (= その時点の視差比)
画面上の点         q = zoom · R(roll) · (k · p − s · cam.xy)
```

- **1.5 倍の寄り（P=1000）で、遠景 r=0.25 は 1.09 倍、前景 r=2 は 3 倍に膨らむ。** 寄りのカットでは前景の r を
  1.3 前後に落とすか外す（すり抜けの演出なら逆に使う）。
- **レンズの zoom は全層一様**（遠近が変わらない）。dolly（cam.z）は遠近が変わる。「寄った」と感じさせたいのは dolly。
- **pan（向きを振る）は全層一様に流れ、視差は出ない。** truck（位置を動かす）が r 倍で流れる。

### 2.2 骨格（1 つの関数だけが transform を書く）

```html
<div class="pcam" style="position:absolute;inset:0;overflow:hidden">
  <div class="pcam-frame" style="position:absolute;inset:0">   <!-- 揺れ・roll・zoom は画面全体 -->
    <img class="pcam-layer" data-r="0.1" data-w="2000" data-h="1125" data-var-src="sky">
    <img class="pcam-layer" data-r="1.0" data-w="2240" data-h="1260" data-var-src="chara">
    <img class="pcam-layer" data-r="2.0" data-w="2560" data-h="1440" data-var-src="fg">
  </div>
</div>
```

```js
const P = 1000;
const cam = { x: 0, y: 0, S: 1, zoom: 1, roll: 0, rf: 1, dof: 0, shake: 0 };
const frame = root.querySelector(".pcam-frame");
const layers = [...root.querySelectorAll(".pcam-layer")].map((el) => {
  const r = +el.dataset.r, w = +el.dataset.w, h = +el.dataset.h;  // 寸法は宣言で持つ (読み込み前に決まる)
  Object.assign(el.style, { position: "absolute", left: "50%", top: "50%",
    width: `${w}px`, height: `${h}px`, transformOrigin: "0 0" });
  return { el, r, d: P / r, w, h };
});
function applyCamera(t) {
  const cz = P * (1 - 1 / cam.S);
  for (const L of layers) {
    const k = L.d / (L.d - cz), s = P / (L.d - cz);
    L.el.style.transform =
      `translate(${-s * cam.x - (k * L.w) / 2}px, ${-s * cam.y - (k * L.h) / 2}px) scale(${k})`;
    L.el.style.filter = cam.dof > 0 ? `blur(${Math.min(24, cam.dof * Math.abs(s - cam.rf))}px)` : "none";
  }
  const a = cam.shake;   // 揺れは全層まとめて (§4.3)。noise は t だけを入力にする
  frame.style.transform = `rotate(${cam.roll + a * 0.3 * noise(t, 3)}deg) scale(${cam.zoom}) ` +
    `translate(${a * 4 * noise(t, 1)}px, ${a * 3 * noise(t, 2)}px)`;
}
const tl = gsap.timeline({ paused: true, onUpdate: () => applyCamera(tl.time()) });
tl.to(cam, { S: 1.3, duration: 4, ease: "expoScale(1, 1.3, sine.inOut)" }, 0);
window.__timelines["<root の id>"] = tl;
```

- **GSAP は `cam` を tween し、DOM は `applyCamera` だけが書く**（1 lens / 1 state / 1 writer。`multi-phase-camera`）。
  サブ composition なら timeline の時刻はそのままその composition の時刻。
- 層の `<img>` は変数（`data-var-src`）で受ける（motion-scene.md §2）。**`will-change: transform` を付けない**
  （Chrome は付けた時点の倍率で固めて、寄っても滲んだままになる）。移動量を整数 px に丸めない（遅い pan が段々になる）。
- `expoScale` は EasePack（`gsap.registerPlugin(EasePack)`）。**倍率は線形補間しない**（寄りが終盤で止まりかけて見える）。
  dolly は cam.z ではなく**被写体の倍率 S を tween** する。

## 3. 縁を出さない・甘くしない・速すぎない（`parallax_plan.py`）

**動きを書いたら、書き出す前に必ず回す。** 動きの範囲と層の寸法を渡すと、層ごとに要る大きさ・足りない量・
元絵の拡大率・最速の 1 コマの移動量を返し、外れたものに所見を付ける。

```bash
python3 <SKILL_DIR>/scripts/parallax_plan.py --duration 4 --fps 24 \
  --x -120 120 --zoom 1 1.3 --roll 1 --shake 6 --ease sine \
  --layer sky:0.1:2000x1125:2000 --layer chara:1.0:2240x1260:2240 --layer fg:2.0:2560x1440:2560
# --layer は 名前:r:構図上の幅x高さ:元絵の横画素数。--json で機械可読
```

| 見るもの | 基準 | 外れたら |
|---|---|---|
| 余白（横移動） | 片側に「移動量 × r」が要る。**手前の層ほど要る** | 動きを減らす / 広く描かせ直す / r を下げる |
| 余白（引き・k < 1） | 構図 ÷ k_min | 引きの終点で全層を見る |
| 余白（傾き） | 1920×1080 を 2° で縦 +6%、1° でも +3%。**横長の傾きは縦を食う** | roll を減らす |
| 拡大率 g（1 原画素が何画面画素か） | **≤ 1.0**（塗りの柔らかい絵は ≤ 1.25、線画・文字の層は 1.0 厳守）。< 0.5 は縮小しすぎ | 元絵を大きく（アップスケール）/ 寄りを減らす |
| 最速の層の速さ | 1080p で **≤ 12 px/コマ**。12〜40 はジャダー（段々の残像）、40 以上は whip の速さ | 遅くする / ブラー / whip にして切る |

スクリプトは上限で見積もる。前景の草のように画面の一部だけ覆う層は、見えてはいけない辺だけ自分で確かめる。
最後は書き出したコマの動きの山と終点を見る。

## 4. 動かし方の作法

### 4.1 速さ・尺・ease

| 項目 | 目安 |
|---|---|
| 尺 | 拍で決める（速い 1〜2 拍 / 普通 1 小節 / ゆっくり 2〜4 小節。previz の camera-moves §7.5） |
| 寄りの量 | 見かけ +20% が「寄った」の下限。Ken Burns は 1 枚 5〜10 秒で +5〜15% |
| 着地の後の止め | 0.5〜1.5 秒（MV は 1〜2 拍） |
| ease | 寄り引き・横移動は `sine.inOut` / `power2.inOut`。サビ頭で強く止めるなら `power3.out`。**線形で始めない・止めない**。長い漂いだけ中央を等速に（`power1.inOut` を長尺で） |
| 2 チャネル | pan と寄りを同じ時刻・同じ ease にすると 1 本の動き。寄りを 0.2〜0.5 拍遅らせると「振り向いてから寄る」 |

### 4.2 呼吸（止めないカメラ）

長く持たせる静止画は、振幅 4〜12 px（被写体の平面）・周期 4〜8 秒の漂い（周波数比 ≈ 1.3 の Lissajous）＋
倍率 ±0.5〜1%を常に乗せる。**漂いも `cam.x` に足して視差比を通す**（奥行きが出る）。曲なら 2 小節で 1 往復。

### 4.3 揺れ（画面全体に掛ける）

手持ちの揺れはほぼ回転で、回転は視差を生まない。**層ごとではなく `.pcam-frame` に掛ける**（層ごとに掛けると
「画像がずれている」に見える）。オーバースキャンは `--shake` と `--roll` で見積もる。

| 種類 | 目安 |
|---|---|
| 手持ち | 2〜6 px、roll 0.1〜0.4°、主 0.3〜1 Hz + 2〜4 Hz を 2〜3 割 |
| 衝撃（着地・ドロップ） | 初期 15〜40 px、8〜15 Hz、**1 拍で 5% 以下に減衰**（τ = 拍 / 3）、倍率のパンチ +2〜4% |
| 低音の地鳴り | 1〜3 px、**fps/2 未満**（超えると折り返して遅い揺れに見える） |

```js
// 非整数比の正弦の和 (周期が見えない)。入力は timeline の時刻だけ
const noise = (t, seed) => 0.6 * Math.sin(2 * Math.PI * 0.47 * t + seed * 1.7)
  + 0.3 * Math.sin(2 * Math.PI * 1.13 * t + seed * 4.1) + 0.1 * Math.sin(2 * Math.PI * 2.71 * t + seed * 2.3);
// 衝撃: A * Math.exp(-(t - t0) / tau) * Math.sin(2 * Math.PI * f * (t - t0))  (x と y で f と位相をずらす)
```

強さは `cam.shake` を 0 → 1 → 0 に tween。**画面に張り付く歌詞・字幕は揺らさない**（一緒に揺らすなら 1/3 以下）。

### 4.4 ピント送り（rack focus）

ぼけは**視差比の差に比例**する: `blur = K · |r − r_focus|`（K ≈ 10 px）。`cam.rf` を人物 1.0 → 遠景 0.25 へ tween し、
`cam.dof = K` をその区間だけ立てる（それ以外は `filter: none`）。大きな面は ≤ 24 px、暗くすると少ないぼけで奥へ下がる。
行の頭の拍に合焦を着地させると歌詞へ視線を送れる。

## 5. レシピ

| 動き | 書き方 | 要点 |
|---|---|---|
| **寄り / 引き（2.5D）** | `tl.to(cam, { S: 1.3, ease: "expoScale(1, 1.3, sine.inOut)" })` | 寄りに roll 0.5〜1.5° か被写体の平面で 20〜60 px の横ずれを足すと「ズーム」でなく「近づくカメラ」。引きは k < 1 の余白 |
| **truck / pan** | truck は `cam.x`、pan は `.pcam-frame` の translate | 広い 1 枚絵の横断は「距離 ÷ 12 px/コマ」から尺を逆算。曲に対して長すぎたら 2 カットに割る |
| **Follow**（人物を画面に留め背景を流す） | 人物の層の r = 0（または `s − s_subject` で動かす） | 接地の影は人物の層に入れる（背景と一緒に流れると滑って見える） |
| **Ken Burns** | 1 枚に `S` と `x` を同じ区間・同じ ease で | **終点から逆算**（終点で主題が三分割の交点か中央）。寄りの中心を主題へ（`coordinate-target-zoom`）。寄り / 引き / 斜めを交互に。層に分けられるなら dolly にする |
| **ドリーズーム（めまい）** | 被写体の距離比 u に対し層の倍率 `k = u / (r·u + 1 − r)` を全層に | 引きながら寄る（u > 1）は背景が迫り、縮む層が無いので余白不要。前景は外す |
| **回り込み風** | 層の画面上の移動を `cam.x · (r − r_subject)` に | 被写体より奥は逆向き・手前は同じ向きに流れる（Disney のマルチプレーンの手）。本当に回すならカード ±10〜15° まで、それ以上はプリビズ |
| **whip pan** | 0.2〜0.35 秒、`power2.in` で振り出し → 最高速の瞬間（拍の上）で切る → `power2.out` で着地 | 中央の 2〜3 コマは画面幅の 20〜40%/コマ。ブラーは安い順に ①横に強くぼかした 1 枚に差し替え ②1/4 に縮めた複製をぼかして拡大 ③残像 ④SVG の方向ブラー（`motion-blur-streak`） |
| **終わらない横移動** | 継ぎ目の無いタイル 2 枚を `x = −((v · r · t) mod T)` | 左右反転の継ぎ目は模様が出るので遠景向き |
| **終わらない寄り（Droste）** | 画像 j を前の画像の中央に 1/q で描き、`scale_j = q^(u − j)`（u = t / 1 枚の秒） | 倍率が等比なので等速に見える。scale > 2 程度の画像は外す |

## 6. 曲に合わせる（イラスト MV）

キーの置き方の正本は previz の camera-moves §7.5（止まるキーは小節頭・動き出しは 1〜4 拍前・1 カット 1 軌道・
サビ頭で切る）。時刻は曲の地図の絶対秒からシーンの開始を引く。

| 区間 | カメラ |
|---|---|
| イントロ・A メロ | 呼吸 + ゆっくりの truck か寄り（2〜4 小節で 1 本） |
| B メロ | 寄りを少しずつ強め、終わりの 1 小節で速度を上げてサビ頭に着地か切り |
| サビ頭・ドロップ | 衝撃の揺れ（1 拍で減衰）か、whip の最高速を拍の上に置いて切る |
| サビ | カットごとに別の動き。速い寄り（1〜2 拍）・強い truck |
| 歌詞の行の頭 | ピント送りで歌詞か人物へ（1〜2 拍） |
| 間奏・ブリッジ | 長い横移動・終わらない移動・回り込み風（4〜8 小節で 1 本） |
| アウトロ | 引きで終止し、最後の小節頭で止めて切る |

**動かすより切る**: 余白・解像度を超える・途中で方向を変えたい・前景がジャダーの域・サビ頭で速度か方向が変わる、
のどれかなら切る（同じ絵の別の寄りへ）。

## 7. 重いもの（ソフトウェア描画の書き出し）

| 操作 | 重さ | 対処 |
|---|---|---|
| 画像への transform | 安〜中（画素数に比例） | 元絵を必要以上に大きくしない（g ≈ 0.8〜1.0 で足りる） |
| 大きな層への `filter: blur` | **高**（半径 × 面積） | ピントの区間だけ。大きな背景は縮小複製か事前ぼかし |
| 全画面の方向ブラー | **高** | whip は差し替え（§5） |
| `preserve-3d` の層を多数 | 中〜高 | 平行な層だけなら 2D 展開 |
| 巨大な透過 PNG の前景 | 中 | 画面の一部しか覆わないなら、その範囲だけの画像に |

## 8. 落とし穴

| 症状 | 原因 | 対処 |
|---|---|---|
| 動きの山で絵の縁・黒が出る | 手前の層の余白不足・引き・roll の縦・揺れの山 | `parallax_plan.py`。roll は縦を食う |
| 層の切れ目に描いていない裏 | 隣の r 比が大きすぎる・背後の描き足し無し | r 比 ≤ 2.5、背景の穴埋め |
| 寄りの終点で甘い | g > 1・`will-change: transform` | §3 / §2.2 |
| 前景が急に画面いっぱい・消える | dolly で前景がカメラに近づいた | 寄りのカットは前景の r を下げる・外す |
| CSS 3D にしたら奥行きが消えた | world・中間に filter / opacity / overflow / clip-path / mask | 2D 展開にする |
| 揺れが機械的 / 書き出すたびに違う | 1 本の正弦・整数比 / `Math.random`・前のコマからの積み上げ | §4.3 のノイズ。入力は時刻だけ |
| 歌詞が読めない | 文字が絵と一緒に動く・揺れる・ぼける | 文字はカメラの外（画面に張り付け。illustration-mv.md §6） |
| 酔う | 画面の大部分が速く横切る・揺れが長い・拍ごとに方向が変わる | 大きな層の速さを抑え、強い揺れは 1 拍で減衰。動画には reduced-motion が無いので作る側で抑える |

## 9. 実測していないこと

- 書き出しの重さ（ぼかし・巨大な画像・常時 `filter: blur(0)` の影響）と、縮小した画像が動くときのきらつき。
- 揺れ・Ken Burns・層の間隔・アニメの撮影の PAN 速度の一次出典の数値（ここの値は設計値）。

初めて使う組み合わせは、短く書き出して動きの山と終点のコマを見てから本番の尺にする。
