# 3D プリビズ（レイアウト）

## 0. 始める前に —— 字コンテ（`scenes` / `cuts`）が先

**プリビズは字コンテの後工程。** 本編の映像にするつもりなら、**字コンテが無いまま
場面を組み始めない**。好みの問題ではなく、**出口が塞がっている**:

| プリビズの出口 | 何が要るか |
|---|---|
| `generate_scene(scene_id=…, previz_asset_id=…)` | **字コンテのシーンの行**。プリビズ単体では投げられない |
| 生成の本文 | `scenes.gen_prompt`（無ければカット列から組まれる）。カメラと空間はプリビズが持つが、**「誰が・どこで・いつ・何をして・何を喋る」は字コンテしか持たない** |
| 生成の尺 | **カットの `duration_seconds` の合計**（`duration_ms` の上書きは拒否される） |
| 確定とレーンへの反映 | `set_scene_confirmed(scene_id, …)` |

**字コンテを飛ばすと、書き出した mp4 はそこで行き止まりになる。** 灰色の代役の動画が
1 本残るだけで、本編には 1 カットも入らない（費用だけが出る）。

### 0.1 手順

```
1. list_scenes(composition_id)   # 字コンテのシーンはあるか
     無ければ screenwriter へ戻す（plan_scenes → apply_scene_proposal）。
     **戻すほうが安い** —— 文字を直すのは無料で、書き出しは課金される
2. list_cuts(scene_id)           # key / duration_seconds / shot / note / 台詞を読む
3. create_previz_scene({ project_id, name, scene_id,
     cuts: [{ key: "C01", duration: 3, cut_id: "…", notes: shot の文 }, …] })
4. 以降は §3（床 → 人物 → カメラ → 動線 → probe）
```

**カット列は字コンテから写す。自分で割り直さない。** `key` に `C01` を、`duration` に
整数秒を、`cut_id` にそのカットを、`notes` に `shot` の文をそのまま入れる（カメラの位置
だけは文からは決まらないので、既定の 1 台が全カットへ複製されて出てくる）。割りを変えると
本編と尺が食い違い、確定したときにレーンのクリップと合わなくなる。

### 0.2 「グリッド絵コンテか、プリビズか」は字コンテを読んでから決める

撮影ゲート（`board_missing`）は**板（グリッド絵コンテ）かプリビズのどちらか一方**で通る。
どちらも全シーンに要るものではない。字コンテを読み、そのシーンで壊れやすいのが
**「空間と動き」ならプリビズ、「絵と顔」なら板**、両方なら両方を作る。**決めるのはシーンごと**で、
全シーンを先に表にして、同じ結論ばかりなら読み直す。**現場の標準は板で、プリビズはリスクのあるシーンに足す**（director の references/scene-method.md §0）。

まず `get_scene_budget(scene_id)` を引く。`layout`（`speakers` 話者数 / `exchanges` 切り返し /
`moving_cameras` カメラが動くカット / `close_ups` アップ）と目安 `previz_recommended` が返る。
**数えられるのは表の ★ の行だけ**。残りの行は字コンテを読んで自分で足す。

| 字コンテを読んで | 板 | プリビズ | ★ 数えられる |
|---|---|---|---|
| 1 人だけ / 立ち位置が動かない / 決め画・イメージカット | 要る | 要らない | — |
| 2 人以上の切り返し・視線の交換がある | 下記 | **切り返しだけでは足さない**（静かな会話は板だけ。他の行に当たるときに足す。180 度は字コンテと `film-grammar` で詰める） | `speakers ≥ 2` かつ `exchanges ≥ 1`（弱い目安） |
| カメラが大きく動く | 下記 | **要る**（動機のある移動・回り込み。寄り 1 回や軽い揺れは字コンテの文で足りる） | `moving_cameras ≥ 1`（数だけ。重さは読む） |
| 人物が移動する・すれ違う | 下記 | **要る** | — |
| 同じ場所を別の角度から何カットも見せる（空間の連続性） | 下記 | **要る** | —（`cut_count` は出るが角度は読む） |
| 身長差・大小・手前奥の位置関係が芝居の意味を持つ | 下記 | **要る**（身長どおりのカプセル。§3.2） | — |

**プリビズを撮るシーンで板を省いてよいのは、次のどちらにも当たらないとき。**
当たるなら板も作り、両方渡す（役割は補い合う。§6.2）。

- **アップが入る**（`close_ups ≥ 1`）—— 顔が画面を占めるカットの同一性は参照画像でしか
  支えられない。プリビズは見た目を持たない
- **人物が 3 人以上出る**（目安）—— 設定資料だけでは誰がどこに立つかの見分けが振れる

当たらないなら**板のためだけにシートを生成しない**（実際に要らないシートを 2 回捨てた）。板を作らないならマスター（絵コンテ用の静止画）も要らない。

### 0.3 字コンテに結ばないでよいとき

**人が「3D で当たりだけ見たい」と言ったとき**は `scene_id` を結ばずに作ってよい（習作。粒度は
変わらない。§3.0）。ただし**「動画まで」へ伸びた時点で字コンテに戻る**（上の出口が要る）。

## 1. この工程が決めるもの・決めないもの

業界の定義（VES 用語集）では previs は「仮想空間でショットの仮の版を作り、案を探り、段取りを
立て、同じ画を共有する協働工程」。**代役（proxy）で組み、質感と照明は持たない**（速く直せるから）。
うちの道具は **techvis**（実寸・機材の可否を実測で見る側）も兼ねるので、**寸法が実物どおり**が前提。

| | ここで決める | ここでは決めない（誰が決めるか） |
|---|---|---|
| 空間 | 立ち位置・動線・向き・**実寸** | 美術の質感・背景の絵（`art-director`） |
| カメラ | 位置・高さ・レンズ・画角・寄り引き | 実際の絵の質（本編の生成） |
| 時間 | カットの割り・尺・タイミング | 音・編集の仕上げ（`compositor`） |
| 繋がり | 180 度・30 度・画面方向を**数値で検算** | 繋がる条件そのもの（`film-grammar` が正本） |

**決めるのは「位置・向き・大きさ・タイミング」まで。** ここを外して光や質感を詰め始めると、
後段の生成が全部やり直す（プリビズの成果は捨てられる）。

| 持ち物 | 正本 |
|---|---|
| ノード・ライト・芝居のキー | `previz_scenes.doc`（`previz_scene.v1` の JSON） |
| カット列（カメラ・尺はここが持つ） | 同じ文書の `cuts[]`。**シーンの尺はカットの合計** |
| 書き出した mp4 | `renders` → 素材（`media_type = video`）。**書き出し直しは同じ素材の新しい版**（id は変わらない） |
| 置けるモデルと芝居 | `assets`（`media_type = model`）+ `list_model_assets` |

**タイムライン（`compositions`）とは別の概念**。あちらはトラックとクリップを持つ HTML が
正本で、こちらは JSON が正本。混ぜない。

## 2. 対象を取り違えない

### 2.1 発話に previz_scene の id ブロックがあるとき

**それが直す対象。作らない。** プリビズの画面から来た指示は、本文の末尾に開いている
シーンの id が機械可読ブロックとして必ず載っている:

```
もう半歩寄って

<previz_scene id="0193…" />
```

このときは `create_previz_scene` を呼ばず、**その id を `get_previz_scene` で読んで
`patch_previz_scene` で直す**。新しく作ると、人が見ている画面は変わらないまま別のシーンが
増える（本人には「効かなかった」ようにしか見えない）。

「もう半歩寄って」「向かい合わせにして」のような相対的な指示は、**いまの値を読んでから**
動かす（読まずに絶対値を書くと元の構図が壊れる）。

### 2.2 発話に attachments があるとき（掴んで渡された「これ」）

左のシーン一覧・ライブラリの項目に加えて、**いま置いてあるもの**（ドープシートの行 /
選んだものの見出し）も右の会話へドラッグして渡せる。渡されたものは末尾に載る:

```
このシーンと同じ画角で、アカネを右奥に立たせて

<previz_scene id="0193-A" />
<attachments>
- previz_scene id=0193-B name="屋台・引き"
- previz_node id=n_akane name="アカネ"
- character id=c-akane name="アカネ"
- asset id=a-knight media=model name="KayKit Knight.glb"
</attachments>
```

**対象（id ブロック）と参照（attachments の行）は別物。** 直すのは前者だけで、後者は
**読むために渡されたもの**。参照のシーンへ patch を当ててはいけない（人が見ていない
別の場面が黙って書き換わる）。

| 行 | 何を指すか | 引く道具 | 何をするか |
|---|---|---|---|
| `previz_scene` | **別の**シーン | `get_previz_scene` | 画角・立ち位置・ラインの参考に**読むだけ** |
| `previz_node` | **いま直しているシーンに置いてあるもの 1 つ** | 対象シーンの `nodes[]` | 「これを動かして」の**これ**。その id を patch する |
| `character` | 登場人物 | `list_characters` | **身長どおりの `capsule`** を置く（§3.2）。身長は id から引く |
| `asset`（`media=model`） | 3D モデル素材 | `list_model_assets` | `model` ノードとして置く（`references/models.md`） |
| `asset`（`media=image`） | 設定画・参考画 | `get_asset_preview` / `ask_gemini` | 構図や見た目の参考に見る |

**名前で当て直さない。** 渡された id をそのまま使う。同名・表記ゆれで別のものを拾っても
絵は普通に出るので、誰も間違いに気づけない。

`previz_node` が来たら、それが作業の対象。**patch のパスは添字**なので、`nodes[]` を引いて
その id が何番目かを**毎回数え直す**（ノードを足し引きすると番号がずれ、外すと隣の人物が動く）:

```jsonc
// nodes[2].id === "n_akane" だったとき
{ "op": "replace", "path": "/nodes/2/transform/t", "value": [1.4, 0.79, -0.6] }
```

`previz_node` が付いているのに本文がカメラの話（「もう半歩寄って」）をしているときは、
**そのノードを寄りの基準として読む** —— カットのカメラの `aim.node` にその id を入れ、
`fov` と `transform.t` で距離を決める。ノードを動かすとは限らない。

## 3. 組む

### 3.0 いくつ作るか（粒度）

| | 単位 |
|---|---|
| プリビズ 1 つ（`previz_scenes` の 1 行 = mp4 1 本） | **芝居 1 つ** —— 同じ場所で、続いた時間に起きること |
| その中の `cuts[]` | **その芝居の割り**（カメラと尺） |

**新しく作るのは芝居が切れるときだけ**（場所が変わる / 時間が飛ぶ / 別の芝居になる）。
字コンテがあるなら、その切れ目がここに一致する。`scene_id` を渡すかどうかで粒度は変わらない
（渡すのは「書き出した mp4 をそのシーンの動画として確定するか」だけの話）。

**アングルが変わるだけなら作らない。** 「3 カットで」と言われたら **1 つ作って `cuts[]` を 3 つ**。
3 つ作ると同じ芝居が枝分かれし、直すたびに食い違い、mp4 も 3 本に割れる。

### 3.1 手順（この順で書く）

実写の現場が **マスター**（全員が見える引きの通し）を撮ってから寄り・切り返しを足すのと
同じ順で組む。芝居は 1 組しか無いので、直しが常に 1 か所で済む。

```
0. list_scenes / list_cuts                    # ★ 字コンテを先に読む（§0。無ければ作らない）
1. list_previz_scenes / create_previz_scene   # scene_id と cuts を字コンテから写す
                                              # ※ 発話に id ブロックがあれば 0 と 1 を飛ばす（それが対象）
2. get_previz_scene                           # ★ rev を取る（取らずに保存すると必ず衝突する）
3. patch_previz_scene                         # 床とセット → 人物 → imaginary_line
4. patch_previz_scene                         # マスターのカット（引き）を 1 つ
5. patch_previz_scene                         # 芝居（keys）。シーン時刻で 1 回だけ書く
6. patch_previz_scene                         # 寄り・切り返しのカットを足す（カメラだけ増やす）
7. probe_previz_scene                         # ★ 構図を数値で確かめる（絵は出ない）
8. 6 と 7 を繰り返す
9. render_previz_scene                        # 動画まで頼まれたときだけ（課金される）
```

**まっさらから作るときは 3〜4 を `create_previz_scene` の `doc` にまとめてよい**（往復が減る。
`cuts` と `duration_seconds` の種だけ渡すこともできる）。**既にあるシーンを直すときは必ず patch。**

### 3.2 実寸で置く（★ ここを外すと工程ごと無意味になる）

単位は **m**、床は `plane` を `y = 0` に（水平に描かれるので回転は書かない）。
**すべての形は原点が中心**なので、床に載せるには高さの半分だけ持ち上げる。

人物は `capsule`。**`size.height` は円筒部だけ**で、全高は `height + 2 * radius`。
身長 H の人物を床に立たせる書き方は:

```
size.radius = r  (0.22〜0.30)      size.height = H - 2r      transform.t[1] = H / 2
```

**身長をそのまま `size.height` に入れると 2r（0.5m 前後）高くなる。** 絵は普通に出るので
誰も気づけないが、目線・カメラ高さ・寄り引き・背の順が全部ずれる —— **3D で先に潰すはずの
事故がそのまま残る**。身長は `character_id` から引く（発話に書かれた身長を信じない）。

机 0.70 / 椅子の座面 0.42 / カウンター 0.95 / ドア 2.00 / 天井 2.40（m）。
**寸法表・目線の高さ・部品を `group` にまとめる書き方は
[references/staging.md](references/staging.md)。**

**会話・対峙のシーンでは `imaginary_line` を必ず引く。** 引かないと probe の `lineFlips` が
**常に空**になり、検査していないのに合格に見える。

```jsonc
{ "op": "add", "path": "/imaginary_line", "value": ["n_akane", "n_master"] }
```

### 3.3 カメラ（カットが持つ）

**シーン直下に `camera` は無い。** パスは必ず `/cuts/<i>/camera/...`。

置き方は「誰を・どのくらいの寄りで・どのレンズで」から決める。距離は 1 式で出る:

```
距離(m) = 見せたい高さ(m) * 焦点距離(mm) / 24
```

（バスト = 胸から上 0.7m を 85mm で → 0.7 × 85 / 24 = **2.5m**。
ショットサイズの表・カメラ高さ・fov 換算は [references/lens.md](references/lens.md)）

`aim` に主役のノードを指定すると、動いても追い続ける。**カメラの高さと `aim.offset[1]` は
揃える**（食い違うと意図しないアオリ / フカンになる）。

```jsonc
{ "op": "replace", "path": "/cuts/0/camera/fov", "value": 28 }
{ "op": "replace", "path": "/cuts/1/camera/transform/t", "value": [-2.2, 1.6, -2.6] }
```

**1 つのカットの中でカメラを飛ばさない。** 切り返しはカットを足して割る（§3.5）。

**カメラを動かすなら [references/camera-moves.md](references/camera-moves.md) を開く（必ず）。**
既定は固定で、**動機 → 形 → 量 → 載せ物**の順に言えるカットだけ動かす: 動機（誰の何に
反応して / 何を見せるために）を `notes` に 1 文、形は「hold → 動き → 止めて見せる」か
「動いたまま切る」かを選ぶ、量は寄りなら距離の +20% 以上（標準 ×1.5）、載せ物（dolly /
crane / Steadicam）が言える軌道。**「カット頭で動き出しカット尻で止まる 2 キーの直線」を
既定にしない**（本番の全カットがこの形で、毎カット末で止まる違和感になった）。pan / tilt は
`aim` を外して `rotation` を書く。四元数・角速度・寄り量・円弧キー・レンズ換算・置き方（`place` / `capsule`）は `scripts/camera_math.py`、probe の読み取りは `scripts/probe_report.py`。

### 3.4 尺とキー

カットの `duration` は台詞と動きの秒数から決める（`/cuts/<i>/duration`）。
**シーンの尺はカットの合計**で、直下に尺は無い。

⚠️ **尺は `frame.fps` のフレームに乗せる。** 乗っていないと `cut_off_frame` で弾かれる
（24fps なら 1/24 = 0.0417 秒の倍数。3.5 秒 = 84 コマは可、3.1 秒は不可）。
迷ったら **0.5 秒刻み**にしておく（24 / 30 / 60 fps のどれでも乗る）。**音楽に合わせる作品では
尺を小節数で決め、カメラの止まるキーを小節頭に置く**（`references/camera-moves.md` §7.5）。

⚠️ **`frame.fps` に 12 を選ばない。** 文書のスキーマは許すが、**参照動画の受け口が
24〜60fps**（§6.2）なので、12fps で焼いたプリビズは**本編の生成へ渡せない**
（`generate_scene` が投入前に断る）。既定の 24 のままにしておくこと。

**時刻の基準がノードとカメラで違う**:

| どこのキーか | `t` の基準 |
|---|---|
| ノード（`nodes[].keys`） | **シーン時刻**（シーンの先頭が 0） |
| カメラ（`cuts[].camera.keys`） | **カット内時刻**（そのカットのイン点が 0） |

芝居はカットをまたいで続くのでシーン時刻、カメラはカットの持ち物なのでカット内時刻。
**カメラのキーにシーン時刻を書くと `key_after_duration` で弾かれる**（2 つ目以降のカットで
必ず尺の外に落ちる）。カットのイン点は「それより前のカットの尺の合計」。

**キーの書式（これ以外は通らない）**: トラックごとに `{ "t": 秒, "v": 値 }` の配列。
`time` / `value` でも `[t, x, y, z]` でもない。

```jsonc
// ノード（nodes[].keys）— トラックは translation / rotation / scale の 3 つだけ
"keys": {
  "translation": [
    { "t": 0,   "v": [0, 0, 0] },
    { "t": 2.5, "v": [3, 0, -1], "ease": "ease-in-out" }  // ease は任意
  ],
  "rotation": [{ "t": 0, "v": [0, 0, 0, 1] }],            // 四元数 [x, y, z, w]
  "scale":    [{ "t": 0, "v": [1, 1, 1] }]
}

// カメラ（cuts[].camera.keys）— translation / rotation / fov。t は**カット内時刻**
"keys": { "fov": [{ "t": 0, "v": 35 }, { "t": 3, "v": 24 }] }
```

- **`v` の形はトラックで決まる**: translation / scale は 3 要素、rotation は 4 要素（四元数）、
  fov は数値
- 時刻は**厳密に昇順**（同じ `t` を 2 つ置かない）。ノードはシーンの尺を、カメラは
  **そのカットの `duration`** を越えない
- 静止させたいノードに `keys` は要らない（`transform` がそのまま使われる）
- `ease` は `linear` / `step` / `ease-in` / `ease-out` / `ease-in-out`。**到達するキーの区間に
  効く**（終点に付ければそこで減速停止）。選び方は `references/camera-moves.md` §2
- 歩速の目安は 1.3 m/s、振り向きは 0.4〜0.8 秒（[references/staging.md](references/staging.md)）
- **書式を間違えると保存が拒まれる。** エラーは
  `nodes/0/keys/rotation/0: 't' is a required property` のように**場所と欠けている名前を指す**
  ので、総当たりせずそこだけ直す

### 3.5 切り返し・別アングル（カットを足す）

**同じシーンの中でカットを足して割る。** 芝居は 1 つ、カメラがカットの数だけある ——
実写で同じ芝居を何度か演じて別アングルから押さえ、編集で繋ぐのと同じ形。繋いだ結果が
**1 本の mp4**（シーン）になる。

```jsonc
{
  "op": "add",
  "path": "/cuts/-",
  "value": {
    "id": "c2",
    "key": "C02",
    "duration": 3.5,
    "camera": {
      "fov": 50,
      "transform": { "t": [-2.2, 1.6, -2.6], "euler_deg": [0, 210, 0], "s": [1, 1, 1] },
      "aim": { "node": "n_master", "offset": [0, 1.45, 0] }
    }
  }
}
```

守ること:

| # | 中身 |
|---|---|
| 1 | **芝居は書き直さない。** ノードのキーはシーン時刻なので、カットを足しても意味が変わらない |
| 2 | **カメラのキーはカット内時刻**（§3.4）。足したカットの `t` は 0 から数える |
| 3 | **カメラは線の同じ側に置く。** 足したら probe の `lineFlips` が空かを必ず確かめる |
| 4 | **同じ被写体を続けて撮るなら 30 度以上振る**か、サイズを 1 段変える（`references/framing.md` §4.2） |
| 5 | `id` はシーン内で一意（`c1` / `c2` …）。`key` は**字コンテのカット見出し**（`C01`）を写す。`cut_id` を書くと字コンテのカットと結ぶ。**独自に採番し直さない** |

2 人芝居のカメラ位置は 4 種類に整理できる（肩なめ / 内側リバース / パラレル / アペックス）。
座標の出し方は [references/staging.md](references/staging.md) §4。

> **カットを増やすほどシーンの尺は伸びる**（合計が尺、上限 120 秒）。参照動画の受け口は
> **30.2 秒まで**（§6.2）なので、超えるなら字コンテ側でシーンを割ってもらう。

### 3.6 意図を残す

`notes` に「なぜこの構図か」「ラインをどこに引いたか」「身長を仮に置いたか」を書く。
人が GUI で直すときの手掛かりになる（`previz_scene.v1` の唯一の自由文）。

## 4. 確かめる（`probe_previz_scene`）

**絵は見られない。** 書き出しは課金されるうえ数分かかるので、**必ず probe で確かめてから**
書き出す。時刻を省くと**各カットの始め・真ん中・終わり**を測る。

返りは `cuts[]`（カットごとに `in` / `out` と `samples`）と `lineFlips`。時刻はどちらも
**シーン時刻**。

| 返り | 読み方 |
|---|---|
| `ndc` | 画面座標。右が +x / 上が +y、`-1..1` が画面内。`null` は**カメラの後ろ** |
| `onscreen` | 画面に入っているか。主役が false なら構図が外れている |
| `distance` | カメラからの距離（m）。寄り引きの目安 |
| `imaginaryLine.cameraSide` | そのカットのカメラがラインのどちら側か |
| `lineFlips` | **隣り合うカットで側が入れ替わった組**。空でなければ 180 度をまたいでいる |

⚠️ **`ndc` はノードの原点＝形の中心**（人物なら腰のあたり）。顔でも足でもないので、
**そのままヘッドルームの判断に使えない**。頭頂・目線の ndc は換算して出す。

見る順序:

1. **主役は始めから終わりまで `onscreen` か**（動く場面ほど終わりで外れる）
2. **頭頂 / 目線 / 足元が枠のどこに来ているか**（ヘッドルーム・三分割・リードルーム）
3. **`lineFlips` が空か**（空でなければ `to` のカットのカメラを線の同じ側へ回す）。
   カット間の側の突き合わせを自分で外積して確かめない —— 道具が返す
4. **同じ被写体の連続カットで 30 度以上振れているか**
5. **`distance` が寄り引きの意図と合っているか**（寄りのはずが 8m 離れていないか）
6. **カメラが動くカットは `times` に動きの始点・中間・終点を渡して測る**（既定の 3 点は
   カットの時刻であって動きの時刻ではない。`references/camera-moves.md` §9）

**換算式・数値の合格範囲・症状別の直し方は
[references/framing.md](references/framing.md)。** 開かずに目分量で判断しない。

## 5. 保存の作法

- **人が開いているシーンは `patch_previz_scene`** で小さく直す。`put_previz_scene` は
  丸ごと上書きなので、人が同時に入れた変更を消してしまう
- `base_rev` は `get_previz_scene` で読んだ値。食い違えば拒まれる（**サーバはマージしない**）
  ので、そのときは読み直して当て直す
- 回転は `euler_deg: [x, y, z]`（度・XYZ 順）で書いてよい（**保存時にサーバが四元数へ畳む**）。
  ただし **`transform` を丸ごと置くときだけ** —— 既に `r` がある文書へ `/transform/euler_deg`
  を足すと「両方ある」で拒まれるので、向きだけ変えるときも `transform` ごと `replace` する
- `matrix` は無い。変換は TRS（`t` / `r` / `s`）だけ

## 6. 書き出し（`render_previz_scene`）

**頼まれてもいないのに押さない。** 依頼が「動画まで」のときだけ投げ、その前に
`get_render_prices` で見積もりを伝える（出力 1 分あたりで課金される。段は文書の frame の寸法と fps で決まる）。

- 既定の `quality` は `draft`。プリビズは確認用で、仕上げは本編が持つ
- 投げる前に**保存を済ませる**。保存していない編集は入らない
- 進捗は `get_render_status`
- 3D に 2D（歌詞・テロップ・写真）を重ねる確定は単独で書き出さず、`place_previz_clip` で層（参照）にする
- 被写界深度・グロー・厚みのある文字で仕上げるなら Blender で描く（`scripts/previz_sample.mjs` → compositor の references/blender-by-hand.md §7）。**動く 3D 文字（トンネル・散らし→集め・バウンス・円筒）は `references/kinetic-typography-3d.md` と `scripts/kinetic_3d.py`**

### 6.2 本番の動画へ渡す（**プリビズは見た目を持たない**）

書き出した mp4 は、そのシーンを本番生成するときの**参照動画**になる。これがプリビズの出口で、
ここを外すと作った意味が無い。

```
render_previz_scene → get_render_status → output_asset_id
  → cinematographer へ「このシーンのプリビズ。asset は <id>」と渡す
  → generate_scene(scene_id=…, previz_asset_id=<id>)   # 板は自動で添わる
```

**必ず `previz_asset_id` で渡す。** `media` に自分で `reference_video` として入れると
サーバが断る。`previz_asset_id` で渡したときだけ「これは灰色の代役で、カメラ・
立ち位置・カットの切り替わる時刻だけを取り、見た目は写すな」という前置きが付く。
これが無いと**代役の灰色と平らな光まで本番に写る**。

動画に一緒に届くもの（動画の入力は絵コンテ・字コンテ・音声だけ。`cinematographer` §0）:

| 何を | どこへ | 誰が | 要否 |
|---|---|---|---|
| グリッド絵コンテのシート | `reference_image`（先頭） | 自動（`bind_board_sheet` 済みなら） | **任意**（§0.2） |
| 文字コンテ（場所・時間帯・光・画・ト書き・台詞） | 本文 | 自動（`scenes.gen_prompt`） | 自動 |
| 人物の設定資料 | `reference_image` | `resolve_slot` で引く | **そのシーンに出る人物ぶんを必ず**（プリビズは見た目を持たない） |

**板は §0.2 の条件で決める**（アップが入る / 人物が 3 人以上なら残し、両方渡す）。
見た目（顔・衣装・光）は板が運ぶ。板を作らないシーンでは、人物・場所・光を
字コンテの言葉で書き切る。スタイルボードや背景のシートは動画に渡さない。

**マスターは動画の段には無い。** マスターは絵コンテを描くための静止画で
（`storyboard` §1.5）、板を作るならその前に描く。板を作らないシーンでは要らない。

**尺が合わないと分かったらここで言う。** プリビズで「3 秒では動きが入らない」と分かったら、
字コンテの `cuts.duration_seconds` を直してもらう（整数秒。プリビズ側で端数にしても本編へは
渡らない）。黙って自分の尺だけ伸ばさない。

**参照動画の受け口**（Seedance 2.5 の実測）: 1 本 **1.8〜30.2 秒**（合計も 30.2 秒まで）、
24〜60 FPS、辺 300〜6000 px・比 0.4〜2.5。**30 秒を超えるシーンは字コンテ側で割ってもらう**
（`screenwriter`）。プリビズを縮めて誤魔化さない。

**カメラは「そっくり」にはならない。** 軌道はよく追うがフレーム単位の一致ではなく、**3〜5 秒の
短い動きが最も安定**。だから作り込みすぎない —— 決めるのは位置・向き・大きさ・タイミングだけ（§1）。

## 7. やらないこと

- **モデル生成 AI を自分から使わない。** 人物はカプセルか、ライブラリのモデルで置く。
  「このキャラの見た目で」と人が言ったときだけ、見積もりを出してから生成する
  （[references/models.md](references/models.md)）。**構図を確かめるのに見た目は要らない**
- **絵づくりの質を 3D で詰めない。** 光も質感も本編の生成が決める（§1）
- **映像文法をここで作り直さない。** 尺のリズム・アクション繋ぎ・切り替えの意味・
  用語の英訳は `film-grammar` が正本。ここはそれを**数値で検算する側**
- **1 つのカットに詰め込まない。** 切り返し・別アングルは**同じシーンにカットを足して**割る
  （シーンを分けるのは**芝居が切れるとき**だけ。§3.0）
- **GLB での持ち出しは請け負わない。** Blender へ渡す GLB は**画面を開いている人だけ**が
  出せる（`GLTFExporter` はブラウザ専用）。「プリビズの画面 → 書き出し → 3D（GLB）」を案内する
