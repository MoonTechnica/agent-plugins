# 実寸で組む・立ち位置を決める（ブロッキング）

プリビズは **techvis の性質**を併せ持つ ——「そのカメラ高さで本当にその画になるか」を
先に確かめる工程なので、**代役の寸法が実物どおりでないと工程ごと無意味になる**。
灰色の箱でよいが、**寸法だけは正しく**。

単位は **m**、床は `plane` を `y = 0` に置く（水平に描かれるので回転は書かない）。
**すべての形（box / sphere / cylinder / capsule）は原点が中心**なので、床に載せるには
高さの半分だけ持ち上げる。

## 1. 人物の代役（★ ここを外すと全部ずれる）

`capsule` は three.js の `CapsuleGeometry(radius, height, …)` に渡され、
**`height` は円筒部だけ**（球の帽子は含まない）。したがって

```
全高 = size.height + 2 * size.radius
```

身長 **H** の人物を床（y = 0）に立たせる書き方:

```
size.radius  = r            # 0.22〜0.30（肩幅の半分ぶん。子どもは 0.18〜0.22）
size.height  = H - 2 * r    # ← 身長をそのまま入れない
transform.t  = [x, H / 2, z]
```

```jsonc
// 身長 1.58m のアカネ（r = 0.25）
{ "id": "n_akane", "kind": "capsule", "label": "アカネ", "character_id": "c-akane",
  "size": { "radius": 0.25, "height": 1.08 },
  "transform": { "t": [1.4, 0.79, -0.6], "euler_deg": [0, 180, 0], "s": [1, 1, 1] } }
```

**`size.height` に身長をそのまま入れると 2r（0.5m 前後）高くなる。**
絵は普通に出るので誰も気づけないが、目線・カメラ高さ・寄り引き・並んだときの背の順が
全部ずれる —— **3D で先に潰すはずの事故がそのまま残る**。

### 身長から出る値

| 何 | 式 | 1.7m のとき |
|---|---|---|
| **目の高さ** | H × 0.93 | 1.58m |
| 肩の高さ | H × 0.82 | 1.39m |
| 腰の高さ | H × 0.53 | 0.90m |
| 座ったときの目の高さ | 座面 + H × 0.48 | 0.42 + 0.82 = 1.24m |

**身長は `character_id` から引く**（`list_characters`）。発話に書かれた身長を信じない。
分からないときは大人 1.70 / 中高生 1.60 を仮に置き、`notes` に「仮」と書く。

**身長を揃えて置かない。** 並んだときに背の順が入れ替わる事故は絵コンテでは気づけず、
作画で初めて出る。ここで潰すのがこの工程の値打ちの半分。

## 2. セットの標準寸法（迷ったらこれ）

| もの | 寸法 (m) | 備考 |
|---|---|---|
| 机 / デスク（天板） | 高さ **0.70** | JIS の事務机の参考寸法 |
| ダイニングテーブル | 高さ 0.70〜0.72 | |
| 椅子の座面 | **0.40〜0.45** | 天板 0.70 と対で使う |
| バーカウンター天板 | **0.90〜1.00** | 合わせる椅子の座面は 0.60〜0.65 |
| キッチンカウンター | 0.85 | |
| ドア | 高さ **2.00** / 幅 0.80 | 開口の見た目に効く |
| 天井 | **2.40** | 住宅の主流（法の下限は 2.10） |
| 階段 | 蹴上 ≤ 0.23 / 踏面 ≥ 0.15 | 住宅の法定。目安は「蹴上×2 + 踏面 = 0.60」 |
| ベッド（シングル） | 0.97 × 1.95 / 高さ 0.45 | |
| 車（セダン） | 1.8 × 4.7 / 高さ 1.45 | |
| 教室の机 | 0.65 × 0.45 / 高さ 0.70 | |

**人が通る幅は 0.6m、すれ違うなら 1.2m。** 動線を引くときの下限。

## 3. 組む順序（マスターから割る）

実写の現場は **master shot**（全員が見える引きの通し）を土台に、そこから寄り・切り返しを
足していく。プリビズも同じ順で組むと直しが 1 か所で済む。

```
1. 床とセット（実寸）              # 場所の骨格。壁は要る面だけ
2. 人物を置く（実寸）              # 誰がどこに立ち、どちらを向くか
3. imaginary_line を引く           # ★ 引かないと 180 度の検査が動かない（§5）
4. マスターのカット（引き・アペックス）を 1 つ作る
5. 芝居（keys）を入れる            # 動線・振り向き。シーン時刻で 1 回だけ
6. 寄り・切り返しのカットを足す    # カメラだけ増やす。芝居は書き直さない
```

**芝居は 1 組しか無い**ので、5 を直すのは常に 1 か所。カットを足しても意味が変わらない。

## 4. 2 人芝居のカメラ位置（Katz の三角形）

2 人（A・B）の間に引いた線の**片側にだけ**カメラを置く。置き方は 4 種類に整理できる。

まず線に沿った基底を作る（XZ 平面だけで考える。高さは §1 の目線から）:

```
axis = normalize(B - A)                # A から B へ（y は 0 にする）
side = [-axis.z, 0, axis.x]            # 線に直交する向き。s = +1 / -1 でどちら側かを選ぶ
```

| 置き方 | 位置（目安） | `aim.node` | 画 |
|---|---|---|---|
| **アペックス**（マスター / 2S） | `(A+B)/2 + side*s*d` | 中点に置いた `group` | 2 人が入る引き |
| **外側リバース**（肩なめ・OTS） | `A - axis*0.7 + side*s*0.5` | **B** | 手前に A の肩、奥に B の顔 |
| **内側リバース**（単独） | `A + side*s*0.9` | **B** | B だけ。相手は写らない |
| **パラレル** | 2 台を線と平行に | 各人 | 関係が薄く見える。対立や断絶に |

**切り返しは同じ `s` のまま A と B を入れ替える。** `s` を反転させたらそれが 180 度越え。

> **中点を狙うには `group` を置く。** `aim` はノード id しか取れないので、2 ショットで
> 2 人の中間を狙いたいときは、中点に**部品を持たない `group`**（何も描かれない）を 1 つ置いて
> それを狙う。3D の現場で「ターゲット null」を置くのと同じ手で、`probe` にも
> そのノードの `ndc` が返るので中心が枠のどこに来ているか確かめられる。

**俳優の並べ方**にも型がある（Katz の I / A / L）:

| 型 | 並び | 向く先 |
|---|---|---|
| **I** | 一直線に向かい合う | 正面。対峙・対立 |
| **A** | 斜めに開いて立つ | 両方が少し客席側を向く。会話の既定 |
| **L** | 直角（片方が座る / 横を向く） | 視線が交わらない。気まずさ・上下関係 |

**A 型が既定**。I 型は正面同士で 2 人とも横顔になりやすく、L 型は視線が合わないので
意図があるときだけ。

## 5. `imaginary_line` は必ず引く（引かないと検査が黙って通る）

```jsonc
{ "op": "add", "path": "/imaginary_line", "value": ["n_akane", "n_master"] }
```

**`imaginary_line` が無いと `probe_previz_scene` の `lineFlips` は常に空**になる
（`cameraSide` が出ないので比べようがない）。**「空だから大丈夫」に見えるのに、
何も検査していない**という形で通ってしまう。会話・対峙のシーンでは最初に引くこと。

線はシーンに 1 組。3 人以上いる場面では**その時点で会話している 2 人**に引き、
組が変わるところでシーンを割るか、`notes` にどちらに引いたかを書く。

## 6. 動線と歩速

| 動き | 速さ | 4m 動くのにかかる尺 |
|---|---|---|
| ゆっくり歩く | 1.0 m/s | 4.0 秒 |
| **普通に歩く** | **1.3 m/s**（不動産の「徒歩 1 分 = 80m」と同じ） | 3.1 秒 |
| 早足 | 1.8 m/s | 2.2 秒 |
| 走る | 3.0〜4.0 m/s | 1.0〜1.3 秒 |

**尺を先に決めてから距離を決めない。** 字コンテのカット尺に対して歩く距離が長すぎると、
プリビズだけ不自然に速く歩く。合わないと分かったら**字コンテ側の尺を直してもらう**
（`screenwriter`）。

振り向きは **0.4〜0.8 秒**（`rotation` のキーを 2 つ。`ease: "ease-in-out"`）。
歩き出しと止まりには 0.2〜0.3 秒の余白を取る（キーを直線で繋ぐと機械的に見える）。
**これは人物の芝居の話。** カメラの `ease` は動きの終わり方で選ぶもので、全部に
`ease-in-out` を付けない（`references/camera-moves.md` §2）。

## 7. 部品で組むものは `group` にまとめる

飛行機・机と椅子・持ち物のように**複数の部品で 1 つのもの**を作るときは、`group` を 1 つ置き、
部品の `parent` にその id を書く。子の `transform` は**親から見た位置**（ローカル座標）。

```jsonc
{ "id": "ally", "kind": "group",
  "transform": { "t": [12, 400, -60], "euler_deg": [0, 15, 0], "s": [1, 1, 1] } },
{ "id": "ally_fus",  "kind": "box", "parent": "ally",
  "transform": { "t": [0, 0, 0],   "euler_deg": [0, 0, 0], "s": [1, 1, 1] }, "size": [1.6, 1.5, 15] },
{ "id": "ally_wing", "kind": "box", "parent": "ally",
  "transform": { "t": [0, -0.2, 1], "euler_deg": [0, 0, 0], "s": [1, 1, 1] }, "size": [11.5, 0.3, 3] }
```

平らに並べると 3 つ損をする（実際に機体 9 部品をルートに置いて起きた）:

- 1 機動かす / 傾けるたびに**部品の数だけ世界座標を計算し直す**
- 動きを付けるとき**部品の数だけキーを同期**させる（`group` なら親 1 つで済む）
- 形を直すとき触る場所が部品の数だけ増える

`parent` は**円環にしない**（`parent_cycle` で弾かれる）。深さは 2〜3 段で足りる。
