# 見た目の層（`render`）—— 3D で確定動画を作るシーンだけ

**プリビズの役割は変えない。** 動画生成の下敷き（構図・動線・カメラ）として使うプリビズには、
この層を**付けない**（灰色の代役のまま。見た目は字コンテと設定資料が運ぶ）。

この層を付けるのは、そのシーンの確定動画を**プリビズと同じ仕組み（three.js を時刻だけで描く）で
3D のまま作る**シーン —— シーンの作り方が `previz3d` のもの（`set_scene_supply`）。3D の文字・
ロゴ・製品の回り込み・3D の背景を飛ぶ・簡単な 3D のキャラの芝居。
設計: docs/designs/2026-11-11-motion-stills-and-3d-final.md §5。

## 1. 書き方

文書の最上位に `render` を足す（`patch_previz_scene`）。**全部任意**で、無ければ今と同じ絵。

```json
"render": {
  "look": "toon",
  "steps": 3,
  "outline": { "color": "#1b1d2a", "thickness": 0.003 },
  "frame_step": 2
}
```

| キー | 中身 | 既定 |
|---|---|---|
| `look` | `previz`（灰色の代役。今の見た目）/ `toon`（段の付いた陰。セル調）/ `flat`（陰の無い塗り。線画の塗り・モーショングラフィック向き） | `previz` |
| `steps` | `toon` の陰の段数（2〜5）。2 = くっきりした 2 階調、4〜5 = 柔らかい | 3 |
| `outline` | 輪郭線。`toon` は既定で黒（太さ 0.003）を引く。消すなら `false`。`previz` / `flat` は書いたときだけ引く | `toon` だけ黒 |
| `frame_step` | コマ打ち（`frame.fps` のコマで数える）。2 = 2 コマ打ち（アニメの 12 枚 / 秒の質感）。キャラの芝居は 2〜3、カメラだけ動くなら 1 | 1 |

- **色はノードの `color`**（代役の色）とモデルの材質の色・テクスチャを引き継ぐ。`toon` / `flat` に
  しても元の色のまま陰の付き方だけが変わる。
- 背景は `world.background`。`flat` の白背景に黒い輪郭線、`toon` の淡い地に濃い輪郭線、が読みやすい。
- **ポスト処理（`render.post`）**: グロー・色調・周辺減光。**書き出しだけに効く**（エディタの小窓には
  掛からないので、書き出して見る）。

  ```json
  "post": {
    "bloom": { "intensity": 1.0, "threshold": 0.8 },
    "color": { "brightness": 0, "contrast": 0.1, "saturation": 0.2, "hue": 0 },
    "vignette": { "darkness": 0.5, "offset": 0.5 }
  }
  ```

  | キー | 中身 |
  |---|---|
  | `bloom` | 明るい所がにじむ（`threshold` より明るい所だけ。`intensity` 0〜3）。夜・ネオン・光る物に。明るい地に掛けると全体が白くにじむ |
  | `color` | 明るさ・コントラスト・彩度（-1〜1、0 が元のまま）・色相（ラジアン） |
  | `vignette` | 周辺減光（`darkness` 0〜1） |

  時刻に依存する効果（ノイズ・明滅）は置けない（書き出すたびに絵が変わる）。
  暗い地に黒い輪郭線は見えない —— 地が暗いなら `outline.color` を明るくする。
- 光（`lights`）は `toon` の陰の段の位置を決める。キーライトの向きを 1 つ決め、`hemisphere` は弱めに。
- 書き出し（`render_previz_scene`）は既定で 2 倍に描いて縮める（GPU の無い書き出しでは
  アンチエイリアスが効かないため）。輪郭線の太さはこの 2 倍の後の画面に対する比率。

## 2. 画像の板と文字の板

3D の空間の中に写真・ロゴ・描いた背景・文字を置く（人物の奥の看板、空間に浮く歌詞、カメラが
回り込む製品名）。どちらも**立てた 1 枚**（原点は板の中心、+Z を向く）で、光を受けず、`toon` /
`flat` でも材質を変えず、輪郭線も引かない。位置・回転・大きさのキーと `visible` はほかのノードと同じ。

```json
{ "id": "sign", "kind": "image", "asset_id": "<画像の素材 id>", "width": 4,
  "transform": { "t": [0, 2, -3], "r": [0, 0, 0, 1], "s": [1, 1, 1] } }
{ "id": "lyric", "kind": "text", "text": "きみの声が\nまだ聞こえる", "font_size": 0.35,
  "font": "sans", "weight": 900, "align": "center", "color": "#ffffff",
  "transform": { "t": [0, 2.6, 1], "r": [0, 0, 0, 1], "s": [1, 1, 1] } }
```

| キー | 中身 |
|---|---|
| `image.width` | 板の幅（m）。高さは画像の縦横比から決まる。透過 PNG は透けて置ける |
| `text.font_size` | 1 文字の高さ（m）。行の間隔はその 1.25 倍。寸法は文字から決まる |
| `text.font` / `weight` | 3D の文字の板: `sans`（Noto Sans JP）/ `serif`（Noto Serif JP）、400 / 700 / 900。既定 `sans` の 700。**2D の文字レイヤーは `mincho` / `brush` / `heavy` / `hand` も選べる**（`motion-graphics.md`）|
| `text.align` / `color` | `left` / `center` / `right`（既定 `center`）。色は既定で白 |
| `text.depth` / `side_color` | **文字の厚み（m）と側面の色**。奥へ伸び、表の面は動かない。同じ字を奥へ重ねた板で出す（面取りは無い）ので、日本語でも書体を選ばず立体に見える。目安は字高の 0.1〜0.15 倍。省略 / 0 は平ら |

- 文字の板は**横組みで、語や行の単位**で置く。縦組み・1 字ずつの出入りは 2D で組んで**カード**（§2.1）に貼る。
  厚みは `depth`（上の表）。字が奥行き方向に散るトンネルは previz の references/kinetic-typography-3d.md。字幕のように
  画面に張り付いた文字は 3D に置かず、compositor が 2D で重ねる（`place_previz_clip`）。
- 板は裏からも見えるが、裏返った絵になる。カメラが回り込むなら板を `rotation` のキーで向け直す。
- 透明度のキーは無い。出し入れは `visible` と `scale` のキーで行う。

### 2.1 2D のカード（AE の 3D レイヤー。パペット・歌詞の組版を 3D に置く）

動く 2D —— パペットで揺らしたイラスト（compositor の layer-rig）・縦組みや 1 字ずつ動く歌詞・写真の
コラージュ —— を、この場面のカメラから見た位置に貼る。中身は composition の 2D のまま動き、カードは
その**置き場所**だけを持つ。画像の板・文字の板では作れない動き（揺れる髪、字ごとの出入り、縦組み）は全部これ。

```json
{ "id": "akane", "kind": "card", "card": "akane", "size": [2, 3],
  "transform": { "t": [-1.2, 1.5, -1], "r": [0, 0, 0, 1], "s": [1, 1, 1] } }
```

- `card` は composition の要素の `data-previz-card` と同じ名前（貼る相手）。1 つの要素は 1 枚のカードにだけ
- `size` は板の幅と高さ（m）。**要素の縦横比と揃える**（400×600 の rig なら 2×3）。ずれると引き伸ばされる
- 位置・回転・大きさのキーと `visible` はほかのノードと同じ（`keys.path: "smooth"` で弧を描かせられる）
- エディタでは半透明の枠だけが見える（中身は書き出しで重なる）。置き方と構図はエディタで決め、
  中身の動きは書き出した 1 コマで見る
- カードは 3D の物（モデル・板）より**いつも手前**に重なる（前後の隠し合いはしない）。人物の陰に隠したい
  2D はカードにせず、3D の層の下に置く（compositor の §9.3）
- 組み方（composition 側）は compositor の references/illustration-mv.md

## 3. 確かめる

- 見た目は `probe_previz_scene`（数値）では分からない。**書き出して 1 コマを見る**
  （`get_asset_preview`）。見るのは: 輪郭線が太すぎ / 細すぎないか、陰の段が汚くないか、
  コマ打ちで動きが飛びすぎていないか。
- エディタのカメラの視点（右下の小窓）も同じ見た目で描かれる。
- 重さ: GPU 無しの書き出しで 1 フレーム 0.3〜0.5 秒（オブジェクト 50〜400 個、worker 1 本。
  toon と輪郭線の上乗せは誤差の範囲）。シーン 1 本なら時間制限の心配は小さい
  （docs/_research/2026-11-11-previz-look-frame-time.md）。

## 4. やらないこと

- **動画生成の下敷きのプリビズに付けない**（生成の入力の見た目が変わる）。
- 動きに物理・乱数を使わない（コマ打ちも時刻の切り捨てで決まる。書き出すたびに同じ絵）。
- 被写界深度はまだ無い。VRM のキャラと VRMA の動きは [models.md](models.md) §6。
