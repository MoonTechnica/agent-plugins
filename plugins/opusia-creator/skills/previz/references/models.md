# モデル素材と芝居（棚から探す・設定画から起こす）

代役はカプセルで足りる（**構図を確かめるのに見た目は要らない**）。モデルを置くのは、
形がないと判断できないとき —— 乗り物・大道具・特徴的なシルエットのとき。

## 1. まず棚を見る（`list_model_assets`）

```
list_model_assets(project_id, name_contains?) → [{ id, name, clips[], bones }]
```

| 返り | 使い方 |
|---|---|
| `id` | `model` ノードの `asset_id` |
| `clips[].name` | `motion.clip` に書けるのは**この名前だけ** |
| `bones` | 0 か空なら**リグが無い**。`motion` を書いても動かない |

⚠️ **当てずっぽうのクリップ名を書かない。** 外れても書き出しは成功し、そのモデルが
**直立不動で映る**だけなので誰も気づけない。

```json
{
  "id": "n_knight", "kind": "model",
  "asset_id": "<… / rig の素材 id>",
  "transform": { "t": [0, 0, 0], "euler_deg": [0, 180, 0], "s": [1, 1, 1] },
  "motion": { "asset_id": "<… / clip 30 の素材 id>", "clip": "Casual_Walk" }
}
```

`… / rig` が本体、`… / clip <id>` が芝居（**1 クリップ = 1 GLB**）。
クリップ GLB は 1 本しか持たないのでプレイヤーが先頭を使う —— 名前が Meshy の採番
（`Armature|xxx|baselayer`）に化けていても、`clips[].name` をそのまま書けば動く。

**モデルの縮尺は素材そのものが持つ**（`size` を持たない）。実寸と食い違うときは
`transform.s` で合わせ、`notes` にその旨を書く。

## 2. 設定画から起こす（頼まれたときだけ・課金される）

**自分から始めない。** 人が「このキャラの見た目で出したい」と言ったときだけ。
プリビズ専用の tool は無く、`generate_asset` を 2 回この順で使う。
どちらも既存の素材（三面図・GLB）から作るので、**`model` の空ノードを
`create_canvas_nodes` で置き、`canvas_node_id` を渡す**（無いと tool が断る）。

| # | `task` / `model` | 渡すもの | 出てくるもの |
|---|---|---|---|
| 1 | `multiview_to_3d` / `tripo-h3.1` | 三面図を **`[前, 左, 後, 右]` の順**で `reference_image` に（前は必須、2〜4 枚） | 素の GLB 1 つ（**リグは無い**） |
| 2 | `rig_model_with_animations` / `meshy-rigging` | 1 の GLB を `source_model` に、`clip_ids` に芝居の id、`height_meters` に身長 | リグ済み本体 1 + **クリップごとに 1 つ**の GLB |

- **先に `estimate_asset_generation` で見積もりを伝える。** 1 体あたり約 $1.3
  （生成 $0.3 + リグ $0.2 + クリップ 1 本 $0.12）。**要るクリップだけ**頼む
- 2 の入力は**人型・手足が明瞭・テクスチャ済み**であること。満たさないと Meshy が断る
- 出来上がりは `list_model_assets` に出る
- **表情と指は出ない**（リグは 24 関節で顔骨・指骨が無い）。プリビズの対象外

## 3. 芝居のクリップ id（`clip_ids` に書く値）

Meshy Animation Library の id。範囲は **`0`〜`696`**、外すと fal が 422 を返す。
**1 回に 10 本まで。**

| 用途 | id | 名前 | いつ使うか |
|---|---|---|---|
| 立ち | `0` | Idle | 何もしていない待ち。**ほぼ必ず入れる** |
| 歩き | `30` | Casual_Walk | 移動。動線を引いたら要る |
| 走り | `14` | Run | 追う・逃げる |
| 左へ振り向く | `572` | Walk_Turn_Left | 切り返しの前後で向きが変わるとき |
| 右へ振り向く | `583` | Walk_Turn_Right | 同上 |
| 手を振る | `290` | Wave_One_Hand | 挨拶・呼びかけ |

**座り**は id が確定していない。要るなら fal のモデルページで探し、確かめてから
**このファイルを直す**（`core` 側には表を持たせていない。ここはデータであってコードではない）。

**id は改廃される。** 外れていたらこのファイルを直すのが正しい直し方。

## 4. 値段

クリップ 1 本 **$0.12**、リグ本体が **$0.20**。上の 6 本なら $0.20 + $0.72 = **$0.92**。
`estimate_asset_generation` も同じ数え方（`output_model` 1 + `output_clip` n）。

**要るぶんだけ頼む。** 10 本頼めば $1.40 になり、使わないクリップも棚に残る。

## 5. 骨について

リグは **24 関節**、Mixamo 系の名前（`mixamorig` 接頭辞なし）。**指と顔の骨は無い。**
リグ済み本体と各クリップのスケルトンは同一なので、リターゲットは要らない。

`name` に使える文字が狭い（空白と `[ ] . : /` が使えない）のは、three.js の
`PropertyBinding` の予約文字と GLB 内のボーン名参照が衝突するため。

## 6. VRM のキャラと VRMA の動き（3D で確定動画を作るシーン向け）

VRM（`.vrm`）は人型のキャラの 3D モデル、VRMA（`.vrma`）は VRM 用の動き。どちらも中身は GLB なので、
`.glb` と同じく素材として取り込み、`model` ノードとして置く。プリビズのプレイヤーが読み分ける。

| 手順 | 中身 |
|---|---|
| 1. 棚を見る | `list_model_assets` の `vrm.kind` が `character`（キャラ）/ `animation`（動き） |
| 2. **使えるかを見る** | キャラの `vrm.usable` が **false なら置かない**（モデル自身の利用条件で、法人の商用の映像に出せない。理由は `vrm.reason`）。書き出しも `license` の失敗で断られる。人に差し替えを頼む |
| 3. 置く | キャラを `model` ノードとして置き、動きは `motion.asset_id` に VRMA の素材 id。`motion.clip` は任意の名前でよい（VRMA の中の動きを 1 本使う） |
| 4. 見る | 書き出して 1 コマを見る（エディタのビューポートにも出る） |

- **材質は MToon（VRM のトゥーン）のまま**。見た目の層（`render.look`）は VRM の材質を差し替えない。
  輪郭線（`render.outline`）とポスト処理（`render.post`）は効く。
- **髪・服・アクセサリはモデルの作りどおりに動く**。プレイヤーは three-vrm の正規の更新
  （`vrm.update`）で、骨 → 視線 → 表情 → 拘束（袖・スカートなどが体についてくる）→ 揺れ
  （スプリングボーン）→ MToon の UV アニメの順に毎コマ更新する。
  - 揺れ方はモデルの設定（VRoid 等で付けたスプリングボーン・コライダー）で決まり、**文書では変えられない**。
    揺れすぎ・揺れなさすぎは人にモデルの設定を直してもらう。
  - 揺れは 0 秒から一定の刻み（24fps なら 1/72 秒）で計算するので、**何度書き出しても、並列で撮っても
    同じ揺れ**になる。エディタで時刻を戻すと 0 秒から計算し直すので、長いシーンでは戻すときに少し重い。
  - 揺れは動きに対して遅れて付く。カットの頭で急に姿勢が変わる VRMA は、最初の数コマで髪が大きく振れる。
    芝居の頭に 0.3〜0.5 秒の静止を入れるか、VRMA を静かな姿勢から始める。
- 同じ VRM を 2 体置いてよい（別の実体として読み直す）。
- **利用条件の判定**: VRM 1.0 は `commercialUsage = corporation` かつ `avatarPermission = everyone`、
  VRM 0.x は `commercialUssageName = Allow` かつ `allowedUserName = Everyone`。書いていない項目は
  許されていると見なさない。自作の VRM が通らないときは、作った人が VRoid 等で利用条件を書き直す。
- **生成で作るキャラの下敷きのプリビズには置かない**（プリビズの役割は変えない）。VRM を置くのは、
  そのシーンの確定動画を 3D のまま作るとき（作り方が `previz3d`）。
