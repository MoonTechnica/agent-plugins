# 構図を数値で確かめる（probe の読み方）

**エージェントは絵を見られない。** 書き出しは課金されるうえ数分かかるので、
`probe_previz_scene` が返す数値を構図の言葉へ翻訳して判断する。ここはその換算表。

## 0. probe が返すもの

```
cuts[]  … id / key / in / out（シーン時刻）と samples[]
  samples[] … time / camera{ position, forward, fov } / nodes[] / imaginaryLine
    nodes[]  … id / label / ndc / onscreen / distance / visible
lineFlips[] … 隣り合うカットでカメラが線の逆側へ回った組
```

| 値 | 意味 |
|---|---|
| `ndc` | 画面座標。**右が +x / 上が +y**、`-1..1` が画面内。`null` は**カメラの後ろ** |
| `onscreen` | 縦横とも ndc が −1〜+1 の内側。端ぎりぎりは「入っている」に含む |
| `distance` | カメラの前方向に沿った距離（m）。負ならカメラの後ろ |
| `visible` | 文書で `visible: false` なら映らない。構図の判断から外す |

⚠️ **`ndc` はノードの原点＝形の中心**。人物のカプセルなら**腰のあたり**であって、
顔でも足でもない。「`ndc.y` が 0 付近だから顔が真ん中」ではない。

⚠️ **`imaginary_line` を引いていないと `lineFlips` は常に空**になる。
検査していないのに合格に見えるので、会話・対峙の場面では必ず先に引く
（`references/staging.md` §5）。

## 1. ndc と実寸の換算（この 2 式で全部出る）

カメラの焦点距離を f（mm）、`aspect` = `frame.width / frame.height`、
被写体までの距離を d（m）とすると:

```
ndc の 1 目盛 = tan(fov/2) * d = (12 / f) * d   メートル（縦）

Δndc_y = Δy(m) * f / (12 * d)
Δndc_x = Δx(m) * f / (12 * d * aspect)
```

逆に「いま画面の縦に何 m 入っているか」は `24 * d / f`。

> **近似が効く条件**: カメラがほぼ水平のとき。強いアオリ / フカンでは崩れるので、
> そのときは §2 の**ヘッドノード**で正確に測る。

### 人物の各部の ndc（原点＝中心から測る）

身長 H の人物を正しく置いてある（原点が H/2）とき、probe が返した `ndc.y` を基準に:

| 部位 | 中心からの Δy | ndc.y |
|---|---|---|
| 頭頂 | +H/2 | `ndc.y + (H/2) * f / (12 d)` |
| 目線 | +0.43 H | `ndc.y + (0.43 H) * f / (12 d)` |
| 足元 | −H/2 | `ndc.y − (H/2) * f / (12 d)` |

（例: H=1.7 / f=85 / d=2.5 → 1 目盛 = 0.353m。頭頂は `ndc.y + 0.85/0.353` = `ndc.y + 2.41`。
つまりこの寄りでは**頭は必ず枠の外**。バストショットとして正しい）

## 2. 正確に測りたいときは「ヘッドノード」を置く

`group` は**部品を持たなければ何も描かれない**ので、狙い / 測定用の目印として置ける
（3D の現場で「ターゲット null」を置くのと同じ手）。人物の子にすると芝居に追従する。

```jsonc
{ "id": "n_akane_head", "kind": "group", "parent": "n_akane",
  "transform": { "t": [0, 0.79, 0], "euler_deg": [0, 0, 0], "s": [1, 1, 1] } }
```

- probe が**頭頂の `ndc` をそのまま**返す（近似も三角関数も要らない）
- `aim.node` に指定すれば**目線の高さを狙う**カメラになる
- `imaginary_line` の端点にも使える

**寄りのカットを作り込むときだけ置く。** 全員に付けると probe の返りが読みにくくなる。

## 3. 業界の構図規則 → 数値

| 規則 | 数値での言い方 |
|---|---|
| **主役が写っている** | 主役ノードが全 sample で `onscreen: true` |
| **ヘッドルーム**（頭上の余白） | 引き〜ミディアム: **頭頂の ndc.y が +0.75〜+0.95**。寄るほど詰め、CU では 1.0 を超えてよい（頭頂が切れる）。**+0.95 を超えて枠内**だと窮屈、**+0.6 未満**は死んだ空間 |
| **目線を上 1/3 に** | 目線の ndc.y ≈ **+0.33**（引きでは 0.2〜0.5 の幅で可） |
| **三分割** | 主役の ndc.x ≈ **±0.33**（中央に置きたい意図があるなら 0） |
| **リードルーム / ノーズルーム** | **人物は向いている側と反対に寄せる**。右を向いているなら ndc.x は **−0.2〜−0.5** |
| **足元** | 全身の画では 足元の ndc.y が **−0.85〜−0.95**（−1.0 に貼り付くと立っている地面が見えない） |
| **2 ショット** | 2 人の ndc.x が **反対符号**で、どちらも絶対値 0.7 以下 |
| **画面方向** | 同じ人物の ndc.x の符号が、隣り合うカットで**入れ替わっていない** |

**「切れてはいけない位置」で切らない。** 関節（首・肘・膝・足首）で枠が来ると
不自然に見える。上の頭頂 / 足元の値がちょうど 0 や ±1.0 付近に来ていたら、
サイズを 1 段動かす（`references/lens.md` §3）。

## 4. 隣り合うカットの検査

### 4.1 180 度（`lineFlips`）

**`lineFlips` が空でなければ跨いでいる。** `to` のカットのカメラを、`from` と同じ側へ回す
（`references/staging.md` §4 の `s` を揃える）。自分で外積を計算しない —— 道具が返す。

意図して跨ぐなら、`notes` に理由を書き、**跨ぐ瞬間を見せる**カットを挟む
（線上の正面カット / カメラが動いて越える / 人物が動いて線を引き直す）。

### 4.2 30 度ルール

同じ被写体を続けて撮るなら**カメラを 30 度以上振る**。probe の `camera.position` と、
被写体の世界座標 S（静止しているなら `transform.t`）から:

```
v1 = C1 - S, v2 = C2 - S     # y は 0 にする（床に落として測る）
θ  = acos( (v1·v2) / (|v1| |v2|) ) * 180 / π
```

**θ < 30 度なら繋がらない**（人物がピクッと飛ぶ）。振れないときは**サイズを 1 段以上**
変える（ミディアム → アップ）。中途半端に寄ると意図ではなく事故に見える。

### 4.3 寄り引きが意図どおりか

そのカットが実際にどのサイズになっているかは、probe の `distance` と `fov` から出る:

```
画面の縦(m) = 24 * distance / f      # f = 12 / tan(fov/2)
```

`references/lens.md` §3 の「見せたい高さ」と突き合わせる。
**隣り合うカットでこの値が ±20% 以内なら同じサイズ**とみなされるので、
30 度振れていないなら繋がらない（4.2）。

## 5. 手順（書き出す前に必ず通る）

```
1. probe_previz_scene（時刻を省く = 各カットの始め・真ん中・終わり）
2. python3 <SKILL_DIR>/scripts/probe_report.py <probe の JSON> --subject <主役>
   → 2〜5 をまとめて見る（式を手で解かない。§1 の換算と §3・§4 の規則）
2. 主役が全 sample で onscreen か             → false なら構図が外れている
3. 頭頂 / 目線 / 足元の ndc を出す（§1）       → §3 の範囲に入っているか
4. lineFlips が空か                            → 空でなければ §4.1
5. 同じ被写体の連続カットで θ ≥ 30 度か        → §4.2
6. distance が寄り引きの意図と合っているか     → §4.3（frame_height_m を読む）
7. 直したら 1 へ戻る（絵は出さない）
```

**動く場面では終わりが外れる。** 時刻を省いた既定は各カットの始め・真ん中・終わりを
測るので、まずそれで見る。動線が複雑なら `times` に 0.5 秒刻みを渡す（一度に 32 点まで）。

## 6. よくある外し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| `ndc` が `null` | 被写体がカメラの**後ろ** | カメラの向き（`aim` を付ける）か位置 |
| 主役が始めは入っていて終わりで外れる | 動線に対してカメラが固定 | `aim.node` を主役に。または `keys` でカメラを振る |
| 顔が切れていないか分からない | `ndc` を顔だと思っている | §1 の換算か §2 のヘッドノード |
| `lineFlips` が空なのに切り返しが繋がらない | **`imaginary_line` を引いていない** | 引く（`staging.md` §5） |
| 寄ったはずが変わらない | `fov` と `transform.t` を同時に動かした | どちらで寄るか決めてから（`lens.md` §5） |
| 2 人が重なる | 線に対してカメラが正面すぎる | `side` 方向へずらす（`staging.md` §4） |
| 見上げた画になってしまう | カメラ高さが相手の目線より低い | `身長 × 0.93` を基準に（`lens.md` §4） |

**繋がる条件そのもの**（なぜ 30 度なのか、尺のリズム、アクション繋ぎ、切り替えの意味）は
`film-grammar` が正本。ここはそれを**この道具の数値で確かめる**ためだけの表。
