# カメラの動き（camera movement）—— 動機 → 形 → 量 → 載せ物

## 1. 動機（なぜ動くか）を先に 1 文で書く

動機のある動きは見えない。動機の無い動きはそれ自体に目が行く。**動かすカットは
`notes` に「誰の・何に反応して / 何を見せるために / どう終わるか」を 1 文で書く**。
語彙の羅列（"medium shot, lateral tracking right"）は動機ではない。

| 動機 | 例 | カメラのキーの決め方 |
|---|---|---|
| **人物に付く**（character-driven） | 立つ → tilt up、歩く → truck、座る → tilt down | 人物ノードのキー時刻（シーン時刻）をカット内時刻へ直し、**0.1〜0.25 秒遅らせて**カメラのキーを置く（カメラは芝居に遅れて付く） |
| **情報を見せる**（reveal） | 机の手紙へ push in、柱の陰から人物が現れる truck | 見せたいものが画面に入った **0.3〜0.5 秒後に `ease-out` で止めて hold** |
| **感情を写す**（emotion-driven） | 告白で寄る、決意で引く | 被写体は動かないので `aim` を人物に固定し、`translation` だけ動かす |

**動機が言えないカット（切り返し・リアクション・対話）は固定が既定。** 動かすなら、その動機を
1 文で書けること。会話と表情の場面は「固定か、ごくゆっくりの push in」が定石。
無動機の動き（じっと立つ人物にカメラだけ寄る）は作り手のコメントで、**多用すると意味が薄れる**
（シーンに 1 回が目安。何を言いたいかが `notes` に書けるときだけ）。

## 2. 形とタイミング

### 2.1 `ease` は「到達するキー」の区間に効く

```
{ "t": 0.7, "v": A },                          // ← A で静止（前のキーと同じ値 = hold）
{ "t": 3.2, "v": B, "ease": "ease-in-out" }    // ← 0.7〜3.2 秒の区間に効く。B で減速停止
```

最後のキーの後は値が保持されるので、**終点の後に hold キーは要らない**。
hold は「同じ値のキーを 2 つ」で作る。

| `ease` | 動き | 使いどころ |
|---|---|---|
| `linear` | 等速 | **追い（Follow / tracking）**、動いたまま切るカット、arc の中間 |
| `ease-in` | 静止から加速 | きっかけで動き出し、**止めずにカット尻へ** |
| `ease-out` | 減速して収まる（settle） | reveal の終点、人物が止まった後の追いの停止 |
| `ease-in-out` | 加速 → 減速停止 | hold → 動き → hold の**自己完結した 1 動作**。**全カットに付けない** |
| `step` | 瞬間移動 | 使わない（カット内でカメラを飛ばさない） |

### 2.2 「カット頭で動き出し、カット尻で止まる」を既定にしない

実写のオペレーターは定速まで加速し、終わりのフレームへ減速して止める —— **ただし追いは
被写体が止まるまで止まらない**。そして編集はその動きを**どこで切るか**を選ぶ。
カットの尺と動きの尺は別物で、4 秒のカットなら動きは 2〜3 秒が普通。

終わり方は **2 択を意識して選ぶ**:

| 終わり方 | いつ | 終点の `ease` |
|---|---|---|
| **(a) 止めてから切る** | reveal。見せたものを観客が 1〜2 秒受け取る | `ease-out` / `ease-in-out` → 残りは hold |
| **(b) 動いたまま切る**（cut on movement） | 流れを切らない。追い。次カットが動きを受け継ぐ | `linear` / `ease-in`（止まる瞬間を入れない） |

**毎カット減速停止は (a) を全部に当てた状態**で、「カットの終わりで毎回止まる」違和感の正体。

```jsonc
// (A) reveal: hold → 動く → 止まって hold。duration 4
"translation": [
  { "t": 0,   "v": [0, 1.4, 3.0] },
  { "t": 0.7, "v": [0, 1.4, 3.0] },                           // きっかけまで hold
  { "t": 3.2, "v": [1.6, 1.4, 3.0], "ease": "ease-in-out" }   // 残り 0.8 秒は構図 2 で受け取る
]
// (B) cut on movement: きっかけで動き出し、動いたまま切る。duration 4
"translation": [
  { "t": 0,   "v": [0, 1.4, 3.0] },
  { "t": 0.5, "v": [0, 1.4, 3.0] },
  { "t": 4.0, "v": [2.2, 1.4, 3.0], "ease": "ease-in" }
]
// (C) 受け継ぎ: 前カットの動きを途中から拾って settle。duration 3
"translation": [
  { "t": 0,   "v": [0.8, 1.4, 3.0] },                         // 既に動いている位置から
  { "t": 1.4, "v": [1.6, 1.4, 3.0], "ease": "ease-out" }
]
```

**1 カットに主要軌道は 1 つ。** 単一軸の移動は意図的で目立ちにくい。無関係な動きを積まない。
身体由来の補助揺れや、Helix・Dronie の一貫した複合軌道は扱える（§8.6–8.8）。複合は
目的・注視点・終点を明記する。名前だけで成立したことにしない。

## 3. 量と速さ（「動かした」で満足しない）

| 項目 | 目安 | 検算 |
|---|---|---|
| **push in の量** | 見かけ **+20%**（距離 ÷ 1.2）が読める**下限**。標準は ×1.5（距離 ÷ 1.5）、**ショットサイズ一段**は距離 × 0.6（`lens.md` の段: バスト 2.5m → アップ 1.4m） | `push-in --distance D [--end E]` |
| じわ T.U（気づかせない寄り） | 長尺専用（『ゴッドファーザー』は 2 分半）。**4 秒のカットでやると何もしていないのと同じ** | — |
| **pan の角速度** | **画面幅 1 枚ぶんに 7 秒以上**（RED）。35mm で約 9°/s、50mm で 6.6°/s、85mm で 4°/s が上限。望遠ほど遅く | `pan-speed` |
| **追い（truck / follow）** | 人物と同速（歩き 1.3 m/s）。カメラは **0.1〜0.25 秒遅れる** | 人物キーを写す |
| **arc** | **1/4〜1/2 周**で軸が変わる。台詞ごとに 180° 回さない。キーは **15° 刻み**（lerp は弦なので粗いと距離が揺れる） | `arc` |
| **動き出しの遅れ** | きっかけの 0.1〜0.25 秒後（24fps で 2〜6 コマ） | — |
| **止めた後の受け取り** | 0.5〜1.5 秒。reveal は 1〜2 秒 | — |
| **crane** | 高さ 2.5m 超へ。場面の入りと終止に | — |
| **AI 生成へ渡す 1 カット** | **3〜8 秒**、動きの部分は 3〜5 秒（**MV のサビ・ドロップ・ダンスは 2〜3 秒**。`genre-playbook` の references/mv-dynamics.md） | — |

本番で実際に起きた外し方: push in が 4 秒で 0.2〜0.36m（被写体 2.4m。見かけ +9〜18%）。
カット間なら「ジャンプカット」と判定される量より小さく、**寄りとして読めない**。

## 4. 語彙 → 伝わるもの → 書き方

| 英 / 絵コンテ | 伝わるもの | JSON の書き方 |
|---|---|---|
| **push in / dolly in**（T.U） | 内面への接近。緊張・親密・気づき | `aim` を人物に、`translation` を被写体へ向かう直線上で。量は §3 |
| **pull back / dolly out**（T.B） | 孤立・状況の提示・終止 | 同上を逆向き。終止なら (b) 型で止めずに切る |
| **truck / tracking**（Follow・横） | 没入。人物に付いて空間を横断 | 人物の `translation` キーに一定のオフセットを足し、時刻を遅らせて写す。終点 `linear` |
| **follow**（後ろから付く） | 入場・探索・憑依。顔は見えない | 人物の動線の後ろ 1.5〜2.5m。`aim.offset` は背中の高さ。**会話には使わない** |
| **pan / tilt**（PAN） | 新しい情報・2 人の間の視線移動 / スケール・支配 | **`aim` を外して `rotation`**（§5）。`aim` があると回転キーは無視される |
| **whip pan**（Q.PAN） | カットの代わり。衝撃 | `rotation` を 0.2〜0.3 秒で。モーションブラーが無いので見た目は再現されない |
| **crane / boom** | スケール。場面の入りと出 | `translation` の y。`aim` が付いていれば見下ろしへ自然に移る |
| **arc / orbit** | 関係性がパララックスで書き換わる。対峙・包囲 | 中点の `group` を `aim` に、円周キー 15° 刻み（§9 の `arc`） |
| **dolly zoom** | 見当識を失わせる。恐怖・気づき | `d · tan(fov/2) = 一定`。`translation` と `fov` に同じ `t`・同じ `ease` |
| **zoom**（fov のみ） | 人工的。意図した違和感だけ | `fov` キー。**T.U を fov で代用しない**（遠近が変わらない） |
| **handheld / Steadicam** | 手持ちの臨場感 / 安定した移動 | 支持方式を選ぶ。必要な揺れは主要経路に合成して既存キーへ焼く（§8.7） |
| **static**（Fix） | 対話・表情 | **既定**。`keys` を書かない |

## 5. pan・tilt は `aim` を外して書く

`aim` はカメラを常にそのノードへ向ける**ロック**なので、付いている限り pan も tilt も
起きない（「tilt up」と注記して 0.2m 上げただけ、が本番で起きた）。2 通りある:

1. **`rotation` キーを書く**（`aim` を消す）。四元数は `camera_math.py look` で出す
   （ヨー → ピッチの順で水平を保つ。`transform.euler_deg` の XYZ 順で yaw と pitch を
   両方書くと**水平が傾く**ので、カメラの向きには使わない）。slerp は等角速度なので
   中間キーは要らない。角速度は `pan-speed` で検算する。
2. **狙いを動かす**: `aim.node` に部品を持たない `group` を置き、その `translation` に
   キーを打つ。カメラ本体は動かず、狙いが A から B へ移る = pan。2 人の間の視線移動に向く。

```jsonc
// 「立ち上がりに付いて tilt up」。人物の立ち上がり（シーン 6.0 秒・カット in 4.6 秒）の 0.15 秒後
"rotation": [
  { "t": 0,   "v": [-0.1305, 0, 0, 0.9914] },                 // look --pitch -15
  { "t": 1.55, "v": [-0.1305, 0, 0, 0.9914] },                // 立ち始めるまで hold
  { "t": 2.4, "v": [0, 0, 0, 1], "ease": "ease-in-out" }      // 立った顔へ
]
```

## 6. 高さとレンズは意味で選ぶ

| 高さ | 伝わるもの |
|---|---|
| 相手の目線（身長 × 0.93） | 中立。既定 |
| それより低い（アオリ） | 支配・威圧・大きさ |
| それより高い（フカン） | 無力・小ささ・客観 |
| 2.5m 超（crane） | 状況・スケール・終止 |

本番の 36 カットは高さ 1.1〜1.6m に集中していた。**シーンに 1 か所は高さを変える**
（頂点のアオリ、終止の俯瞰）。数値は `lens.md` §4。

**広角は奥行き方向の動きを誇張し、望遠は殺す。** push in / pull back / follow は 24〜35mm
側で効き、85mm 以上では同じ移動量が死ぬ。**原因はレンズではなく距離**: 画面上の大きさの変化率は
「カメラの速さ ÷ 被写体までの距離」で、広角は同じサイズを撮るために近づいているから速く見える。
**速度感が欲しいなら、まず被写体との距離を詰める**（広角はその結果として要る）。望遠で動きを感じさせるなら前景を横切らせる（§8）。
**動かすカットはレンズも一緒に決める。**

## 7. シーン全体の設計（平坦にしないために）

> **この節の既定（動かすのは 1/3 以下・移動カットは固定で区切る）は物語もの・MV の A メロ /
> ブリッジのもの。** MV のサビ・ドロップ・ダンス・大サビは逆に、**2/3 以上を動かし、カットごとに
> 別の動きを並べる**（`genre-playbook` の references/mv-dynamics.md §2）。抑制の既定をそこへ当てると
> 曲が跳ねているのに画が止まる。

1. **字コンテからシーンの感情曲線を 1 行で書く**（頂点はどのカットか）
2. **ショットサイズを頂点へ向けて段階的に寄せる**（ロング → フル → ウエスト → バスト → アップ。
   画面内の大きさは物語上の重要さに比例させる）。頂点の後に引き（T.B / crane up）で終止
3. **動かすカットを選ぶ**。目安は**全カットの 1/3 以下**。きっかけがある・見せたいものが
   画面外にある・頂点、のカットだけ
4. **同じ動きをシーンで繰り返さない**（push in を 3 回すると重要さが同じになる）
5. **隣り合うカットの関係を決める**: 動 → 静（受け止める）/ 静 → 動（弾みをつける）/
   動 → 動（前の動きを受け継ぐ。方向を揃えるか、意図して逆らう）。**移動カット同士は
   固定カットで区切る**のが既定
6. **動くカットは長め、固定の反応カットは短め**

作品のカメラの規則・シーンの視点・入りと出の型は `film-grammar` の references/scene-camera.md、
動くカット同士の繋ぎ（向きと速さを揃える・止め → 止めが既定）は同 references/cut-to-cut.md §1。

## 7.5 音楽に合わせる（MV・ダンス・BGM 主体）

作法の正本は `film-grammar` の `references/beat-sync.md`。カメラのキーで守ること:

- **拍に乗せると決めたカット（サビ・ドロップ・ダンス）では、止まるキーを小節頭（カット内時刻 =
  シーン時刻 − カットの in 点）に置き、動き出しをその 1〜4 拍前に**。動きの尺は拍数で決める
  （速い = 1〜2 拍、普通 = 1 小節、ゆっくり = 2〜4 小節）。**A メロ・ブリッジ・台詞のある区間では
  止まる位置を芝居や歌詞に合わせてよい**（全部が小節頭で止まると機械的になる）。カメラの止まりは
  拍から外れてよいが、**カットの切り替わりは拍の上**（`compositor` の `align_scene_cuts`）
- **1 カットの主要軌道は 1 つ。拍ごとに無関係な軌道へ切り替えない**。身体由来の補助揺れは§8.7。A メロ・ブリッジは 1 フレーズ
  （4 小節）に 1 回が目安、**サビはカットごとに別の動き**（mv-dynamics.md §2）。溜めは小節頭で収めるのが
  既定で、尻切れにするなら意図（不安・宙吊り）を `notes` に書く
- サビ頭・ドロップで速度か方向が変わるなら、**その時刻でカットを割る**（1 カット内で飛ばさない）
- **キーの `t` は小数でよい**（コマに乗せる必要があるのはカットの `duration` だけ）。
  拍の時刻は `区間の start_sec + k × 60 / BPM` を絶対時刻で求めてから in 点を引く。
  毎拍コマへ丸めて足し込まない
- 生成モデルはプリビズのカメラを「軌道は追うがフレーム単位では一致しない」ので、拍への
  厳密な吸着はタイムライン（`compositor`）に任せる。ここで決めるのは**どの小節で動き、
  どの小節頭で止まるか**まで

## 8. 3D でしか確かめられないことに動きを使う

板（グリッド絵コンテ）で渡せるものにカメラ移動を足さない。動かすなら、**動いて初めて
見えるもの**を置く:

- **パララックス**: 前景ノード（柱・机・通行人）をカメラと被写体の間に置き、truck / arc で
  横切らせる。前景の無い truck は pan と区別がつかない
- **遮蔽からの reveal**: 陰の人物が `probe` の `ndc` で画面に入る時刻を調べ、その 0.3〜0.5 秒後に止める
- **ドア・通路を抜ける follow**: 空間の連続性を 1 カットで保証する
- **高さの変化の途中経過**: crane の間に何が見え、いつ人物が小さくなるか
- **2 人の周りの orbit**: イマジナリーラインを**連続的に跨ぐ唯一の合法的な手段**。跨いだ後の
  カットは新しい側から撮る（`imaginaryLine.cameraSide` で確認）
- **長回しの追従**: 歩速・動線・距離が同時に成立するか

**写実の撮影では物理的に成立する経路にする**。床より下へ行かない、壁・机・人物を
貫通しない。**載せ物（dolly / crane / Steadicam / 手持ち / drone / FPV）を `notes` に書く**。
明示的に非現実の仮想カメラを求められた場合は、その意図を残して設計する。

## 8.5 1 カットで構図を作り直す・長回し・主観の度合い

出典は `docs/_research/2026-10-03-camera-work-techniques.md` Part 1（Spielberg の oner の分析・1917 /
Children of Men / Birdman の AC 誌記事・Film Art・Mascelli ほか）。

**動くカットは「開始構図・経路・終了構図」の 3 つ組で `notes` に書く。** 開始と終了は**どちらも止め絵として
成立する構図**にする（途中で切られても、前後のカットに繋がる）。

| 状況 | 決め方 |
|---|---|
| 1 カットの中で構図を変えたい | **まず人物を動かす**（カメラへ近づく・離れる・奥へ行く）。カメラは整え直す程度に動かす（Spielberg の oner）。人物ノードのキーを先に打ち、カメラはそれに従わせる |
| 通過点に構図を置く（1 カットで複数の画） | 各通過点を**独立した 1 カットとして成立**させる（Children of Men「すべてのショットがそれ自体で 1 ショット」）。`probe` を通過点の時刻でも取る |
| 人物を追う | 人物を画面内で**後退させない**（前方へ出そうなら出す。連れ戻すパンをしない）。**カメラの減速は人物の減速に従属**させる（人物より先に止まらない・人物が止まったら動き続けない） |
| カメラが追いつけない・回り込めない地点 | 人物に**理由のある足止め**（振り向く・誰かに声を掛ける）を置く（『グッドフェローズ』のコパカバーナはドアマンへのチップ）。その芝居が人物に合うかを確かめる |
| 動きの前後の静止 | 静止を撮るか、動いている最中で始まり終わるかを決める。後者なら前後のカットと向き・速さを繋ぐ（`film-grammar` の references/cut-to-cut.md §1） |
| 望遠で横に動く | 近景を手前に置いて横切らせる。置けないなら望遠で動かさない（§8 のパララックス） |

**長回し**（1 カットで長く持たせる）は、**「途切れなさ」が何を意味するかを 1 文で書けるときだけ**
（実時間 / 逃げ場の無さ / そこにいる感覚 / サスペンス）。書けないなら割る。書けるなら:

- **場所の寸法とタイミングをショットに合わせてから**カメラを置く（『1917』は塹壕の長さを台詞の長さに合わせて測った）
- **レンズは 1 本に固定**し、例外は場所の性格で決める（『1917』は 40mm 主体、狭い所は 35mm）
- 生成の 1 回の尺には上限があるので、プリビズで通しの軌道を作ってから、**隠れた継ぎ目**（前景で塞ぐ・暗部へ寄る）で
  割る位置を決める（`ai-video-craft` の references/seams.md §4・§5）

**主観の度合いは POV の有無ではなく、カメラが誰の動きに同期しているかで決まる。**

| 狙い | カメラ |
|---|---|
| 主観寄り | 人物の速度と向きにカメラを同期させる（同行）。POV は使わなくてよい |
| 観察者に留める | 人物の目の位置に入らない。固定・引き |
| POV を使う | 見ている人物の顔のカットで前後を挟み、短くする |

**高さと角度は別の変数。** 低い位置から水平（子供・地面の世界）と、目の高さから見上げる（支配）は意味が違う。
`transform.t[1]`（高さ）と `aim`（角度）を別々に決める。ダッチ（傾き）や極端なアングルは**場面に 1〜数回**まで、
先に水平・目の高さの基準ショットを見せてから使う。ハイ / ローは意味だけでなく実用でも選ぶ（地理と奥の動作を
見せる → ハイ、背景から人物を切り離す → ロー）。クロースアップは原則目の高さ。

## 8.6 Orbit・向き固定の円周移動・Pan / Tilt / Roll

文字コンテの `shot` / `note` を読み、**位置の経路と向きの制御を分ける**。
定義は `film-grammar` の references/shot-vocabulary.md §3、選択は同 references/camera-design.md。

| 指示 | プリビズへの落とし方 |
|---|---|
| Orbit / Arc（被写体を見続ける） | `translation` に円弧。中心のノードを `aim.node` に指定。対象が動くなら注視点と円の中心の移動を別に考える |
| Circular Dolly（世界座標で向きを固定） | 同じ円弧の `translation`、`aim` は削除、`transform.r` は一定、古い `keys.rotation` も削除。遠くの固定点への aim では向きが変わるので代用しない |
| Pan / Tilt | `translation` を一定、`aim` を削除、`rotation` に yaw / pitch のキー。対象から対象へ向ける用途は既存の動く aim ノードでもよい |
| Roll / FPV のバンク | `aim` を削除。yaw / pitch で視線を決めた後にローカル視線軸まわりの roll を合成。`camera_math.py look --roll` を使う |

円弧は `camera_math.py arc` が `translation` だけを出す。**注視するかは呼び出し側の選択**。
既存の `aim` があれば `rotation` より優先されるので、バンク・主観の回転を足しても消される。
`roll` という独自JSONフィールドやカメラの `parent` を作らず、既存のキーに焼く。

回転は四元数の最短経路で補間される。**360°回転を始点と終点の同じ四元数だけで書くと動かない**。
意図した回転方向が保たれるよう、隣接キーの角度差を180°未満にして中間を打つ。
真下向きは forward だけでは画面上の北が決まらないので、yaw の基準も明示する。

## 8.7 身体の揺れを主要経路に重ねる

既存のスキーマには揺れ専用トラックが無い。**主要経路を評価した位置・向きに補助動作を
合成し、最後に `translation` / `rotation` のキー1列ずつに焼く**。同時刻のキーを重ねない。

- 並進: `p(t) = p_base(t) + rotate(q_base(t), offset_local(t))`。
  カメラの右・上・前後の揺れを世界座標へ直す。高さの揺れなら世界YかローカルYかを選ぶ。
- 回転: `q(t) = q_base(t) * q_local_offset(t)`。四元数を成分ごとに足さない。
  主観の見回しと呼吸の pitch、歩調の小さな roll を合成するときも同じ。
- 呼吸・歩調は `A × sin(2πft + phase)` などで記述できる。歩行は実際の接地に位相を合わせ、
  停止区間で歩行の振幅だけを0へ滑らかにする。各カットで無理由に位相をリセットしない。
- ノイズは同じ時刻に同じ値が出る連続的な信号にする。毎フレーム独立乱数を足すと細かなちらつきになる。
- 足の接地・着地・反動は発生時刻以降の減衰応答にする。全尺を同じ強さで揺らさない。
- 振幅はm / 度、周期はHz、時刻はカット内秒として決める。レンズと距離で見え方が変わるため、
  固定の強度を全カットへ流用しない。人体の厳密なシミュレーションと称さない。
- 主要経路と同じ時刻列へ焼き、最も速い揺れの1周期を最低8点程度から試す（作画上の開始値）。
  大きな回転はさらに細分化。始点・終点だけでなく揺れの極値や接地の前後でも構図を測る。

揺れはプリビズを再生して調整し、動画生成での微小動作の厳密一致は保証しない。
2Dの画面全体の揺れだけなら合成も候補だが、視差や体の移動は再現できない。

## 8.8 空撮・FPVの経路を作る

カメラの高さは**世界Yのm**、地表との間隔は**その地点の地形高との差**。
平面上でY一定の移動を地形追従と呼ばない。地形や建物は代役を置き、途中での遮蔽と通過空間を確認する。

| 軌道 | 実装する内容 |
|---|---|
| Dronie | 注視するノードを決めて `aim`。そのノードから離れつつYを上げる `translation` |
| Rocket / Top-down の移動 | XZを固定してYを変える / 地面に沿ってXZを変える。真下の一定姿勢なら `aim` を外し pitch=-90°と方位を固定 |
| Helix / Spiral descent | 円弧の角度とともに高さを変える。`arc --to-height`。半径も変えるなら `--to-radius` |
| 円周の拡大 / 縮小 | `arc --to-radius`。注視して回るか向きを保つかは§8.6で選ぶ |
| Boomerang | 離れて上昇する区間と戻って下降する区間の楕円軌道を連続にする。途中で位置・速度を飛ばさない |
| Reveal | 遮蔽物・稜線を置き、何が見える時刻かを測る。開始から対象が露出していたら直す |
| 地形沿い・低空・開口通過 | 通過点を世界座標で並べ、各点の地表間隔と開口を確認。直線補間で壁や山を横切らないよう点を足す |
| FPV chase / bank / dive / swoop | 接線方向から yaw / pitch を決め（バンク無しなら §8.9 の `follow_path`）、旋回で roll を加える。進行先と注視対象は必ずしも同じではない。急降下後の引き起こしを連続にする |

見せ場と次カットの接続に必要な終点を先に決める。経路中の距離と水平線も確認し、
空撮の `far` は最遠の見せたい代役より遠くする。`near`・`far`・fov は現行スキーマで許す範囲に収める。

例（既存の `arc` を拡張。`height` は中心Yへの相対値ではなく世界Y）:

```sh
python3 <SKILL_DIR>/scripts/camera_math.py arc --center 0 0 0 --radius 8 --height 3 \
  --to-height 18 --to-radius 14 --from-deg 0 --to-deg 180 --start 0.5 --end 6 --step 10
python3 <SKILL_DIR>/scripts/camera_math.py look --yaw 30 --pitch -20 --roll 15
```

前者の出力をカメラの `keys.translation` に置き、中心の人物を注視するなら `aim`、
向きを固定するなら `aim` と回転キーを外す。後者は向きとバンクの四元数。
roll の正はローカル視線軸（-Z）について右手系。機体の回転と背景の見かけの回転は逆なので、
画面の傾きを再生して確認する。補間結果は経路の代表点と曲がり角で測り、最後は通しで見る。

## 8.9 曲線の経路と進む向き（フライスルー・語のあいだを縫う）

キーとキーの間は**既定で直線**（曲がり角で向きが折れる）。キーを全部通る滑らかな曲線にするなら、
`keys.path: "smooth"`。ノードの `keys` にも同じ指定ができる（物が弧を描いて回り込む）。

```json
"camera": { "fov": 40, "follow_path": true, "transform": { … },
  "keys": { "path": "smooth", "translation": [
    { "t": 0, "v": [0, 1.4, 10] }, { "t": 1.5, "v": [-2.5, 1.6, 5] },
    { "t": 3, "v": [1.5, 1.4, 1.5], "ease": "ease-in-out" } ] } }
```

- **曲線の形は `path`、速さの緩急は各キーの `ease`**（AE の空間補間と時間補間）。通過点を増やすほど曲線は
  意図どおりになる。点の間隔が不揃いでも行き過ぎない（centripetal Catmull-Rom）
- **`follow_path: true` で進む向きを向く**（AE の「パスに沿って方向を設定」）。回転のキーは使われない。
  上は常に +Y なので、バンク（roll）を付けたいときは使わず、§8.8 の `look --roll` で回転を焼く。
  `aim` があれば `aim` が勝つ（見続けたい被写体があるなら `aim`）
- 止まりかけのキーの上でも向きは曲線の形から決まる（ease で速さが 0 でも振り向かない）
- 文字や 2D のカード（look.md §2）を通過点の脇に置き、カメラが**近づく・横切る・抜ける**順に並べる。
  カードが near より手前に入るとそのコマだけ消えるので、通過点はカードから 0.3m 以上離す

## 9. 検算と、本番で起きた外し方

```
python3 <SKILL_DIR>/scripts/camera_math.py look --yaw 30 --pitch -15        # 四元数
python3 <SKILL_DIR>/scripts/camera_math.py look --from 0 1.5 3 --to 2 1.5 0 # 2 点から
python3 <SKILL_DIR>/scripts/camera_math.py pan-speed --from-yaw -20 --to-yaw 25 --seconds 3 --fov 38
python3 <SKILL_DIR>/scripts/camera_math.py push-in --distance 2.4 --end 1.6
python3 <SKILL_DIR>/scripts/camera_math.py dolly-zoom --distance 2.5 --fov 27 --to-distance 3.5
python3 <SKILL_DIR>/scripts/camera_math.py arc --center 0 0 0 --radius 3 --height 1.4 \
  --from-deg 0 --to-deg 90 --start 0.5 --end 3.5 --ease ease-in-out   # translation キー列
```

`<SKILL_DIR>` はこの SKILL.md があるディレクトリ。`arc` は **ease を区間ごとの属性ではなく
キーの時刻の間隔で表す**（区間ごとに `ease-in` / `linear` を混ぜると継ぎ目で速度が跳ぶ）。

動かしたら `probe_previz_scene` を**動きの始点・中間・終点の 3 時刻**で叩き、主役が
`onscreen` か・ヘッドルームが保たれるか・前景が被らないかを見る。

| 外し方（本番 11 シーンで起きたこと） | 直し方 |
|---|---|
| 全カットが「キー 2 つ・t=0 → t=尺」 | hold → 動き → hold。きっかけの時刻を `notes` に書く（§2） |
| 終点が全部 `ease-in-out` | 終わり方の 2 択を選ぶ。追いは `linear`（§2.2） |
| push in が距離の 10% | 下限 +20%、標準 ×1.5（§3） |
| 「tilt up」と書いて `aim` 固定のまま y を 0.2m 上げた | `aim` を外して `rotation`（§5） |
| 高さが全部アイレベル | 頂点と終止で高さを変える（§6） |
| `notes` が語彙の羅列 | 動機を 1 文で（§1） |
| 動くカットが連続 | 固定で区切る。動かすのは 1/3 以下（§7） |
