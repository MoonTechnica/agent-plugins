# シーンごとに「板だけ / 板 + プリビズ」を決める

**方式はシーン単位で決める。** 作品全体・波全体・パイロットの結果で一律にしない。
全部プリビズ、全部グリッド絵コンテ、のどちらも**決めた結果ではなく、決めなかった結果**として
起きる（1 回の判断を写す、機械の数字をそのまま採る、頼まれた言葉をそのまま全シーンへ広げる）。

## 0 現場の基準（これに合わせる）

| 現場の事実 | 出典 |
|---|---|
| **絵コンテは全カットの土台。** 3D レイアウト / プリビズは、絵コンテを見て**リスクのあるカット・シーンにだけ足す** | 薬屋のひとりごと（1 話約 250 カット中、3DLO は約 200）/ 進撃の巨人 / シャフト（3DLO は作画の補助）。CGWORLD 各記事 |
| **足すかどうかは絵コンテの段階で決める。** 基準は「カット内に 3D 要素（船・巨人・建築背景）があるか」「作画でパースを決めてから 3D を後乗せすると苦労するか」 | 進撃の巨人 The Final Season（cgworld.jp/article/202407-shingeki1.html） |
| **何でも 3D にはしない。** アクションに強い作画陣がいるなら作画先行（＝板だけ）にした | 同上（立体機動は作画先行） |
| 3D が担うのは**カメラ・レンズ感・位置関係・パース**。芝居と光は含まないことが多い | 同上 / 薬屋 / シャフト |
| 実写も previs / techvis は**複雑なシークエンスに限る**（多数のキャラの戦闘・大型クリーチャー・複数プレート・スタント・制約のあるセットやロケ）。目的は不確実性とコストを減らすこと | CGW 2013「Orchestrators of the Dream」/ RedShark「Storyboarding and previz」 |

**ここから先は「現場の一般則」ではなく推測**: 会話劇・感情芝居・イメージカットは板だけで足りる
（「会話には使わない」と明言した一次資料は無く、絵コンテで 180 度などを詰める運用からの推測）。

→ **標準は板。プリビズは「空間・カメラ・パース・位置関係」が壊れやすいシーンに足す。**
全シーンがプリビズになる作品は、現場の感覚ではむしろ例外。

## 1 いつ・何を決めるか

④ の字コンテ（`plan_scenes` → `apply_scene_proposal`）が済んだら、**⑤ / ⑤' のどちらにも
着手する前に、全シーンぶんの方式を先に決める。** 作りながら決めると先の方式が次へ引き継がれる。

```
for scene in list_scenes(composition_id):
    get_scene_budget(scene.id)   # layout と previz_recommended（数えられる行だけ。弱い目安）
    list_cuts(scene.id)          # shot / note / 台詞を読んで、数えられない行を足す
→ 1 シーン 1 行の方式表を作る
```

| シーン | 足す理由（現場の基準） | 方式 | 理由（1 行） |
|---|---|---|---|
| S1 | — | 板だけ | 1 人・会話・アップ中心 |
| S2 | 3D 要素・パースの整合 | 板 + プリビズ | 屋敷の広間を 4 方向から見せる |
| S3 | 位置関係が崩れやすい | 板 + プリビズ | 5 人が動きながら会話 |
| S4 | — | 板だけ | イメージカット |

方式は `板だけ` / `板 + プリビズ` が標準の 2 つ。**プリビズだけ（板を作らない）**にしてよいのは
`previz` §0.2 の条件（アップも 3 人以上も無い）に当たるときで、現場の標準ではなく
**この製作系で板 1 枚ぶんの生成費を省く最適化**。理由を書いて選ぶ。

**プリビズを足す条件**（現場の基準を、本リポジトリの語に写したもの）:

- カメラが**大きく動く**（動機のある移動・回り込み・追う）。寄り 1 回や軽い揺れは字コンテの文で足りる
- **パース・空間の整合が要る**: 建築 / 大きな背景 / メカ・船・巨人など 3D 的な被写体 / 同じ場所を多方向から何カットも見せる
- **位置関係が壊れやすい**: 人物が移動・すれ違う / 3 人以上が動く / 身長差・手前奥が芝居の意味を持つ
- **繋がらないと撮り直しが高くつく**: 長いシーン・高額なモデルで撮るシーン

**足さない（板だけ）の典型**: 1〜2 人の静かな会話（切り返しだけでは足さない。180 度は
字コンテと `film-grammar` で詰められる）・感情芝居・決め画・イメージカット・作画に当たるアクション。

## 2 偏りの検算（表を作ったら必ず）

**全シーンが同じ方式になったら、決める前に読み直す。**

1. `previz_recommended` が**機械的に立っただけ**ではないか。これは「2 人以上の切り返し」
   「カメラが動くカットが 1 つ以上」の**弱い目安**で、軽い動きや静かな会話でも立つ。
   現場の基準（§1 の条件）に当たるかを読む。**立った = 組む、ではない**
2. 逆に `false` を「足さない」と読んでいないか。**人の移動・位置関係・パース・別角度の連続**は数えられない
3. プリビズを足したシーンで、**板も作ったか**。アップ（`close_ups ≥ 1`）と 3 人以上は板が要る
4. 全部が同じ結論のままなら、**そうなる理由を表の下に 1 行書く**。書けないなら読み直しが足りない

**3D に渡す精度は先に決める**（現場でリテイクの原因になる）: シルエットまで固めるのか、
キーポーズ（位置と向き）だけか。プリビズは位置・向き・大きさ・タイミングまで（`previz` §1）。

**人が方式を指定したとき**（「全部プリビズで」「絵コンテだけで」）はそれに従う。指定が
**1 シーン・1 区間**なら、そこだけ。言葉を全シーンへ広げない。

## 3 並列に出すとき（波・パイロット）

- **パイロット 1 本は「通しで作り切って実費と絵柄を確かめる」ためで、方式を決めるためではない。**
  パイロットが板だけだったからといって、残りも板だけにしない（逆も同じ）
- `open_work` の `instruction` に、**そのシーンの方式と理由 1 行**を書く
  （例: 「S2 は板 + プリビズ。広間を多方向から見せるので空間を先に固定する」）。
  相手は会話を引き継がないので、書かないと**自分の既定へ倒れる**
- 相手は `get_work_order` の `layout` / `previz_recommended` を見られるが、**方式の決定は
  あなたの表が優先**。食い違ったら表を直してから追伸で伝え直す（`parallel-work` §4）

## 4 途中で変えるとき

**動画生成の前なら変えてよい。** 板だけで組んで空間が振れると分かったらプリビズを足す。
組んだプリビズだけで足りると分かったら板は作らない。変えたら表を直し、相手のスレッドへ追伸で伝える。
**動画生成の後で方式を変えるのは撮り直し**になるので、人に費用を示してから。
