# 採用動画の高解像度化

**ユーザーがアップスケールを明示的に依頼した場合だけ使う手順。**
完成・仕上げ・書き出しの依頼や納品解像度の指定だけでは実行しない（`director` §1.0）。
依頼がある場合も、全シーンの採用・区間修正が揃ってから、依頼された素材だけに行う。
生成解像度は `cinematographer` §0.1。

1. `get_model_capabilities(topaz-video-upscale, video_upscale)` を読み、
   `plan_timeline_upscale` に `composition_id` と `settings` を渡す。
   `settings.target_short_edge` は納品の短辺（720 / 1080 / 2160）。
   倍率指定なら null にして `fields.upscale_factor` を使う。
   `fields.preset` は Proteus / Iris / Gaia 等の補正モデル。ノイズ・圧縮・輪郭・粒子・
   ディテール回復・FPS・H.264 もカタログの語彙で指定する。
   FPS は未指定で元のまま。必要が無ければ詳細値も未指定にする。
2. 重複排除された素材と見積もり・スキップ理由を読む。既定は Topaz Precision / Proteus。
   同じ素材を複数クリップで使っても生成は1回。使用区間ではなく**元動画の全尺**が課金対象。
   既に十分な寸法ならスキップする。4倍超・5分超・実測不足はそのまま報告し、
   再生成や連続アップスケールで埋めない。100素材を超える場合は `variable_ids` で分割する。
3. スキップされない `items[].source` を `sources` として、同じ設定・対象に新しい UUID の
   `batch_id` を付けて `upscale_timeline` へ渡す。クリップに紐づく既存キャンバスに
   結果ノードを追加し、元素材から結果への系譜を残す。同じ素材を複数キャンバスで使う場合も
   生成は1回で、結果を各キャンバスに配置する。紐づくキャンバスが無い場合のみ補完する。
   ノードを自分で追加する必要はない。
   **通信の再送は同じ batch_id・sources・設定**で行う。勝手に新しいIDを発行しない。
4. `get_timeline_upscale` で各素材の完了を追う。`batch_id` を省くと最新バッチを復元できる。
   失敗分の再試行は、返った**同じ sources・settings・batch_id**に新しい `retry_id` を付ける。
   再試行の通信再送でも同じ retry_id を使う。成功分は再生成されず、各素材のキャンバスに残る。
   `jobs[].canvas_id` が各素材のキャンバスを指す。
5. `get_asset_preview` / `ask_gemini` で画・尺・音声・同期を元素材と比べてから
   `apply_timeline_upscale` で適用する。**生成完了だけでは適用されない**。
   選んだ素材を使うこのタイムライン内の全箇所が対象。映像は各クリップの結果ノードに、対応する音声は
   元の素材に固定される。元シーンや別タイムライン、
   クリップの尺・イン点は変わらず、元素材も残る。途中で変わった対象は `conflicts` に残るので
   上書きせず確認する。適用後もクリップから同じキャンバスを開ける。その後、束ねの検査と書き出しを行う。

一括処理の取り込みでは、映像を再エンコードせずに元動画の音声を引き継ぐ。
音声が MP4 非対応の場合のみ AAC へ変換する。検品で音・尺の不整合が見つかれば
適用せず報告する。手元での補修は [ローカルとサーバの分担](local-vs-server.md)。
