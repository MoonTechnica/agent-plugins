# 途中経過の残し方（段が変わったら 1 行）

`share_asset` が「作ったもの」を出すのに対して、こちらは「いまどこにいるか」を出す。

## なぜ要るか

**このプロダクトのターンは長い。** 実測（`docs/designs/2026-09-09-agent-conversation-legibility.md` §0）:

| 実測 | 値 |
|---|---|
| 推論 25 回のターンでテキストを出した回数 | **4 回**（16%） |
| 最初の確定行までの秒数 | 16〜141 秒 |
| 基準づくりの委譲 10 分間に会話へ出た行 | **2 本** |

黙っていても仕事は進むが、**依頼した人には「止まっている」のと区別が付かない**。
道具の呼び出しや思考は会話に残らないので、**残るのは書いた文章だけ**である。

## どこで書くか（この段取りで「状態が変わった」と言えるところ）

| ここを通ったら | 1 行で言うこと |
|---|---|
| 形式が決まった（`set_work_format`） | 何形式で作るか、なぜそれか |
| 基準を宣言した（`declare_deliverable`） | 何をもって完成とするか（尺・比率・intent）。人が追伸で直せること |
| 基準が凍った（脚本 / 作品スタイル / 字コンテ） | 何が決まったか。**次の波が出せるようになった**こと |
| 波を出した（`open_work` → 委譲） | 誰に何を頼んだか、何本か |
| 波が返った | 何が返ってきたか、次に何をするか |
| reviewer の判定が返った（`close_work` の verdict） | 合格 / 不合格と、落ちた基準。次に直す段 |
| 見積もりを出した（§5） | 一発ぶんと現実ぶん |
| 段を飛ばした / 順番を変えた（§1「順番を飛ばしてよいとき」） | **飛ばした理由**。黙って飛ばさない |
| 生成が続けて失敗した | 何が起きていて、次に何を変えるか |

**基準を作る段（脚本・作品スタイル・1 曲目）は 1 人ずつ直列に走る**ので、ここが
いちばん長く無言になりやすい。待たせている自覚があるときほど 1 行置く。

## 書き方

- **1〜2 文**。同僚に「いま何をしているか」を言うつもりで書く
- 道具名・内部 id・JSON を出さない（使ったモデル名は出してよい）
- **道具 1 回ごとには書かない。** 束ごと・状態ごと
- 「作業中です」だけの中身の無い行を書かない。**何が決まったか / 次に何をするか**を入れる
- 素材を作ったら文章で代替せず `share_asset` で実体を出す（§「作ったものは必ず見せる」）
