# 費用の見積もり（詳細）

要点と「いつ見積もるか」は `SKILL.md` §5 にある。ここは**額を出すときに開く**。

## 1. 金額はサーバに数えさせる

```
estimate_scene_generation(request)   # generate_scene と同じ指定。尺はカット列、参照も撮るときと同じ
estimate_asset_generation(request)   # generate_asset と同じ指定（盤面のノードは要らない）
estimate_render(composition_id)      # render_composition。段（寸法・fps）と尺は本文から
get_render_prices()                  # render_previz_scene はこちら（文書の frame で段が決まる）
```

**単価 × 数量を自分で計算しない。** モデルごとに課金の単位が違い（秒 / 枚 / トークン /
分）、段（品質・寸法・解像度・音の有無）、参照素材の実寸による追加課金まで絡む
（単価は全組織で同じ原価。マークアップは無い）。手で数えると 60 倍（分と秒）や 4 倍（品質）の取り違えが起きる。

| 返り値 | 読み方 |
|---|---|
| `credits_min` = `credits_max` | その額で決まり |
| `credits_min` < `credits_max` | 出来上がりの寸法で段が決まる。**max で伝える** |
| `predicted=true` | トークン課金（Seedance）の予測。`aspect_ratio` を渡すと狭まる |
| `available=false` / `price_missing=true` | **不明であって 0 ではない**。`note` の理由を添えて人に上げる |

単価の一覧（`get_model_prices`）は**モデルを比べる表を作るとき**だけ引く。

## 2. 総額の出し方

```
1 パスの費用 = Σ（シーンの数量 × そのシーンで使うモデルの credits_per_unit）
直しの見込み = 直すカットの秒数の見込み × video_edit の単価（gemini-omni-flash。解像度の段）
仕上げの費用 = 採用素材だけの video_upscale の見積もり（明示的な依頼がある場合だけ）
実質の費用   = 1 パスの費用 + 直しの見込み + 仕上げの費用
```

**直しはシーンを撮り直さず、だめなカットの差し替えで行う**（`cinematographer` §5）。撮り直しは
シーン全体の秒数ぶんかかるので、AI からは撮り直さない（人が明確に指示したときだけ。
そのときは承認待ちになり、カードに見積が出る）。直しの見込みの目安は**本番の総尺の
2〜3 割**を 1 回ずつ直す想定。ユーザーには**1 パスと実質の両方**を出す。

人に「撮り直して」と頼まれたら、**そのシーンの 1 パスぶん**を先に言う
（`estimate_scene_generation` で引く）。区間の直しとの差が桁で開くことが多い。

生成と区間修正は最小解像度で見積もる（`cinematographer` §0.1）。アップスケールは
ユーザーが明示的に依頼した場合だけ別項目で含める。完成・仕上げ・書き出しの依頼や
納品解像度の指定だけでは含めない（`director` §1.0）。依頼があり、素材がまだ無く実寸を
渡せない間は見積もりを暫定と伝え、採用素材が揃ったらその素材と納品寸法で
`estimate_asset_generation(task: video_upscale)` を引き直す。

書き出し（`render_composition` / `render_previz_scene`）と画像生成も足す。動画に比べれば
小さいが、カット数が多いと絵コンテだけで無視できない額になる。

- **絵コンテ・設定資料**: `estimate_asset_generation`（`board_sheet` を付ければシートの
  寸法もサーバが決めて数える）
- **書き出し**: `estimate_render(composition_id)`。段（寸法・fps）と尺は本文から数える

**見積もりの tool がエラーを返したら「ツールの不具合で未確定」で済ませない。** エラー文を
そのまま添えて人に上げる（推測の金額で埋めない）。

## 3. モデル選定が費用そのもの

同じ尺でも、選ぶモデルで**桁が変わる**。`list_model_catalog(task, modality)` で候補を
出し、単価を並べてから決める。

**一覧の並び順が既定**で、タスクごとに先頭が品質と単価の釣り合いで選んだモデル。
動画は**用途がはっきりしているなら `use` を渡す**（台詞 `dialogue` / アクション `action` /
実写の人物 `photoreal_people` / 商品 `product` / カメラワーク `camera` / 長回し `long_take` /
キャラの同一性 `character_consistency` / プリビズの動き `previz_motion` / 下書き `draft`）。
向くモデルが先頭に来るので、特別な理由が無ければ先頭を使う。各モデルの `suited_for` に
推されている用途が出る。テスト・尺合わせは `use: draft` の先頭で通す。

| 段 | 方針 |
|---|---|
| 設定資料（画像） | 1 対象 1 枚のシートで撮る（`art-director`）。面ごとに投げると枚数ぶん増える |
| 絵コンテ（画像） | 1 シーン 1 枚のグリッドで撮る（`storyboard`）。構図が決まればよい |
| 本番の動画 | 用途に合うモデルの最小解像度で採用素材を揃え、最後に必要な素材だけアップスケール |
| テスト / 尺合わせ | 一番安いモデルで通してから本番モデルに差し替える |

**いきなり全カットを最高品質で回さない。** 安いモデルで 1 シーン通し、繋がりを
確かめてから本番に上げる。

**マスターは画像 1 枚**（絵コンテ用の静止画。`storyboard` §1.5）で、動画の通し撮りは無い。
同じ場所・同じ光のシーンは 1 枚を使い回せる。
**グリッド絵コンテも省けることがある** —— 撮影ゲートは板かプリビズのどちらか一方で通るので、
アップも 3 人以上の人物も無いシーンでは板を作らない（`previz` §0.2）。シート 1 枚ぶんが浮く。

## 4. クレジット不足で拒否されたとき

生成・書き出し・会話の開始が 402 / "insufficient credits" で拒否されることがある。
補充はアプリの課金画面からで、あなたには操作できない（残高を返す tool も無い）。

- **黙って安いモデルに落とさない。** 何を削るかはユーザーの判断なので選択肢を出す
- 補充を待つ間にできること: 見積もりの提示、安いモデル案、尺の圧縮案

| 削り方 | 影響 |
|---|---|
| 尺を詰める | 内容が減る。いちばん素直 |
| 納品解像度を落とす | 生成は既に最小解像度が基本。納品寸法を下げると仕上げのアップスケール費用を減らせる |
| モデルを下げる | 品質。絵柄が変わることがある |
| 直す区間を絞る | 気になる箇所が残る |

## 5. 依頼の予算（`threads.budget_micro_usd`）

依頼（会話）ごとに使える原価の上限がある。プロジェクト設定
（`agent_policy.request_budget_micro_usd`。既定は 20 USD 相当）から最初の発話で写され、
null なら組織の残高だけが上限。使った額は生成・書き出し・あなた自身のセッションの
原価が自動で積まれる（`usage_events`）。

- 依頼文に「予算 10 ドルまで」とあれば最初の 2 手のあとに `set_thread_budget(micro_usd)`
  （1 USD = 1_000_000）。**下げるだけ**。上げるのは人の決裁（承認待ち `budget_raise`）
- 超えると `generate_scene` / `generate_asset` / `render_composition` が断られ、セッションも
  止まる。**止まる前に**見積もりと縮小案（§4 の表）を出して、収まる形を先に提案する
- 止まったら確定行に「使い切った額 / 残っている段 / 上げるか縮めるか」を書いて終える
  （`closing-the-loop.md` §4）
