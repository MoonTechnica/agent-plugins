# 成果物の置き場所と届け方（作ったものは、必ず DB に登録し、GUI で見られる形にする）

**試作でも途中経過でも、エージェントの成果物はすべて Opusia に登録され（DB）、ユーザーが GUI で
適切に見られること。** 手元（サンドボックス）のファイル・単体の HTML・会話の文章だけで終わらせない。
見えない成果物は、ユーザーにとっては存在しない。

## 0. 守ること（例外なし）

| # | 守ること |
|---|---|
| 1 | **作ったものは必ずサービスに登録する。** 映像・画像・音声 → `register_upload` / 生成 tool で asset に。シーン → `create_previz_scene` 等で DB に。手元に置いただけは成果物ではない |
| 2 | **登録した先が、GUI のどこで開けるかを言える。** 「モーション画面の ○○ シーン」「タイムライン ○○ の 12 秒」「素材タブの ○○」まで。言えないなら見られない場所に置いている |
| 3 | **GUI で見られる形か確かめる。** 開く tool（描画した 1 コマ・`share_asset`・`list_previz_scene_uses`）で、実際に出ることを実測する。登録しただけで見えない（リストに出ない・描画できない・別の場所にある）なら未完成 |
| 4 | **試作もこの対象。** 試作を作ること自体は良い（「1 コーラスだけ先に」等）が、**登録して・場所を言って・本編との関係（本編に入れる手順）を書く**。複製や別タイムラインを作るなら §3 の一文を最初に |

見られない・見つからない成果物が出たら、**それは作業の失敗**。原因を推測で断定せず、
実測（使用箇所・描画・一覧に出るか）を見せて直す。

## 1. 置く先を決める順

| # | 確かめること | 置く先 |
|---|---|---|
| 1 | 依頼に**添付・名指し**されたシーン / タイムライン / 素材があるか | **そこ**。直せるなら `patch_previz_scene` 等で**その場で直す** |
| 2 | 無ければ、**本編のタイムライン**（下書きクリップが並んでいるもの） | 本編のクリップを置き換える（`place_previz_clip` が下書きを上書きする） |
| 3 | 本編に置くと困る事情がある（まだ見せたくない・比較したい・ユーザーが「試作で」と言った） | 別の置き場。**その理由を先に言う**（§3） |

**判断できないときは作る前に聞く。** 作ってから「どちらに置いたか分かりません」は不可。

## 2. 複製・試作・別タイムラインを作らない

- **直す = 既存を直す。** 作り直しのために新しいシーンを作らない（`create_previz_scene` を繰り返さない。
  `.claude/` の他の規則と同じく、`patch_previz_scene` で直せばそのシーンを置いた全部が変わる）。
- **二重に出る（絵と歌詞を別に動かしたい等）ときも複製しない。** 1 つのシーンの**レイヤー**に分ける
  （previz の `references/motion-graphics.md` §2.7）。元のシーンを残したまま歌詞だけの複製を作ると、
  どちらが正本か分からなくなり、直した内容が片方にしか入らない。
- 複製が**本当に要る**とき（1 本のタイムラインだけ変えたい）は `detach_previz_clip`
  （複製して付け替えまで 1 回）。その後に**元の置き場も整理する**（使われなくなった複製を残さない）。
- 試作用のタイムラインは、**特別な理由があるときだけ**。「1 コーラスだけ先に」は本編の該当区間に置けば足りる。作るなら §0 の 4 つ（登録・場所を言う・見られると実測・本編に入れる手順）を満たす。

## 3. 例外で別の場所に置いたら

ユーザーが画面で見つけられるように、**最初の一文**で次を言う（作業の最後ではなく）:

1. **何を・どこに置いたか**（シーン名 + id、タイムライン名 + 何秒から）
2. **なぜ本編ではないか**
3. **本編に入れるにはどうするか**（どの tool を・誰が）

## 4. 完了報告に必ず入れる（実測して書く）

「置きました」は**推測で書かない**。tool の返りと `list_previz_scene_uses` / `timeline_report.py` で確かめた値だけ。

| 項目 | 確かめ方 |
|---|---|
| 置いたシーンの名前と id | tool の返り |
| そのシーンを**使っているタイムライン**と位置（秒） | `list_previz_scene_uses` |
| 本編に入っているか（下書きのままではないか） | `timeline_report.py` の `motion_layers` / クリップ一覧 |
| ユーザーが開いて見る場所 | シーン名 / タイムライン名 / 秒（口頭で辿れるように） |
| 作ったものの実体 | `share_asset`（映像・画像・音声）。シーンなら描画した 1 コマ |

**ずれが見つかったとき**（見ている場所に直したものが入っていない等）は、原因を推測で断定せず、
実測（使用箇所の一覧・版・最終更新）を見せて、**一度で揃える**。選択肢を並べて待つ前に、
本編を正とする（§1）なら**そのまま揃える**。

## 5. 聴けない・見られないものの扱い

**音は誰も聴けない。動画は静止画（`get_asset_preview` の `poster_url` とコンタクトシート）でしか見られない。**

| 自分の目で確かめる（コンタクトシート） | 確かめられない → 「未確認」と書いて人に渡す |
|---|---|
| 構図・色・顔・人物の見た目・カット間の人物の一貫性・継ぎ目 | 口合わせ（音と口の同期）・音質・ナレーションの読みと間・BGM の感じ |
| 撮影済み・取り込み素材の内容（文字起こし `read_transcript` とコンタクトシート） | 曲の聴き取り（曲の地図は `measure_music` の表から読む） |

- **画はまず自分の目**。足りなければ別の時刻のコマをもう 1 枚見る
- 確かめられないことは、完了カードに「未確認」と書いて人に渡す。**確かめたふりをしない**
- 外部の確認が失敗しても作業は止めない（確認だけ飛ばし、「未確認」と書いて続ける）→ [closing-the-loop.md](closing-the-loop.md) §4
- 書き出しの自動の意図判定（L3。コンタクトシートだけを見る）は `agent_policy.media_review`（既定は切）が false なら走らない。可否は人が決める。エージェントが自分で true にしない
