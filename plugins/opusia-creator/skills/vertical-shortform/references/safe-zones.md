# セーフゾーンの実寸（プラットフォーム別）

画面は全プラットフォーム共通で **1080 x 1920（9:16）**。
違うのは **UI がどれだけ覆うか**。

## 1. 共通の安全域

```
        1080 px
   ┌───────────────┐
   │   上 140 px    │  ステータス・アカウント
   ├──┬─────────┬──┤
   │  │         │  │
   │60│  840 x  │180│  右は操作列（いいね・コメント・共有）
   │  │  1280   │  │
   │  │         │  │
   ├──┴─────────┴──┤
   │  下 400-500 px │  キャプション・音源・操作
   └───────────────┘
```

**中央 840 x 1280（左上 x=60, y=140）に収めれば、どこに出しても隠れない。**
§2 の表で各辺が一番深い値（上 140 / 下 500 / 左 60 / 右 180）の内側。
別の寸法で組むときは `python3 <SKILL_DIR>/scripts/safe_zone.py --size <WxH>` が矩形を出す。
1 か所で作って複数のプラットフォームへ出すなら、これを基準にする。

## 2. プラットフォーム別

| | 上 | 下 | 左 | 右 |
|---|---|---|---|---|
| **TikTok** | 約 140 px | 約 400 px | 約 60 px | 約 180 px |
| **Instagram リール** | 約 100 px | **約 500 px**（最も深い） | — | 操作列あり |
| **YouTube ショート** | — | 約 320 px | — | 操作列あり |

**下部が最も深く、プラットフォーム差が大きい**（320〜500 px）。
リールが最も深いので、**リールに出す可能性があるなら下 500 px を空ける**。

## 3. 特に危ない場所

| 場所 | 何が乗るか |
|---|---|
| **右下** | 操作列とキャプションが重なる。**最悪** |
| **左下** | タイトル・投稿者名・購読ボタンが乗る |
| **下端中央** | 音源表示・スクロール誘導 |
| **上端** | 端末のステータスバー（時刻・電波） |

## 4. UI は増える

過去の変更はいずれも**覆う面積が増える方向**だった。

- TikTok にボタンが追加され、右の死角が広がった
- リールの音源表示が拡大し、下がさらに深くなった
- ショートの購読ボタンが大きくなった

**ギリギリに置かない。** 今は見えていても、UI が更新された時点で隠れる。
余裕を持って 840 x 1280 の内側に置くのが、作り直しを避ける唯一の方法。

## 5. 確認のしかた

書き出したものを**実機で、実際のアプリに投稿できる状態にして**見る。
プレビューは UI を重ねないので、**編集画面では最後まで気づけない**。

簡易な確認としては、840 x 1280 の枠を描いた画像を最前面に重ねて、
はみ出しているものが無いかを見る。
